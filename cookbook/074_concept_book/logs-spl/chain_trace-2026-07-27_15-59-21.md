### binary_search_tree (0.0s)

## Binary Search Tree

**Definition.** A *binary search tree* (BST) is a rooted binary tree in which every node $v$ stores a key $k(v)$ drawn from a totally ordered set, subject to the *BST invariant*: for every node $v$, all keys in the left subtree of $v$ are strictly less than $k(v)$, and all keys in the right subtree of $v$ are strictly greater than $k(v)$. Formally, if $L(v)$ and $R(v)$ denote the left and right subtrees,

$$\forall u \in L(v):\ k(u) < k(v), \qquad \forall u \in R(v):\ k(u) > k(v).$$

This invariant holds recursively at every node, not merely at the root.

**Worked Example.** Insert the sequence $\langle 5, 3, 7, 1, 4 \rangle$ into an initially empty BST. The first key, $5$, becomes the root. Key $3 < 5$ goes left; $7 > 5$ goes right. Key $1 < 5$, then $1 < 3$, so it becomes the left child of $3$. Key $4 < 5$, then $4 > 3$, so it becomes the right child of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node. An in-order traversal (left $\to$ root $\to$ right) yields $\langle 1, 3, 4, 5, 7 \rangle$—the keys in sorted order, which is a direct consequence of the invariant.

**Key Theorem (Search Complexity).** A search, insertion, or deletion in a BST containing $n$ nodes requires $O(h)$ comparisons, where $h$ is the height of the tree. For a *balanced* BST, $h = \Theta(\log n)$, giving $O(\log n)$ worst-case operations. In the degenerate case—keys inserted in sorted order—the tree degenerates to a linked list with $h = n - 1$ and $O(n)$ operations. Self-balancing variants (AVL trees, red–black trees) maintain $h = O(\log n)$ unconditionally.

**Lab Cell (SymPy/Python).**

```python
# Minimal BST node; insert and in-order traversal
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root

def inorder(root):
    return [] if root is None else inorder(root.left) + [root.key] + inorder(root.right)

root = None
for k in [5, 3, 7, 1, 4]:
    root = insert(root, k)

print(inorder(root))   # → [1, 3, 4, 5, 7]
```

## Black Height Property

**Definition.** Let $T$ be a red-black tree and let $v$ be any node in $T$. The *black height* of $v$, denoted $\mathrm{bh}(v)$, is the number of black nodes on any simple path from $v$ (exclusive) to a descendant leaf (null sentinel). The *Black Height Property* is the invariant that, for every node $v$ in $T$, every simple path from $v$ to a descendant leaf contains the same number of black nodes. Formally,

$$\forall v \in T,\; \forall \text{ leaves } \ell_1, \ell_2 \text{ descended from } v:\quad \mathrm{bh}(v, \ell_1) = \mathrm{bh}(v, \ell_2).$$

This invariant is one of the five defining properties of a red-black tree and is the structural guarantee that prevents the tree from becoming arbitrarily unbalanced.

**Worked Example.** Consider the following red-black tree (B = black, R = red):

```
        10(B)
       /      \
     5(R)    20(B)
    /   \
  3(B)  7(B)
```

Null sentinels are black. Starting from the root $10$: the path $10 \to 5 \to 3 \to \mathrm{nil}$ passes through $\{10, 3, \mathrm{nil}\}$, contributing $2$ black nodes (excluding $10$, counting $3$ and nil). The path $10 \to 20 \to \mathrm{nil}$ passes through $\{20, \mathrm{nil}\}$, also contributing $2$ black nodes. Every path yields $\mathrm{bh}(\text{root}) = 2$, confirming the property holds.

**Key Theorem.** *A red-black tree on $n$ internal nodes has height at most $2\log_2(n+1)$.*

*Proof sketch.* Let $h$ be the height and $b = \mathrm{bh}(\text{root})$. Because no two consecutive red nodes may appear (the red property), at least half of the nodes on any root-to-leaf path are black, so $b \geq h/2$. A subtree of black height $b$ contains at least $2^b - 1$ internal nodes, giving $n \geq 2^{h/2} - 1$. Solving yields $h \leq 2\log_2(n+1)$, guaranteeing $O(\log n)$ search, insert, and delete. $\blacksquare$

**Lab Cell (SymPy).**

```python
from sympy import symbols, log, solve, simplify

n, h, b = symbols('n h b', positive=True)

# Lower bound on internal nodes given black height b
min_nodes = 2**b - 1

# If b >= h/2, substitute b = h/2 for the tightest bound
bound = min_nodes.subs(b, h/2)

# Solve for h given n internal nodes
h_max = solve(bound - n, h)
print("Height bound:", simplify(h_max[0]))   # 2*log(n + 1)/log(2)
```

### no_red_edge_property (0.0s)

## No Red Edge Property

**Definition.** Let $G = (V, E, w)$ be a weighted undirected graph with distinct edge weights $w : E \to \mathbb{R}$. Given a spanning tree $T \subseteq E$, call an edge $e \in E \setminus T$ a *candidate* edge. Adding $e$ to $T$ creates exactly one cycle $C_e$. We say $T$ satisfies the **No Red Edge Property** if, for every non-tree edge $e$, the weight $w(e)$ is *not* strictly greater than every tree edge on $C_e$. Equivalently, $T$ contains no edge that is the unique maximum-weight edge of any cycle in $G$.

The terminology arises from the red–blue framework: an edge is colored **red** if it is the heaviest edge on some cycle; the property asserts that a minimum spanning tree (MST) must be free of red edges.

**Worked Example.** Consider the graph with vertices $\{A, B, C\}$ and edges
$$e_1 = AB,\ w = 1;\quad e_2 = BC,\ w = 4;\quad e_3 = AC,\ w = 3.$$
Let $T = \{e_1, e_2\}$. The only non-tree edge is $e_3$. Adding $e_3$ creates the cycle $A\text{–}B\text{–}C\text{–}A$. The weights on this cycle are $1, 4, 3$; the maximum is $w(e_2) = 4$, which lies *inside* $T$. Hence $e_2$ is red and $T$ violates the No Red Edge Property. The true MST is $T^* = \{e_1, e_3\}$ with total weight $4$, which admits no red edge.

**Key Theorem (MST Characterization).** *A spanning tree $T$ of $G$ is a minimum spanning tree if and only if $T$ satisfies the No Red Edge Property.*

*Proof sketch.* $(\Rightarrow)$ If $T$ contained a red edge $e^* \in T$ lying on cycle $C$ with some non-tree edge $f$ satisfying $w(f) < w(e^*)$, then swapping $e^*$ for $f$ yields a spanning tree of strictly smaller total weight, contradicting minimality. $(\Leftarrow)$ If $T$ is not an MST, let $T^*$ be an MST; a standard exchange argument produces a red edge in $T$. $\square$

**Lab Cell (SymPy/NetworkX).**

```python
import networkx as nx

G = nx.Graph()
G.add_weighted_edges_from([("A","B",1), ("B","C",4), ("A","C",3)])

T = nx.minimum_spanning_tree(G, algorithm="kruskal")
print("MST edges:", list(T.edges(data=True)))

# Verify No Red Edge Property: no non-tree edge is heavier than all cycle edges
tree_edges = set(T.edges())
for u, v, d in G.edges(data=True):
    if (u, v) not in tree_edges and (v, u) not in tree_edges:
        path_weights = [T[a][b]["weight"] for a,b in zip(
            nx.shortest_path(T,u,v), nx.shortest_path(T,u,v)[1:])]
        assert d["weight"] <= max(path_weights), f"Red edge detected: ({u},{v})"
print("No Red Edge Property satisfied.")
```

### rooted_tree (0.0s)

## Rooted Tree

**Definition.** A *rooted tree* is a connected, acyclic graph $T = (V, E)$ together with a distinguished vertex $r \in V$ called the *root*. The root imposes a natural hierarchical orientation on every edge: each edge $\{u, v\} \in E$ is directed away from $r$, so that $u$ is the *parent* of $v$ if $u$ lies on the unique path from $r$ to $v$. Vertices with no children are called *leaves*; all others are *internal nodes*. The *depth* of a vertex $v$, denoted $d(v)$, is the number of edges on the path from $r$ to $v$, so $d(r) = 0$. The *height* of the tree is $h(T) = \max_{v \in V} d(v)$.

**Worked Example.** Consider the vertex set $V = \{1, 2, 3, 4, 5\}$ with edges $E = \{\{1,2\},\{1,3\},\{2,4\},\{2,5\}\}$ and root $r = 1$. The unique paths from the root determine the following structure: vertex $1$ is the root at depth $0$; vertices $2$ and $3$ are its children at depth $1$; vertices $4$ and $5$ are children of $2$ at depth $2$. The leaves are $\{3, 4, 5\}$ and the height is $h(T) = 2$. The total number of edges satisfies $|E| = |V| - 1 = 4$, consistent with the tree property.

**Theorem (Unique-Path Property).** *In any rooted tree $T$ with root $r$, there exists a unique path between $r$ and every vertex $v \in V$.*

*Proof sketch.* Since $T$ is connected, at least one path from $r$ to $v$ exists. Since $T$ is acyclic, any two distinct paths would together form a cycle—a contradiction. Therefore the path is unique. $\square$

This uniqueness is what makes rooted trees so powerful in algorithms: every vertex has a well-defined *ancestor chain*, enabling efficient divide-and-conquer strategies such as tree traversal and dynamic programming on subtrees.

**Lab Cell.**

```python
from sympy import symbols
from sympy.combinatorics import Permutation
# Build the rooted tree as a parent-pointer dictionary
parent = {2: 1, 3: 1, 4: 2, 5: 2}
root = 1

def depth(v, parent, root):
    d = 0
    while v != root:
        v = parent[v]
        d += 1
    return d

depths = {v: depth(v, parent, root) for v in parent}
depths[root] = 0
print("Depths:", depths)
# Height of the tree
height = max(depths.values())
print("Height:", height)
```

### tree_height (0.0s)

## Tree Height

**Definition.** Let $T$ be a rooted tree with root $r$. The *height* of a node $v$, written $h(v)$, is the length of the longest path (measured in edges) from $v$ to any leaf in the subtree rooted at $v$. The *height of the tree*, written $h(T)$, is defined as the height of the root:

$$h(T) = h(r) = \max_{v \in \text{leaves}(T)} d(r, v),$$

where $d(r, v)$ denotes the number of edges on the unique path from $r$ to leaf $v$. Leaves themselves have height $0$. An empty tree is assigned height $-1$ by convention, which simplifies recursive formulae.

**Recursive characterisation.** For any internal node $v$ with children $c_1, c_2, \ldots, c_k$,

$$h(v) = 1 + \max_{1 \le i \le k} h(c_i).$$

This recurrence is the computational foundation of every tree-height algorithm.

**Worked example.** Consider the binary tree whose edges are $\{(A,B),(A,C),(B,D),(B,E),(C,F)\}$ with root $A$. Applying the recurrence bottom-up: $h(D)=h(E)=h(F)=0$; $h(B)=1+\max(0,0)=1$; $h(C)=1+\max(0)=1$; $h(A)=1+\max(1,1)=2$. Thus $h(T)=2$, confirmed by the path $A\to B\to D$ (or $A\to B\to E$), each containing exactly two edges.

**Theorem (height–node bound).** A binary tree with $n$ nodes satisfies

$$\lfloor \log_2 n \rfloor \le h(T) \le n-1.$$

The lower bound is achieved by a complete binary tree (levels filled left to right), where $n \approx 2^{h+1}$. The upper bound is achieved by a path graph (each node has exactly one child), which degenerates to a linked list.

*Proof sketch.* A complete binary tree of height $h$ contains at most $2^{h+1}-1$ nodes, giving $h \ge \log_2(n+1)-1 > \lfloor \log_2 n\rfloor - 1$, hence the lower bound. A path of $n$ nodes has $n-1$ edges from root to leaf, giving the upper bound. $\square$

**Lab cell.**

```python
from sympy import symbols, Function, Max, Integer
from sympy.combinatorics import *

def tree_height(adj, root):
    """Return height of rooted tree given as adjacency dict {node: [children]}."""
    children = adj.get(root, [])
    if not children:
        return 0
    return 1 + max(tree_height(adj, c) for c in children)

adj = {'A': ['B', 'C'], 'B': ['D', 'E'], 'C': ['F'], 'D': [], 'E': [], 'F': []}
print(tree_height(adj, 'A'))  # Expected: 2
```

### 2_4_tree (19.1s)

## 2 4 Tree

A **2-4 tree** (also written 2–4 tree or (2,4)-tree) is a balanced search tree in which every internal node has between 2 and 4 children and every leaf resides at the same depth. More formally:

**Definition.** A 2-4 tree $T$ satisfies three invariants:
1. *Degree invariant*: every internal node holds $k$ keys and $k+1$ child pointers, where $1 \le k \le 3$.
2. *Search-tree invariant*: for a node with keys $k_1 < k_2 < \cdots < k_m$, the $i$-th subtree contains only values $v$ with $k_{i-1} < v \le k_i$ (using sentinels $k_0 = -\infty$, $k_{m+1} = +\infty$).
3. *Depth invariant*: all external (null) leaves lie at the same depth $h$.

Because every internal node has at least 2 children, a tree of height $h$ stores at least $2^h - 1$ keys; since each node has at most 4 children, it stores at most $4^h - 1$ keys. Solving $n \ge 2^h - 1$ gives $h = O(\log n)$, guaranteeing logarithmic operations.

**Worked Example.** Insert the sequence $\{3, 7, 1, 5, 9, 2\}$ into an initially empty 2-4 tree. After inserting 3, 7, 1, the root holds keys $\langle 1, 3, 7 \rangle$ — a valid 3-node. Inserting 5 would create a 4-key node $\langle 1, 3, 5, 7 \rangle$, violating the degree invariant. We **split**: the median key 5 is promoted to a new root, and the node is divided into $\langle 1, 3 \rangle$ (left child) and $\langle 7 \rangle$ (right child). Continuing with 9 and 2 requires no further splits; the final tree has height 2 and all leaves at depth 2.

**Theorem (Operation Complexity).** In a 2-4 tree with $n$ keys, search, insertion, and deletion each run in $\Theta(\log n)$ worst-case time.

*Proof sketch.* Height is $\Theta(\log n)$ by the degree bounds above. Search visits one node per level. Insertion may trigger a split cascade, but splits propagate upward at most $h$ levels, each taking $O(1)$ time. Deletion is handled by fusing or redistributing keys between siblings, again at most $h$ levels.

**Lab Cell (SymPy).**

```python
from sympy import floor, log

def tree_height_bounds(n: int):
    h_min = int(floor(log(n + 1, 4)))   # max branching
    h_max = int(floor(log(n + 1, 2)))   # min branching
    return h_min, h_max

print(tree_height_bounds(15))   # (1, 3)
print(tree_height_bounds(100))  # (3, 6)
```

The lab cell computes the guaranteed height interval for a given $n$, illustrating how the 2-4 structure confines growth to a narrow logarithmic band regardless of insertion order.

### red_black_tree (19.1s)

## Red Black Tree

**Definition.** A *red-black tree* is a binary search tree in which every node carries one additional attribute, its *color*, drawn from $\{\texttt{RED}, \texttt{BLACK}\}$. The structure satisfies five invariants:

1. Every node is either red or black.
2. The root is black.
3. Every null leaf (sentinel $\texttt{NIL}$) is black.
4. If a node is red, both of its children are black (*no two consecutive red nodes*).
5. For every node $x$, all simple paths from $x$ to a descendant $\texttt{NIL}$ contain the same number of black nodes, called the *black-height* $\text{bh}(x)$.

These invariants together guarantee that the tree remains *approximately balanced*: no path from root to leaf is more than twice as long as any other.

**Worked Example.** Insert the keys $\{10, 20, 30\}$ in order.

- Insert $10$: root, colored black. Tree: $\texttt{B}(10)$.
- Insert $20$: new red right child. Parent is black, so no violation. Tree: $\texttt{B}(10) \to \texttt{R}(20)$.
- Insert $30$: red right child of $20$. Now $20$ (red) has a red child $30$ — invariant 4 violated. Uncle of $30$ is $\texttt{NIL}$ (black), so perform a *left rotation* at $10$ and recolor: $20$ becomes the new black root, with red children $10$ and $30$.

Final tree: $\texttt{B}(20)$, left child $\texttt{R}(10)$, right child $\texttt{R}(30)$.

**Key Theorem.** *A red-black tree storing $n$ internal nodes has height at most $2\log_2(n+1)$.*

*Proof sketch.* Let $h$ be the height and $\text{bh}$ the black-height of the root. By invariant 4, at least half the nodes on any root-to-leaf path are black, so $\text{bh} \ge h/2$. By invariant 5, the subtree rooted at any node with black-height $k$ contains at least $2^k - 1$ internal nodes, giving $n \ge 2^{\text{bh}} - 1 \ge 2^{h/2} - 1$. Solving yields $h \le 2\log_2(n+1)$. $\blacksquare$

As a consequence, search, insertion, and deletion each run in $O(\log n)$ worst-case time.

**Lab Cell.**

```python
# Verify black-height invariant on a small hand-built tree using SymPy

n = symbols('n', positive=True)

# Theoretical height bound
height_bound = 2 * log(n + 1, 2)

# Check bound for n = 3 (our example above, height = 2)
n_val = 3
actual_height = 2
bound_val = ceiling(height_bound.subs(n, n_val))

print(f"n = {n_val}, actual height = {actual_height}, bound = {bound_val}")
assert actual_height <= bound_val, "Invariant violated!"
print("Black-height bound satisfied.")
```

### colour_flip_push_pull (26.8s)

## Colour Flip Push Pull

**Definition.** Let $T$ be a left-leaning red-black (LLRB) tree, in which each node carries a *colour* $c \in \{\text{RED}, \text{BLACK}\}$ encoding the bond between that node and its parent. A **colour flip** at node $h$ is the atomic operation

$$\text{flipColors}(h): \quad c(h) \leftarrow \overline{c(h)},\quad c(h.\text{left}) \leftarrow \overline{c(h.\text{left})},\quad c(h.\text{right}) \leftarrow \overline{c(h.\text{right})},$$

where $\overline{\cdot}$ denotes colour negation. A flip is *valid* precisely when both children of $h$ share the same colour. The **push-down** phase applies a colour flip to any node with two red children before descending further, effectively splitting a 4-node in the 2-3-4 tree analogy and pushing the extra red link upward. The **pull-up** phase, executed on the return path of a recursive call, applies left/right rotations and a colour flip to re-absorb stray red links and restore the LLRB invariants.

**Worked Example.** Consider inserting the key $50$ into the LLRB tree shown below, where a bold edge indicates a red link:

```
        40 (B)
       /     \
   20 (B)   60 (B)
              \
             70 (R)
```

Inserting $50$ as a red node under $60$ produces two consecutive right-leaning red links, violating the left-lean invariant. The pull-up phase first applies a *left rotation* at $60$, then detects that $40$ now has two red children ($20$ and the promoted $60$). A colour flip at $40$ yields $40$ red with both children black, pushing the redness upward for the caller to handle. The black-height is preserved throughout: each path still passes through the same number of black nodes.

**Key Theorem (Invariant Preservation).** Let $h$ be a node satisfying the LLRB invariants before a colour flip. If both $h.\text{left}$ and $h.\text{right}$ are red, then after $\text{flipColors}(h)$:

1. The black-height of every root-to-leaf path is unchanged.
2. No two consecutive red links are introduced on any root-to-leaf path.
3. The left-lean property is preserved provided $h$ is embedded in a correct push-down/pull-up sequence.

*Proof sketch.* Flipping the two children from red to black increments each path's black count by one, while flipping $h$ from black to red decrements it by one; the net change is zero. Consecutive-red violations cannot arise because the flip's precondition guarantees both children were red (hence their subtrees contain no upward-propagating red link).

**Lab Cell (SymPy).**

```python
from sympy import symbols, Eq, solve

# Verify black-height invariance symbolically
bh = symbols('bh', positive=True)
# Before flip: paths through red children contribute bh black nodes
before = bh
# After flip: children become black (+1), parent becomes red (-1)
after = bh + 1 - 1
print(Eq(before, after))   # True: black-height is preserved
```

### left_leaning_property (21.3s)

## Left Leaning Property

**Definition.** A *left-leaning red-black tree* (LLRB tree) is a binary search tree in which every node is colored either red or black, subject to the standard red-black invariants plus one additional structural constraint: the *left-leaning property*, which requires that every red link in the tree connects a node to its *left* child. Equivalently, no node may have a red right child. Formally, for every internal node $v$, if the link from $v$ to its right child is red, the tree violates the left-leaning property and must be repaired.

We denote the color of the link from a node $v$ to its parent by $\mathrm{color}(v) \in \{\mathrm{RED}, \mathrm{BLACK}\}$. The left-leaning property states:

$$\forall v \in T,\quad \mathrm{color}(\mathrm{right}(v)) = \mathrm{RED} \implies \bot.$$

This restriction reduces the number of valid tree shapes, simplifying implementation: only two rotation cases (left-rotate and right-rotate) and one color-flip case are needed during insertion, compared with the four cases required by general red-black trees.

**Worked Example.** Insert the keys $3, 1, 2$ in order into an initially empty LLRB tree.

1. Insert $3$: root, colored black. Tree: $\mathbf{3}$.
2. Insert $1$: placed as left child of $3$ with a red link. Left-leaning property holds.
3. Insert $2$: placed as right child of $1$ with a red link. This creates a *red right link* at node $1$, violating the left-leaning property. A left-rotation at $1$ is applied, making $2$ the left child of $3$ and $1$ the left child of $2$, both via red links. Now two consecutive red left links exist, so a right-rotation at $3$ is applied, followed by a color-flip. The final tree has $2$ as the black root, with red children $1$ (left) and $3$ (right).

**Key Theorem** (Black-Height Uniformity). In any LLRB tree satisfying the left-leaning property, every root-to-null path contains the same number of black links. Consequently, if the tree holds $n$ keys, its height satisfies $h \leq 2\lfloor \log_2(n+1) \rfloor$, guaranteeing $O(\log n)$ search, insertion, and deletion.

*Proof sketch.* Because red links are left-leaning and no two consecutive red links may appear on any root-to-leaf path (inherited from the standard red-black invariant), at most every other link on any path is red. Uniformity of black-height then bounds the total path length by twice the black-height, which is $\lfloor \log_2(n+1) \rfloor$.

**Lab Cell (SymPy).**

```python

print(f"Height bound  (n=15): {height_bound.subs(n, 15)}")   # 8
```

Running this cell confirms that a 15-node LLRB tree has a black-height of $4$ and a worst-case height of $8$, consistent with the theorem.

### 2_4_tree_add_leaf (22.4s)

## 2-4 Tree Add Leaf

**Definition.** A **2-4 tree** (also called a 2-3-4 tree) is a balanced search tree in which every internal node holds between 1 and 3 keys and has between 2 and 4 children, and every leaf resides at the same depth. Formally, a node is called a *2-node*, *3-node*, or *4-node* according to whether it contains 1, 2, or 3 keys respectively. The **add-leaf** operation inserts a new key $k$ while preserving these invariants.

The insertion procedure proceeds in two phases. In the **search phase**, traverse from the root toward the appropriate leaf position by comparing $k$ against each node's keys, descending to the child whose key range contains $k$. In the **split-and-insert phase**, apply a *proactive splitting* strategy: whenever the traversal reaches a 4-node, split it immediately before descending. Splitting a 4-node with keys $\langle a, b, c \rangle$ promotes the median key $b$ into the parent and creates two 2-nodes holding $\langle a \rangle$ and $\langle c \rangle$. Because 4-nodes are split on the way down, the target leaf's parent is guaranteed to have room for a new key upon arrival.

**Worked Example.** Consider the 2-4 tree containing keys $\{2, 5, 8\}$ stored in a single 4-node (the root). Insert $k = 6$.

1. The root is a 4-node, so split it: promote median $5$, yielding a new root $\langle 5 \rangle$ with left child $\langle 2 \rangle$ and right child $\langle 8 \rangle$.
2. Compare $6 > 5$: descend to the right child $\langle 8 \rangle$, a 2-node with room.
3. Insert $6$ into this node, producing the 3-node $\langle 6, 8 \rangle$.

The resulting tree has root $\langle 5 \rangle$, left leaf $\langle 2 \rangle$, and right leaf $\langle 6, 8 \rangle$ — all leaves at depth 1.

**Theorem (Height Bound).** For a 2-4 tree storing $n$ keys, the height $h$ satisfies
$$\log_4 n \;\leq\; h \;\leq\; \log_2 n.$$
Because at most one split occurs per level during top-down insertion and the tree has height $O(\log n)$, each add-leaf operation runs in $\Theta(\log n)$ time.

**Lab Cell.**

```python
h_max = floor(log(n, 2))

for size in [4, 16, 64, 256]:
```

### 2_4_tree_remove_leaf (18.6s)

## 2 4 Tree Remove Leaf

### Definition

A **2-4 tree** (also called a 2-3-4 tree) is a balanced search tree in which every internal node holds between 1 and 3 keys and has between 2 and 4 children, and all leaves reside at the same depth. A **leaf node** is a node with no children; it stores between 1 and 3 keys directly. Removing a key from a leaf proceeds in two phases: locate the target key, then restore the 2-4 invariant if the leaf becomes **underflowing** (i.e., it would be left with 0 keys, violating the minimum-occupancy requirement).

Formally, let $T$ be a 2-4 tree and let $k$ be a key stored at leaf $\ell$. The removal algorithm is:

1. **Simple removal.** If $\ell$ holds 2 or 3 keys, delete $k$ from $\ell$. The node retains at least 1 key; no structural repair is needed.
2. **Underflow repair.** If $\ell$ holds exactly 1 key (a 2-node), deleting $k$ leaves $\ell$ empty. Two sub-cases apply:
   - *Transfer (rotation).* If an adjacent sibling $s$ under the same parent $p$ holds 2 or 3 keys, rotate: pull the separator key from $p$ down into $\ell$, and push the sibling's nearest key up into $p$ in its place. $\ell$ now holds 1 key and $s$ loses one key without underflowing.
   - *Fusion (merge).* If every adjacent sibling is a 2-node, merge $\ell$ with one sibling $s$ and the separator key from $p$ into a single 3-node. Remove the separator from $p$. If $p$ itself becomes a 2-node that underflows, propagate the fix upward.

### Worked Example

Consider a leaf $\ell = [17]$ with parent $p = [15, 20]$ and sibling $s = [18, 19]$. Removing $17$ from $\ell$ triggers underflow. Since $s$ holds 2 keys, apply transfer: pull separator $18$ from $p$ into $\ell$ (giving $\ell = [18]$) and push $19$ up into $p$ (giving $p = [15, 19]$). No merge is required.

### Key Theorem

**Theorem (Leaf Removal Complexity).** In a 2-4 tree with $n$ keys, removing a key from a leaf requires at most $O(\log n)$ comparisons and at most $O(\log n)$ structural fixups, since tree height satisfies $h = O(\log n)$ and each level requires at most one transfer or fusion.

### amortized_potential_method (18.3s)

## Amortized Potential Method

**Definition.** Let $D$ denote the set of possible data-structure states, and let $\Phi: D \to \mathbb{R}_{\geq 0}$ be a *potential function* satisfying $\Phi(D_0) = 0$ for the initial state $D_0$. For an operation $i$ with actual cost $c_i$ that transitions the structure from state $D_{i-1}$ to $D_i$, the *amortized cost* is defined as

$$\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1}).$$

The key accounting identity follows immediately: summing over a sequence of $n$ operations,

$$\sum_{i=1}^{n} \hat{c}_i = \sum_{i=1}^{n} c_i + \Phi(D_n) - \Phi(D_0) \geq \sum_{i=1}^{n} c_i,$$

since $\Phi(D_n) \geq 0$ and $\Phi(D_0) = 0$. Thus an upper bound on $\sum \hat{c}_i$ is simultaneously an upper bound on the total actual cost. The analyst's task is to choose $\Phi$ cleverly so that every $\hat{c}_i$ is small, absorbing the occasional expensive operation into accumulated potential.

**Worked Example: Dynamic Array Doubling.** Consider an array that doubles capacity whenever it is full. Let $\Phi(D) = 2s - m$, where $s$ is the current number of elements and $m$ is the current capacity. Initially $s = m = 0$, so $\Phi = 0$.

- *Ordinary push* (no resize): $c_i = 1$, $s$ increases by 1, $m$ unchanged, so $\Delta\Phi = 2$. Thus $\hat{c}_i = 1 + 2 = 3$.
- *Push triggering resize*: capacity doubles from $m$ to $2m$; the resize copies $m$ elements, so $c_i = m + 1$. After the operation $s = m + 1$ and the new capacity is $2m$, giving $\Phi(D_i) = 2(m+1) - 2m = 2$ and $\Phi(D_{i-1}) = 2m - m = m$. Hence $\hat{c}_i = (m+1) + (2 - m) = 3$.

Every operation has amortized cost exactly 3, so $n$ pushes cost $O(n)$ in total.

**Theorem (Potential Method Bound).** *If $\Phi \geq 0$ everywhere and each amortized cost $\hat{c}_i \leq T$, then the total actual cost of $n$ operations satisfies $\sum_{i=1}^{n} c_i \leq nT$.*

*Proof sketch.* By definition, $\sum c_i = \sum \hat{c}_i - \Phi(D_n) + \Phi(D_0) \leq nT - 0 + 0 = nT$. $\square$

```python
print("Total actual cost bound:", simplify(total_actual))
```

### red_black_2_4_correspondence (18.3s)

## Red Black 2 4 Correspondence

**Definition.** A *2-3-4 tree* is a perfectly height-balanced search tree in which every internal node holds either one key (a **2-node**, with two children), two keys (a **3-node**, with three children), or three keys (a **4-node**, with four children), and every leaf resides at the same depth. A *red-black tree* is a binary search tree in which each node carries a color bit—red or black—satisfying four invariants: (1) the root is black; (2) red nodes have only black children; (3) every root-to-null path contains the same number of black nodes (the *black-height*); and (4) null sentinels are black. The **red-black/2-3-4 correspondence** is a bijection: every 2-3-4 tree maps to a unique red-black tree, and vice versa, obtained by "splitting" multi-key nodes into binary clusters of black and red nodes.

**Translation rules.** A 2-node with key $k$ becomes a single black node. A 3-node with keys $k_1 < k_2$ becomes a black node for $k_2$ with a red left child $k_1$ (or symmetrically $k_1$ black with red right child $k_2$). A 4-node with keys $k_1 < k_2 < k_3$ becomes a black node $k_2$ with a red left child $k_1$ and a red right child $k_3$.

**Worked example.** Consider the 4-node $[10, 20, 30]$. Applying the rule gives a black node $20$, red left child $10$, and red right child $30$. Inserting the value $25$ into the 2-3-4 tree splits the 4-node into a 2-node $20$ promoted to the parent, with children $[10]$ and $[30]$. In the red-black representation this corresponds to *color-flipping*: nodes $10$ and $30$ turn black, and $20$ turns red (then re-blackened at the root), exactly matching the red-black insertion rebalancing step.

**Key theorem.** A red-black tree of black-height $h$ corresponds to a 2-3-4 tree of height $h$. Because a 2-3-4 tree storing $n$ keys has height $\Theta(\log n)$, every operation on a red-black tree runs in $O(\log n)$ worst-case time.

**Lab cell.**

```python
print(f"Red left child:  {red_left}")
print(f"Red right child: {red_right}")

```

Running this cell confirms that the bijection preserves search-tree order: every node satisfies $k_{\text{left}} < k_{\text{root}} < k_{\text{right}}$, so in-order traversal of the red-black tree recovers the sorted sequence of the original 2-3-4 node.

### red_black_add (19.9s)

## Red Black Add

**Definition.** A *red-black tree* is a binary search tree in which every node carries a colour attribute, either *red* or *black*, satisfying the following invariants:

1. Every node is red or black.
2. The root is black.
3. Every null leaf (sentinel) is black.
4. A red node has no red children (*no double-red*).
5. Every simple path from a node to any descendant null leaf contains the same number of black nodes (*black-height uniformity*).

The operation **red\_black\_add** inserts a key $k$ into such a tree while restoring all five invariants. The algorithm proceeds in two phases. Phase 1 performs an ordinary BST insertion, colouring the new node red to preserve black-height. Phase 2 applies a sequence of local *fix-up* rotations and recolourings to eliminate any double-red violation introduced by Phase 1.

**Worked Example.** Consider inserting $k = 4$ into the tree with root $10$ (black), left child $5$ (black), and $5$'s left child $2$ (red). Standard BST insertion places $4$ as the right child of $2$, coloured red. Now $2$ (red) has a red child $4$, violating Invariant 4. The fix-up procedure inspects $4$'s uncle, which is the null sentinel (black). This triggers a *right rotation* at $5$ followed by a *left rotation* at $10$, then a recolouring: $5$ becomes black and its two children $2$ and $10$ become red. All five invariants hold in the resulting tree.

**Key Theorem** *(Logarithmic Height).* A red-black tree storing $n$ keys has height at most $2\log_2(n+1)$. Because at least half of any root-to-leaf path must be black (Invariant 4) and all such paths have equal black-height $h_b$ (Invariant 5), the total height satisfies $h \leq 2h_b \leq 2\log_2(n+1)$. Consequently, **red\_black\_add** runs in $O(\log n)$ time in the worst case, performing at most $O(\log n)$ fix-up steps with at most two rotations total.

### red_black_remove (24.2s)

## Red Black Remove

**Definition.** A *red-black tree* is a binary search tree in which every node carries a colour attribute $c \in \{\text{RED}, \text{BLACK}\}$ and the following invariants hold: (I) the root is BLACK; (II) every RED node has two BLACK children; (III) every root-to-null path contains the same number of BLACK nodes, called the *black-height* $\text{bh}(T)$. The **red-black remove** operation deletes a key $k$ while restoring all four invariants through a bounded sequence of recolouring steps and rotations.

**Procedure.** Deletion proceeds in two phases.

*Phase 1 — BST splice.* Locate the node $u$ holding key $k$. If $u$ has two non-null children, replace $k$ with its in-order successor $v$ (the minimum of the right subtree) and redirect deletion to $v$, which has at most one non-null child. Let $x$ be the child that replaces the spliced node (possibly a sentinel null, conceptually coloured BLACK).

*Phase 2 — Fixup.* If the removed node was RED, no invariant is violated and the procedure terminates. If it was BLACK, the path through $x$ loses one black unit, creating a *double-black* deficit. The fixup loop propagates or resolves this deficit via four cases keyed on the colour of $x$'s sibling $s$:

| Case | Condition | Action |
|------|-----------|--------|
| 1 | $s$ is RED | Rotate parent toward $x$; recolour — transforms to case 2, 3, or 4 |
| 2 | $s$ is BLACK, both children of $s$ BLACK | Recolour $s$ RED; push deficit to parent |
| 3 | $s$ is BLACK, $s$'s far child BLACK, near child RED | Rotate $s$ away from $x$; recolour — transforms to case 4 |
| 4 | $s$ is BLACK, $s$'s far child RED | Rotate parent toward $x$; recolour far child and parent BLACK |

Each iteration either terminates (cases 1→4, 3→4, case 4) or moves the deficit one level up (case 2), so the loop executes $O(\log n)$ times.

**Key Theorem.** Red-black remove runs in $O(\log n)$ time and performs at most three rotations.

*Proof sketch.* The BST splice is $O(\log n)$ by tree height. The fixup loop ascends at most $O(\log n)$ levels. Cases 1 and 3 each trigger exactly one rotation before reaching a terminal case; case 4 is always terminal with one rotation. Hence total rotations $\leq 3$. $\blacksquare$

**Worked Example.** Delete $15$ from the tree with keys $\{10, 15, 20\}$ where $15$ is the BLACK root, $10$ and $20$ are RED leaves. The in-order successor of $15$ is $20$; splice replaces $15$ with $20$ and removes $20$'s original node (RED) — no fixup required. The resulting tree has BLACK root $20$ and RED left child $10$, satisfying all invariants.

```python
    """Return black-height of a sentinel-terminated path (recursive)."""

    left  = black_height(node.get('left'),  new_bh)
```

### red_black_performance (16.8s)

## Red Black Performance

**Definition.** A *red-black tree* is a self-balancing binary search tree in which every node carries a colour bit (red or black) subject to four invariants: (1) the root is black; (2) every leaf (NIL sentinel) is black; (3) both children of every red node are black; (4) every simple path from a given node to any descendant leaf contains the same number of black nodes, called the *black-height* $bh(x)$ of node $x$. These invariants together bound the height of an $n$-node tree.

**Key Theorem (Height Bound).** For a red-black tree with $n$ internal nodes, the height $h$ satisfies

$$h \leq 2\log_2(n+1).$$

*Proof sketch.* By invariant (4), every subtree rooted at $x$ contains at least $2^{bh(x)}-1$ internal nodes. Since invariant (3) prevents two consecutive red nodes, at least half of the nodes on any root-to-leaf path are black, giving $bh(\text{root}) \geq h/2$. Combining: $n \geq 2^{h/2}-1$, so $h \leq 2\log_2(n+1)$. $\square$

Because search, insertion, and deletion each traverse at most one root-to-leaf path, all three operations run in $O(\log n)$ worst-case time—unlike an ordinary BST, which degrades to $O(n)$ on sorted input.

**Worked Example.** Insert the keys $\{10, 20, 30\}$ into an empty red-black tree. After inserting 10 (root → coloured black), insert 20 as a red right child of 10—no violation. Insert 30 as a red right child of 20: this creates two consecutive red nodes (violation of invariant 3). A single left rotation at node 10 and a colour swap yield 20 as the new black root with red children 10 and 30. The black-height is 1 throughout; $h = 2 \leq 2\log_2(4) = 4$. ✓
