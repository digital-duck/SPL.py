### recursion (0.0s)

## Recursion

**Definition.** A function $f$ is defined *recursively* if its value at an argument is expressed in terms of its value at one or more strictly simpler arguments, together with one or more *base cases* that terminate the descent. Formally, a recursive definition specifies:

1. **Base case(s):** explicit values $f(n_0), f(n_1), \ldots$ for the smallest inputs.
2. **Recursive case:** a rule $f(n) = g\bigl(n,\, f(n-1),\, f(n-2),\ldots\bigr)$ for $n$ beyond the base cases, where $g$ involves only arguments strictly less than $n$.

Well-foundedness—the guarantee that repeated application of the recursive case always reaches a base case—is what separates a valid recursive definition from a circular one.

**Worked example: the factorial function.** Define $n!$ for $n \in \mathbb{N}_0$ by

$$
0! = 1, \qquad n! = n \cdot (n-1)! \quad \text{for } n \geq 1.
$$

Computing $4!$ unwinds as follows:

$$
4! = 4 \cdot 3! = 4 \cdot 3 \cdot 2! = 4 \cdot 3 \cdot 2 \cdot 1! = 4 \cdot 3 \cdot 2 \cdot 1 \cdot 0! = 24.
$$

Each call reduces $n$ by $1$; since $n$ is a non-negative integer, the chain terminates at $0!$ in exactly $n$ steps. The *call stack* at depth $k$ holds the pending multiplication $k \cdot (\cdots)$, so the process requires $O(n)$ space as well as $O(n)$ time.

**Key theorem (Structural Induction Principle).** Let $P(n)$ be a property of natural numbers. If $P(0)$ holds, and $P(k)$ implies $P(k+1)$ for every $k \geq 0$, then $P(n)$ holds for all $n \in \mathbb{N}_0$. This principle is the mathematical counterpart of recursion: the base case mirrors the inductive base; the inductive step mirrors the recursive case. Any terminating recursion can therefore be reasoned about by induction, and correctness proofs for recursive algorithms follow this template directly.

## Backtracking

**Definition.** Backtracking is a systematic algorithm design paradigm for solving constraint-satisfaction and combinatorial search problems. Given a partial candidate solution, the algorithm extends it one component at a time; whenever an extension violates a problem constraint, the algorithm *backtracks*—it undoes the most recent choice and tries the next available alternative. Formally, let $\mathcal{S}$ be a finite set of candidates representable as sequences $(c_1, c_2, \dots, c_k)$ with $c_i \in D_i$. A *constraint predicate* $P(c_1,\dots,c_j)$ is evaluated incrementally; backtracking performs a depth-first traversal of the implicit search tree, pruning every subtree rooted at a node that violates $P$.

**Worked Example: Four-Queens Problem.** Place four non-attacking queens on a $4\times 4$ chessboard. Represent a solution as a tuple $(c_1, c_2, c_3, c_4)$ where $c_i \in \{1,2,3,4\}$ is the column of the queen in row $i$. The constraint is that no two queens share a column or diagonal: for all $i \neq j$,

$$c_i \neq c_j \quad \text{and} \quad |c_i - c_j| \neq |i - j|.$$

Starting with $c_1 = 1$: we try $c_2 = 1$ (column conflict, prune), $c_2 = 2$ (diagonal conflict, prune), $c_2 = 3$ (valid). Continuing, $c_3 = 1$ (diagonal conflict), $c_3 = 2$ (conflict), $c_3 = 3$ (column conflict), $c_3 = 4$ (conflict)—all pruned. Backtrack to $c_2 = 4$; proceed to find the solution $(1, 3, ?, ?)$. Exhausting $c_1 = 1$ ultimately yields $(2,4,1,3)$ and $(3,1,4,2)$ as the two distinct solutions.

**Key Theorem (Pruning Efficiency).** Let $T$ be the search tree explored by backtracking and $T_0$ the full $\prod_i |D_i|$-leaf tree of all candidate sequences. Then $|T| \leq |T_0|$, with equality only when no constraint eliminates any partial candidate early. In practice, effective pruning reduces $|T|$ exponentially relative to brute-force enumeration.

**Lab Cell.**

```python
from sympy.combinatorics import Permutation

def four_queens():
    solutions = []
    def bt(queens):
        r = len(queens)
        if r == 4:
            solutions.append(tuple(queens)); return
        for c in range(4):
            if all(c != q and abs(c - q) != r - i
                   for i, q in enumerate(queens)):
                bt(queens + [c])
    bt([])
    return solutions

print(four_queens())   # [(1, 3, 0, 2), (2, 0, 3, 1)]
```

## Binary Search Tree

**Definition.** A *binary search tree* (BST) is a rooted binary tree in which every node $v$ stores a key $k(v)$ drawn from a totally ordered set, subject to the *BST invariant*: for every node $v$, all keys in the left subtree of $v$ are strictly less than $k(v)$, and all keys in the right subtree of $v$ are strictly greater than $k(v)$. Formally, if $L(v)$ and $R(v)$ denote the left and right subtrees,

$$\forall u \in L(v):\ k(u) < k(v), \qquad \forall u \in R(v):\ k(u) > k(v).$$

This invariant holds recursively at every node, not merely at the root.

**Worked Example.** Insert the sequence $\langle 5, 3, 7, 1, 4 \rangle$ into an initially empty BST. The first key, $5$, becomes the root. Key $3 < 5$ goes left; $7 > 5$ goes right. Key $1 < 5$, then $1 < 3$, so it becomes the left child of $3$. Key $4 < 5$, then $4 > 3$, so it becomes the right child of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node. An in-order traversal (left $\to$ root $\to$ right) yields $\langle 1, 3, 4, 5, 7 \rangle$—the keys in sorted order, which is a direct consequence of the invariant.

**Key Theorem (Search Complexity).** A search, insertion, or deletion in a BST containing $n$ nodes requires $O(h)$ comparisons, where $h$ is the height of the tree. For a *balanced* BST, $h = \Theta(\log n)$, giving $O(\log n)$ worst-case operations. In the degenerate case—keys inserted in sorted order—the tree degenerates to a linked list with $h = n - 1$ and $O(n)$ operations. Self-balancing variants (AVL trees, red–black trees) maintain $h = O(\log n)$ unconditionally.

**Lab Cell (SymPy/Python).**

```python
# Minimal BST node; insert and in-order traversal
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root

def inorder(root):
    return [] if root is None else inorder(root.left) + [root.key] + inorder(root.right)

root = None
for k in [5, 3, 7, 1, 4]:
    root = insert(root, k)

print(inorder(root))   # → [1, 3, 4, 5, 7]
```

### divide_and_conquer_root_choice (20.4s)

## Divide And Conquer Root Choice

**Definition.** Given a continuous function $f : [a, b] \to \mathbb{R}$ with $f(a)$ and $f(b)$ of opposite sign, the *divide-and-conquer root choice* (commonly called the **bisection method**) is the iterative procedure that locates a root $c \in [a, b]$ satisfying $f(c) = 0$ by repeatedly halving the search interval. At each step $k$, a midpoint $m_k = \tfrac{a_k + b_k}{2}$ is evaluated, and the subinterval $[a_k, m_k]$ or $[m_k, b_k]$ is retained according to which endpoint pair preserves opposite signs. The method exploits the **Intermediate Value Theorem**: if $f$ is continuous and $f(a_k) \cdot f(b_k) < 0$, then a root exists inside the interval.

**Worked Example.** Let $f(x) = x^3 - x - 2$. Note $f(1) = -2 < 0$ and $f(2) = 4 > 0$, so a root lies in $[1, 2]$.

| Step | $a_k$ | $b_k$ | $m_k$ | $f(m_k)$ | New interval |
|------|--------|--------|--------|-----------|--------------|
| 1 | 1.000 | 2.000 | 1.500 | $-0.125$ | $[1.5, 2.0]$ |
| 2 | 1.500 | 2.000 | 1.750 | $+1.609$ | $[1.5, 1.75]$ |
| 3 | 1.500 | 1.750 | 1.625 | $+0.666$ | $[1.5, 1.625]$ |

After step 3 the root is bracketed within an interval of width $0.125$, already half the original in each iteration. The true root is $x^* \approx 1.5214$.

**Key Theorem (Linear Convergence).** After $n$ bisection steps, the absolute error satisfies

$$|m_n - x^*| \leq \frac{b - a}{2^n}.$$

*Proof sketch.* Each iteration discards exactly half the current interval; by induction, the interval width after $n$ steps is $(b-a)/2^n$, and $x^*$ remains inside every retained interval, so the midpoint deviates from $x^*$ by at most half that width. $\square$

To achieve tolerance $\varepsilon$, one requires at least $n \geq \lceil \log_2((b-a)/\varepsilon) \rceil$ steps — a predictable, guaranteed cost regardless of $f$'s shape.

**Lab Cell (SymPy).**

```python
from sympy import symbols, Rational

def bisect(f, a, b, tol=1e-6, maxiter=50):
    a, b = Rational(a), Rational(b)
    for _ in range(maxiter):
        m = (a + b) / 2
        if f(m) == 0 or (b - a) / 2 < tol:
            return float(m)
        if f(a) * f(m) < 0:
            b = m
        else:
            a = m
    return float((a + b) / 2)

x = symbols('x')

print(bisect(f, 1, 2))   # → 1.521379...
```

## Exponential Running Time

**Definition.** An algorithm runs in *exponential time* if its worst-case running time is bounded by $T(n) = O(2^n)$, or more generally $O(c^n)$ for some constant $c > 1$. Formally, we say $T(n) \in O(2^n)$ if there exist positive constants $C$ and $n_0$ such that

$$T(n) \leq C \cdot 2^n \quad \text{for all } n \geq n_0.$$

Unlike polynomial-time algorithms whose cost grows as $n^k$ for some fixed $k$, an exponential-time algorithm's cost doubles (or multiplies by $c$) with every unit increase in input size. This growth rate renders such algorithms computationally infeasible for all but the smallest inputs.

**Worked Example.** Consider the naïve recursive computation of the $n$-th Fibonacci number:

$$F(n) = F(n-1) + F(n-2), \quad F(0) = 0,\ F(1) = 1.$$

Each call spawns two sub-calls, producing a binary recursion tree of depth $n$. The number of function calls satisfies the recurrence $T(n) = T(n-1) + T(n-2) + O(1)$, whose solution grows as $T(n) = O(\phi^n)$ where $\phi = \frac{1+\sqrt{5}}{2} \approx 1.618$ is the golden ratio. For $n = 50$, this yields on the order of $10^{10}$ calls — already impractical on modern hardware — compared to just 50 steps for the linear iterative version.

**Theorem (Exponential Lower Bound for Brute-Force Search).** Any algorithm that enumerates all subsets of an $n$-element set must perform at least $2^n$ operations, since the power set $\mathcal{P}(S)$ has exactly $2^n$ elements. Consequently, subset-enumeration problems — including the exact 0/1 Knapsack decision problem — have no known polynomial-time solutions, and naïve approaches are inherently exponential.

The practical implication is stark: a problem solvable in $1$ second at $n = 20$ would require approximately $2^{10} \approx 1000$ seconds at $n = 30$, and over $10^9$ years at $n = 90$.

### subtraction_recurrence_trick (0.0s)

## Subtraction Recurrence Trick

**Definition.** Let $\{a_n\}$ be a sequence satisfying a linear recurrence of the form

$$a_n = a_{n-1} - f(n), \quad n \geq 1,$$

where $f(n)$ is a known function of $n$ and $a_0$ is given. The *subtraction recurrence trick* is the technique of telescoping this recurrence—summing both sides over a range of indices—to express $a_n$ as a closed-form sum and, when possible, evaluate that sum in closed form. More precisely, writing

$$a_n - a_{n-1} = -f(n)$$

and summing from $k = 1$ to $k = n$ yields the **telescoping identity**

$$a_n = a_0 - \sum_{k=1}^{n} f(k).$$

The utility of this trick lies in reducing a recursive definition to a direct formula, provided the resulting sum $\sum_{k=1}^{n} f(k)$ is recognisable (e.g., arithmetic, geometric, or a standard closed form).

---

**Worked Example.** Define the sequence by $a_0 = 10$ and $a_n = a_{n-1} - \frac{1}{n(n+1)}$ for $n \geq 1$. Applying the telescoping identity:

$$a_n = 10 - \sum_{k=1}^{n} \frac{1}{k(k+1)}.$$

Using partial fractions, $\dfrac{1}{k(k+1)} = \dfrac{1}{k} - \dfrac{1}{k+1}$, so the sum telescopes further:

$$\sum_{k=1}^{n} \frac{1}{k(k+1)} = 1 - \frac{1}{n+1} = \frac{n}{n+1}.$$

Therefore $a_n = 10 - \dfrac{n}{n+1}$, a closed form requiring no iteration.

---

**Key Theorem (Telescoping Sum).** *If $a_n - a_{n-1} = g(n)$ for all $n \geq 1$, then*

$$a_n = a_0 + \sum_{k=1}^{n} g(k).$$

*Proof sketch.* Write out the $n$ equations $a_1 - a_0 = g(1),\ a_2 - a_1 = g(2),\ \ldots,\ a_n - a_{n-1} = g(n)$ and add them. Every intermediate term $a_1, a_2, \ldots, a_{n-1}$ cancels, leaving $a_n - a_0 = \sum_{k=1}^{n} g(k)$. $\square$

---

**Lab Cell (SymPy).**

```python
from sympy import symbols, Sum, factor, simplify, Rational

n, k = symbols('n k', positive=True, integer=True)

f = 1 / (k * (k + 1))
closed_sum = Sum(f, (k, 1, n)).doit()   # telescopes symbolically
a_n = 10 - closed_sum
print("Closed form:", simplify(a_n))    # 10 - n/(n+1)

# Verify numerically for n = 5

for i in range(1, 6):
    a -= Rational(1, i * (i + 1))

print("a_5 (formula):  ", a_n.subs(n, 5))
```

## Optimal Binary Search Tree

**Definition.** Let $K = \langle k_1, k_2, \ldots, k_n \rangle$ be a sorted sequence of $n$ distinct keys, and let $p_i$ denote the probability that a search targets key $k_i$. Define $n+1$ *dummy keys* $d_0, d_1, \ldots, d_n$ representing unsuccessful searches, with $q_j$ the probability of a query falling between $k_j$ and $k_{j+1}$. We require $\sum_{i=1}^{n} p_i + \sum_{j=0}^{n} q_j = 1$. An **optimal binary search tree (OBST)** is a binary search tree over $K$ that minimises the expected search cost

$$E[\text{cost}] = \sum_{i=1}^{n} (d_i + 1)\, p_i + \sum_{j=0}^{n} (d_j + 1)\, q_j,$$

where $d_i$ denotes the depth of node $k_i$ (root at depth 0).

**Worked Example.** Consider $n = 3$ keys with probabilities $p_1 = 0.15,\ p_2 = 0.10,\ p_3 = 0.05$ and dummy-key probabilities $q_0 = 0.25,\ q_1 = 0.20,\ q_2 = 0.15,\ q_3 = 0.10$. Applying the Knuth–Yao recurrence, define $e[i,j]$ as the minimum expected cost of a BST over keys $k_i, \ldots, k_j$, and $w[i,j] = \sum_{l=i}^{j} p_l + \sum_{l=i-1}^{j} q_l$ as the total probability mass. The base cases are $e[i,i-1] = q_{i-1}$. For each subproblem of length $\ell$, we try every root $r \in \{i,\ldots,j\}$:

$$e[i,j] = \min_{r=i}^{j}\bigl\{e[i,r-1] + e[r+1,j]\bigr\} + w[i,j].$$

Filling the table bottom-up yields the OBST with $k_1$ as root ($E[\text{cost}] \approx 2.75$), outperforming a naïve balanced tree.

**Key Theorem (Knuth 1971).** There exists an optimal root $r^*(i,j)$ such that $r^*(i,j-1) \leq r^*(i,j) \leq r^*(i+1,j)$. This *monotone root* property allows the inner minimisation to scan only $O(1)$ amortised candidates, reducing the naive $O(n^3)$ algorithm to $O(n^2)$ time and space.

**Lab Cell.**

```python
from sympy import symbols, Rational, Matrix

p = [Rational(15,100), Rational(10,100), Rational(5,100)]
q = [Rational(25,100), Rational(20,100), Rational(15,100), Rational(10,100)]
n = len(p)

e = [[Rational(0)] * (n + 2) for _ in range(n + 2)]
w = [[Rational(0)] * (n + 2) for _ in range(n + 2)]
for i in range(1, n + 2):
    e[i][i - 1] = q[i - 1]
    w[i][i - 1] = q[i - 1]

for length in range(1, n + 1):
    for i in range(1, n - length + 2):
        j = i + length - 1
        w[i][j] = w[i][j-1] + p[j-1] + q[j]
        e[i][j] = min(e[i][r-1] + e[r+1][j] for r in range(i, j+1)) + w[i][j]

print("Minimum expected search cost:", e[1][n])
```
