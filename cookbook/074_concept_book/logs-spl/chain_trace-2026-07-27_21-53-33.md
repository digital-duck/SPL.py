## Maximum Flow

**Definition.** Let $G = (V, E)$ be a directed graph with a designated *source* $s \in V$ and *sink* $t \in V$. A *capacity function* $c : E \to \mathbb{R}_{\geq 0}$ assigns a non-negative upper bound to each edge. A *flow* is a function $f : E \to \mathbb{R}_{\geq 0}$ satisfying two conditions:

1. **Capacity constraint**: $0 \leq f(u,v) \leq c(u,v)$ for all $(u,v) \in E$.
2. **Flow conservation**: for every vertex $v \notin \{s, t\}$,
$$\sum_{u:(u,v)\in E} f(u,v) = \sum_{w:(v,w)\in E} f(v,w).$$

The *value* of the flow is $|f| = \sum_{w:(s,w)\in E} f(s,w)$, the total flow leaving the source. The **maximum flow problem** asks for a flow $f^*$ that maximises $|f|$ subject to the above constraints.

**Worked Example.** Consider the graph with vertices $\{s, a, b, t\}$ and directed edges:

$$s \xrightarrow{10} a, \quad s \xrightarrow{8} b, \quad a \xrightarrow{5} b, \quad a \xrightarrow{7} t, \quad b \xrightarrow{9} t.$$

One feasible flow assigns $f(s,a)=7$, $f(s,b)=8$, $f(a,b)=0$, $f(a,t)=7$, $f(b,t)=8$, giving $|f|=15$. No augmenting path from $s$ to $t$ remains in the residual graph, so $|f^*|=15$.

**Key Theorem (Max-Flow Min-Cut).** For any network $(G, c, s, t)$,

$$\max_{f} |f| = \min_{(S,T)} \sum_{\substack{u \in S,\, v \in T \\ (u,v)\in E}} c(u,v),$$

where the minimum is taken over all *$s$–$t$ cuts* $(S, T)$, i.e., partitions $V = S \cup T$ with $s \in S$ and $t \in T$. The theorem follows from the Ford–Fulkerson method: the algorithm terminates precisely when no augmenting path exists in the residual graph, at which point the set of vertices reachable from $s$ in that graph defines a minimum cut.

**Lab Cell.**

```python
import sympy as sp
from sympy.combinatorics.named_groups import *

# SymPy does not ship a max-flow solver; use NetworkX for computation.
import networkx as nx

G = nx.DiGraph()
G.add_edge('s', 'a', capacity=10)
G.add_edge('s', 'b', capacity=8)
G.add_edge('a', 'b', capacity=5)
G.add_edge('a', 't', capacity=7)
G.add_edge('b', 't', capacity=9)

flow_value, flow_dict = nx.maximum_flow(G, 's', 't')
print("Maximum flow value:", flow_value)   # Expected: 15
print("Flow on each edge:", flow_dict)
```

Running this cell confirms $|f^*| = 15$ and exhibits the edge-level flow decomposition, illustrating both the capacity constraints and conservation law at every interior vertex.

## Tuple Selection

**Definition.** A *tuple* of length $n$ over a collection of sets $S_1, S_2, \ldots, S_n$ is an ordered sequence $t = (t_1, t_2, \ldots, t_n)$ where each component $t_i \in S_i$. The *$i$-th selection function* (also called the $i$-th *projection*) is the map

$$\pi_i : S_1 \times S_2 \times \cdots \times S_n \longrightarrow S_i, \qquad \pi_i(t_1, t_2, \ldots, t_n) = t_i.$$

Indexing is conventionally 1-based in mathematics and 0-based in most programming languages; context always governs which convention applies. Tuple selection is a *total* function: it is defined for every tuple in the domain, and it returns exactly one value.

**Worked Example.** Let $t = (3, \, \pi, \, \texttt{"hello"}, \, \mathrm{True})$, a 4-tuple drawn from $\mathbb{Z} \times \mathbb{R} \times \Sigma^* \times \mathbb{B}$. Applying the projection functions gives

$$\pi_1(t) = 3, \quad \pi_2(t) = \pi, \quad \pi_3(t) = \texttt{"hello"}, \quad \pi_4(t) = \mathrm{True}.$$

Notice that each projection *forgets* all components except the selected one. In a relational database, tuple selection generalises to the *projection operator* $\Pi_A$, which retains a subset of attributes $A$ from every row of a relation.

**Key Theorem (Universal Property of Products).** Given any set $X$ and functions $f_i : X \to S_i$ for $i = 1, \ldots, n$, there exists a *unique* function $\langle f_1, \ldots, f_n \rangle : X \to S_1 \times \cdots \times S_n$ such that

$$\pi_i \circ \langle f_1, \ldots, f_n \rangle = f_i \quad \text{for all } i.$$

This universal property characterises the Cartesian product up to isomorphism: the projections $\pi_i$ are the canonical interface through which the product is observed. Any compound function that extracts the $i$-th result can always be factored through $\pi_i$.

**Lab Cell.**

```python
from sympy import symbols, Tuple

# Construct a symbolic 4-tuple
a, b, c, d = symbols('a b c d')
t = Tuple(a, b, c, d)

# Tuple selection (0-based in SymPy)
print(t[0])   # a   — π₁
print(t[2])   # c   — π₃

# Verify via slice: project onto components {1, 3}
projection = Tuple(t[1], t[3])
print(projection)   # (b, d)
```

Running this cell confirms that `t[i]` implements $\pi_{i+1}$ exactly, and that composing two projections into a new tuple realises the pairing map $\langle f_1, f_2 \rangle$ from the theorem above.

## Exam Scheduling

**Definition.** An *exam scheduling problem* is a constraint satisfaction problem defined by a triple $(E, S, C)$, where $E = \{e_1, e_2, \ldots, e_n\}$ is a set of exams, $S = \{s_1, s_2, \ldots, s_m\}$ is a set of students, and $C \subseteq E \times E$ is a *conflict relation* such that $(e_i, e_j) \in C$ if and only if at least one student is enrolled in both $e_i$ and $e_j$. A *valid schedule* is a function $f : E \to T$, where $T = \{1, 2, \ldots, k\}$ is a set of time slots, satisfying $f(e_i) \neq f(e_j)$ for all $(e_i, e_j) \in C$. The *chromatic number* $\chi(G)$ of the conflict graph $G = (E, C)$ gives the minimum number of slots required.

**Worked Example.** Suppose a department offers five exams $\{A, B, C, D, E\}$ and enrolment data yields the conflict graph edges $\{(A,B),(A,C),(B,C),(B,D),(C,E),(D,E)\}$. Construct $G$ and seek a valid 3-colouring. Assign slot 1 to $A$; since $B$ and $C$ conflict with $A$, assign slot 2 to $B$ and slot 3 to $C$. Exam $D$ conflicts with $B$ (slot 2) but not with slots 1 or 3, so assign slot 1 to $D$. Exam $E$ conflicts with $C$ (slot 3) and $D$ (slot 1), so assign slot 2 to $E$. The schedule $f = \{A\!\to\!1,\, B\!\to\!2,\, C\!\to\!3,\, D\!\to\!1,\, E\!\to\!2\}$ is valid, confirming $\chi(G) \leq 3$.

**Key Theorem (Graph Colouring Lower Bound).** For any conflict graph $G$, the chromatic number satisfies
$$\chi(G) \geq \omega(G),$$
where $\omega(G)$ denotes the *clique number*, i.e., the size of the largest complete subgraph. *Proof sketch:* Every pair of exams within a clique conflicts mutually, so they must all receive distinct slots; thus at least $\omega(G)$ slots are necessary. In general $\chi(G)$ may exceed $\omega(G)$ (graphs that are not perfect), but for interval graphs arising in many practical timetabling instances, $\chi(G) = \omega(G)$.

**Lab Cell (SymPy / NetworkX).**

```python
import networkx as nx

G = nx.Graph()
G.add_edges_from([('A','B'),('A','C'),('B','C'),
                  ('B','D'),('C','E'),('D','E')])

colouring = nx.coloring.greedy_color(G, strategy='largest_first')
num_slots  = max(colouring.values()) + 1

print("Assignment:", colouring)
print("Slots used:", num_slots)
print("Clique lower bound:", nx.graph_clique_number(G))
```

Running this cell prints the slot assignment and confirms that the greedy algorithm achieves the theoretical lower bound on this instance, illustrating how graph-theoretic tools translate directly into practical scheduling decisions.
