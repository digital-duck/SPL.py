## Graph

**Definition.** A *graph* $G$ is an ordered pair $G = (V, E)$, where $V$ is a finite nonempty set whose elements are called *vertices* (or *nodes*), and $E \subseteq \{\{u, v\} : u, v \in V,\, u \neq v\}$ is a set of two-element subsets of $V$ called *edges*. The *order* of $G$ is $|V|$ and the *size* is $|E|$. When an edge $\{u, v\} \in E$ exists, the vertices $u$ and $v$ are said to be *adjacent*, and each is a *neighbor* of the other. The *degree* of a vertex $v$, written $\deg(v)$, counts the number of edges incident to $v$.

**Worked Example.** Let $V = \{1, 2, 3, 4\}$ and $E = \{\{1,2\},\{1,3\},\{2,4\},\{3,4\}\}$. This graph has order 4 and size 4. Computing degrees: $\deg(1) = 2$ (adjacent to 2 and 3), $\deg(2) = 2$, $\deg(3) = 2$, $\deg(4) = 2$. The sum of all degrees equals $2 + 2 + 2 + 2 = 8 = 2|E|$, which illustrates the handshaking identity below.

**Key Theorem (Handshaking Lemma).** For any graph $G = (V, E)$,
$$\sum_{v \in V} \deg(v) = 2|E|.$$
*Proof sketch.* Each edge $\{u,v\}$ contributes exactly 1 to $\deg(u)$ and exactly 1 to $\deg(v)$, so it is counted exactly twice in the sum over all vertices. Summing over all $|E|$ edges gives $2|E|$. $\square$

An immediate corollary is that the number of vertices of odd degree is always even, a fact with far-reaching consequences in the theory of Eulerian paths.

### vertex_degree (0.0s)

## Vertex Degree

**Definition.** Let $G = (V, E)$ be an undirected graph with vertex set $V$ and edge set $E \subseteq \binom{V}{2}$. The *degree* of a vertex $v \in V$, denoted $\deg(v)$, is the number of edges incident to $v$:

$$\deg(v) = \bigl|\{\, e \in E \mid v \in e \,\}\bigr|.$$

A vertex with degree zero is called *isolated*. In a directed graph, one distinguishes the *in-degree* $\deg^-(v)$ (edges entering $v$) from the *out-degree* $\deg^+(v)$ (edges leaving $v$), with $\deg(v) = \deg^-(v) + \deg^+(v)$.

---

**Worked Example.** Consider the graph $G$ with $V = \{A, B, C, D\}$ and edges $E = \{AB, AC, BC, CD\}$.

| Vertex | Incident edges | Degree |
|--------|---------------|--------|
| $A$    | $AB,\, AC$    | $2$    |
| $B$    | $AB,\, BC$    | $2$    |
| $C$    | $AC,\, BC,\, CD$ | $3$ |
| $D$    | $CD$          | $1$    |

Observe that $\sum_{v \in V} \deg(v) = 2 + 2 + 3 + 1 = 8 = 2|E|$, since each edge contributes exactly one to each of its two endpoint degrees.

---

**Theorem (Handshaking Lemma).** For any undirected graph $G = (V, E)$,

$$\sum_{v \in V} \deg(v) = 2|E|.$$

*Proof sketch.* Define the incidence sum $S = \sum_{v \in V} \deg(v)$. Each edge $e = \{u, w\}$ is counted once when $v = u$ and once when $v = w$, contributing exactly $2$ to $S$. Summing over all $|E|$ edges gives $S = 2|E|$. $\square$

An immediate corollary is that every graph contains an even number of vertices of odd degree — a fact used repeatedly in Eulerian circuit theory.

---

### adjacency_list (0.0s)

## Adjacency List

**Definition.** Let $G = (V, E)$ be a graph with vertex set $V = \{v_1, v_2, \ldots, v_n\}$ and edge set $E \subseteq V \times V$. The *adjacency list* representation of $G$ is a collection of $n$ lists $A = (A[v_1], A[v_2], \ldots, A[v_n])$, where each list $A[v_i]$ contains exactly the neighbors of $v_i$:

$$A[v_i] = \bigl\{ u \in V : (v_i, u) \in E \bigr\}.$$

For an undirected graph, the edge $\{u, v\}$ appears in both $A[u]$ and $A[v]$. For a directed graph, the arc $(u, v)$ appears only in $A[u]$. The total storage consumed is $\Theta(|V| + |E|)$, since the union of all lists has size $|E|$ (directed) or $2|E|$ (undirected), and we maintain one list header per vertex.

**Worked Example.** Consider the undirected graph $G$ with $V = \{1, 2, 3, 4\}$ and $E = \{\{1,2\},\{1,3\},\{2,4\},\{3,4\}\}$. The adjacency list is:

$$A[1] = [2,\,3],\quad A[2] = [1,\,4],\quad A[3] = [1,\,4],\quad A[4] = [2,\,3].$$

The degree of vertex $1$ is $\deg(1) = |A[1]| = 2$, consistent with the handshaking lemma $\sum_{v \in V} \deg(v) = 2|E| = 8$.

**Key Theorem (Space–Time Trade-off).** Let $G$ have $n$ vertices and $m$ edges. The adjacency list supports neighbor enumeration of a vertex $v$ in $\Theta(\deg(v))$ time and edge existence queries in $O(\deg(v))$ time. By contrast, an adjacency matrix supports existence queries in $O(1)$ but requires $\Theta(n^2)$ space. For *sparse* graphs where $m = O(n)$, the adjacency list is strictly preferable; for *dense* graphs where $m = \Theta(n^2)$, both representations consume comparable space.

**Lab Cell.**

```python
import sympy as sp
from collections import defaultdict

edges = [(1,2),(1,3),(2,4),(3,4)]
adj = defaultdict(list)
for u, v in edges:
    adj[u].append(v)
    adj[v].append(u)          # omit for directed graphs

for vertex, neighbors in sorted(adj.items()):
    print(f"A[{vertex}] = {neighbors}")

# Degree sequence
degrees = [len(adj[v]) for v in sorted(adj)]
print("Degree sequence:", degrees)
print("Sum of degrees:", sum(degrees), "= 2|E| =", 2*len(edges))
```

Running this cell prints the four neighbor lists and confirms $\sum \deg(v) = 8$, verifying the handshaking lemma computationally.

### graph_traversal (0.0s)

## Graph Traversal

**Definition.** Let $G = (V, E)$ be a graph with vertex set $V$ and edge set $E \subseteq V \times V$. A *traversal* of $G$ is a systematic procedure that visits every vertex reachable from a designated source $s \in V$ exactly once, recording the order of discovery. The choice of data structure governing which vertex to explore next determines the traversal strategy. **Breadth-First Search (BFS)** uses a FIFO queue: starting from $s$, BFS discovers all vertices at distance $k$ before any vertex at distance $k+1$, where distance is measured in hop count. This level-by-level expansion is the defining characteristic of BFS and forms the basis for shortest-path computation in unweighted graphs.

**Worked Example.** Consider the undirected graph $G$ with $V = \{1,2,3,4,5\}$ and edges $E = \{(1,2),(1,3),(2,4),(3,4),(4,5)\}$, with source $s = 1$.

BFS initialises the queue with $[1]$ and marks 1 as visited. It dequeues 1 and enqueues its neighbours $\{2, 3\}$, yielding queue $[2, 3]$. It dequeues 2 and enqueues unvisited neighbour 4, yielding $[3, 4]$. It dequeues 3; neighbour 4 is already visited, so nothing is added. It dequeues 4 and enqueues 5. Finally, it dequeues 5, which has no unvisited neighbours. Discovery order: $1, 2, 3, 4, 5$. Vertices at distance 1 from the source ($\{2,3\}$) appear before those at distance 2 ($\{4\}$), which appear before distance 3 ($\{5\}$), exactly as the definition requires.

**Key Theorem (Complexity).** For a graph represented as an adjacency list, BFS runs in time $\Theta(|V| + |E|)$ and uses $O(|V|)$ auxiliary space. This linear bound is optimal: any correct traversal must inspect every edge at least once to guarantee reachability.

*Proof sketch.* Each vertex is enqueued at most once, contributing $O(|V|)$ operations. Each edge $(u,v)$ is examined when $u$ is processed; in an undirected graph each edge appears in two adjacency lists, yielding $2|E|$ edge inspections total. The total work is therefore $O(|V| + |E|)$. The matching lower bound holds because an adversary can hide an unvisited vertex behind any unexamined edge, so no algorithm can do better.

## Stack

**Definition.** A *stack* is an abstract data type that maintains an ordered collection of elements subject to a single discipline: the element most recently inserted is the first to be removed. This policy is called *last-in, first-out* (LIFO). Formally, a stack $S$ over a set $\mathcal{U}$ supports three primitive operations:

- $\operatorname{push}(S, x)$: insert element $x \in \mathcal{U}$ onto the top of $S$.
- $\operatorname{pop}(S)$: remove and return the top element of $S$; undefined on an empty stack.
- $\operatorname{peek}(S)$: return the top element without removing it.

The *size* $|S|$ denotes the number of elements currently held. A stack of capacity $n$ implemented on an array satisfies $0 \le |S| \le n$. Each of the three operations executes in $O(1)$ time.

**Worked example.** Consider evaluating the arithmetic expression $3\;4\;+\;2\;\times$ written in *reverse Polish notation* (postfix). Scanning left to right:

| Token | Action | Stack (bottom → top) |
|-------|--------|----------------------|
| $3$ | push | $[3]$ |
| $4$ | push | $[3,\,4]$ |
| $+$ | pop twice, push $3+4$ | $[7]$ |
| $2$ | push | $[7,\,2]$ |
| $\times$ | pop twice, push $7\times 2$ | $[14]$ |

The final element $14$ is the result. At every step the operands needed for an operator are exactly the two topmost elements, so a single stack suffices with no lookahead—a direct consequence of the LIFO discipline.

**Theorem (stack-sortable permutations).** The number of distinct permutations of $\{1,2,\dots,n\}$ that can be sorted using a single stack (i.e., passed through push/pop operations in a fixed left-to-right scan) equals the $n$-th Catalan number

$$C_n = \frac{1}{n+1}\binom{2n}{n}.$$

*Proof sketch.* A permutation is stack-sortable if and only if it avoids the pattern $231$. A bijection between $231$-avoiding permutations of length $n$ and full binary trees with $n$ internal nodes establishes the count $C_n$, which satisfies the recurrence $C_{n+1} = \sum_{k=0}^{n} C_k C_{n-k}$ with $C_0 = 1$.

**Lab cell.**

```python
from sympy import binomial, factorial, symbols, simplify

n = symbols('n', positive=True, integer=True)

def catalan(k):
    return binomial(2*k, k) // (k + 1)

# Verify C_0 through C_6
print([catalan(k) for k in range(7)])
# → [1, 1, 2, 5, 14, 42, 132]

# Postfix evaluator using a Python list as a stack
def eval_postfix(tokens):
    stack = []
    ops = {'+': lambda a,b: a+b, '*': lambda a,b: a*b,
           '-': lambda a,b: a-b, '/': lambda a,b: a/b}
    for t in tokens:
        if t in ops:
            b, a = stack.pop(), stack.pop()
            stack.append(ops[t](a, b))
        else:
            stack.append(float(t))
    return stack[0]

print(eval_postfix(['3','4','+','2','*']))  # → 14.0
```

## Depth First Search

**Definition.** Let $G = (V, E)$ be a finite graph with vertex set $V$ and edge set $E$. *Depth-first search* (DFS) is a graph traversal algorithm that begins at a designated source vertex $s \in V$ and explores as far as possible along each branch before backtracking. Formally, DFS maintains a set $\text{visited} \subseteq V$ and, upon visiting vertex $u$, recursively visits every neighbour $v \in N(u)$ for which $v \notin \text{visited}$. Each vertex receives two timestamps: a *discovery time* $d[u]$ when it is first entered, and a *finish time* $f[u]$ when all descendants of $u$ have been fully explored.

**Worked Example.** Consider the directed graph $G$ with $V = \{1, 2, 3, 4, 5\}$ and edges $E = \{(1,2),(1,3),(2,4),(3,4),(4,5)\}$. Starting DFS from vertex $1$ with neighbours visited in numerical order:

1. Visit $1$: $d[1] = 1$. Recurse to $2$.
2. Visit $2$: $d[2] = 2$. Recurse to $4$.
3. Visit $4$: $d[4] = 3$. Recurse to $5$.
4. Visit $5$: $d[5] = 4$, $f[5] = 5$. Backtrack to $4$: $f[4] = 6$.
5. Backtrack to $2$: $f[2] = 7$. Recurse from $1$ to $3$.
6. Visit $3$: $d[3] = 8$; neighbour $4$ already visited, so $f[3] = 9$.
7. Finish $1$: $f[1] = 10$.

The DFS produces the finish-time ordering $f[5] < f[4] < f[2] < f[3] < f[1]$.

**Key Theorem (Parenthesis Theorem).** For any two vertices $u, v$ in a DFS of $G$, exactly one of the following holds: the intervals $[d[u], f[u]]$ and $[d[v], f[v]]$ are disjoint, or one is entirely contained within the other. Formally,

$$[d[v], f[v]] \subseteq [d[u], f[u]] \iff v \text{ is a descendant of } u \text{ in the DFS forest.}$$

This nesting structure is the foundation for cycle detection, topological sorting, and strongly connected component algorithms, all of which run in $\Theta(|V| + |E|)$ time.

**Lab Cell.**

```python
import sympy
from sympy.combinatorics.named_groups import SymmetricGroup

# Build adjacency list and run DFS with timestamps
graph = {1: [2, 3], 2: [4], 3: [4], 4: [5], 5: []}
visited, d, f, timer = set(), {}, {}, [0]

def dfs(u):
    visited.add(u)
    timer[0] += 1; d[u] = timer[0]
    for v in graph[u]:
        if v not in visited:
            dfs(v)
    timer[0] += 1; f[u] = timer[0]

dfs(1)
print("Discovery:", d)   # {1:1, 2:2, 4:3, 5:4, 3:8}
print("Finish:   ", f)   # {5:5, 4:6, 2:7, 3:9, 1:10}
```

Running this cell reproduces the timestamps computed by hand, confirming the parenthesis theorem: the interval $[2,7]$ for vertex $2$ properly contains $[3,6]$ for vertex $4$, which in turn contains $[4,5]$ for vertex $5$.

## Cycle Detection Via Dfs

**Definition.** A *cycle* in a directed graph $G = (V, E)$ is a sequence of vertices $v_0, v_1, \ldots, v_k$ with $k \geq 1$ such that $(v_i, v_{i+1}) \in E$ for $0 \leq i < k$ and $v_k = v_0$. A graph containing no cycle is called a *directed acyclic graph* (DAG). Cycle detection asks: given $G$, does it contain at least one cycle?

The standard algorithm exploits *depth-first search* (DFS) and a three-color vertex coloring scheme. Each vertex is assigned one of three states:

- **White** ($0$): not yet visited.
- **Gray** ($1$): currently on the DFS recursion stack (i.e., the path from the root to the current vertex).
- **Black** ($2$): fully processed; all descendants have been explored.

A *back edge* — an edge $(u, v)$ where $v$ is Gray at the time $u$ is being explored — witnesses a cycle, because $v$ lies on the current DFS path and $u$ is reachable from $v$, so the edge $(u, v)$ closes a loop.

**Worked Example.** Consider $G$ with vertices $\{A, B, C\}$ and edges $A \to B$, $B \to C$, $C \to A$. DFS from $A$: color $A$ Gray, recurse to $B$, color $B$ Gray, recurse to $C$, color $C$ Gray. Exploring $C$'s neighbor $A$ reveals $A$ is Gray — a back edge is found, confirming a cycle.

**Theorem (Correctness).** A directed graph $G$ contains a cycle if and only if a DFS of $G$ produces a back edge.

*Proof sketch.* ($\Rightarrow$) If a cycle $v_0 \to \cdots \to v_k = v_0$ exists, DFS must eventually enter $v_0$, making it Gray. Before $v_0$ turns Black, DFS must traverse all vertices reachable from $v_0$, including $v_{k-1}$. When $v_{k-1}$ examines edge $(v_{k-1}, v_0)$, it finds $v_0$ Gray, yielding a back edge. ($\Leftarrow$) A back edge $(u, v)$ with $v$ Gray implies $v$ is an ancestor of $u$ in the DFS tree; the tree path from $v$ to $u$ together with $(u, v)$ forms a cycle. $\square$

Time complexity is $\Theta(|V| + |E|)$, matching standard DFS.

**Lab Cell (SymPy / Python).**

```python
def has_cycle(graph: dict[str, list[str]]) -> bool:
    WHITE, GRAY, BLACK = 0, 1, 2
    color = {v: WHITE for v in graph}

    def dfs(u: str) -> bool:
        color[u] = GRAY
        for v in graph[u]:
            if color[v] == GRAY:
                return True          # back edge found
            if color[v] == WHITE and dfs(v):
                return True
        color[u] = BLACK
        return False

    return any(dfs(v) for v in graph if color[v] == WHITE)

# Example: A → B → C → A (cyclic)
G = {"A": ["B"], "B": ["C"], "C": ["A"]}
print(has_cycle(G))   # True

# Example: A → B → C (acyclic)
H = {"A": ["B"], "B": ["C"], "C": []}
print(has_cycle(H))   # False
```

Running this code confirms the theorem: the cyclic graph returns `True` and the acyclic graph returns `False`, with the coloring scheme preventing redundant exploration.
