### decision_problem (17.1s)

## Decision Problem

**Definition.** A *decision problem* is a computational problem whose answer is restricted to one of two values: **yes** or **no**. Formally, a decision problem is a pair $(L, \Sigma)$ where $\Sigma$ is a finite alphabet and $L \subseteq \Sigma^*$ is a language. Given an input string $w \in \Sigma^*$, the problem asks whether $w \in L$. An algorithm *decides* $L$ if it halts on every input and returns the correct yes/no answer. This binary framing is not a restriction in practice: most quantitative problems (e.g., "is the shortest path shorter than $k$?") are reducible to decision form by introducing a threshold parameter.

**Worked Example.** Consider the *primality decision problem*: given a positive integer $n$, decide whether $n$ is prime. The input is the binary encoding of $n$, so the alphabet is $\Sigma = \{0, 1\}$ and the language is $L_{\text{PRIME}} = \{\langle n \rangle : n \text{ is prime}\}$. For $n = 17$, a trial-division algorithm checks divisibility by each integer $d$ with $2 \leq d \leq \lfloor\sqrt{17}\rfloor = 4$. Since $17$ is not divisible by $2$, $3$, or $4$, the algorithm halts and returns **yes**. For $n = 15$, the check $15 = 3 \times 5$ yields **no**. The algorithm terminates for every $n$, so it decides $L_{\text{PRIME}}$ in $O(\sqrt{n})$ arithmetic steps — equivalently, $O(2^{k/2})$ steps where $k = \lfloor\log_2 n\rfloor + 1$ is the bit-length of the input. The landmark result that $L_{\text{PRIME}} \in \mathbf{P}$ was established by the AKS algorithm (Agrawal, Kayal, Saxena, 2002), which runs in $O(k^{12})$ time.

**Key Theorem (Church–Turing).** Every effectively computable function can be computed by a Turing machine. As a corollary, a decision problem is *decidable* if and only if there exists a Turing machine that halts on all inputs and accepts precisely the strings in $L$. Problems for which no such machine exists — such as the *Halting Problem* $L_{\text{HALT}}$ — are called *undecidable*.

**Lab Cell.**

```python
from sympy import isprime

def decide_prime(n: int) -> str:
    return "yes" if isprime(n) else "no"

test_cases = [2, 15, 17, 100, 101]
for n in test_cases:
    print(f"n = {n:>3}  →  {decide_prime(n)}")
```

Running this cell prints `yes` for $n \in \{2, 17, 101\}$ and `no` for $n \in \{15, 100\}$, confirming the decision oracle on five representative inputs. SymPy's `isprime` implements a deterministic Miller–Rabin test for small $n$ and a combination of probabilistic checks for large $n$, illustrating that efficient decision procedures often exploit number-theoretic structure rather than exhaustive search.

### polynomial_time (33.0s)

## Polynomial Time

**Definition.** An algorithm runs in *polynomial time* if there exists a polynomial $p$ such that, for every input of size $n$, the algorithm terminates in at most $p(n)$ elementary operations. Formally, we write the worst-case time complexity as $T(n) = O(n^k)$ for some fixed constant $k \geq 0$. The class of all decision problems solvable by a deterministic algorithm in polynomial time is denoted $\mathbf{P}$.

The choice of $n$ as the *input size* is deliberate: for a graph with $V$ vertices and $E$ edges, $n = |V| + |E|$; for an integer $m$, $n = \lfloor \log_2 m \rfloor + 1$, the number of bits required to encode $m$. This encoding convention ensures that input size reflects the actual information content of the data, not an incidental numeric magnitude.

**Worked Example.** Consider sorting an array of $n$ integers with Merge Sort. At each recursive level the algorithm performs $O(n)$ comparisons, and the recursion depth is $\lceil \log_2 n \rceil$, giving $T(n) = O(n \log n)$. Since $\log n \leq n$ for all $n \geq 1$, we have $T(n) = O(n^2)$, confirming that Merge Sort lies in $\mathbf{P}$ with $k = 2$. By contrast, naive enumeration of all subsets of an $n$-element set requires $2^n$ steps — exponential growth that no polynomial dominates for large $n$.

**Key Theorem (Cobham–Edmonds Thesis).** The class $\mathbf{P}$ is *robust*: it is invariant under changes of reasonable computational model (Turing machines, RAM machines, circuit families of polynomial size) and under polynomial changes of encoding. Consequently, membership in $\mathbf{P}$ is a meaningful, model-independent certificate of tractability.

This robustness justifies treating $\mathbf{P}$ as the formal boundary between *feasible* and *infeasible* computation, underpinning the celebrated open question of whether $\mathbf{P} = \mathbf{NP}$.

**Lab Cell.**

```python
from sympy import symbols, O, log

n = symbols('n', positive=True)

merge_sort  = n * log(n)   # Merge Sort work
exponential = 2**n         # brute-force enumeration

print(O(merge_sort, n))           # O(n*log(n))
print(merge_sort.subs(n, 1000))   # ≈ 9965
print(exponential.subs(n, 100))   # > 10^30
```

Running this cell makes the gulf between polynomial and exponential growth concrete: at $n = 100$, Merge Sort performs roughly $10^4$ operations while brute-force enumeration demands more than $10^{30}$ — computationally unreachable on any foreseeable hardware.

### np_class (36.7s)

## NP Class

**Definition.** A decision problem $L$ belongs to the class **NP** (Nondeterministic Polynomial time) if there exists a polynomial-time *verifier* $V$ and a polynomial $p$ such that for every input $x$:

$$x \in L \iff \exists\, c \text{ with } |c| \leq p(|x|) \text{ and } V(x, c) = 1.$$

The string $c$ is called a *certificate* (or *witness*). Intuitively, NP captures every problem whose solutions can be *checked* efficiently, even if finding them may be hard. The class P consists of problems solvable in polynomial time; it is known that $\mathrm{P} \subseteq \mathrm{NP}$, though whether $\mathrm{P} = \mathrm{NP}$ remains the central open question in theoretical computer science.

**Worked Example: 3-SAT.** Consider a Boolean formula $\varphi$ in conjunctive normal form with clauses of size at most 3, for instance:

$$\varphi = (x_1 \vee \neg x_2 \vee x_3) \wedge (\neg x_1 \vee x_2 \vee x_4) \wedge (\neg x_3 \vee \neg x_4 \vee x_1).$$

The problem 3-SAT asks: does there exist a truth assignment satisfying $\varphi$? The assignment $x_1 = \top,\, x_2 = \top,\, x_3 = \bot,\, x_4 = \bot$ serves as a certificate. Verifying it requires inspecting each clause exactly once — an $O(n)$ procedure in the number of literals $n$. Hence 3-SAT $\in$ NP.

**Key Theorem (Cook–Levin, 1971).** *Every problem in NP can be encoded as a 3-SAT instance in polynomial time.* Consequently, a polynomial-time algorithm for 3-SAT would yield polynomial-time algorithms for every problem in NP — collapsing the distinction between P and NP entirely. This positions 3-SAT as a canonical benchmark problem for the class, a role made precise by the notion of NP-completeness introduced in the following section.

**Lab Cell.**

```python
from sympy.logic.boolalg import And, Or, Symbol
from sympy.logic.inference import satisfiable

x1, x2, x3, x4 = map(Symbol, ["x1", "x2", "x3", "x4"])

phi = And(
    Or(x1, ~x2, x3),
    Or(~x1, x2, x4),
    Or(~x3, ~x4, x1),
)

model = satisfiable(phi)
print(model)  # prints a satisfying assignment, or False if UNSAT
```

Running this cell returns a satisfying assignment, confirming the certificate found above. SymPy's `satisfiable` implements a DPLL-based solver; its worst-case complexity is exponential, consistent with the absence of any known polynomial algorithm for 3-SAT.

### karp_reduction (18.9s)

## Karp Reduction

**Definition.** Let $A$ and $B$ be decision problems (languages over $\{0,1\}^*$). A *Karp reduction* (also called a *polynomial-time many-one reduction*) from $A$ to $B$, written $A \leq_p B$, is a function $f : \{0,1\}^* \to \{0,1\}^*$ satisfying two conditions:

1. $f$ is computable in polynomial time.
2. For every input $x$: $x \in A \iff f(x) \in B$.

Intuitively, $f$ translates any instance of $A$ into an instance of $B$ such that "yes" maps to "yes" and "no" maps to "no." If $A \leq_p B$ and $B$ is solvable in polynomial time, then so is $A$—simply compute $f(x)$ and feed it to $B$'s algorithm. Karp reductions are the formal backbone of $\mathbf{NP}$-hardness: a problem $B$ is $\mathbf{NP}$-hard if every problem $A \in \mathbf{NP}$ satisfies $A \leq_p B$.

**Worked Example: 3-SAT $\leq_p$ Independent Set.** Given a 3-CNF formula $\varphi$ with $k$ clauses $C_1, \ldots, C_k$, construct a graph $G = (V, E)$ as follows. For each clause $C_i = (\ell_{i,1} \vee \ell_{i,2} \vee \ell_{i,3})$, introduce three vertices $v_{i,1}, v_{i,2}, v_{i,3}$ (one per literal) and connect them in a triangle. Then add an edge between $v_{i,a}$ and $v_{j,b}$ whenever $i \neq j$ and $\ell_{i,a} = \neg \ell_{j,b}$ (conflicting literals). Set the target size $t = k$. The claim is: $\varphi$ is satisfiable $\iff$ $G$ has an independent set of size $k$.

*Proof sketch.* ($\Rightarrow$) A satisfying assignment picks at least one true literal per clause; choosing the corresponding vertex yields $k$ vertices with no edges between them—triangle edges are avoided by selecting one vertex per triangle, and conflict edges are avoided because a variable cannot be simultaneously true and false. ($\Leftarrow$) An independent set of size $k$ must contain exactly one vertex per triangle; the literals these represent are mutually consistent and satisfy every clause. The construction runs in $O(k^2)$ time, confirming polynomiality.

**Key Theorem (Cook–Levin, Karp 1972).** If $A \leq_p B$ and $B \in \mathbf{P}$, then $A \in \mathbf{P}$. Equivalently, if $A$ is $\mathbf{NP}$-hard and $A \leq_p B$, then $B$ is $\mathbf{NP}$-hard. This transitivity property makes Karp reductions the primary tool for proving new problems hard.

**Lab Cell.**

```python
from sympy import symbols, And, Or, Not, satisfiable

# 3-CNF: (x1 ∨ x2 ∨ ¬x3) ∧ (¬x1 ∨ x3 ∨ x2) ∧ (¬x2 ∨ ¬x3 ∨ x1)
x1, x2, x3 = symbols('x1 x2 x3')
phi = And(Or(x1, x2, ~x3), Or(~x1, x3, x2), Or(~x2, ~x3, x1))
model = satisfiable(phi)
print(model)  # {x1: True, x2: False, x3: False} or similar
```

### np_hard (17.4s)

## Np Hard

**Definition.** A decision problem $L$ is said to be *NP-hard* if every problem in the complexity class $\mathbf{NP}$ can be reduced to $L$ in polynomial time. Formally, $L$ is NP-hard when for every $L' \in \mathbf{NP}$ there exists a polynomial-time many-one reduction $f$ such that

$$x \in L' \iff f(x) \in L.$$

Crucially, NP-hard problems need not themselves belong to $\mathbf{NP}$: the class NP-hard is not restricted to decision problems and includes optimization and function problems whose certificates may not be efficiently verifiable. A problem that is both NP-hard and in $\mathbf{NP}$ is called *NP-complete*. NP-hardness therefore characterizes the *lower bound* on difficulty — solving an NP-hard problem in polynomial time would collapse $\mathbf{P}$ and $\mathbf{NP}$.

**Worked Example: The Travelling Salesman Problem.** Consider $n$ cities with pairwise distances $d_{ij} \geq 0$. The optimization form of TSP asks: find a Hamiltonian cycle $\pi$ minimizing $\sum_{i=1}^{n} d_{\pi(i),\pi(i+1)}$. The corresponding decision version asks whether a tour of cost at most $B$ exists. This decision problem is NP-complete (and the optimization version NP-hard) because the NP-complete problem Hamiltonian Cycle reduces to it in polynomial time: set all edge weights to $1$ and let $B = n$; a tour of cost $n$ exists if and only if a Hamiltonian cycle exists.

**Key Theorem (Cook–Levin, 1971).** Boolean Satisfiability (SAT) — the problem of deciding whether a propositional formula has a satisfying assignment — is NP-complete. Consequently, any problem to which SAT reduces in polynomial time is NP-hard. This theorem underpins the entire reductive hierarchy: one establishes NP-hardness of a new problem $L$ by exhibiting a polynomial-time reduction from a *known* NP-hard problem to $L$.

**Lab Cell.**

```python
from itertools import permutations
import sympy as sp

# Brute-force TSP on a small instance (NP-hard in general)
distances = {
    (0,1): 10, (0,2): 15, (0,3): 20,
    (1,2): 35, (1,3): 25, (2,3): 30,
}
dist = lambda a, b: distances.get((min(a,b), max(a,b)), 0)

cities = [1, 2, 3]
best_cost, best_tour = sp.oo, None
for perm in permutations(cities):
    tour = (0,) + perm + (0,)
    cost = sum(dist(tour[i], tour[i+1]) for i in range(len(tour)-1))
    if cost < best_cost:
        best_cost, best_tour = cost, tour

print(f"Optimal tour: {best_tour}, cost: {best_cost}")
```

This exhaustive search runs in $O(n!)$ time, illustrating why no polynomial-time algorithm is known for NP-hard problems.

### reduction_proof_technique (16.4s)

## Reduction Proof Technique

**Definition.** A *reduction* is a transformation that converts an instance of one problem into an instance of another, typically simpler or already-solved problem, in such a way that a solution to the second yields a solution to the first. Formally, let $A$ and $B$ be computational or mathematical problems. We say $A$ *reduces to* $B$, written $A \leq B$, if there exists a computable function $f$ such that for every instance $x$ of $A$,

$$x \in A \iff f(x) \in B.$$

The function $f$ is called the *reduction function* or *witness map*. The power of this technique lies in its transitivity: if $A \leq B$ and $B \leq C$, then $A \leq C$, so difficulty propagates along the chain.

**Worked Example.** Consider proving that finding the minimum element of a list $L = [a_1, \ldots, a_n]$ is no harder than sorting. Define $f(L) = \texttt{sort}(L)$, which returns a non-decreasing sequence $L'$. Then $\min(L) = L'[0]$. Any algorithm that sorts in $O(n \log n)$ time immediately gives a minimum-finding algorithm in the same bound, though we already know $O(n)$ suffices. The reduction shows *membership in a difficulty class*, not necessarily the tightest algorithm.

**Key Theorem (Reduction and Hardness).** Let $H$ be a problem known to require at least $T(n)$ steps in the worst case (a *lower bound*). If $H \leq_p P$ via a polynomial-time reduction (i.e., $f$ runs in $O(n^k)$ for some constant $k$), then $P$ also requires at least $T(n) - O(n^k)$ steps. In particular, if $T(n)$ is super-polynomial, no polynomial-time algorithm exists for $P$ unless one exists for $H$.

*Proof sketch.* Suppose an algorithm $\mathcal{A}$ solves $P$ in time $S(n)$. Compose $f$ with $\mathcal{A}$: the composed procedure solves $H$ in time $O(n^k) + S(n)$. If $S(n)$ is polynomial, the composition violates the lower bound on $H$, a contradiction. $\square$

**Lab Cell (SymPy).**

```python
from sympy import symbols, solve, Eq

# Reduce root-finding to polynomial factoring
x = symbols('x')
p = x**3 - 6*x**2 + 11*x - 6   # instance of "find roots"
roots = solve(Eq(p, 0), x)       # solved via factoring (the simpler B)
print(roots)                      # [1, 2, 3]
```

This cell illustrates the pattern: the root-finding instance ($A$) is handed directly to `solve`, which internally reduces the problem to factoring over $\mathbb{Q}$ ($B$), returning solutions without the caller needing to implement the factor step.

### reduction_general_pattern (18.5s)

## Reduction General Pattern

**Definition.** A *reduction* is a systematic transformation that maps an instance of one problem to an instance of a simpler — or already-solved — problem, preserving the essential structure needed to recover the original answer. Formally, given a family of objects $\{P_n\}$ indexed by $n \in \mathbb{N}$, a *reduction formula* is a relation of the form

$$P_n = f(n) \cdot P_{n-k} + g(n), \quad k \geq 1,$$

where $f$ and $g$ are known functions of $n$. Iterated application drives $n$ toward a *base case* $P_{n_0}$ that can be evaluated directly, after which the full answer is reconstructed by unwinding the chain.

**Worked Example.** Consider the integral $I_n = \int_0^{\pi/2} \sin^n x\, dx$. Integration by parts with $u = \sin^{n-1} x$ and $dv = \sin x\, dx$ yields

$$I_n = \frac{n-1}{n}\, I_{n-2}, \quad n \geq 2,$$

with base cases $I_0 = \tfrac{\pi}{2}$ and $I_1 = 1$. To compute $I_6$:

$$I_6 = \frac{5}{6} I_4 = \frac{5}{6} \cdot \frac{3}{4} I_2 = \frac{5}{6} \cdot \frac{3}{4} \cdot \frac{1}{2} I_0 = \frac{15}{48} \cdot \frac{\pi}{2} = \frac{5\pi}{32}.$$

Each step reduces the exponent by $2$ until a base case is reached; the answer is assembled on the way back up.

**Key Theorem (Well-Founded Reduction).** Let $\{P_n\}$ satisfy a reduction $P_n = f(n) \cdot P_{n-k} + g(n)$ for all $n > n_0$, and suppose $P_{n_0}$ is finite. Then every $P_n$ is well-defined and can be expressed as a closed-form product-sum:

$$P_n = \left(\prod_{j=1}^{m} f(n - (j-1)k)\right) P_{n_0} + \sum_{i=0}^{m-1} g(n - ik) \prod_{j=0}^{i-1} f(n - jk),$$

where $m = \lfloor (n - n_0)/k \rfloor$. The proof follows by induction on $m$: the base case is trivial, and the inductive step substitutes the hypothesis into the recurrence and simplifies.

**Lab Cell.**
```python
from sympy import symbols, factorial, pi, simplify, Rational

def I(n):
    if n == 0:
        return pi / 2
    if n == 1:
        return 1
    return Rational(n - 1, n) * I(n - 2)

for n in range(0, 9):
    print(f"I_{n} =", simplify(I(n)))
```
Running this cell verifies the Wallis-type pattern and illustrates how the reduction formula collapses an infinite family of integrals to two base evaluations.

### canonical_np_hard_problems (36.8s)

## Canonical NP-Hard Problems

**Definition.** A decision problem $L$ is *NP-hard* if every problem in the class NP can be reduced to $L$ in polynomial time under many-one (Karp) reductions. Formally, $L$ is NP-hard if for all $L' \in \mathbf{NP}$ there exists a polynomial-time computable function $f$ such that $x \in L' \iff f(x) \in L$. NP-hard problems are at least as hard as the hardest problems in NP; if any one of them admitted a polynomial-time algorithm, it would follow that $\mathbf{P} = \mathbf{NP}$.

The canonical NP-hard problem is the *Boolean Satisfiability Problem* (SAT): given a Boolean formula $\varphi$ over variables $x_1, \ldots, x_n$, does there exist an assignment of truth values that makes $\varphi$ evaluate to true? SAT occupies a distinguished position because it is the first problem proved NP-complete and because virtually every other NP-hardness proof reduces from it, directly or through its restricted form *3-SAT*, in which $\varphi$ is written as a conjunction of clauses each containing exactly three literals.

**Worked Example.** Consider the 3-SAT instance $\varphi = (x_1 \vee x_2 \vee \neg x_3) \wedge (\neg x_1 \vee x_3 \vee x_4)$. Assign $x_1 = \mathtt{T},\, x_2 = \mathtt{F},\, x_3 = \mathtt{T},\, x_4 = \mathtt{F}$. Clause 1 evaluates to $\mathtt{T} \vee \mathtt{F} \vee \mathtt{F} = \mathtt{T}$; clause 2 evaluates to $\mathtt{F} \vee \mathtt{T} \vee \mathtt{F} = \mathtt{T}$. Hence $\varphi$ is satisfiable. Verifying a proposed assignment takes $O(|\varphi|)$ time, confirming that 3-SAT $\in \mathbf{NP}$.

**Theorem (Cook–Levin, 1971).** SAT is NP-complete. Every language $L \in \mathbf{NP}$ is polynomial-time reducible to SAT.

*Proof sketch.* Given a nondeterministic Turing machine $M$ accepting $L$ in time $p(n)$, encode the entire computation tableau of $M$ on input $x$ as a Boolean formula $\varphi_{M,x}$ of size $O(p(n)^2)$. The formula is satisfiable if and only if $M$ accepts $x$. Because 3-SAT is reducible from SAT via local clause splitting, 3-SAT is likewise NP-complete. Subsequent reductions from 3-SAT establish NP-hardness for a wide family of combinatorial problems studied in later sections.

**Lab Cell.**

```python
from itertools import product
from sympy.logic.boolalg import And, Or, Not
from sympy.abc import x1, x2, x3, x4

clause1 = Or(x1, x2, Not(x3))
clause2 = Or(Not(x1), x3, x4)
phi = And(clause1, clause2)

sat = any(
    phi.subs({x1: a, x2: b, x3: c, x4: d})
    for a, b, c, d in product([True, False], repeat=4)
)
print("Satisfiable:", sat)
```

Running this cell confirms `Satisfiable: True`, providing an exhaustive brute-force witness that matches the manual assignment above.
