## Recursion

**Definition.** A function $f$ is defined *recursively* if its value at an argument is expressed in terms of its value at one or more strictly simpler arguments, together with one or more *base cases* that terminate the descent. Formally, a recursive definition specifies:

1. **Base case(s):** explicit values $f(n_0), f(n_1), \ldots$ for the smallest inputs.
2. **Recursive case:** a rule $f(n) = g\bigl(n,\, f(n-1),\, f(n-2),\ldots\bigr)$ for $n$ beyond the base cases, where $g$ involves only arguments strictly less than $n$.

Well-foundedness—the guarantee that repeated application of the recursive case always reaches a base case—is what separates a valid recursive definition from a circular one.

**Worked example: the factorial function.** Define $n!$ for $n \in \mathbb{N}_0$ by

$$
0! = 1, \qquad n! = n \cdot (n-1)! \quad \text{for } n \geq 1.
$$

Computing $4!$ unwinds as follows:

$$
4! = 4 \cdot 3! = 4 \cdot 3 \cdot 2! = 4 \cdot 3 \cdot 2 \cdot 1! = 4 \cdot 3 \cdot 2 \cdot 1 \cdot 0! = 24.
$$

Each call reduces $n$ by $1$; since $n$ is a non-negative integer, the chain terminates at $0!$ in exactly $n$ steps. The *call stack* at depth $k$ holds the pending multiplication $k \cdot (\cdots)$, so the process requires $O(n)$ space as well as $O(n)$ time.

**Key theorem (Structural Induction Principle).** Let $P(n)$ be a property of natural numbers. If $P(0)$ holds, and $P(k)$ implies $P(k+1)$ for every $k \geq 0$, then $P(n)$ holds for all $n \in \mathbb{N}_0$. This principle is the mathematical counterpart of recursion: the base case mirrors the inductive base; the inductive step mirrors the recursive case. Any terminating recursion can therefore be reasoned about by induction, and correctness proofs for recursive algorithms follow this template directly.

### backtracking (16.2s)

## Backtracking

**Definition.** Backtracking is a systematic algorithm design paradigm for solving constraint-satisfaction and combinatorial search problems. Given a partial candidate solution, the algorithm extends it one component at a time; whenever an extension violates a problem constraint, the algorithm *backtracks*—it undoes the most recent choice and tries the next available alternative. Formally, let $\mathcal{S}$ be a finite set of candidates representable as sequences $(c_1, c_2, \dots, c_k)$ with $c_i \in D_i$. A *constraint predicate* $P(c_1,\dots,c_j)$ is evaluated incrementally; backtracking performs a depth-first traversal of the implicit search tree, pruning every subtree rooted at a node that violates $P$.

**Worked Example: Four-Queens Problem.** Place four non-attacking queens on a $4\times 4$ chessboard. Represent a solution as a tuple $(c_1, c_2, c_3, c_4)$ where $c_i \in \{1,2,3,4\}$ is the column of the queen in row $i$. The constraint is that no two queens share a column or diagonal: for all $i \neq j$,

$$c_i \neq c_j \quad \text{and} \quad |c_i - c_j| \neq |i - j|.$$

Starting with $c_1 = 1$: we try $c_2 = 1$ (column conflict, prune), $c_2 = 2$ (diagonal conflict, prune), $c_2 = 3$ (valid). Continuing, $c_3 = 1$ (diagonal conflict), $c_3 = 2$ (conflict), $c_3 = 3$ (column conflict), $c_3 = 4$ (conflict)—all pruned. Backtrack to $c_2 = 4$; proceed to find the solution $(1, 3, ?, ?)$. Exhausting $c_1 = 1$ ultimately yields $(2,4,1,3)$ and $(3,1,4,2)$ as the two distinct solutions.

**Key Theorem (Pruning Efficiency).** Let $T$ be the search tree explored by backtracking and $T_0$ the full $\prod_i |D_i|$-leaf tree of all candidate sequences. Then $|T| \leq |T_0|$, with equality only when no constraint eliminates any partial candidate early. In practice, effective pruning reduces $|T|$ exponentially relative to brute-force enumeration.

**Lab Cell.**

```python
from sympy.combinatorics import Permutation

def four_queens():
    solutions = []
    def bt(queens):
        r = len(queens)
        if r == 4:
            solutions.append(tuple(queens)); return
        for c in range(4):
            if all(c != q and abs(c - q) != r - i
                   for i, q in enumerate(queens)):
                bt(queens + [c])
    bt([])
    return solutions

print(four_queens())   # [(1, 3, 0, 2), (2, 0, 3, 1)]
```

### recursion_tree (16.1s)

## Recursion Tree

**Definition.** A *recursion tree* is a rooted tree that models the execution of a recursive algorithm by representing each recursive call as a node. The root corresponds to the initial call on an input of size $n$; each internal node spawns children corresponding to the sub-calls it makes; and each leaf represents a base case. The *cost* associated with a node is the work done at that call level, exclusive of its children. The total running time of the algorithm equals the sum of costs over all nodes in the tree.

More precisely, if an algorithm satisfies the recurrence

$$T(n) = a\,T\!\left(\frac{n}{b}\right) + f(n), \quad T(1) = \Theta(1),$$

then the recursion tree has depth $\log_b n$, exactly $a^k$ nodes at depth $k$, each performing cost $f(n/b^k)$, and $a^{\log_b n} = n^{\log_b a}$ leaves.

**Worked Example.** Consider merge sort, governed by $T(n) = 2\,T(n/2) + \Theta(n)$.

- **Level 0** (root): one call of size $n$, cost $cn$.
- **Level 1**: two calls of size $n/2$, total cost $2 \cdot c(n/2) = cn$.
- **Level $k$**: $2^k$ calls of size $n/2^k$, total cost $cn$.
- **Leaves** (level $\log_2 n$): $n$ calls of size $1$, total cost $\Theta(n)$.

Summing across all $\log_2 n + 1$ levels gives $T(n) = \Theta(n \log n)$.

**Key Theorem (Master Theorem, simplified).** For $T(n) = a\,T(n/b) + \Theta(n^d)$ with $a \geq 1$, $b > 1$, $d \geq 0$:

$$T(n) = \begin{cases} \Theta(n^d \log n) & \text{if } a = b^d, \\ \Theta(n^{\log_b a}) & \text{if } a > b^d, \\ \Theta(n^d) & \text{if } a < b^d. \end{cases}$$

The recursion-tree method provides the intuition behind each case: when $a = b^d$ the cost per level is constant at $\Theta(n^d)$ and there are $\log_b n$ levels; otherwise one of the two ends of the tree dominates.

**Lab Cell.**

```python
from sympy import symbols, Function, rsolve, log, simplify

n = symbols('n', positive=True)
T = Function('T')

# Solve T(n) = 2*T(n/2) + n symbolically
recurrence = T(n) - 2*T(n/2) - n
sol = rsolve(recurrence, T(n), {T(1): 1})
print(simplify(sol))          # expects n*log(n) + n
```

Running this cell confirms $T(n) = n\log_2 n + n$, consistent with the tree analysis above.

## N Queens

**Definition.** The *N-queens problem* asks: in how many ways can $N$ non-attacking queens be placed on an $N \times N$ chessboard? A queen attacks every square in its row, column, and both diagonals. Formally, a placement is a bijection $\sigma : \{1,\dots,N\} \to \{1,\dots,N\}$ where $\sigma(i)$ denotes the column of the queen in row $i$, subject to the constraint that no two queens share a diagonal:

$$
|\sigma(i) - \sigma(j)| \neq |i - j| \quad \text{for all } i \neq j.
$$

Because $\sigma$ is a bijection, the row- and column-conflict conditions are automatically satisfied; only the diagonal conditions remain non-trivial.

**Worked Example ($N = 4$).** Label rows and columns $1$ through $4$. We seek permutations $\sigma$ of $\{1,2,3,4\}$ satisfying the diagonal constraint. Consider $\sigma = (2,4,1,3)$: queens sit at $(1,2),(2,4),(3,1),(4,3)$. Checking all pairs:

| Pair $(i,j)$ | $|\sigma(i)-\sigma(j)|$ | $|i-j|$ | Conflict? |
|---|---|---|---|
| $(1,2)$ | $2$ | $1$ | No |
| $(1,3)$ | $1$ | $2$ | No |
| $(1,4)$ | $1$ | $3$ | No |
| $(2,3)$ | $3$ | $1$ | No |
| $(2,4)$ | $1$ | $2$ | No |
| $(3,4)$ | $2$ | $1$ | No |

All pairs pass; this is a valid solution. The $4$-queens problem has exactly $2$ distinct solutions (up to reflection: $(2,4,1,3)$ and $(3,1,4,2)$).

**Key Theorem.** For $N \geq 1$, solutions exist if and only if $N = 1$ or $N \geq 4$. The total solution count $Q(N)$ grows roughly as $(0.143\,N)^N$, though no closed form is known; $Q(8) = 92$, $Q(12) = 14{,}200$. The problem is a canonical instance of *constraint satisfaction* and *backtracking search*, both central to combinatorial algorithms.

**Lab Cell.**

```python
from sympy.utilities.iterables import permutations

def n_queens(N):
    solutions = []
    for sigma in permutations(range(1, N + 1)):
        if all(abs(sigma[i] - sigma[j]) != abs(i - j)
               for i in range(N) for j in range(i + 1, N)):
            solutions.append(sigma)
    return solutions

sols = n_queens(6)
print(f"Q(6) = {len(sols)}")
print("First solution (column per row):", sols[0])
```

Running this cell yields $Q(6) = 4$, confirming the known count. Increase $N$ to observe how backtracking (implicit here via exhaustive filtering) scales exponentially — motivating pruned search algorithms such as branch-and-bound.
