### directed_graph (15.6s)

## Directed Graph

A **directed graph** (or *digraph*) is a set of nodes connected by edges that each carry a direction — an arrow pointing from one node to another. Formally, a directed graph $G = (V, E)$ consists of a vertex set $V$ and an edge set $E \subseteq V \times V$, where each edge $(u, v)$ is an ordered pair meaning "there is a connection *from* $u$ *to* $v$." The reverse edge $(v, u)$ is a separate, independent relationship that may or may not exist.

This directional asymmetry makes directed graphs the natural model for any system where relationships are one-way or carry a specific flow: web pages linking to other pages, dependencies between software packages, prerequisites in a course catalog, or money moving between bank accounts.

**Worked Example.** Consider four courses: Math 101, CS 101, CS 201, and CS 301, where a student must complete certain courses before enrolling in others.

```
Math 101 → CS 201
CS 101   → CS 201
CS 201   → CS 301
```

This is a directed graph with $V = \{\text{Math 101, CS 101, CS 201, CS 301}\}$ and three directed edges. Notice that CS 101 and Math 101 both point *into* CS 201, but CS 201 does not point back — there is no circular dependency. A path from CS 101 to CS 301 exists: CS 101 → CS 201 → CS 301. No path exists from CS 301 back to CS 101, which correctly reflects that completing an advanced course doesn't retroactively satisfy a prerequisite.

**Problem-Solving Application.** A common task on directed graphs is detecting a **cycle** — a path that starts and ends at the same node. Cycles matter because they signal a contradiction: if package A depends on B and B depends on A, neither can be installed first. The standard algorithm is depth-first search (DFS) with a "currently visiting" flag. As DFS explores each node, it marks it *in progress*; if it ever encounters an *in-progress* node again, a cycle exists. This runs in $O(|V| + |E|)$ time.

When working with directed graphs, always ask two diagnostic questions: *Which direction does each edge flow?* and *Are there cycles?* Direction determines reachability; cycles determine whether a valid ordering (called a **topological sort**) is even possible. Both questions drive most real-world graph algorithms, from build systems to recommendation engines.

## Directed Walks, Paths, and Cycles

A **directed graph** (digraph) assigns a direction to every edge: an edge from vertex $u$ to vertex $v$ is written $(u, v)$ and can only be traversed in that order. Once you add direction, the way you move through the graph becomes more structured — and three terms describe the kinds of movement precisely.

A **directed walk** is any sequence of vertices $v_0, v_1, v_2, \ldots, v_k$ such that $(v_i, v_{i+1})$ is a directed edge for each consecutive pair. Vertices and edges may repeat freely. A **directed path** tightens this: no vertex may appear more than once. A **directed cycle** is a closed walk — it starts and ends at the same vertex — in which no intermediate vertex repeats.

These distinctions matter because they correspond to qualitatively different situations in real systems. A walk models any sequence of hops (a packet bouncing through routers, possibly revisiting nodes). A path models a route with no backtracking (a courier's delivery sequence). A cycle signals the possibility of looping behavior (a dependency loop in a build system, a feedback loop in a state machine).

**Worked example.** Consider the digraph with edges $(A,B)$, $(B,C)$, $(C,A)$, $(B,D)$, and $(D,C)$. Is the sequence $A \to B \to D \to C \to A$ a walk, a path, or a cycle?

- Every consecutive pair is a directed edge. ✓ It is a walk.
- No vertex repeats until the final return to $A$. ✓ It is a cycle.

Now consider $A \to B \to C \to A \to B$. This is a walk (edges exist at each step), but not a path (vertex $A$ and $B$ both repeat) and not a simple cycle (it doesn't return cleanly to the start without repeating).

**Problem-solving application.** Detecting cycles in a digraph is a core task in software dependency resolution. If package $X$ depends on $Y$, and $Y$ depends on $X$, the dependency graph contains a directed cycle — and no installation order can satisfy both requirements. A standard solution is **depth-first search with coloring**: mark each vertex white (unvisited), gray (in progress), or black (done). If DFS ever reaches a gray vertex, a back edge exists, confirming a cycle. The algorithm runs in $O(V + E)$ time, making it practical even for graphs with thousands of packages.

The key habit: always ask whether your problem needs a walk (repetition allowed), a path (no revisits), or a cycle (closed loop) — the right structure determines which algorithm to reach for.

### underlying_graph (20.5s)

## Underlying Graph

A directed graph (digraph) assigns a direction to every edge — each edge points from a source vertex to a target vertex. The **underlying graph** of a digraph is the undirected graph you get by stripping away those directions, keeping the same vertices and the same connections but treating every edge as a simple, two-way link.

Formally, if $G = (V, E)$ is a digraph where each edge is an ordered pair $(u, v)$, then its underlying graph $G' = (V, E')$ replaces every directed edge $(u, v)$ (and its possible reverse $(v, u)$) with a single undirected edge $\{u, v\}$. If both $(u, v)$ and $(v, u)$ exist in $G$, they collapse to one edge in $G'$.

**Worked example.** Consider a digraph with vertices $\{A, B, C\}$ and directed edges $(A, B)$, $(B, C)$, $(A, C)$. Visually, every arrow points in one direction. The underlying graph simply connects $A$–$B$, $B$–$C$, and $A$–$C$ without any arrowheads — a triangle. Now add the reverse edge $(C, A)$ to the digraph. In the underlying graph, $A$–$C$ is already present, so nothing changes: the underlying graph is still the same triangle.

**Why it matters in problem-solving.** The underlying graph is the key tool for checking **weak connectivity** of a digraph. A digraph is *weakly connected* if its underlying graph is connected — meaning you can reach any vertex from any other vertex when you're allowed to travel edges in either direction. This is a weaker condition than *strong connectivity*, which requires a directed path in both directions between every pair of vertices.

In practice, suppose you're modeling a one-way street network and want to verify that no neighborhood is completely isolated. You convert the street map to its underlying graph and run a standard breadth-first search (BFS) or depth-first search (DFS) on it. If BFS visits every intersection, the network is weakly connected — no neighborhood is cut off entirely, even if you can't drive back the same way you came. If some vertices are unreachable in the underlying graph, those locations are structurally isolated regardless of traffic direction, and the network has a design flaw worth fixing.

The underlying graph thus acts as a diagnostic layer: it separates topology (what is connected to what) from flow (which direction information or traffic travels).

### orientation (20.8s)

## Orientation

**Orientation** describes the *handedness* of an ordered arrangement — whether a sequence of vectors, vertices, or axes follows a consistent clockwise or counterclockwise sense. It is a binary property: every finite-dimensional vector space, polygon, or coordinate frame is either positively oriented or negatively oriented, and swapping any two elements flips it. This distinction is not cosmetic. Computer graphics, robotics, and computational geometry all depend on tracking orientation to avoid silently mirrored output.

For a pair of vectors $\mathbf{u}, \mathbf{v}$ in $\mathbb{R}^2$, the signed area of the parallelogram they span is the determinant

$$\det\begin{pmatrix} u_1 & v_1 \\ u_2 & v_2 \end{pmatrix} = u_1 v_2 - u_2 v_1.$$

If this value is **positive**, the angle from $\mathbf{u}$ to $\mathbf{v}$ goes counterclockwise — the standard positive orientation. If **negative**, the rotation is clockwise, meaning the ordered pair is negatively oriented. A determinant of zero means the vectors are collinear and span no area, so orientation is undefined.

**Worked example.** A triangle has vertices listed as $A = (0,0)$, $B = (4,0)$, $C = (4,3)$. Form edge vectors from $A$: $\mathbf{u} = B - A = (4,0)$ and $\mathbf{v} = C - A = (4,3)$. Compute

$$\det\begin{pmatrix} 4 & 4 \\ 0 & 3 \end{pmatrix} = 12 - 0 = 12 > 0.$$

The vertices are in counterclockwise order, so the triangle is positively oriented.

**Problem-solving application.** Suppose a polygon-fill algorithm requires all input triangles to be counterclockwise. You receive a mesh where some triangles have their vertices listed in an unknown order. For each triangle with vertices $P_1, P_2, P_3$:

1. Compute $d = (P_2 - P_1) \times (P_3 - P_1)$ (the 2-D cross product, i.e., the determinant above).
2. If $d > 0$, the triangle is already counterclockwise — keep it.
3. If $d < 0$, swap any two vertices (e.g., exchange $P_2$ and $P_3$) to reverse orientation.
4. If $d = 0$, flag the triangle as degenerate and discard it.

This three-line check, applied in a loop, normalizes an entire mesh in $O(n)$ time. The key insight is that orientation is encoded in the sign of a single determinant — you never need angles or trigonometry.

### strong_weak_connectivity (15.6s)

## Strong Weak Connectivity

A graph can be connected in two meaningfully different ways depending on whether its edges have direction. In an **undirected** graph, connectivity is all-or-nothing: either you can travel between every pair of vertices (connected) or you cannot (disconnected). Directed graphs — where each edge is a one-way street — introduce a richer distinction.

A directed graph (digraph) is **strongly connected** if, for every ordered pair of vertices $(u, v)$, there exists a directed path from $u$ to $v$ *and* a directed path from $v$ to $u$. It is **weakly connected** if the underlying undirected graph (obtained by ignoring edge directions) is connected — meaning you can reach any vertex from any other, but only if you're allowed to travel edges in either direction.

Strong connectivity is the stricter condition. Every strongly connected graph is also weakly connected, but not vice versa.

**Worked example.** Consider four cities connected by one-way roads:

```
A → B → C → A     (a cycle)
B → D
```

From $A$ you can reach $B$, $C$, and $D$. From $D$, however, you cannot reach $A$, $B$, or $C$ — there is no outgoing edge from $D$. So the graph is *not* strongly connected. But if you ignore directions, every city is reachable from every other, so it *is* weakly connected.

**Problem-solving application.** Suppose you're analyzing a social network where a directed edge means "user X follows user Y." You want to find communities where information circulates freely — meaning a post from any member can eventually reach every other member and vice versa. That's exactly a **strongly connected component (SCC)**: a maximal subgraph that is strongly connected.

Tarjan's algorithm identifies all SCCs in $O(V + E)$ time using a single depth-first search. Each SCC can then be contracted into a single node, producing a **condensation graph** — a directed acyclic graph (DAG) showing how information flows *between* communities. Nodes with no incoming edges in the condensation are source communities; nodes with no outgoing edges are sinks.

Checking weak connectivity is simpler: run a standard BFS or DFS on the undirected version of the graph and confirm every vertex is visited. If not, the graph has isolated components that need to be bridged before any global coordination is possible.

The strong/weak distinction matters in routing, compiler analysis (detecting circular dependencies), and any system where one-way relationships constrain reachability.

### strongly_connected_orientation (19.2s)

## Strongly Connected Orientation

An **orientation** of an undirected graph assigns a direction to every edge, turning each $\{u, v\}$ into either the arc $(u \to v)$ or $(v \to u)$. A **strongly connected orientation** is one where the resulting directed graph is strongly connected: for every pair of vertices $u$ and $v$, there exists a directed path from $u$ to $v$ (and separately, from $v$ to $u$). Not every undirected graph can be oriented this way — the structure of the graph places a hard constraint.

The precise condition is captured by **Robbins' Theorem** (1939):

> **Theorem (Robbins).** An undirected graph $G$ has a strongly connected orientation if and only if $G$ is 2-edge-connected — that is, $G$ is connected and contains no *bridge* (an edge whose removal disconnects the graph).

The intuition is clean: if edge $e = \{u, v\}$ is a bridge, then after orienting it, say as $u \to v$, there is no way to get from $v$'s side back to $u$'s side without crossing $e$, and you've just pointed it the wrong way for that return trip. A 2-edge-connected graph avoids this trap: every edge belongs to a cycle, so you can always route traffic both ways by going around.

**Worked example.** Consider the cycle graph $C_4$ with vertices $A, B, C, D$ and edges $\{A,B\}, \{B,C\}, \{C,D\}, \{D,A\}$. This graph is 2-edge-connected (every edge is in the 4-cycle, so no edge is a bridge). Orient every edge clockwise: $A \to B \to C \to D \to A$. From any vertex you can reach any other by following the directed cycle — strongly connected. Now add the diagonal $\{A, C\}$ as a bridge connecting two separate triangles: any orientation of that single bridge will cut off return flow on one side.

**Problem-solving application.** Suppose you are designing one-way street layouts for a city district. Robbins' Theorem tells you immediately which districts are impossible to make fully navigable with one-way streets: any block whose removal disconnects the district (a bridge road) is an insurmountable obstacle. Your first step, before attempting any orientation, is to check 2-edge-connectivity using a depth-first search that identifies bridges in $O(V + E)$ time. If bridges exist, you must either add a parallel road (a second edge) or accept that some destinations will require a detour through a two-way street. Once the underlying graph is bridge-free, a DFS-based algorithm can construct a valid strongly connected orientation efficiently, also in $O(V + E)$.
