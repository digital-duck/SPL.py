### base_case (18.5s)

## 基本情形

**定义**

递归是一种"把大问题拆成同类小问题"的策略，而**基本情形**（base case）是递归得以终止的那个出口。没有基本情形，函数会无限调用自身，最终导致栈溢出。形式上，一个递归定义由两部分构成：基本情形给出最小输入的直接答案，递归情形则将较大的输入化归为规模更小的同类问题。数学归纳法与此结构完全对应：基本情形对应归纳基础，递归情形对应归纳步骤。

**例题：计算阶乘**

定义 $n! = n \times (n-1) \times \cdots \times 1$，并约定 $0! = 1$。用递归写法：

$$
n! = \begin{cases} 1 & n = 0 \\ n \times (n-1)! & n \geq 1 \end{cases}
$$

这里 $n = 0$ 就是基本情形——它不再调用自身，直接返回 $1$。用 Python 实现：

```python
def factorial(n: int) -> int:
    if n == 0:          # 基本情形
        return 1
    return n * factorial(n - 1)   # 递归情形
```

追踪 `factorial(3)` 的调用链：

```
factorial(3) → 3 × factorial(2)
                    → 2 × factorial(1)
                          → 1 × factorial(0)
                                → 1        # 基本情形触发
```

返回时逐层展开：$1 \to 1 \to 2 \to 6$。

**解题应用**

判断一段递归代码是否正确，首先问两个问题：①基本情形是否覆盖了所有"最小输入"？②每次递归调用是否真的让输入规模缩小、最终到达基本情形？

考虑斐波那契数列 $F(n) = F(n-1) + F(n-2)$。这里需要**两个**基本情形：

```python
def fib(n: int) -> int:
    if n == 0:   # 基本情形 1
        return 0
    if n == 1:   # 基本情形 2
        return 1
    return fib(n - 1) + fib(n - 2)
```

若只写 `if n == 0` 而漏掉 `if n == 1`，调用 `fib(1)` 时会触发 `fib(0) + fib(-1)`，进而无限递归。这说明：**基本情形的数量和位置由问题本身决定，不能随意省略**。设计递归时，先把基本情形写对，再补递归情形，是最稳妥的顺序。

### induction_proof (19.5s)

## Induction Proof

**数学归纳法**是证明"对所有正整数 $n$ 成立"的命题时最常用的工具。它的逻辑结构只有两步：先验证最小情形，再证明"如果第 $k$ 步成立，那么第 $k+1$ 步也成立"。两步合并，就像多米诺骨牌——第一块倒下，后面每一块都跟着倒。

**形式化表述。** 设 $P(n)$ 是关于正整数 $n$ 的命题。若满足：

1. **基础步骤**：$P(1)$ 成立；
2. **归纳步骤**：对任意 $k \geq 1$，若 $P(k)$ 成立（归纳假设），则 $P(k+1)$ 也成立，

则 $P(n)$ 对所有正整数 $n$ 成立。

---

### 例题：证明前 $n$ 个正整数之和

**命题**：$\displaystyle 1 + 2 + \cdots + n = \frac{n(n+1)}{2}$

**基础步骤**：当 $n = 1$ 时，左边 $= 1$，右边 $= \dfrac{1 \cdot 2}{2} = 1$，成立。

**归纳假设**：设 $n = k$ 时命题成立，即

$$1 + 2 + \cdots + k = \frac{k(k+1)}{2}$$

**归纳步骤**：需证 $n = k+1$ 时也成立。在等式两边同时加上 $k+1$：

$$1 + 2 + \cdots + k + (k+1) = \frac{k(k+1)}{2} + (k+1) = (k+1)\left(\frac{k}{2} + 1\right) = \frac{(k+1)(k+2)}{2}$$

这正是将 $n = k+1$ 代入公式的结果，归纳步骤成立。由数学归纳法，命题对所有正整数 $n$ 成立。$\blacksquare$

---

### 解题应用

遇到需要归纳证明的题目，按以下流程操作：

1. **识别命题**：将待证结论写成关于 $n$ 的统一形式 $P(n)$。
2. **验证基础**：代入最小值（通常是 $n = 1$）直接计算。
3. **写出归纳假设**：明确假设 $P(k)$ 成立，把它当作已知条件。
4. **推导 $P(k+1)$**：从 $P(k)$ 出发，通过代数变形到达目标形式——这是最考验技巧的一步，关键在于把"$k+1$ 的情形"拆出"$k$ 的情形"加上一个新项。
5. **收尾**：说明两步均成立，结论成立。

常见错误是在归纳步骤中直接"假设结论成立"，绕过推导过程——那是循环论证，不是归纳证明。正确做法是只假设 $P(k)$，然后**推导**出 $P(k+1)$。

### reduction (28.0s)

## 规约（Reduction）

**定义**

规约是算法设计与计算理论中的核心思想：将一个未知的、较难的问题 $A$，转化为另一个已知解法的问题 $B$ 来求解。换句话说，如果我们能把问题 $A$ 的任意实例在合理的时间内"翻译"成问题 $B$ 的实例，那么 $B$ 的求解算法就能间接解决 $A$。规约的方向很重要：我们说"$A$ 规约到 $B$"（记作 $A \leq_p B$），意味着 $B$ 至少和 $A$ 一样难——解决了 $B$，就解决了 $A$；若 $B$ 有高效算法，$A$ 也随之有了高效算法。

**具体例子**

考虑两个问题：
- 问题 $A$：给定 $n$ 个整数，判断其中是否有两个数之和等于目标值 $T$（Two-Sum 判定）。
- 问题 $B$：给定一个已排序数组和目标值，用双指针在 $O(n)$ 内判断是否存在满足条件的数对。

解决 $A$ 的策略：先对输入数组排序（$O(n \log n)$），再把问题转化为排序数组上的 Two-Sum，直接调用问题 $B$ 的双指针算法。整个过程中，排序是"转化"步骤，双指针是"借用"的已知工具。通过这次规约，$A$ 被高效解决，而我们无需从零设计算法。

**解题应用**

规约的思维在实际编程中随处可见。例如，"在一个无向图中判断是否存在欧拉回路"乍看复杂，但可以规约为一个简单的图度数检查：欧拉回路存在当且仅当图连通且每个顶点的度数均为偶数。判断连通性（DFS/BFS）和统计度数都是已知操作，规约让问题迎刃而解。

使用规约解题时，建议分三步走：
1. **识别结构**：问题的本质是什么？排序、图遍历、区间覆盖？
2. **寻找已知问题**：有哪个经典问题与之结构相似？
3. **设计转化**：如何将输入从 $A$ 的格式映射到 $B$ 的格式，输出如何反向解释？

规约不仅是一种解题技巧，也是判断问题难度的语言——当你无法为 $A$ 找到高效算法时，尝试把某个已知的难问题规约到 $A$，就能证明 $A$ 本身也很难。这是计算复杂性理论的基石。

### recursion (18.1s)

## 递归

**定义**

递归（Recursion）是指一个函数在其自身定义中调用自身的编程技术。递归函数必须满足两个条件：一是**基本情形**（base case），即能够直接返回结果而无需再次调用自身的终止条件；二是**递归步骤**（recursive step），即将问题规模缩小后调用自身。缺少任意一个，函数要么无法终止，要么无法解决问题。

**工作示例：计算阶乘**

数学上，$n!$ 定义为 $n! = n \times (n-1) \times \cdots \times 1$，其中 $0! = 1$。这天然具有递归结构：

$$n! = \begin{cases} 1 & \text{若 } n = 0 \\ n \times (n-1)! & \text{若 } n > 0 \end{cases}$$

对应的 Python 实现如下：

```python
def factorial(n):
    if n == 0:          # 基本情形
        return 1
    return n * factorial(n - 1)   # 递归步骤

print(factorial(5))   # 输出 120
```

调用 `factorial(5)` 时，执行栈依次展开：$5 \to 4 \to 3 \to 2 \to 1 \to 0$，到达基本情形后逐层返回，最终得到 $5 \times 4 \times 3 \times 2 \times 1 = 120$。

**解题应用：翻转字符串**

递归不只适用于数学公式，同样可以处理字符串和列表等数据结构。给定字符串 `s`，如何递归地将其翻转？

思路：空字符串翻转后仍为空字符串（基本情形）；否则，翻转结果等于"去掉首字符后的剩余部分的翻转"加上首字符。

```python
def reverse(s):
    if s == "":           # 基本情形
        return ""
    return reverse(s[1:]) + s[0]   # 递归步骤

print(reverse("hello"))   # 输出 "olleh"
```

**常见陷阱与调试思路**

初学者最常见的错误是忘记缩小问题规模，导致无限递归（`RecursionError`）。调试时，在函数入口打印当前参数，可以直观看到递归是否在向基本情形收敛。此外，对于调用层数极深的情形，可以考虑改用循环或记忆化（memoization）来提升效率，但递归本身的思维框架——"把大问题拆成同类的小问题"——是算法设计中最核心的模式之一，贯穿分治、树遍历、动态规划等众多领域。

### divide_and_conquer (15.6s)

## 分而治之

**定义**

分而治之（Divide and Conquer）是一种递归算法设计策略：将一个规模较大的问题拆分为若干结构相同的子问题，分别求解后再将子问题的结果合并，得到原问题的答案。这一策略的核心在于"拆分—递归—合并"三个步骤的循环应用。

**经典示例：归并排序**

归并排序（Merge Sort）是分而治之最典型的应用。对一个长度为 $n$ 的数组排序时，算法分三步进行：

1. **拆分**：将数组从中间一分为二，得到左右两个子数组。
2. **递归**：对左、右子数组分别递归地调用归并排序，直到子数组长度为 1（天然有序）。
3. **合并**：将两个已排序的子数组逐一比较，按序合并为一个有序数组。

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left  = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    return result + left[i:] + right[j:]
```

每一层递归将问题规模减半，共有 $\log_2 n$ 层；每层合并的总操作数为 $O(n)$，因此整体时间复杂度为 $O(n \log n)$，显著优于简单选择排序的 $O(n^2)$。

**问题求解应用**

分而治之的适用性远不止排序。遇到以下信号时，可以考虑这一策略：

- 问题可以自然地分解为**结构相同、规模更小**的子问题；
- 子问题之间**相互独立**，结果可直接合并；
- 暴力枚举的复杂度难以接受，需要借助递归压缩搜索空间。

例如，在一个含 $n$ 个元素的**有序**数组中查找目标值，二分搜索每次排除一半候选元素，将 $O(n)$ 的线性搜索压缩为 $O(\log n)$。解题时，先问自己："能否将问题规模减半，并用相同方法处理每一半？"若答案是肯定的，分而治之往往是最自然的起点。
