### er_random_graph (16.3s)

## Er Random Graph

An **Erdős–Rényi random graph**, denoted $G(n, p)$, is a probability model for networks. Given $n$ labeled vertices, each possible edge between any pair of vertices is included independently with probability $p$. The result is a random graph where structure emerges from chance — no deterministic wiring, no preferential attachment, just coin flips.

The total number of possible edges in a graph on $n$ vertices is $\binom{n}{2}$, so the expected number of edges in $G(n, p)$ is $p\binom{n}{2}$. Each vertex has expected degree $(n-1)p$, which gives you immediate intuition: a sparse network has small $p$, a dense one has $p$ close to 1.

**Worked example.** Suppose you model a classroom of $n = 30$ students, where any two students independently become study partners with probability $p = 0.1$. The expected number of study-partner pairs is $0.1 \times \binom{30}{2} = 0.1 \times 435 = 43.5$. Each student expects $(29)(0.1) = 2.9$ partners. You can simulate one realization in Python:

```python
import networkx as nx
import matplotlib.pyplot as plt

G = nx.erdos_renyi_graph(n=30, p=0.1, seed=42)
print(f"Edges: {G.number_of_edges()}")
print(f"Average degree: {sum(d for _, d in G.degree()) / G.number_of_nodes():.2f}")
nx.draw(G, node_size=200, with_labels=False)
plt.show()
```

Running this typically yields around 40–47 edges and average degree near 2.9, matching the expectation — but the exact graph changes each run.

**Problem-solving application.** One of the most useful properties of $G(n, p)$ is the **phase transition** in connectivity. When $p < \frac{\ln n}{n}$, the graph almost surely has isolated vertices and is disconnected. When $p > \frac{\ln n}{n}$, it is almost surely connected. For $n = 1000$, the threshold is roughly $p^* = \frac{\ln 1000}{1000} \approx 0.0069$. This means that for a network of a thousand nodes, you only need about a 0.7% edge probability to expect full connectivity — a surprisingly small threshold.

This threshold matters practically: network designers use it to set minimum communication probabilities in distributed systems, and epidemiologists use it to estimate when a disease can spread to the whole population. The $G(n,p)$ model is rarely a perfect fit for real networks (which tend to have hubs and clustering), but it provides an essential baseline — a null model against which real structure stands out.

### expected_value (15.8s)

## Expected Value

The **expected value** of a random variable is the long-run average outcome you would observe if you repeated an experiment many times. It does not predict any single trial — it describes where outcomes cluster on average. Formally, for a discrete random variable $X$ taking values $x_1, x_2, \ldots, x_n$ with probabilities $p_1, p_2, \ldots, p_n$:

$$E[X] = \sum_{i=1}^{n} x_i \cdot p_i$$

This is a weighted average: each outcome is weighted by how likely it is to occur.

**Worked example.** Suppose a carnival game costs $\$2$ to play. You roll a standard six-sided die: rolling a 6 pays $\$8$, rolling a 4 or 5 pays $\$3$, and anything else pays nothing. What is your expected net gain per play?

First, compute expected gross winnings:

$$E[\text{winnings}] = 8 \cdot \frac{1}{6} + 3 \cdot \frac{2}{6} + 0 \cdot \frac{3}{6} = \frac{8}{6} + \frac{6}{6} = \frac{14}{6} \approx \$2.33$$

Subtract the $\$2$ entry fee:

$$E[\text{net}] = 2.33 - 2.00 = +\$0.33$$

On average, you gain about 33 cents per play — the game favors you slightly. A carnival operator would lose money long-term at these odds, which is why real carnival games are designed so $E[\text{net}] < 0$ for the player.

**Problem-solving application.** Expected value drives decisions wherever outcomes are uncertain. An insurance company pricing a policy calculates the expected payout across thousands of customers and sets premiums above that figure to ensure profit. A software team deciding whether to refactor a legacy module might estimate: a 30% chance the refactor saves 40 hours of future debugging, a 50% chance it saves 10 hours, and a 20% chance it introduces new bugs costing 15 hours. The expected savings are:

$$E[\text{hours saved}] = 0.30(40) + 0.50(10) + 0.20(-15) = 12 + 5 - 3 = 14 \text{ hours}$$

If the refactor itself costs 10 hours, the expected net benefit is positive — a rational argument for doing it. The key skill is identifying all outcomes, assigning realistic probabilities, and computing the weighted sum. Expected value does not guarantee a specific result; it tells you which choice is better *in expectation* across repeated or analogous decisions.

### expected_vertex_degree (19.4s)

## Expected Vertex Degree

The **degree** of a vertex in a graph is the number of edges incident to it — in other words, how many neighbors it has. In a fixed graph you can simply count, but in a **random graph** or when analyzing a large network statistically, you need to reason about the *expected* degree: the average degree a randomly chosen vertex will have, weighted by probability.

In the Erdős–Rényi random graph model $G(n, p)$, you start with $n$ labeled vertices and independently connect each pair with probability $p$. Fix any vertex $v$. It has $n - 1$ potential neighbors, and each edge exists independently with probability $p$, so the degree of $v$ is a sum of $n - 1$ independent Bernoulli random variables. By linearity of expectation:

$$\mathbb{E}[\deg(v)] = (n-1)\,p$$

This result holds for every vertex equally, so it is also the expected degree of a uniformly randomly chosen vertex from the graph.

**Worked example.** Suppose you model a social network with $n = 1000$ users and set $p = 0.01$ (each pair of users is connected with 1% probability). Then:

$$\mathbb{E}[\deg(v)] = 999 \times 0.01 \approx 9.99$$

On average, each user has about 10 friends. The total number of edges in the graph has expected value $\binom{1000}{2} \times 0.01 = 4{,}995$, which you can verify using the handshaking lemma: $\mathbb{E}[\text{edges}] = \frac{n \cdot \mathbb{E}[\deg(v)]}{2} = \frac{1000 \times 9.99}{2} \approx 4{,}995$.

**Problem-solving application.** Expected degree is a critical design parameter in network engineering. If you are building a peer-to-peer system where each node should reliably reach the rest of the network, you need the graph to be *connected* with high probability. For $G(n, p)$, the sharp threshold for connectivity is approximately $p = \frac{\ln n}{n}$, giving an expected degree of $\ln n$. For $n = 10{,}000$ nodes, that means $p \approx \frac{9.21}{10{,}000}$ and each node needs roughly $9$ to $10$ peers on average — far fewer than you might guess from a 10,000-node network. Setting $p$ below this threshold risks disconnected components; setting it much higher wastes bandwidth. Expected degree converts an abstract connectivity goal into a concrete connection-rate budget, making it indispensable in distributed systems design, epidemic modeling, and graph generation.

### giant_component (15.2s)

## Giant Component

In a network or graph, a **connected component** is a maximal set of nodes where every pair is reachable from every other. Most small, sparse networks consist of many disconnected fragments. But as you add edges randomly, something dramatic happens: at a critical density, a single component suddenly absorbs most of the graph. That dominant structure is the **giant component**.

The transition is sharp. When a random graph on $n$ nodes has average degree $\langle k \rangle < 1$, all components are small — typically $O(\log n)$ in size. The moment $\langle k \rangle$ crosses 1, a giant component emerges that contains $\Theta(n)$ nodes, growing to encompass almost the entire graph as $\langle k \rangle$ increases. This is an example of a **phase transition**, borrowing language from physics.

**Worked example.** Consider 10,000 nodes where each pair of nodes is connected independently with probability $p$. The average degree is $\langle k \rangle = (n-1)p \approx np$.

- At $p = 0.00005$, $\langle k \rangle = 0.5$: the largest component has roughly $O(\log n) \approx 20$ nodes.
- At $p = 0.0001$, $\langle k \rangle = 1.0$: a giant component first materializes.
- At $p = 0.0003$, $\langle k \rangle = 3.0$: the giant component holds about 94% of all nodes.

You can verify this experimentally with NetworkX:

```python
import networkx as nx

n, p = 10_000, 0.0003
G = nx.erdos_renyi_graph(n, p)
components = sorted(nx.connected_components(G), key=len, reverse=True)
giant_fraction = len(components[0]) / n
print(f"Giant component: {giant_fraction:.1%} of nodes")
```

**Problem-solving application.** The giant component concept guides decisions in network design and epidemiology. In disease modeling, an infection spreads network-wide only when the contact graph has a giant component. Vaccination strategies aim to fragment the giant component by removing high-degree nodes — dropping $\langle k \rangle$ below the critical threshold and splitting the network into isolated clusters too small to sustain an epidemic. The same logic applies to cybersecurity: segmenting a corporate network so that no single giant component connects all machines limits the blast radius of a breach. Identifying the giant component and the bridges that hold it together is therefore the first diagnostic step in resilience analysis of any large network.

## Network Resilience

Network resilience is the ability of a network to maintain acceptable performance when nodes, edges, or communication pathways fail. A resilient network keeps critical functions running even as parts of it break down — whether from hardware failure, targeted attack, or random disruption. The key insight is that resilience is not just about redundancy; it depends on *where* redundancy exists and *how* the network is connected.

Two properties drive resilience in practice. **Connectivity** measures whether a path still exists between any two nodes after failures. **Robustness** measures how much performance degrades as failures accumulate. A network can remain connected but become slow or bottlenecked, so both matter.

**Worked example.** Consider a small internet backbone with six routers (nodes) and nine fiber links (edges). Router 3 is a hub connecting five others. If router 3 fails, the network splits into two isolated clusters — no path exists between them. This makes router 3 an *articulation point* (or cut vertex): a single node whose removal disconnects the graph. Now compare a redesigned backbone where no single router connects more than three others, and every pair of routers has at least two independent paths between them. Removing any one router leaves all remaining routers reachable. The redesigned network has higher resilience because it eliminates articulation points and increases *edge-disjoint paths* between critical nodes.

**Problem-solving application.** You are given a network graph and asked to identify its weakest points before deploying it in production.

```python
import networkx as nx

G = nx.Graph()
G.add_edges_from([
    (0,1),(0,2),(1,3),(2,3),(3,4),(3,5),(4,5)
])

# Find articulation points (single-node failures that disconnect the graph)
cut_vertices = list(nx.articulation_points(G))
print("Articulation points:", cut_vertices)

# Find bridges (single-edge failures that disconnect the graph)
bridges = list(nx.bridges(G))
print("Bridges:", bridges)

# Measure node connectivity: minimum nodes to remove to disconnect the graph
k = nx.node_connectivity(G)
print("Node connectivity:", k)
```

Running this reveals which nodes and edges are structural vulnerabilities. A node connectivity of 1 means a single failure can isolate part of the network. The fix is targeted: add redundant links around articulation points and bridges until node connectivity reaches at least 2. Resilience engineering is fundamentally this loop — measure vulnerability, add targeted redundancy, re-measure — rather than adding capacity everywhere indiscriminately.
