### bit_representation (0.0s)

## Bit Representation

**Definition.** Every integer and real number stored in a digital computer is encoded as a finite sequence of *bits*, each belonging to the set $\{0, 1\}$. For a non-negative integer $n$, the **binary representation** is the unique tuple $(b_{k-1}, b_{k-2}, \ldots, b_1, b_0)$ with each $b_i \in \{0,1\}$ satisfying

$$n = \sum_{i=0}^{k-1} b_i \cdot 2^i.$$

The integer $k$ is the **bit-width**. A signed integer is typically encoded using *two's complement*: for a $k$-bit word, the value of a pattern $(b_{k-1}, \ldots, b_0)$ is

$$n = -b_{k-1} \cdot 2^{k-1} + \sum_{i=0}^{k-2} b_i \cdot 2^i,$$

placing the representable range at $[-2^{k-1},\, 2^{k-1}-1]$.

**Worked Example.** Convert $n = 45$ to an 8-bit two's complement word.

1. Repeated division by 2: $45 = 32 + 8 + 4 + 1 = 2^5 + 2^3 + 2^2 + 2^0$.
2. Set $b_5 = b_3 = b_2 = b_0 = 1$, all others $0$.
3. Result: $\mathtt{0010\,1101}_2$.

Verification: $0\cdot2^7 + 0\cdot2^6 + 1\cdot2^5 + 0\cdot2^4 + 1\cdot2^3 + 1\cdot2^2 + 0\cdot2^1 + 1\cdot2^0 = 32+8+4+1 = 45$. $\checkmark$

**Key Theorem (Uniqueness of Binary Expansion).** For every integer $n \geq 0$ there exists a unique finite sequence $(b_{k-1}, \ldots, b_0)$ with $b_{k-1} = 1$ (unless $n = 0$) such that $n = \sum_{i=0}^{k-1} b_i 2^i$. The proof follows by strong induction: the base case $n \in \{0,1\}$ is immediate; for $n \geq 2$, write $n = 2q + r$ with $r = n \bmod 2$, apply the inductive hypothesis to $q$, and prepend $r$. Uniqueness follows because the map $\mathbb{Z}/2^k\mathbb{Z} \to \{0,1\}^k$ is a bijection.


## Sset Interface

### Definition

An **sset** (symbolic set) is a first-class mathematical object that pairs a carrier set with a declared algebraic signature. Formally, an sset $S$ is a triple

$$S = (U,\, \Sigma,\, \llbracket\cdot\rrbracket)$$

where $U$ is the **universe** (a Python iterable or a lazily described domain), $\Sigma = \{\sigma_1, \sigma_2, \ldots\}$ is a finite **signature** of named operations, and $\llbracket \sigma_i \rrbracket : U^{a_i} \to U$ is the **interpretation** of each $\sigma_i$ with arity $a_i$. The *interface* of an sset is the contract that any concrete implementation must satisfy: it must expose membership testing (`__contains__`), iteration (`__iter__`) over a representative sample, and an `.ops` mapping that resolves each signature symbol to a callable.

In SPL, `sset_interface` is the abstract base from which every symbolic domain (integers modulo $n$, polynomial rings, graph vertex sets, and so on) inherits. It enforces a uniform protocol so that higher-order recipes—pattern matching, algebraic rewriting, automated theorem checking—can operate polymorphically across domains without knowing the concrete representation.

### Worked Example

Consider the sset $\mathbb{Z}_5 = (\{0,1,2,3,4\},\; \{+, \times\},\; \llbracket\cdot\rrbracket)$ where $\llbracket + \rrbracket(a,b) = (a+b)\bmod 5$. Constructing it under `sset_interface` requires registering both operations in `.ops`:

```python
ops = {'+': lambda a, b: (a + b) % 5,
       '*': lambda a, b: (a * b) % 5}
```

Membership of $3$ is resolved by `3 in Z5`, and the expression $3 + 4$ is evaluated by dispatching through `Z5.ops['+'](3, 4)` to yield $2$.

### Key Theorem

**Homomorphism Preservation.** Let $S = (U, \Sigma, \llbracket\cdot\rrbracket_S)$ and $T = (V, \Sigma, \llbracket\cdot\rrbracket_T)$ be two ssets sharing the same signature. A function $\varphi : U \to V$ is a *homomorphism* if and only if for every $\sigma \in \Sigma$ and every tuple $(u_1,\ldots,u_a) \in U^a$,

$$\varphi\!\left(\llbracket\sigma\rrbracket_S(u_1,\ldots,u_a)\right) = \llbracket\sigma\rrbracket_T\!\left(\varphi(u_1),\ldots,\varphi(u_a)\right).$$

Because `sset_interface` enforces a uniform `.ops` dictionary, SPL's `sset_homomorphism_check` routine can verify this property mechanically by sampling the domain and comparing both sides—no manual proof is required for finite carriers.

### binary_trie (0.0s)

## Binary Trie

**Definition.** A *binary trie* (from *re**trie**val*) is a rooted tree in which every internal node has exactly two children, labelled $0$ and $1$, and each node at depth $d$ represents the set of all binary strings sharing a common prefix of length $d$. Formally, let $\Sigma = \{0,1\}$. A binary trie over a finite set $S \subseteq \Sigma^*$ is the smallest rooted binary tree $T$ such that for every string $s = s_1 s_2 \cdots s_k \in S$ there exists a root-to-node path whose edge labels spell out $s_1, s_2, \ldots, s_k$. Nodes terminating a stored string are marked; unmarked internal nodes act purely as routing structure.

**Worked Example.** Insert the strings $\{0,01,10,110\}$ into an initially empty trie. Starting from the root:

- String $0$: follow edge $0$; mark that node.
- String $01$: follow edge $0$, then edge $1$; mark the resulting leaf.
- String $10$: follow edge $1$, then edge $0$; mark that leaf.
- String $110$: follow edge $1$, then edge $1$, then edge $0$; mark the final node.

The trie has depth $3$ and seven nodes in total (root plus six descendants). A membership query for $10$ costs exactly $2$ edge traversals — proportional to the length of the query string, not the size of $S$.

**Key Theorem (Query Complexity).** Let $T$ be a binary trie storing a set $S$ of binary strings, and let $\ell_{\max} = \max_{s \in S} |s|$. Then membership, insertion, and deletion each run in $O(\ell_{\max})$ time and require at most $O(|S| \cdot \ell_{\max})$ nodes in the worst case, with the best case (maximally shared prefixes) reducing node count to $O(\ell_{\max})$.

*Proof sketch.* Each operation traverses at most one root-to-leaf path of length $\leq \ell_{\max}$, performing $O(1)$ work per node. Node count is bounded by summing, over all strings, the number of nodes not shared with a previously inserted string; in the worst case (no shared prefixes) this is $|S| \cdot \ell_{\max}$. $\square$

**Lab Cell.**

```python
from sympy import symbols

class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

def insert(root, s):
    node = root
    for bit in s:
        node = node.children.setdefault(bit, TrieNode())
    node.is_end = True

def search(root, s):
    node = root
    for bit in s:
        if bit not in node.children:
            return False
        node = node.children[bit]
    return node.is_end

root = TrieNode()
for w in ["0", "01", "10", "110"]:
    insert(root, w)

print(search(root, "10"))   # True
print(search(root, "11"))   # False
```

### hash_table (0.0s)

## Hash Table

**Definition.** A *hash table* is a data structure that implements an associative array, mapping a set of keys $K$ to a set of values $V$ through a *hash function* $h : U \to \{0, 1, \ldots, m-1\}$, where $U$ is the universe of possible keys and $m$ is the number of available *slots* (buckets). The hash function compresses an arbitrarily large key space into a fixed index range, enabling average-case $O(1)$ lookup, insertion, and deletion. When two distinct keys $k_1 \neq k_2$ satisfy $h(k_1) = h(k_2)$, a *collision* occurs; standard resolution strategies include *chaining* (each slot holds a linked list of entries) and *open addressing* (probing alternative slots according to a fixed sequence).

A widely used hash function for integer keys is the *division method*:

$$h(k) = k \bmod m$$

where $m$ is chosen to be a prime not close to a power of 2, reducing systematic clustering.

**Worked Example.** Let $m = 7$ and consider inserting the keys $\{10, 22, 31, 4, 15\}$ using the division method. Computing $h(k) = k \bmod 7$:

| Key $k$ | $h(k)$ |
|---------|--------|
| 10 | 3 |
| 22 | 1 |
| 31 | 3 |
| 4  | 4 |
| 15 | 1 |

Slots 3 and 1 each receive two keys, so chaining appends $31$ behind $10$ and $15$ behind $22$. A lookup for key $31$ computes $h(31)=3$, accesses slot 3, and traverses the chain of length 2.

**Key Theorem (Simple Uniform Hashing).** Under the assumption that every key is equally likely to hash to any of the $m$ slots independently of all others, the expected length of a chain at any slot is $\alpha = n/m$, called the *load factor*, where $n$ is the number of stored keys. Consequently, the expected time for a successful search is $\Theta(1 + \alpha)$. Keeping $\alpha = O(1)$—achieved by resizing the table so that $m = \Theta(n)$—guarantees $O(1)$ amortised performance.

**Lab Cell (SymPy).**

```python
from sympy import isprime

keys = [10, 22, 31, 4, 15]

for slot, chain in enumerate(table):

print(f"\nLoad factor α = {load_factor:.3f}")
```

### jump_pointers (0.0s)

## Jump Pointers

**Definition.** Let $T = (V, E)$ be a rooted tree with $n$ nodes and root $r$. For each node $v \in V$ and non-negative integer $k$, the *jump pointer* $\text{up}[v][k]$ denotes the $2^k$-th ancestor of $v$ in $T$; that is, the unique node reached by following $2^k$ parent edges from $v$ toward the root. Formally,

$$\text{up}[v][0] = \text{parent}(v), \qquad \text{up}[v][k] = \text{up}[\,\text{up}[v][k-1]\,][k-1], \quad k \geq 1.$$

If $v$ has fewer than $2^k$ ancestors, the pointer is conventionally set to a sentinel (often the root or a null node). This recurrence expresses the key structural invariant: the $2^k$-th ancestor equals the $2^{k-1}$-th ancestor of the $2^{k-1}$-th ancestor—a doubling identity that underpins the technique's efficiency.

**Worked Example.** Consider the path $1 \to 2 \to 3 \to 4 \to 5$ rooted at node $1$, where each edge leads from parent to child. For node $v = 5$ and levels $k = 0, 1, 2$:

$$\text{up}[5][0] = 4, \quad \text{up}[5][1] = \text{up}[4][0] = 3, \quad \text{up}[5][2] = \text{up}[3][1] = \text{up}[\text{up}[3][0]][0] = \text{up}[2][0] = 1.$$

To find the $3$rd ancestor of $5$, write $3 = 2^1 + 2^0$ in binary. Apply: first jump $2^1 = 2$ steps to reach node $3$, then jump $2^0 = 1$ step to reach node $2$. The answer is $2$, obtained in two table lookups.

**Key Theorem.** *After $\mathcal{O}(n \log n)$ preprocessing time and space to populate the jump-pointer table, the $d$-th ancestor of any node can be computed in $\mathcal{O}(\log n)$ time.*

*Proof sketch.* The table has $n \cdot \lceil \log_2 n \rceil$ entries, each computable in $\mathcal{O}(1)$ via the recurrence, giving the preprocessing bound. For a query $d$, decompose $d$ in binary using at most $\lceil \log_2 n \rceil$ bits; each set bit corresponds to one table lookup and one pointer traversal, yielding $\mathcal{O}(\log n)$ total steps. $\blacksquare$

This technique forms the backbone of the $\mathcal{O}(n \log n, \log n)$ algorithm for Lowest Common Ancestor (LCA) queries.

**Lab Cell.**
```python
import sympy as sp

# Build jump-pointer table for a path graph: parent[i] = i-1, root = 1
n = 8
LOG = n.bit_length()
parent = {i: i - 1 for i in range(2, n + 1)}
parent[1] = 1  # root points to itself as sentinel

up = [[None] * (n + 1) for _ in range(LOG)]
for v in range(1, n + 1):
    up[0][v] = parent[v]
for k in range(1, LOG):
    for v in range(1, n + 1):
        up[k][v] = up[k-1][up[k-1][v]]

def kth_ancestor(v, d):
    for k in range(LOG):
        if (d >> k) & 1:
            v = up[k][v]
    return v

# Verify: 3rd ancestor of 5 in path 1->2->...->8
print(kth_ancestor(5, 3))  # Expected: 2
```

## Leaf Linked List

### Definition

Let $T$ be a rooted tree whose internal nodes serve solely as routing structures and whose **leaf nodes** store actual data. A **leaf linked list** is an augmented representation of $T$ in which every leaf node carries an additional pointer to the next leaf in left-to-right (in-order) traversal order, forming a singly linked list $L = \langle \ell_1, \ell_2, \ldots, \ell_n \rangle$ over the leaf set $\mathcal{L}(T)$.

Formally, for each leaf $\ell_i \in \mathcal{L}(T)$, define

$$\ell_i.\texttt{next} = \begin{cases} \ell_{i+1} & \text{if } i < n, \\ \texttt{nil} & \text{if } i = n. \end{cases}$$

The structure supports two independent access patterns: hierarchical lookup through the tree edges and sequential scan through the $\texttt{next}$ chain, without requiring re-traversal of interior nodes.

### Worked Example

Consider the binary search tree built from the key sequence $\{3, 1, 4, 1, 5\}$ (duplicates resolved left). After insertion the leaves are, in in-order, $1, 1, 3, 4, 5$. Augmenting with $\texttt{next}$ pointers gives

$$\ell_1(1) \xrightarrow{\texttt{next}} \ell_2(1) \xrightarrow{\texttt{next}} \ell_3(3) \xrightarrow{\texttt{next}} \ell_4(4) \xrightarrow{\texttt{next}} \ell_5(5) \xrightarrow{\texttt{next}} \texttt{nil}.$$

A range query $[2, 4]$ locates $\ell_3$ in $O(\log n)$ tree time and then streams $\ell_3, \ell_4$ through the linked list in $O(k)$ time, where $k = 2$ is the output size.

### Key Theorem

**Theorem (Range-Query Complexity).** Let $T$ be a balanced binary search tree on $n$ keys augmented as a leaf linked list. A range query $[a, b]$ returning $k$ leaves executes in $O(\log n + k)$ time.

*Proof sketch.* The left boundary $a$ is located by a standard tree search in $O(\log n)$. Each subsequent leaf in $[a, b]$ is reached by a single $\texttt{next}$ dereference in $O(1)$; there are exactly $k$ such steps. Total cost is $O(\log n) + O(k) = O(\log n + k)$. $\square$

The bound is optimal: $\Omega(\log n)$ is required for locating the start, and $\Omega(k)$ is unavoidable for reading $k$ outputs.

### Lab Cell

```python
from sympy import symbols, Rational

# Represent leaves as (key, next_index) pairs
leaves = [(1, 1), (1, 2), (3, 3), (4, 4), (5, None)]

def range_scan(leaves, lo, hi):
    # Locate first leaf >= lo (simulating O(log n) tree descent)
    start = next((i for i, (k, _) in enumerate(leaves) if k >= lo), None)
    result = []
    idx = start
    while idx is not None:
        key, nxt = leaves[idx]
        if key > hi:
            break
        result.append(key)
        idx = nxt
    return result

print(range_scan(leaves, 2, 4))   # Expected: [3, 4]
```

### binary_trie_operations (0.0s)

## Binary Trie Operations

### Definition

A **binary trie** (from *retrieval*) is a rooted tree in which every internal node has exactly two children, labeled $0$ and $1$. Each root-to-leaf path spells out a binary string, and the set of all such strings constitutes the **language** of the trie. Formally, let $\Sigma = \{0,1\}$ and $\Sigma^* $ denote the set of all finite binary strings. A binary trie $T$ over a finite set $S \subseteq \Sigma^*$ is the minimal prefix-closed tree satisfying: for every $w \in S$, every prefix of $w$ appears as a node of $T$.

Three primitive operations define the interface:

- **Insert$(w)$**: Follow the path $w_1, w_2, \ldots, w_n$ from the root, creating any missing nodes, and mark the terminal node.
- **Search$(w)$**: Traverse the same path; return *true* if and only if the terminal node is marked.
- **Delete$(w)$**: Unmark the terminal node of $w$ and prune any newly childless, unmarked nodes upward toward the root.

Each operation runs in $O(|w|)$ time and $O(|w|)$ worst-case additional space, where $|w|$ is the length of the query string.

### Worked Example

Let $S = \{010, 011, 10\}$. Insert these strings in order.

After inserting $010$: nodes $\varepsilon \to 0 \to 01 \to 010^\star$ are created (${}^\star$ marks terminal).  
After inserting $011$: the path shares $\varepsilon, 0, 01$; only node $011^\star$ is new.  
After inserting $10$: nodes $1 \to 10^\star$ are added under the root.

Searching for $01$ returns *false* because node $01$ exists but is **not** marked. Deleting $011$ unmarks $011$ and prunes it (no children), but $01$ is retained because it still has child $010$.

### Key Theorem

**Theorem (Space complexity of a binary trie).** A binary trie storing $n$ strings from $\Sigma^*$, each of length at most $L$, uses at most $nL$ nodes.

*Proof sketch.* Each insertion traces a path of length at most $L$ and creates at most $L$ new nodes. Summing over all $n$ insertions gives the bound. Shared prefixes only reduce this count; hence $nL$ is a tight upper bound. $\blacksquare$

In practice, when the stored strings share long common prefixes, the actual node count is $O(nL / \log n)$ for random binary inputs.

```python
from sympy import symbols, Function

```

### level_based_binary_search (0.0s)

## Level Based Binary Search

**Definition.** Let $A = (a_0, a_1, \ldots, a_{n-1})$ be a sorted array of $n$ elements with $n = 2^k - 1$ for some positive integer $k$. A *level-based binary search* assigns each index $i$ a *level* $\ell(i)$ defined as the largest power of two that divides $i + 1$:

$$\ell(i) = \nu_2(i + 1), \quad i = 0, 1, \ldots, n-1,$$

where $\nu_2(m)$ denotes the 2-adic valuation of $m$ (the exponent of the highest power of $2$ dividing $m$). The search proceeds top-down through decreasing levels, comparing the target $x$ against the element at the current index and halving the remaining search interval, exactly as classical binary search does but with the midpoint selection made explicit by the level structure.

More precisely, the root of the implicit search tree sits at index $m = \lfloor n/2 \rfloor$ (level $k-1$). At each step the algorithm compares $x$ with $a_m$ and descends left (subtract a level-$({\ell(m)-1})$ offset) or right (add the same offset), repeating until a match is found or the interval is empty.

**Worked example.** Let $n = 7$, so $A = (2, 5, 8, 12, 16, 23, 38)$. The level assignments are:

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|-----|---|---|---|---|---|---|---|
| $\ell(i)$ | 0 | 1 | 0 | 2 | 0 | 1 | 0 |

Search for $x = 23$. Start at $m = 3$ (level 2): $a_3 = 12 < 23$, go right. Move to $m = 5$ (level 1): $a_5 = 23 = x$. Found in **2 comparisons**.

**Key theorem.** *For a sorted array of $n = 2^k - 1$ elements, level-based binary search terminates in at most $k = \lceil \log_2(n+1) \rceil$ comparisons.*

*Proof sketch.* Each comparison eliminates exactly one level, reducing the active sub-interval by half. Since the implicit tree has height $k$, no root-to-leaf path exceeds $k$ edges, bounding the comparison count by $k$. $\blacksquare$

This matches the classical $O(\log n)$ bound, but the level structure makes the midpoint sequence cache-friendly and branch-predictable when implemented iteratively.

**Lab cell.**

```python
import sympy as sp

def level_based_binary_search(arr, target):
    n = len(arr)
    lo, hi = 0, n - 1
    comparisons = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        comparisons += 1
        if arr[mid] == target:
            return mid, comparisons
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1, comparisons

A = [2, 5, 8, 12, 16, 23, 38]
idx, comps = level_based_binary_search(A, 23)
print(f"Found at index {idx} in {comps} comparison(s)")

# Verify logarithmic bound
n = sp.Symbol('n', positive=True)
print(sp.ceiling(sp.log(len(A) + 1, 2)))  # Expected: 3
```

### xfasttrie (0.0s)

## Xfasttrie

**Definition.** An *x-fast trie* is a deterministic data structure for storing a dynamic set $S$ of integers drawn from a bounded universe $U = \{0, 1, \ldots, u-1\}$, where $u = 2^w$ for some word length $w$. It supports predecessor and successor queries in $O(\log w)$ time and insertions or deletions in $O(w)$ amortized time, using $O(n \log u)$ space, where $n = |S|$.

The structure consists of a complete binary trie of depth $w$ over the binary representations of all keys, together with a collection of $w + 1$ hash tables $H_0, H_1, \ldots, H_w$. The table $H_\ell$ stores every node at depth $\ell$ that is an *ancestor* of at least one key currently in $S$. Each internal node carries two pointers: a *descendant pointer* that skips down to the smallest (or largest) leaf in its subtree, enabling rapid navigation when part of the path is missing.

**Worked Example.** Let $w = 4$, so the universe is $\{0, \ldots, 15\}$, and let $S = \{3, 9, 14\}$ in binary $\{0011, 1001, 1110\}$. The hash table $H_0$ stores the single root node (prefix $\varepsilon$). At depth 1, $H_1$ stores both children of the root, since one element begins with $0$ and two begin with $1$. Continuing this process, $H_4$ stores exactly the three leaves. A predecessor query for $x = 11 = 1011_2$ performs a binary search over the depth levels: find the deepest level $\ell^*$ such that the length-$\ell^*$ prefix of $x$ appears in $H_{\ell^*}$, which takes $O(\log w)$ hash-table lookups. The node found at $\ell^*$ carries a descendant pointer directly to the predecessor leaf $9$.

**Key Theorem** *(Willard, 1983).* An x-fast trie on $n$ keys from a universe of size $u = 2^w$ answers predecessor and successor queries in $O(\log w)$ time and supports updates in $O(w)$ time, using $O(n w)$ space.

*Proof sketch.* The binary search over $w + 1$ levels, each a constant-time hash lookup, yields $O(\log w)$ query time. Each insertion touches at most $w$ nodes (one per level), each requiring a single hash-table update, giving $O(w)$ update time. Space is $O(n w)$ because each of the $n$ keys contributes at most $w$ ancestors across all hash tables.

**Lab Cell.**

```python
from sympy import Integer, log, floor

w = 4
u = Integer(2)**w
S = [3, 9, 14]

# Compute the prefix of each key at each depth
for key in S:
    prefixes = [key >> (w - ell) for ell in range(w + 1)]
    print(f"key={key:>2} ({key:0{w}b}): prefixes = {prefixes}")

query_time = log(w, 2)
print(f"\nQuery time O(log w) = O(log {w}) = O({query_time})")
```

## Probabilistic Sampling

**Definition.** Let $(\Omega, \mathcal{F}, \mathbb{P})$ be a probability space and let $X : \Omega \to \mathbb{R}^d$ be a random variable with distribution $\mu$. A *probabilistic sample* of size $n$ is a collection $\{x_1, x_2, \ldots, x_n\}$ of independent realisations drawn according to $\mu$, written $x_i \overset{\text{i.i.d.}}{\sim} \mu$. The act of generating such a collection is called **probabilistic sampling**. When $\mu$ admits a density $p(x)$ with respect to Lebesgue measure, sampling means producing points whose long-run histogram converges to $p$.

Two foundational mechanisms cover most practical cases. **Inverse transform sampling** exploits the cumulative distribution function $F(x) = \mathbb{P}(X \le x)$: if $U \sim \mathrm{Uniform}(0,1)$ then $F^{-1}(U) \sim \mu$. **Rejection sampling** handles distributions known only up to a normalising constant: propose $y \sim q$ from a tractable envelope satisfying $p(y) \le M q(y)$ for all $y$, then accept $y$ with probability $p(y)/(Mq(y))$; accepted draws are exactly distributed according to $\mu$.

**Worked example.** Suppose $X \sim \mathrm{Exponential}(\lambda)$, so $p(x) = \lambda e^{-\lambda x}$ for $x \ge 0$ and $F(x) = 1 - e^{-\lambda x}$. Solving $u = F(x)$ for $x$ gives the inverse transform $F^{-1}(u) = -\ln(1-u)/\lambda$. Drawing $u = 0.632$ and $\lambda = 1$ yields $x = -\ln(0.368) \approx 1.00$, a single sample from $\mathrm{Exp}(1)$.

**Theorem (Glivenko–Cantelli).** Let $F_n$ denote the empirical distribution function of $n$ i.i.d. samples from $F$. Then
$$\sup_{x \in \mathbb{R}} |F_n(x) - F(x)| \xrightarrow{\text{a.s.}} 0 \quad \text{as } n \to \infty.$$
This guarantees that sufficiently large samples faithfully represent the true distribution, providing the theoretical foundation for Monte Carlo estimation.

**Lab cell (SymPy/NumPy).**

```python
# Inverse-transform sampling for Exp(lambda_)
rng = np.random.default_rng(42)
lam = 1.0
u = rng.uniform(size=10_000)
samples = -np.log1p(-u) / lam          # numerically stable form

# Verify: sample mean should approximate 1/lambda

```

## Treap

**Definition.** A *treap* is a binary search tree (BST) in which every node stores two keys: a *search key* $k$ drawn from a totally ordered set, and a *priority* $p$ drawn uniformly at random from $\mathbb{R}$ (or a large integer range). The structure simultaneously satisfies the BST property on search keys and the max-heap property on priorities:

- **BST property:** for every node $v$, all keys in its left subtree are $< k_v$ and all keys in its right subtree are $> k_v$.
- **Heap property:** for every non-root node $v$ with parent $u$, $p_v < p_u$.

The name is a portmanteau of *tree* and *heap*.

**Worked Example.** Insert keys $\{3, 1, 4, 1, 5\}$ (ignoring the duplicate for clarity: $\{1, 3, 4, 5\}$) with randomly assigned priorities $p_1=0.9,\; p_3=0.5,\; p_4=0.7,\; p_5=0.2$. The node with the largest priority becomes the root: node $1$ ($p=0.9$). Node $4$ ($p=0.7$) is its right child; node $3$ ($p=0.5$) is the left child of $4$; node $5$ ($p=0.2$) is the right child of $4$. One can verify that in-order traversal yields $1,3,4,5$, confirming the BST property, while every parent has a higher priority than its children, confirming the heap property.

**Key Theorem.** *The treap on $n$ distinct keys with independent, uniformly random priorities is identically distributed to a random BST built by inserting the same keys in a uniformly random order.* In particular, the expected height is $\Theta(\log n)$ and the expected cost of search, insertion, and deletion is $O(\log n)$. Insertion and deletion are implemented via standard BST pointer manipulation followed by rotations that restore the heap property; each operation requires $O(\text{depth})$ rotations in expectation.

The treap's elegance lies in reducing tree balance to a probabilistic argument: because priorities are independent of keys, no adversary can construct a worst-case input sequence that forces $O(n)$ height.

**Lab Cell.**

```python
import random

class Node:
    def __init__(self, key):
        self.key, self.pri = key, random.random()
        self.left = self.right = None

def rotate_right(y):
    x = y.left; y.left = x.right; x.right = y; return x

def rotate_left(x):
    y = x.right; x.right = y.left; y.left = x; return y

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
        if root.left.pri > root.pri:
            root = rotate_right(root)
    else:
        root.right = insert(root.right, key)
        if root.right.pri > root.pri:
            root = rotate_left(root)
    return root

keys = [5, 2, 8, 1, 4, 7, 9]
root = None
for k in keys:
    root = insert(root, k)

def inorder(node):
    if node is None: return []
    return inorder(node.left) + [node.key] + inorder(node.right)

print("In-order:", inorder(root))   # Expected: [1, 2, 4, 5, 7, 8, 9]
print("Root key:", root.key, "  Root priority:", round(root.pri, 4))
```

Running the lab cell confirms that in-order traversal recovers the sorted sequence regardless of insertion order, while the root holds the node with the highest sampled priority.

## Yfasttrie

**Definition.** Let $U = 2^w$ be a universe of non-negative integers. A *Y-fast trie* (Willard, 1983) is a dynamic ordered-set data structure over a subset $S \subseteq \{0, 1, \ldots, U-1\}$ of size $n$ that supports predecessor and successor queries in $O(\log \log U)$ worst-case time, and insertions and deletions in $O(\log \log U)$ expected amortised time, using $O(n)$ space.

The structure builds on the *X-fast trie*, which stores one hash table $H_i$ for each level $i \in \{0, 1, \ldots, w\}$ of a binary trie. Each $H_i$ maps a $i$-bit prefix to a pointer to that trie node. A predecessor query on an X-fast trie binary-searches over levels to locate the deepest ancestor of the query key, taking $O(\log w) = O(\log \log U)$ time, but an X-fast trie alone requires $O(n \log U)$ space.

The Y-fast trie reduces space by partitioning $S$ into $\lceil n / \log U \rceil$ contiguous *clusters*, each of size $\Theta(\log U)$. Within each cluster the elements are stored in a balanced binary search tree (e.g., a red-black tree). A single *representative* from each cluster—its minimum element—is inserted into an underlying X-fast trie. A predecessor query for key $q$ first searches the X-fast trie for the representative immediately above or below $q$ in $O(\log \log U)$ time, then descends into the corresponding BST and performs a standard predecessor search in $O(\log \log U)$ time, since each BST has $O(\log U)$ keys. Both phases share the same asymptotic bound.

**Worked example.** Take $w = 4$ ($U = 16$) and $S = \{1, 3, 5, 9, 11, 14\}$. With $\log U = 4$, the six elements form two clusters: $C_1 = \{1, 3, 5\}$ and $C_2 = \{9, 11, 14\}$. Representatives $\{1, 9\}$ enter the X-fast trie. A predecessor query for $q = 10$: the X-fast trie returns representative $9$, directing us to $C_2$; the BST over $C_2$ then finds $\text{pred}(10) = 9$ in $O(\log 3)$ steps.

**Theorem (Willard 1983).** *A Y-fast trie on $n$ keys from universe $\{0,\ldots,2^w-1\}$ occupies $O(n)$ space and answers predecessor queries in $O(\log \log U)$ worst-case time.*

*Proof sketch.* Space follows because $O(n / \log U)$ representatives contribute $O(n)$ hash-table entries across all $w+1$ levels of the X-fast trie ($O(n / \log U \cdot \log U) = O(n)$), and the BSTs collectively hold $n$ keys. The query bound combines the $O(\log \log U)$ binary search over trie levels with the $O(\log \log U)$ BST descent. $\square$

## Fusion Tree

### Definition

A **fusion tree** is a search tree data structure designed for the integer predecessor problem over a universe $\{0, 1, \ldots, U-1\}$. Introduced by Fredman and Willard (1993), it stores a set $S$ of $n$ integers drawn from $w$-bit machine words, where $w$ denotes the native word size of the underlying hardware. The structure achieves query time $O(\log n / \log w)$ by replacing naive binary comparisons with parallel bitwise operations that compare multiple keys simultaneously within a single word.

A fusion tree partitions its keys into a $B$-ary trie where each internal node holds up to $B = w^{1/5}$ keys. Within each node, the $B$ stored keys are *compressed* into a single machine word via a sketching function $\text{sketch}: \{0,1\}^w \to \{0,1\}^{B^4}$ that retains only the bits distinguishing the node's keys from one another — called the **distinguishing bits**. A query key $x$ is sketched identically and compared against all $B$ node keys in $O(1)$ word-RAM operations using a carefully constructed parallel bitmask.

### Worked Example

Suppose $w = 16$ and a node stores $B = 3$ keys: $k_1 = 0011$, $k_2 = 0110$, $k_3 = 1010$ (in 4-bit shorthand for illustration). The distinguishing bits are positions $\{0, 2, 3\}$ (bits that differ across at least one pair). The sketch maps each key by extracting these bits: $\text{sketch}(k_1) = 010$, $\text{sketch}(k_2) = 110$, $\text{sketch}(k_3) = 100$. These three 3-bit sketches are packed into a single integer

$$
M = \text{sketch}(k_1) \;\Vert\; \text{sketch}(k_2) \;\Vert\; \text{sketch}(k_3) = 010\,110\,100.
$$

For a query $x = 0101$, compute $\text{sketch}(x) = 101$ and replicate it as $X = 101\,101\,101$. The predecessor rank of $x$ among the node's keys is recovered from the subtraction $X - M$ in $O(1)$ via the sign bits of each packed field, locating the correct child pointer without a single explicit comparison.

### Key Theorem

**Theorem (Fredman–Willard, 1993).** A fusion tree storing $n$ integers from a $w$-bit universe supports predecessor queries and insertions in $O(\log n / \log w)$ worst-case time on the word-RAM model with word size $w \geq \log^2 n$.

Setting $w = \Theta(\log n)$ yields the celebrated $O(\log n / \log \log n)$ query bound, which breaks the $\Omega(\log n)$ comparison-tree barrier and remains the asymptotically fastest known deterministic predecessor structure for polynomial universes.

