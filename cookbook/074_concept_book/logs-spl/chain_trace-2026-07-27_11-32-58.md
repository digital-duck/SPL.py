## Amortized Analysis

**Definition.** Amortized analysis is a method for computing the *average cost per operation* in a sequence of operations on a data structure, providing a guarantee over the entire sequence rather than on any single worst-case operation. Formally, given a sequence of $n$ operations $o_1, o_2, \ldots, o_n$ with actual costs $c_1, c_2, \ldots, c_n$, the **amortized cost** $\hat{c}_i$ of operation $o_i$ satisfies

$$\sum_{i=1}^{n} \hat{c}_i \;\geq\; \sum_{i=1}^{n} c_i.$$

The amortized cost may exceed the actual cost for some operations and fall below it for others, provided the cumulative amortized cost never underestimates the cumulative actual cost. Three principal techniques achieve this: aggregate analysis, the accounting method, and the potential method.

**Worked Example: Dynamic Array Doubling.** Consider an array that doubles in capacity whenever it is full. Starting from capacity 1, inserting $n$ elements triggers doublings at sizes $1, 2, 4, \ldots, 2^{\lfloor \log_2 n \rfloor}$. The total copying work across all doublings is

$$1 + 2 + 4 + \cdots + 2^{\lfloor \log_2 n \rfloor} < 2n.$$

Adding the $n$ unit-cost insertions, the total actual cost is less than $3n$. Dividing by $n$ operations gives an amortized cost of $O(1)$ per insertion, even though individual doublings cost $\Theta(n)$.

**Key Theorem (Potential Method).** Define a potential function $\Phi: \text{States} \to \mathbb{R}_{\geq 0}$ with $\Phi(\text{initial state}) = 0$. The amortized cost of operation $i$ is

$$\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1}),$$

where $D_i$ denotes the data structure state after operation $i$. Summing over all $n$ operations and applying the telescoping property:

$$\sum_{i=1}^{n} \hat{c}_i = \sum_{i=1}^{n} c_i + \Phi(D_n) - \Phi(D_0) \;\geq\; \sum_{i=1}^{n} c_i.$$

For the dynamic array, setting $\Phi(D) = 2 \cdot |\text{elements}| - |\text{capacity}|$ yields $\hat{c}_i \leq 3$ for every insertion, confirming the $O(1)$ amortized bound.

**Lab Cell.**
```python
from sympy import symbols, summation, floor, log, simplify

n = symbols('n', positive=True, integer=True)
k = symbols('k', nonnegative=True, integer=True)

# Total copying cost across all doublings up to n insertions
doubling_cost = summation(2**k, (k, 0, floor(log(n, 2))))
print("Total doubling cost (closed form):", simplify(doubling_cost))
# Verify amortized cost per insertion is O(1)
print("Amortized cost per insertion:", simplify(doubling_cost / n))
```

## Backing Array

**Definition.** A *backing array* is the contiguous block of memory that underlies a dynamic data structure—most commonly a dynamic array or array-based stack—storing the actual elements. The backing array has a fixed *capacity* $C$ at any moment, while the structure tracks a separate *size* $n \leq C$ denoting how many positions are currently occupied. When $n$ reaches $C$, the structure allocates a new, larger backing array, copies all elements, and releases the old one. This operation is called a *resize* or *reallocation*.

Formally, let $B_k$ denote the backing array after the $k$-th resize, with capacity $C_k$. Under the standard *doubling strategy*, $C_0 = 1$ and $C_k = 2^k$. Elements at logical indices $0, 1, \ldots, n-1$ reside at physical addresses $\text{base}(B_k) + i \cdot w$, where $w$ is the element width in bytes, giving $O(1)$ random access.

**Worked Example.** Suppose we append the sequence $[10, 20, 30, 40, 50]$ to an initially empty dynamic array with $C_0 = 2$.

| Step | Action | $n$ | $C$ | Resize? |
|------|--------|-----|-----|---------|
| 1 | append 10 | 1 | 2 | No |
| 2 | append 20 | 2 | 2 | No |
| 3 | append 30 | 3 | 4 | Yes ($C: 2 \to 4$) |
| 4 | append 40 | 4 | 4 | No |
| 5 | append 50 | 5 | 8 | Yes ($C: 4 \to 8$) |

After all five appends, the backing array holds eight slots, five occupied.

**Key Theorem (Amortized $O(1)$ Append).** With the doubling strategy, any sequence of $n$ appends starting from an empty structure costs $O(n)$ total time, so the *amortized* cost per append is $O(1)$.

*Proof sketch.* The total copy work across all resizes is $\sum_{k=0}^{\lfloor \log_2 n \rfloor} 2^k = 2^{\lfloor \log_2 n \rfloor + 1} - 1 < 2n$. Adding the $n$ individual append costs gives $O(n)$ overall. $\square$

**Lab Cell.**

```python
from sympy import symbols, summation, ceiling, log, simplify, S

k, n = symbols('k n', positive=True, integer=True)
total_copy_work = summation(2**k, (k, 0, ceiling(log(n, 2))))
print("Total copy work:", simplify(total_copy_work))
# Verify amortized bound: total_copy_work / n → O(1)
print("Ratio to n:", simplify(total_copy_work / n))
```

Running this cell confirms that total copy work grows as $\Theta(n)$, validating the amortized analysis symbolically.

## List Interface

**Definition.** A *list interface* is an abstract specification of a sequential container that supports ordered storage and retrieval of elements by position. Formally, let $S$ be a set of elements and $\mathbb{Z}_{\geq 0}$ the set of non-negative integers. A list $L$ of length $n$ is a total function

$$L : \{0, 1, \ldots, n-1\} \longrightarrow S,$$

where $L(i)$ denotes the element at *index* $i$. The interface exposes a minimal set of operations — commonly $\texttt{get}(i)$, $\texttt{set}(i, x)$, $\texttt{insert}(i, x)$, and $\texttt{delete}(i)$ — along with the invariant that indices remain contiguous after every mutation. The distinction between an *interface* and an *implementation* is fundamental: the interface describes *what* the operations must do, while concrete data structures (arrays, linked lists) specify *how* they are realized with particular time and space trade-offs.

**Worked Example.** Consider the list $L = [7, 3, 9, 1]$, so $n = 4$ and $L(0) = 7,\, L(2) = 9$. Executing $\texttt{insert}(1, 5)$ yields $L' = [7, 5, 3, 9, 1]$ with $n' = 5$. Formally, the new function satisfies

$$L'(i) = \begin{cases} L(i) & i < 1, \\ 5 & i = 1, \\ L(i-1) & i > 1. \end{cases}$$

Every element at index $\geq 1$ is shifted right by one, preserving the contiguity invariant.

**Key Theorem (Index-Shift Invariant).** Let $L$ be a list of length $n$. After $\texttt{insert}(k, x)$ for any $0 \leq k \leq n$, the resulting list $L'$ has length $n+1$, and for all $i \in \{0,\ldots,n\}$:

$$L'(i) = \begin{cases} L(i) & 0 \leq i < k, \\ x & i = k, \\ L(i-1) & k < i \leq n. \end{cases}$$

*Proof sketch.* Define $L'$ by the three cases above. Totality on $\{0,\ldots,n\}$ follows because the cases partition the index domain. Contiguity is immediate by construction. $\square$

**Lab Cell.**

```python
from sympy import symbols, Function, Piecewise, Integer

# Represent the list as a Python list and verify the index-shift invariant
L = [7, 3, 9, 1]
k, x = 1, 5

L_prime = L[:k] + [x] + L[k:]          # insert at position k
expected = {i: (L[i] if i < k else (x if i == k else L[i-1]))
            for i in range(len(L) + 1)}

assert all(L_prime[i] == expected[i] for i in range(len(L_prime))), \
    "Index-shift invariant violated"

print("L      =", L)
print("L'     =", L_prime)
print("L'[k]  =", L_prime[k], "  (inserted element)")
```

Running this cell confirms the theorem mechanically: `L' = [7, 5, 3, 9, 1]` and `L'[1] == 5`.

## Resize Operation

**Definition.** Let $A$ be an array (tensor) with shape $\mathbf{s} = (s_1, s_2, \ldots, s_n) \in \mathbb{Z}_{>0}^n$, so that the total number of elements is $N = \prod_{i=1}^n s_i$. A *resize operation* maps $A$ to a new array $B$ with target shape $\mathbf{t} = (t_1, t_2, \ldots, t_m)$, subject to the constraint

$$\prod_{j=1}^m t_j = N.$$

Formally, $\operatorname{resize}(A, \mathbf{t}) = B$ where the bijection between flat indices is given by the identity map: element $A[\,\overline{i}\,]$ at multi-index $\overline{i}$ (read in row-major order) becomes $B[\,\overline{j}\,]$ at the multi-index $\overline{j}$ satisfying $\operatorname{ravel}(\overline{i}, \mathbf{s}) = \operatorname{ravel}(\overline{j}, \mathbf{t})$. Here $\operatorname{ravel}(\overline{i}, \mathbf{s}) = \sum_{k=1}^n i_k \prod_{\ell=k+1}^n s_\ell$ is the standard row-major linearisation. Crucially, resize is a *reinterpretation* of the same flat data buffer, not an interpolation or sampling; no new values are computed.

**Worked Example.** Consider the matrix

$$A = \begin{pmatrix} 1 & 2 & 3 \\ 4 & 5 & 6 \end{pmatrix}, \quad \mathbf{s} = (2, 3), \quad N = 6.$$

Flattening row-major yields the sequence $(1, 2, 3, 4, 5, 6)$. Applying $\operatorname{resize}(A, (3, 2))$ regroups this sequence into three rows of two:

$$B = \begin{pmatrix} 1 & 2 \\ 3 & 4 \\ 5 & 6 \end{pmatrix}, \quad \mathbf{t} = (3, 2).$$

Note that $B[1, 0] = 3 = A[0, 2]$, consistent with both having flat index $2$.

**Key Theorem (Shape Equivalence).** Two shapes $\mathbf{s}$ and $\mathbf{t}$ admit a resize operation between them if and only if $\prod_{i} s_i = \prod_{j} t_j$. Moreover, $\operatorname{resize}(\operatorname{resize}(A, \mathbf{t}), \mathbf{s}) = A$ for all valid $\mathbf{t}$, so the operation is its own inverse with appropriate target shape. This follows immediately from the bijectivity of $\operatorname{ravel}$ on finite index sets of equal cardinality.

**Lab Cell.**

```python
from sympy import Array, reshape

A = Array([[1, 2, 3], [4, 5, 6]])   # shape (2, 3)
B = reshape(A, (3, 2))              # resize to shape (3, 2)
print(B)                            # [[1, 2], [3, 4], [5, 6]]

# Verify round-trip identity
assert reshape(B, (2, 3)) == A
```

Running this cell confirms both the reshaped output and the round-trip guarantee, grounding the theorem in a directly executable verification.

## Array Stack

**Definition.** A *stack* is an abstract data type that maintains a linear sequence of elements under a *last-in, first-out* (LIFO) discipline. Formally, a stack $S$ over a universe $U$ is a tuple $(A, t)$ where $A$ is a finite array and $t \in \mathbb{Z}_{\geq 0}$ is the *top pointer* indicating the index of the most recently inserted element. The four canonical operations are:

- $\texttt{push}(S, x)$: set $A[t+1] \leftarrow x$, then $t \leftarrow t + 1$.
- $\texttt{pop}(S)$: return $A[t]$, then $t \leftarrow t - 1$ (undefined when $t = 0$).
- $\texttt{peek}(S)$: return $A[t]$ without modifying $t$.
- $\texttt{isEmpty}(S)$: return $\mathbf{true}$ iff $t = 0$.

An *array stack* implements these operations by backing $S$ with a contiguous block of memory of fixed capacity $n$. When $t = n$ a *stack overflow* occurs; when $t = 0$ and $\texttt{pop}$ is called a *stack underflow* occurs.

**Worked Example.** Let $n = 4$ and begin with $t = 0$. Execute the sequence $\texttt{push}(3),\, \texttt{push}(7),\, \texttt{push}(1),\, \texttt{pop}(),\, \texttt{peek}()$.

| Operation | $A$ (indices 1–4) | $t$ | Returned |
|---|---|---|---|
| initial | $[\cdot,\cdot,\cdot,\cdot]$ | 0 | — |
| $\texttt{push}(3)$ | $[3,\cdot,\cdot,\cdot]$ | 1 | — |
| $\texttt{push}(7)$ | $[3,7,\cdot,\cdot]$ | 2 | — |
| $\texttt{push}(1)$ | $[3,7,1,\cdot]$ | 3 | — |
| $\texttt{pop}()$ | $[3,7,\cdot,\cdot]$ | 2 | 1 |
| $\texttt{peek}()$ | $[3,7,\cdot,\cdot]$ | 2 | 7 |

Note that $\texttt{pop}$ does not erase $A[3]$; the element $1$ is simply made inaccessible by decrementing $t$.

**Theorem (Constant-Time Operations).** Each of $\texttt{push}$, $\texttt{pop}$, $\texttt{peek}$, and $\texttt{isEmpty}$ runs in $O(1)$ time and $O(1)$ auxiliary space.

*Proof sketch.* Each operation performs exactly one array read or write at index $t$ and at most one arithmetic update to $t$. Because array access by index is $O(1)$ in the RAM model, the total work is bounded by a constant independent of $t$ or $n$. $\square$

A consequence is that a sequence of $m$ mixed push/pop operations costs $\Theta(m)$ time in total, giving an amortized cost of $O(1)$ per operation even when capacity doubling is introduced.

**Lab Cell.**

```python
from sympy import symbols, Integer

# Simulate an array stack symbolically
capacity = 4
A = [None] * (capacity + 1)   # 1-indexed; index 0 unused
t = 0

def push(x):
    global t
    if t == capacity:
        raise OverflowError("Stack overflow")
    t += 1;  A[t] = x

def pop():
    global t
    if t == 0:
        raise IndexError("Stack underflow")
    val = A[t];  t -= 1;  return val

push(Integer(3)); push(Integer(7)); push(Integer(1))
print("pop →", pop())    # 1
print("peek →", A[t])    # 7
print("top pointer t =", t)  # 2
```

Running this cell confirms the table above: `pop` returns $1$, `peek` reveals $7$, and $t$ settles at $2$.

## Fast Array Stack

**Definition.** A *fast array stack* is an abstract stack (last-in, first-out) implemented over a contiguous backing array whose capacity doubles whenever the occupied size equals its length and halves whenever the occupied size falls to one-quarter of its length. Formally, let $A$ be an array of capacity $c$, and let $n$ denote the number of elements currently stored, with the invariant

$$\frac{c}{4} \;\leq\; n \;\leq\; c.$$

The three primitive operations are:

- $\texttt{push}(x)$: if $n = c$, reallocate $A$ with capacity $2c$; then set $A[n] \leftarrow x$ and $n \leftarrow n+1$.
- $\texttt{pop}()$: if $n = c/4$, reallocate $A$ with capacity $c/2$; decrement $n$ and return $A[n]$.
- $\texttt{peek}()$: return $A[n-1]$ without modification.

Each reallocation copies all $n$ elements, costing $\Theta(n)$ in the worst case. The central question is whether repeated calls remain efficient in aggregate.

**Worked example.** Start with $c = 1$, $n = 0$. Push the sequence $1, 2, 3, 4, 5$:

| Step | Operation | $n$ | $c$ | Reallocate? |
|------|-----------|-----|-----|-------------|
| 1 | push(1) | 1 | 1 | no ($n < c$ after) — initial slot used |
| 2 | push(2) | 2 | 2 | yes: $n=1=c$, double to $c=2$ |
| 3 | push(3) | 3 | 4 | yes: $n=2=c$, double to $c=4$ |
| 4 | push(4) | 4 | 4 | no |
| 5 | push(5) | 5 | 8 | yes: $n=4=c$, double to $c=8$ |

Total element-copy work across all reallocations: $1 + 2 + 4 = 7$, while the five pushes themselves cost $5$. The total work is $12$ for five operations, giving an empirical average of $2.4$ per operation.

**Theorem (Amortized $O(1)$ per operation).** Assign each element a *charge* of $3$ units when pushed. One unit pays for the push itself; the remaining two are banked. When a doubling reallocation copies $n$ elements, each of the $n/2$ elements inserted since the last doubling has banked exactly $2$ units, collectively covering the $n$ copy operations. A symmetric argument using a charge of $2$ units handles halving. Therefore, every push and pop runs in $O(1)$ *amortized* time, and the worst-case time for any sequence of $m$ operations is $O(m)$.

**Lab cell.**

```python
from sympy import symbols, summation, simplify, Integer

# Verify total copy work for k doublings starting from capacity 1
k = symbols('k', positive=True, integer=True)
# Capacities after i doublings: 2^i; copy work at doubling i is 2^(i-1)
i = symbols('i', nonneg=True, integer=True)
total_copy_work = summation(2**i, (i, 0, k - 1))
print("Total copy work for k doublings:", simplify(total_copy_work))
# Expected: 2**k - 1  (always less than final capacity 2**k)
```

Running this cell yields $2^{k}-1$, confirming that total reallocation cost never exceeds the final capacity — the hallmark of geometric resizing efficiency.
