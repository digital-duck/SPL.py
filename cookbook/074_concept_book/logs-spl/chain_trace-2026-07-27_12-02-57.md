## Binary Search Tree

**Definition.** A *binary search tree* (BST) is a rooted binary tree in which every node $v$ stores a key $k(v)$ drawn from a totally ordered set, subject to the *BST invariant*: for every node $v$, all keys in the left subtree of $v$ are strictly less than $k(v)$, and all keys in the right subtree of $v$ are strictly greater than $k(v)$. Formally, if $L(v)$ and $R(v)$ denote the left and right subtrees,

$$\forall u \in L(v):\ k(u) < k(v), \qquad \forall u \in R(v):\ k(u) > k(v).$$

This invariant holds recursively at every node, not merely at the root.

**Worked Example.** Insert the sequence $\langle 5, 3, 7, 1, 4 \rangle$ into an initially empty BST. The first key, $5$, becomes the root. Key $3 < 5$ goes left; $7 > 5$ goes right. Key $1 < 5$, then $1 < 3$, so it becomes the left child of $3$. Key $4 < 5$, then $4 > 3$, so it becomes the right child of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node. An in-order traversal (left $\to$ root $\to$ right) yields $\langle 1, 3, 4, 5, 7 \rangle$—the keys in sorted order, which is a direct consequence of the invariant.

**Key Theorem (Search Complexity).** A search, insertion, or deletion in a BST containing $n$ nodes requires $O(h)$ comparisons, where $h$ is the height of the tree. For a *balanced* BST, $h = \Theta(\log n)$, giving $O(\log n)$ worst-case operations. In the degenerate case—keys inserted in sorted order—the tree degenerates to a linked list with $h = n - 1$ and $O(n)$ operations. Self-balancing variants (AVL trees, red–black trees) maintain $h = O(\log n)$ unconditionally.

**Lab Cell (SymPy/Python).**

```python
# Minimal BST node; insert and in-order traversal
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root

def inorder(root):
    return [] if root is None else inorder(root.left) + [root.key] + inorder(root.right)

root = None
for k in [5, 3, 7, 1, 4]:
    root = insert(root, k)

print(inorder(root))   # → [1, 3, 4, 5, 7]
```

## Black Height Property

**Definition.** Let $T$ be a red-black tree and let $v$ be any node in $T$. The *black height* of $v$, denoted $\mathrm{bh}(v)$, is the number of black nodes on any simple path from $v$ (exclusive) to a descendant leaf (null sentinel). The *Black Height Property* is the invariant that, for every node $v$ in $T$, every simple path from $v$ to a descendant leaf contains the same number of black nodes. Formally,

$$\forall v \in T,\; \forall \text{ leaves } \ell_1, \ell_2 \text{ descended from } v:\quad \mathrm{bh}(v, \ell_1) = \mathrm{bh}(v, \ell_2).$$

This invariant is one of the five defining properties of a red-black tree and is the structural guarantee that prevents the tree from becoming arbitrarily unbalanced.

**Worked Example.** Consider the following red-black tree (B = black, R = red):

```
        10(B)
       /      \
     5(R)    20(B)
    /   \
  3(B)  7(B)
```

Null sentinels are black. Starting from the root $10$: the path $10 \to 5 \to 3 \to \mathrm{nil}$ passes through $\{10, 3, \mathrm{nil}\}$, contributing $2$ black nodes (excluding $10$, counting $3$ and nil). The path $10 \to 20 \to \mathrm{nil}$ passes through $\{20, \mathrm{nil}\}$, also contributing $2$ black nodes. Every path yields $\mathrm{bh}(\text{root}) = 2$, confirming the property holds.

**Key Theorem.** *A red-black tree on $n$ internal nodes has height at most $2\log_2(n+1)$.*

*Proof sketch.* Let $h$ be the height and $b = \mathrm{bh}(\text{root})$. Because no two consecutive red nodes may appear (the red property), at least half of the nodes on any root-to-leaf path are black, so $b \geq h/2$. A subtree of black height $b$ contains at least $2^b - 1$ internal nodes, giving $n \geq 2^{h/2} - 1$. Solving yields $h \leq 2\log_2(n+1)$, guaranteeing $O(\log n)$ search, insert, and delete. $\blacksquare$

**Lab Cell (SymPy).**

```python
from sympy import symbols, log, solve, simplify

n, h, b = symbols('n h b', positive=True)

# Lower bound on internal nodes given black height b
min_nodes = 2**b - 1

# If b >= h/2, substitute b = h/2 for the tightest bound
bound = min_nodes.subs(b, h/2)

# Solve for h given n internal nodes
h_max = solve(bound - n, h)
print("Height bound:", simplify(h_max[0]))   # 2*log(n + 1)/log(2)
```

### no_red_edge_property (26.9s)

## No Red Edge Property

**Definition.** Let $G = (V, E, w)$ be a weighted undirected graph with distinct edge weights $w : E \to \mathbb{R}$. Given a spanning tree $T \subseteq E$, call an edge $e \in E \setminus T$ a *candidate* edge. Adding $e$ to $T$ creates exactly one cycle $C_e$. We say $T$ satisfies the **No Red Edge Property** if, for every non-tree edge $e$, the weight $w(e)$ is *not* strictly greater than every tree edge on $C_e$. Equivalently, $T$ contains no edge that is the unique maximum-weight edge of any cycle in $G$.

The terminology arises from the red–blue framework: an edge is colored **red** if it is the heaviest edge on some cycle; the property asserts that a minimum spanning tree (MST) must be free of red edges.

**Worked Example.** Consider the graph with vertices $\{A, B, C\}$ and edges
$$e_1 = AB,\ w = 1;\quad e_2 = BC,\ w = 4;\quad e_3 = AC,\ w = 3.$$
Let $T = \{e_1, e_2\}$. The only non-tree edge is $e_3$. Adding $e_3$ creates the cycle $A\text{–}B\text{–}C\text{–}A$. The weights on this cycle are $1, 4, 3$; the maximum is $w(e_2) = 4$, which lies *inside* $T$. Hence $e_2$ is red and $T$ violates the No Red Edge Property. The true MST is $T^* = \{e_1, e_3\}$ with total weight $4$, which admits no red edge.

**Key Theorem (MST Characterization).** *A spanning tree $T$ of $G$ is a minimum spanning tree if and only if $T$ satisfies the No Red Edge Property.*

*Proof sketch.* $(\Rightarrow)$ If $T$ contained a red edge $e^* \in T$ lying on cycle $C$ with some non-tree edge $f$ satisfying $w(f) < w(e^*)$, then swapping $e^*$ for $f$ yields a spanning tree of strictly smaller total weight, contradicting minimality. $(\Leftarrow)$ If $T$ is not an MST, let $T^*$ be an MST; a standard exchange argument produces a red edge in $T$. $\square$

**Lab Cell (SymPy/NetworkX).**

```python
import networkx as nx

G = nx.Graph()
G.add_weighted_edges_from([("A","B",1), ("B","C",4), ("A","C",3)])

T = nx.minimum_spanning_tree(G, algorithm="kruskal")
print("MST edges:", list(T.edges(data=True)))

# Verify No Red Edge Property: no non-tree edge is heavier than all cycle edges
tree_edges = set(T.edges())
for u, v, d in G.edges(data=True):
    if (u, v) not in tree_edges and (v, u) not in tree_edges:
        path_weights = [T[a][b]["weight"] for a,b in zip(
            nx.shortest_path(T,u,v), nx.shortest_path(T,u,v)[1:])]
        assert d["weight"] <= max(path_weights), f"Red edge detected: ({u},{v})"
print("No Red Edge Property satisfied.")
```

### rooted_tree (14.9s)

## Rooted Tree

**Definition.** A *rooted tree* is a connected, acyclic graph $T = (V, E)$ together with a distinguished vertex $r \in V$ called the *root*. The root imposes a natural hierarchical orientation on every edge: each edge $\{u, v\} \in E$ is directed away from $r$, so that $u$ is the *parent* of $v$ if $u$ lies on the unique path from $r$ to $v$. Vertices with no children are called *leaves*; all others are *internal nodes*. The *depth* of a vertex $v$, denoted $d(v)$, is the number of edges on the path from $r$ to $v$, so $d(r) = 0$. The *height* of the tree is $h(T) = \max_{v \in V} d(v)$.

**Worked Example.** Consider the vertex set $V = \{1, 2, 3, 4, 5\}$ with edges $E = \{\{1,2\},\{1,3\},\{2,4\},\{2,5\}\}$ and root $r = 1$. The unique paths from the root determine the following structure: vertex $1$ is the root at depth $0$; vertices $2$ and $3$ are its children at depth $1$; vertices $4$ and $5$ are children of $2$ at depth $2$. The leaves are $\{3, 4, 5\}$ and the height is $h(T) = 2$. The total number of edges satisfies $|E| = |V| - 1 = 4$, consistent with the tree property.

**Theorem (Unique-Path Property).** *In any rooted tree $T$ with root $r$, there exists a unique path between $r$ and every vertex $v \in V$.*

*Proof sketch.* Since $T$ is connected, at least one path from $r$ to $v$ exists. Since $T$ is acyclic, any two distinct paths would together form a cycle—a contradiction. Therefore the path is unique. $\square$

This uniqueness is what makes rooted trees so powerful in algorithms: every vertex has a well-defined *ancestor chain*, enabling efficient divide-and-conquer strategies such as tree traversal and dynamic programming on subtrees.

**Lab Cell.**

```python
from sympy import symbols
from sympy.combinatorics import Permutation
# Build the rooted tree as a parent-pointer dictionary
parent = {2: 1, 3: 1, 4: 2, 5: 2}
root = 1

def depth(v, parent, root):
    d = 0
    while v != root:
        v = parent[v]
        d += 1
    return d

depths = {v: depth(v, parent, root) for v in parent}
depths[root] = 0
print("Depths:", depths)
# Height of the tree
height = max(depths.values())
print("Height:", height)
```

## Tree Height

**Definition.** Let $T$ be a rooted tree with root $r$. The *height* of a node $v$, written $h(v)$, is the length of the longest path (measured in edges) from $v$ to any leaf in the subtree rooted at $v$. The *height of the tree*, written $h(T)$, is defined as the height of the root:

$$h(T) = h(r) = \max_{v \in \text{leaves}(T)} d(r, v),$$

where $d(r, v)$ denotes the number of edges on the unique path from $r$ to leaf $v$. Leaves themselves have height $0$. An empty tree is assigned height $-1$ by convention, which simplifies recursive formulae.

**Recursive characterisation.** For any internal node $v$ with children $c_1, c_2, \ldots, c_k$,

$$h(v) = 1 + \max_{1 \le i \le k} h(c_i).$$

This recurrence is the computational foundation of every tree-height algorithm.

**Worked example.** Consider the binary tree whose edges are $\{(A,B),(A,C),(B,D),(B,E),(C,F)\}$ with root $A$. Applying the recurrence bottom-up: $h(D)=h(E)=h(F)=0$; $h(B)=1+\max(0,0)=1$; $h(C)=1+\max(0)=1$; $h(A)=1+\max(1,1)=2$. Thus $h(T)=2$, confirmed by the path $A\to B\to D$ (or $A\to B\to E$), each containing exactly two edges.

**Theorem (height–node bound).** A binary tree with $n$ nodes satisfies

$$\lfloor \log_2 n \rfloor \le h(T) \le n-1.$$

The lower bound is achieved by a complete binary tree (levels filled left to right), where $n \approx 2^{h+1}$. The upper bound is achieved by a path graph (each node has exactly one child), which degenerates to a linked list.

*Proof sketch.* A complete binary tree of height $h$ contains at most $2^{h+1}-1$ nodes, giving $h \ge \log_2(n+1)-1 > \lfloor \log_2 n\rfloor - 1$, hence the lower bound. A path of $n$ nodes has $n-1$ edges from root to leaf, giving the upper bound. $\square$

**Lab cell.**

```python
from sympy import symbols, Function, Max, Integer
from sympy.combinatorics import *

def tree_height(adj, root):
    """Return height of rooted tree given as adjacency dict {node: [children]}."""
    children = adj.get(root, [])
    if not children:
        return 0
    return 1 + max(tree_height(adj, c) for c in children)

adj = {'A': ['B', 'C'], 'B': ['D', 'E'], 'C': ['F'], 'D': [], 'E': [], 'F': []}
print(tree_height(adj, 'A'))  # Expected: 2
```
