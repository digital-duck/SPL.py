## Node

A **node** (also called a *vertex*) is the fundamental unit of a graph. Formally, given a graph $G = (V, E)$, a node is any element $v \in V$, where $V$ is a finite, non-empty set and $E \subseteq V \times V$ is the set of edges connecting pairs of nodes. Every structural property of a graph — connectivity, reachability, distance — is ultimately defined in terms of relationships among nodes.

The **degree** of a node $v$, written $\deg(v)$, counts the number of edges incident to it:

$$\deg(v) = |\{u \in V : (v, u) \in E\}|$$

In a directed graph, this splits into **in-degree** $\deg^-(v)$ and **out-degree** $\deg^+(v)$, counting incoming and outgoing edges respectively. The degree sequence of a graph is the sorted list of all node degrees; it is a graph invariant used to characterise structure without reference to labelling.

**Worked example.** Consider the graph $G$ with node set $V = \{A, B, C, D\}$ and edge set $E = \{(A,B),(A,C),(B,D),(C,D)\}$. The degree of each node is:

$$\deg(A) = 2,\quad \deg(B) = 2,\quad \deg(C) = 2,\quad \deg(D) = 2$$

Every node has degree 2, so $G$ is a **regular graph** of degree 2 — in fact, it is the 4-cycle $C_4$.

**Theorem (Handshaking Lemma).** For any undirected graph $G = (V, E)$,

$$\sum_{v \in V} \deg(v) = 2|E|$$

*Proof sketch.* Each edge $(u, v)$ contributes exactly 1 to $\deg(u)$ and exactly 1 to $\deg(v)$, hence 2 to the total degree sum. Summing over all edges gives $2|E|$. $\blacksquare$

An immediate corollary is that the number of odd-degree nodes in any graph must be even.

**Lab cell.**

```python
import sympy as sp
from sympy.combinatorics.named_groups import *

# Represent G as an adjacency dictionary
G = {'A': ['B','C'], 'B': ['A','D'], 'C': ['A','D'], 'D': ['B','C']}

degrees = {v: len(neighbors) for v, neighbors in G.items()}
print("Degrees:", degrees)

edge_count = sum(degrees.values()) // 2
print("Edge count via Handshaking Lemma:", edge_count)

# Verify: number of odd-degree nodes is even

print("Odd-degree nodes:", odd_nodes)   # expect []
```

## Pointer Reference

**Definition.** A *pointer* is a variable whose value is a memory address — a non-negative integer $a \in \mathbb{Z}_{\geq 0}$ that identifies a location in the computer's address space. A *reference* is an alias: a second name bound irrevocably to an existing object at the time of its creation, with no independent address of its own. Formally, if the address-of operator is $\&$ and the dereference operator is $*$, then for a variable $x$ stored at address $a$:

$$\&x = a, \qquad *(\&x) = x.$$

A pointer variable $p$ satisfies $*p = x$ whenever $p = \&x$. A reference $r$ bound to $x$ satisfies $r \equiv x$ at all times — it is not a copy but a transparent alias, so $\&r = \&x$ always holds.

**Worked Example.** Suppose integer $x = 42$ resides at address $a = 0\text{x}1000$. Declare pointer $p = \&x$, so $p = 0\text{x}1000$ and $*p = 42$. Now execute $*p = 99$; because $*p$ and $x$ name the same memory cell, $x$ becomes $99$ simultaneously. If instead a reference $r$ is bound to $x$ at initialization, then assigning $r = 99$ has the identical effect: the value at address $0\text{x}1000$ changes to $99$, and both $x$ and $r$ reflect the new value. The critical difference appears in re-targeting: pointer $p$ may later be set to $\&y$ for a different variable $y$, whereas reference $r$ cannot be rebound — its aliasing relationship is fixed at binding time.

**Key Theorem (Aliasing Invariant).** Let $r$ be a reference bound to variable $x$ at address $a$. For all subsequent program states $S$:

$$\&r\big|_S = a = \&x\big|_S.$$

No operation on $r$ can change this equality. This invariant makes references safer than pointers for compiler alias analysis and enables optimizations such as copy elision.

**Lab Cell (SymPy).**

```python
import sympy as sp

# Model pointer arithmetic symbolically
a, offset = sp.symbols('a offset', integer=True, nonneg=True)
sizeof_int = 4  # bytes

# Address of the k-th element in an array starting at base a
k = sp.Symbol('k', integer=True, nonneg=True)
ptr_k = a + k * sizeof_int

print("Address of element k:", ptr_k)
print("Address of element 3:", ptr_k.subs(k, 3))   # a + 12
print("Difference (pointer subtraction):",
      sp.simplify(ptr_k.subs(k, 5) - ptr_k.subs(k, 2)))  # 12 = 3 * sizeof_int
```

Running this cell confirms that pointer subtraction yields the *element count* between two addresses, not the raw byte difference — a foundational rule governing pointer arithmetic in typed languages.

## Dllist

**Definition.** A *doubly linked list* (dllist) is a linear data structure consisting of a sequence of nodes $N_1, N_2, \ldots, N_n$, where each node $N_i$ stores three fields: a data element $d_i$, a pointer $\text{next}_i$ to the successor node $N_{i+1}$, and a pointer $\text{prev}_i$ to the predecessor node $N_{i-1}$. Boundary sentinels are defined by $\text{prev}_1 = \text{null}$ and $\text{next}_n = \text{null}$. Formally, a dllist of length $n$ is a tuple

$$L = \bigl(N_1, N_2, \ldots, N_n\bigr), \quad N_i = (d_i,\, \text{prev}_i,\, \text{next}_i),$$

where pointer consistency requires $\text{next}_i = N_{i+1}$ and $\text{prev}_{i+1} = N_i$ for all $1 \le i < n$.

The bidirectional linkage distinguishes the dllist from a singly linked list, enabling $O(1)$ traversal in either direction from any node.

**Worked Example.** Consider the list $L = (3, 7, 12)$. The three nodes are

$$N_1 = (3, \text{null}, N_2), \quad N_2 = (7, N_1, N_3), \quad N_3 = (12, N_2, \text{null}).$$

To *delete* $N_2$ in place, reassign two pointers: set $\text{next}_1 \leftarrow N_3$ and $\text{prev}_3 \leftarrow N_1$. Node $N_2$ is then unreachable from $L$, and no element shifts position. The resulting list $L' = (3, 12)$ satisfies pointer consistency with exactly two pointer writes, independent of $n$.

**Key Theorem (Insertion and Deletion Complexity).** In a dllist with a direct reference to node $N_i$, both insertion of a new node immediately after $N_i$ and deletion of $N_i$ execute in $\Theta(1)$ time and $\Theta(1)$ auxiliary space.

*Proof sketch.* Each operation requires updating at most four pointer fields (two on the target node, one each on its neighbors). Because no iteration over the list is performed, the number of operations is bounded by a constant independent of $n$. $\square$

This contrasts with arrays, for which insertion or deletion at an arbitrary interior position costs $\Theta(n)$ due to element shifting.

**Lab Cell (SymPy).**

```python
from sympy import symbols, Eq, solve

# Represent node addresses symbolically and verify pointer consistency
prev1, next1, prev2, next2, prev3, next3 = symbols(
    'prev1 next1 prev2 next2 prev3 next3')

N1, N2, N3 = 1, 2, 3   # integer stand-ins for addresses

constraints = [
    Eq(next1, N2), Eq(prev2, N1),   # N1 <-> N2
    Eq(next2, N3), Eq(prev3, N2),   # N2 <-> N3
]

solution = solve(constraints, [next1, prev2, next2, prev3])
print("Pointer assignments:", solution)

# Simulate deletion of N2
next1_after = N3
prev3_after = N1
print(f"After deleting N2: next(N1)={next1_after}, prev(N3)={prev3_after}")
assert next1_after == prev3_after - 1 + 1  # consistency trivially holds
print("Pointer consistency verified.")
```

## Xor List

**Definition.** An *XOR linked list* is a doubly linked list in which each node stores a single field $\text{npx}$ defined as the bitwise exclusive-or of the memory addresses of its predecessor and successor:

$$\text{npx}(v) = \text{addr}(\text{prev}(v)) \oplus \text{addr}(\text{next}(v)),$$

where $\oplus$ denotes the bitwise XOR operation on non-negative integers. For the head node, $\text{prev} = 0$ (the null address), so $\text{npx}(\text{head}) = \text{addr}(\text{next}(\text{head}))$; symmetrically for the tail. Because XOR is its own inverse—$a \oplus b \oplus b = a$ for all $a, b \in \mathbb{Z}_{\geq 0}$—traversal requires only the address of the previously visited node.

**Worked Example.** Consider a list of three nodes with (symbolic) addresses $A = 100$, $B = 200$, $C = 300$. The stored fields are:

$$\text{npx}(A) = 0 \oplus 200 = 200, \quad \text{npx}(B) = 100 \oplus 300 = 340, \quad \text{npx}(C) = 200 \oplus 0 = 200.$$

To move forward from $A$ to $B$, the traversal computes $\text{next} = \text{npx}(A) \oplus \text{addr}(\text{prev}) = 200 \oplus 0 = 200$, yielding $B$. From $B$ to $C$: $\text{next} = 340 \oplus 100 = 300$, yielding $C$. Backward traversal is identical with the roles of prev and next exchanged.

**Key Theorem (Space Optimality).** An XOR linked list representing $n$ nodes requires exactly $n$ pointer-width words for linkage, compared with $2n$ words for a conventional doubly linked list. Formally, if each address occupies $w$ bits, the total linkage storage is $S_{\text{XOR}} = nw$ bits versus $S_{\text{std}} = 2nw$ bits, a factor-of-two reduction. The correctness of traversal follows directly from the self-inverse property of XOR: for any three consecutive addresses $p, q, r$, the node at $q$ stores $p \oplus r$, and $(p \oplus r) \oplus p = r$, $(p \oplus r) \oplus r = p$, enabling movement in either direction from a single stored word.

**Lab Cell.**

```python
from sympy import symbols, Xor, Integer

# Symbolic XOR of two integer addresses
p, q, r = Integer(100), Integer(200), Integer(300)
npx_B = p ^ r           # Python int XOR on SymPy Integers
print("npx(B) =", npx_B)                     # 340

print("Recover prev:", npx_B ^ int(r))        # 100 = addr(A)

```
