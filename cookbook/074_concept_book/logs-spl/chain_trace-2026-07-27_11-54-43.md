### binary_search_tree (0.0s)

## Binary Search Tree

**Definition.** A *binary search tree* (BST) is a rooted binary tree in which every node $v$ stores a key $k(v)$ drawn from a totally ordered set, subject to the *BST invariant*: for every node $v$, all keys in the left subtree of $v$ are strictly less than $k(v)$, and all keys in the right subtree of $v$ are strictly greater than $k(v)$. Formally, if $L(v)$ and $R(v)$ denote the left and right subtrees,

$$\forall u \in L(v):\ k(u) < k(v), \qquad \forall u \in R(v):\ k(u) > k(v).$$

This invariant holds recursively at every node, not merely at the root.

**Worked Example.** Insert the sequence $\langle 5, 3, 7, 1, 4 \rangle$ into an initially empty BST. The first key, $5$, becomes the root. Key $3 < 5$ goes left; $7 > 5$ goes right. Key $1 < 5$, then $1 < 3$, so it becomes the left child of $3$. Key $4 < 5$, then $4 > 3$, so it becomes the right child of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node. An in-order traversal (left $\to$ root $\to$ right) yields $\langle 1, 3, 4, 5, 7 \rangle$—the keys in sorted order, which is a direct consequence of the invariant.

**Key Theorem (Search Complexity).** A search, insertion, or deletion in a BST containing $n$ nodes requires $O(h)$ comparisons, where $h$ is the height of the tree. For a *balanced* BST, $h = \Theta(\log n)$, giving $O(\log n)$ worst-case operations. In the degenerate case—keys inserted in sorted order—the tree degenerates to a linked list with $h = n - 1$ and $O(n)$ operations. Self-balancing variants (AVL trees, red–black trees) maintain $h = O(\log n)$ unconditionally.

**Lab Cell (SymPy/Python).**

```python
# Minimal BST node; insert and in-order traversal
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root

def inorder(root):
    return [] if root is None else inorder(root.left) + [root.key] + inorder(root.right)

root = None
for k in [5, 3, 7, 1, 4]:
    root = insert(root, k)

print(inorder(root))   # → [1, 3, 4, 5, 7]
```

### scapegoat_tree (17.9s)

## Scapegoat Tree

**Definition.** A *scapegoat tree* is a self-balancing binary search tree that maintains balance lazily: it performs insertions and deletions without storing any balance metadata per node, instead rebuilding subtrees when a balance invariant is violated. Formally, a binary search tree $T$ with $n$ nodes is said to be *$\alpha$-weight-balanced* (for a fixed parameter $\alpha \in (1/2, 1)$) if, for every node $v$,

$$\text{size}(\text{left}(v)) \leq \alpha \cdot \text{size}(v) \quad \text{and} \quad \text{size}(\text{right}(v)) \leq \alpha \cdot \text{size}(v),$$

where $\text{size}(v)$ denotes the number of nodes in the subtree rooted at $v$. A node violating this condition is called a *scapegoat*. During an insertion, the algorithm walks back up the path from the newly inserted leaf and rebuilds the entire subtree rooted at the first scapegoat found into a perfectly balanced BST.

**Worked Example.** Suppose $\alpha = 2/3$ and consider inserting the sequence $1, 2, 3, 4$ into an initially empty tree. After inserting $1, 2, 3$, the root holds $1$ with size $3$; its right child has size $2$. Since $2/3 > 2/3$ is false, the right subtree is $2/3$-weight-balanced. Inserting $4$ yields a right child of size $3$ at the root of size $4$: $3/4 > 2/3$, so the root is the scapegoat. The algorithm flattens the entire tree into a sorted array $[1, 2, 3, 4]$ and rebuilds it as a perfectly balanced BST with $2$ as the root.

**Key Theorem.** For a scapegoat tree with parameter $\alpha$, the amortized cost of $m$ insertions beginning from an empty tree is $O(m \log m)$. Consequently, the amortized cost per insertion is $O(\log n)$. This follows from a potential argument: define $\Phi(T) = \sum_{v} \Delta(v)$, where $\Delta(v) = |\text{size}(\text{left}(v)) - \text{size}(\text{right}(v))|$. Each rebuild of a subtree of size $s$ costs $O(s)$ but reduces $\Phi$ by $\Omega(s)$, paying for itself amortized. Search and predecessor/successor queries run in $O(\log n)$ worst-case time because the tree height is bounded by $\log_{1/\alpha} n$.

```python
    height_bound = floor(log(n, 1 / alpha))
    print(f"n={n:>5}: height ≤ {height_bound}")
```

### subtree_size (16.4s)

## Subtree Size

**Definition.** Let $T = (V, E)$ be a rooted tree with root $r \in V$. For any node $v \in V$, the *subtree rooted at $v$*, denoted $T_v$, is the induced subgraph consisting of $v$ and all its descendants. The *subtree size* of $v$ is defined as

$$
\text{sz}(v) = |V(T_v)| = 1 + \sum_{c \in \text{children}(v)} \text{sz}(c).
$$

The base case is a leaf node $\ell$, for which $\text{children}(\ell) = \emptyset$ and therefore $\text{sz}(\ell) = 1$. The subtree size counts every node in $T_v$, including $v$ itself.

**Worked Example.** Consider the rooted tree below, with root $A$:

```
        A
       / \
      B   C
     / \
    D   E
```

Computing bottom-up: $\text{sz}(D) = 1$, $\text{sz}(E) = 1$, $\text{sz}(C) = 1$, $\text{sz}(B) = 1 + 1 + 1 = 3$, and $\text{sz}(A) = 1 + 3 + 1 = 5$. Observe that $\text{sz}(A) = |V| = 5$, which is always the case for the root.

**Key Theorem (Subtree-Size Recurrence and Complexity).** For a tree with $n$ nodes, the values $\{\text{sz}(v)\}_{v \in V}$ can be computed by a single post-order depth-first traversal in $O(n)$ time and $O(h)$ auxiliary stack space, where $h$ is the height of $T$. The post-order guarantee ensures that when $\text{sz}(v)$ is evaluated, $\text{sz}(c)$ is already known for every child $c$ of $v$.

*Proof sketch.* Each node is visited exactly once; at each visit, the algorithm performs work proportional to the degree of that node. Since $\sum_{v \in V} \deg(v) = 2(n-1)$ for a tree, the total work is $O(n)$. Stack depth equals the length of the root-to-node path, which is at most $h$. $\square$

Subtree sizes are fundamental in a wide range of algorithms: they enable $O(\log n)$ ancestor queries via Euler-tour flattening, underpin centroid decomposition, and allow balanced partition of trees for parallel processing.

**Lab Cell.**

```python
from sympy import symbols, Function
from collections import defaultdict

def subtree_sizes(adj, root):
    sz = {}
    def dfs(v, parent):
        sz[v] = 1
        for c in adj[v]:
            if c != parent:
                dfs(c, v)
                sz[v] += sz[c]
    dfs(root, None)
    return sz

adj = defaultdict(list)
for u, v in [('A','B'), ('A','C'), ('B','D'), ('B','E')]:
    adj[u].append(v); adj[v].append(u)

print(subtree_sizes(adj, 'A'))
# {'D': 1, 'E': 1, 'B': 3, 'C': 1, 'A': 5}
```

### tree_height (15.2s)

## Tree Height

**Definition.** Let $T$ be a rooted tree with root $r$. The *height* of a node $v$, written $h(v)$, is the length of the longest path (measured in edges) from $v$ to any leaf in the subtree rooted at $v$. The *height of the tree*, written $h(T)$, is defined as the height of the root:

$$h(T) = h(r) = \max_{v \in \text{leaves}(T)} d(r, v),$$

where $d(r, v)$ denotes the number of edges on the unique path from $r$ to leaf $v$. Leaves themselves have height $0$. An empty tree is assigned height $-1$ by convention, which simplifies recursive formulae.

**Recursive characterisation.** For any internal node $v$ with children $c_1, c_2, \ldots, c_k$,

$$h(v) = 1 + \max_{1 \le i \le k} h(c_i).$$

This recurrence is the computational foundation of every tree-height algorithm.

**Worked example.** Consider the binary tree whose edges are $\{(A,B),(A,C),(B,D),(B,E),(C,F)\}$ with root $A$. Applying the recurrence bottom-up: $h(D)=h(E)=h(F)=0$; $h(B)=1+\max(0,0)=1$; $h(C)=1+\max(0)=1$; $h(A)=1+\max(1,1)=2$. Thus $h(T)=2$, confirmed by the path $A\to B\to D$ (or $A\to B\to E$), each containing exactly two edges.

**Theorem (height–node bound).** A binary tree with $n$ nodes satisfies

$$\lfloor \log_2 n \rfloor \le h(T) \le n-1.$$

The lower bound is achieved by a complete binary tree (levels filled left to right), where $n \approx 2^{h+1}$. The upper bound is achieved by a path graph (each node has exactly one child), which degenerates to a linked list.

*Proof sketch.* A complete binary tree of height $h$ contains at most $2^{h+1}-1$ nodes, giving $h \ge \log_2(n+1)-1 > \lfloor \log_2 n\rfloor - 1$, hence the lower bound. A path of $n$ nodes has $n-1$ edges from root to leaf, giving the upper bound. $\square$

**Lab cell.**

```python
from sympy import symbols, Function, Max, Integer
from sympy.combinatorics import *

def tree_height(adj, root):
    """Return height of rooted tree given as adjacency dict {node: [children]}."""
    children = adj.get(root, [])
    if not children:
        return 0
    return 1 + max(tree_height(adj, c) for c in children)

adj = {'A': ['B', 'C'], 'B': ['D', 'E'], 'C': ['F'], 'D': [], 'E': [], 'F': []}
```

### height_bound_invariant (19.7s)

## Height Bound Invariant

**Definition.** Let $p/q$ be a rational number in lowest terms. The *naive height* (or *Weil height*) of $p/q$ is defined by

$$H\!\left(\frac{p}{q}\right) = \max\!\left(|p|,\, |q|\right).$$

More generally, for a polynomial $f(x) = a_n x^n + \cdots + a_0 \in \mathbb{Z}[x]$, the height of $f$ is $H(f) = \max_{0 \le i \le n} |a_i|$. The *height bound invariant* asserts that whenever two polynomials $f$ and $g$ are combined by an algebraic operation, the height of the result is controlled — bounded above by an explicit function of the individual heights and degrees. Concretely, for the product:

$$H(fg) \;\le\; \binom{\deg f + \deg g}{\deg f}\, H(f)\, H(g).$$

This inequality is not merely a curiosity; it is the engine behind termination proofs for symbolic-computation algorithms, guaranteeing that intermediate expressions cannot grow without bound in an uncontrolled way.

**Worked Example.** Let $f(x) = 3x^2 + 7x - 5$ and $g(x) = 2x - 4$. Then $H(f) = 7$, $H(g) = 4$, $\deg f = 2$, $\deg g = 1$. The bound gives

$$H(fg) \;\le\; \binom{3}{2} \cdot 7 \cdot 4 = 3 \cdot 28 = 84.$$

Direct multiplication yields $fg = 6x^3 + 2x^2 - 38x + 20$, so $H(fg) = 38$, which is comfortably below the bound of $84$.

**Key Theorem (Mignotte, 1974).** *If $f, g \in \mathbb{Z}[x]$ and $g \mid f$ in $\mathbb{Z}[x]$, then*

$$H(g) \;\le\; \binom{\deg f}{\lfloor \deg f / 2 \rfloor}\, H(f).$$

This divisor bound is the cornerstone of polynomial GCD algorithms: it guarantees that any factor of $f$ has height bounded by a quantity depending only on $f$, enabling coefficient reconstruction after modular computation without an infinite search.

**Lab Cell (SymPy).**

```python
from sympy import Poly, symbols, binomial
from sympy.abc import x

f = Poly(3*x**2 + 7*x - 5, x, domain='ZZ')
g = Poly(2*x - 4,           x, domain='ZZ')

H = lambda p: max(abs(c) for c in p.all_coeffs())
product = f * g

bound = int(binomial(f.degree() + g.degree(), f.degree())) * H(f) * H(g)
print(f"H(f)      = {H(f)}")
print(f"H(g)      = {H(g)}")
print(f"H(fg)     = {H(product)}")
print(f"Bound     = {bound}")
assert H(product) <= bound, "Height bound violated!"
```

Running this cell confirms $H(fg) = 38 \le 84$ and raises no assertion error, providing computational evidence of the invariant. Experiment by increasing coefficients of $f$ or $g$ to observe how the bound scales linearly with each height and combinatorially with degree.

### rebuild_operation (23.1s)

## Rebuild Operation

**Definition.** Let $T$ be a rooted expression tree whose nodes carry labels from an alphabet $\Sigma$ and whose leaves carry atomic terms from a domain $\mathcal{D}$. A *rebuild operation* is a function

$$\mathrm{rebuild} : T \times \Phi \;\longrightarrow\; T'$$

where $\Phi$ denotes a finite set of rewrite rules $\phi_i : \ell_i \mapsto r_i$, and $T'$ is a new tree obtained by replacing each subtree $s \subseteq T$ that matches the left-hand side $\ell_i$ of some rule with the corresponding right-hand side $r_i$, evaluated bottom-up. The operation is *complete* if every reducible subtree is replaced in a single pass, and *confluent* if the final tree $T'$ is independent of the order in which rules are applied.

**Worked Example.** Consider the arithmetic expression

$$E = (x^2 + 2x + 1) - (x + 1)^2.$$

Its initial tree contains a subtraction node whose children are the expanded polynomial $x^2 + 2x + 1$ and the squared binomial $(x+1)^2$. Applying the rule $\phi_1 : a^2 + 2ab + b^2 \mapsto (a+b)^2$ bottom-up, the left child is rewritten to $(x+1)^2$. The rebuild operation then propagates this change upward: the subtraction node now sees identical children, and rule $\phi_2 : u - u \mapsto 0$ reduces the root to the atomic term $0$. Thus $\mathrm{rebuild}(T,\{\phi_1,\phi_2\}) = T'$ with $T'$ the single-leaf tree labelled $0$.

**Key Theorem (Termination under Noetherian Ordering).** Let $>$ be a Noetherian (well-founded) ordering on expression trees such that $r_i < \ell_i$ for every rule $\phi_i \in \Phi$. Then the rebuild operation terminates for all inputs $T$. Moreover, if $\Phi$ is also Church–Rosser (locally confluent), then by Newman's Lemma the normal form $T'$ is unique.

*Proof sketch.* Each application of a rule strictly decreases the tree measure under $>$. Because $>$ is well-founded, no infinite descending chain exists, so the process must halt. Confluence then guarantees that any two terminating reduction sequences reach the same tree. $\square$

**Lab Cell (SymPy).**

```python

x = symbols('x')

E = (x**2 + 2*x + 1) - (x + 1)**2

# Rebuild via symbolic simplification (applies rewrite rules internally)

print("After rebuild :", E_rebuilt)   # 0

# Inspect the internal expression tree depth
from sympy import count_ops

print("Operation count after :", count_ops(E_rebuilt))
```

Running this cell confirms that `simplify` implements a rebuild operation: the tree collapses from a multi-node structure to a single constant, and `count_ops` drops to zero, matching the theoretical result.

### scapegoat_node (19.4s)

## Scapegoat Node

**Definition.** Let $T$ be a binary search tree in which every node $v$ stores a subtree size $\text{size}(v)$, defined as the number of nodes in the subtree rooted at $v$. A node $v$ is called a *scapegoat node* with balance parameter $\alpha \in \bigl(\tfrac{1}{2}, 1\bigr)$ if

$$\text{size}(\text{child}(v)) > \alpha \cdot \text{size}(v),$$

where $\text{child}(v)$ denotes the heavier child of $v$. Equivalently, $v$ is the lowest ancestor of a newly inserted node $u$ for which the subtree rooted at $v$ violates the $\alpha$-weight-balance condition. The scapegoat node is the node held "responsible" for the imbalance; its entire subtree is rebuilt into a perfectly balanced BST, restoring the invariant.

**Worked Example.** Consider an $\alpha = 0.6$ scapegoat tree. Suppose a sequence of insertions has produced the following sizes along the path from the root to a newly inserted leaf $u$:

| Node | $\text{size}(v)$ | $\text{size}(\text{heavy child})$ | Ratio | Violates? |
|------|-----------------|----------------------------------|-------|-----------|
| $r$  | 10              | 5                                | 0.50  | No        |
| $a$  | 7               | 5                                | 0.71  | **Yes**   |
| $b$  | 5               | 3                                | 0.60  | No        |

Walking up from $u$, the first node whose heavy-child ratio exceeds $0.6$ is $a$, with ratio $5/7 \approx 0.71$. Node $a$ is therefore the scapegoat node. Its subtree of size 7 is flattened into a sorted array by an in-order traversal ($\Theta(7)$ time) and then rebuilt as a perfectly balanced BST ($\Theta(7)$ time), after which every node in the rebuilt subtree satisfies the $\alpha$-balance condition.

**Key Theorem (Amortised Cost of Scapegoat Rebuilding).** In a scapegoat tree with parameter $\alpha$, a sequence of $n$ insertions costs $O(n \log n)$ amortised time. Specifically, between any two rebuilds of the same subtree of size $s$, at least $\lfloor (1 - \alpha) s \rfloor$ insertions must occur into that subtree. Assigning each insertion a credit of $\Theta(\log n)$ tokens covers the $\Theta(s)$ rebuild cost, yielding $O(\log n)$ amortised time per operation.

**Lab Cell (SymPy).**

```python
from sympy import symbols, floor, log, simplify

alpha, s = symbols('alpha s', positive=True)

# Minimum insertions before a rebuild of a subtree of size s
min_insertions = floor((1 - alpha) * s)

# Amortised cost per insertion (credit argument)
credit_per_op = s / min_insertions   # simplifies to 1/(1-alpha)
print("Credit ratio:", simplify(credit_per_op))

# Numerical check: alpha=0.6, s=7
print("Min insertions before rebuild:", int((1 - 0.6) * 7))
```

Running this cell confirms that the credit ratio $\tfrac{1}{1-\alpha}$ is a constant independent of $s$, validating the $O(\log n)$ amortised bound for any fixed $\alpha < 1$.

### amortized_analysis (0.0s)

## Amortized Analysis

**Definition.** Amortized analysis is a method for computing the *average cost per operation* in a sequence of operations on a data structure, providing a guarantee over the entire sequence rather than on any single worst-case operation. Formally, given a sequence of $n$ operations $o_1, o_2, \ldots, o_n$ with actual costs $c_1, c_2, \ldots, c_n$, the **amortized cost** $\hat{c}_i$ of operation $o_i$ satisfies

$$\sum_{i=1}^{n} \hat{c}_i \;\geq\; \sum_{i=1}^{n} c_i.$$

The amortized cost may exceed the actual cost for some operations and fall below it for others, provided the cumulative amortized cost never underestimates the cumulative actual cost. Three principal techniques achieve this: aggregate analysis, the accounting method, and the potential method.

**Worked Example: Dynamic Array Doubling.** Consider an array that doubles in capacity whenever it is full. Starting from capacity 1, inserting $n$ elements triggers doublings at sizes $1, 2, 4, \ldots, 2^{\lfloor \log_2 n \rfloor}$. The total copying work across all doublings is

$$1 + 2 + 4 + \cdots + 2^{\lfloor \log_2 n \rfloor} < 2n.$$

Adding the $n$ unit-cost insertions, the total actual cost is less than $3n$. Dividing by $n$ operations gives an amortized cost of $O(1)$ per insertion, even though individual doublings cost $\Theta(n)$.

**Key Theorem (Potential Method).** Define a potential function $\Phi: \text{States} \to \mathbb{R}_{\geq 0}$ with $\Phi(\text{initial state}) = 0$. The amortized cost of operation $i$ is

$$\hat{c}_i = c_i + \Phi(D_i) - \Phi(D_{i-1}),$$

where $D_i$ denotes the data structure state after operation $i$. Summing over all $n$ operations and applying the telescoping property:

$$\sum_{i=1}^{n} \hat{c}_i = \sum_{i=1}^{n} c_i + \Phi(D_n) - \Phi(D_0) \;\geq\; \sum_{i=1}^{n} c_i.$$

For the dynamic array, setting $\Phi(D) = 2 \cdot |\text{elements}| - |\text{capacity}|$ yields $\hat{c}_i \leq 3$ for every insertion, confirming the $O(1)$ amortized bound.

**Lab Cell.**
```python
from sympy import symbols, summation, floor, log, simplify

n = symbols('n', positive=True, integer=True)
k = symbols('k', nonnegative=True, integer=True)

# Total copying cost across all doublings up to n insertions
doubling_cost = summation(2**k, (k, 0, floor(log(n, 2))))
print("Total doubling cost (closed form):", simplify(doubling_cost))
# Verify amortized cost per insertion is O(1)
print("Amortized cost per insertion:", simplify(doubling_cost / n))
```

## Scapegoat Existence Lemma

**Definition.** Let $T$ be a consistent set of first-order sentences over a countable language $\mathcal{L}$. A *scapegoat extension* of $T$ is a pair $(\mathcal{L}^*, T^*)$ where $\mathcal{L}^* = \mathcal{L} \cup C$ for a countable set of fresh constant symbols $C = \{c_0, c_1, c_2, \ldots\}$, and $T^* \supseteq T$ is a set of $\mathcal{L}^*$-sentences satisfying the *witness property*: for every $\mathcal{L}^*$-formula $\varphi(x)$ with exactly one free variable, there exists a constant $c_i \in C$ such that

$$T^* \vdash \bigl(\exists x\,\varphi(x)\bigr) \to \varphi(c_i).$$

The constant $c_i$ is called a *scapegoat* (or Henkin witness) for $\varphi$. Informally, whenever the theory asserts that *some* element satisfies $\varphi$, it is forced to name one.

**Worked Example.** Consider the theory $T$ over the language $\mathcal{L} = \{<, 0\}$ asserting that the universe is a dense linear order without endpoints. The sentence $\exists x\,(0 < x)$ is provable in $T$. The scapegoat construction adds a fresh constant $c_0$ and the axiom $0 < c_0$ to $T^*$, thereby nominating $c_0$ as the explicit witness. Similarly, $\exists x\,(x < c_0)$ later receives its own scapegoat $c_1$ with $c_1 < c_0$, and so on. The resulting chain of witnesses will, after closure under all formulas, provide the skeleton of a countable dense linear order.

**Scapegoat Existence Lemma.** *If $T$ is a consistent $\mathcal{L}$-theory and $\mathcal{L}$ is countable, then $T$ has a scapegoat extension $T^*$ that is still consistent.*

*Proof sketch.* Enumerate all $\mathcal{L}^*$-formulas with one free variable as $\varphi_0(x), \varphi_1(x), \ldots$ Define $T_0 = T$ and, at stage $n$, set

$$T_{n+1} = T_n \cup \bigl\{\exists x\,\varphi_n(x) \to \varphi_n(c_n)\bigr\},$$

where $c_n$ is a constant not appearing in $T_n$. Each $T_{n+1}$ remains consistent: if it were not, then $T_n \vdash \neg(\exists x\,\varphi_n(x) \to \varphi_n(c_n))$, which forces $T_n \vdash \exists x\,\varphi_n(x)$ and $T_n \vdash \neg\varphi_n(c_n)$; but $c_n$ is fresh, so a substitution argument yields $T_n \vdash \neg\varphi_n(x)$ for all $x$, contradicting $T_n \vdash \exists x\,\varphi_n(x)$. The union $T^* = \bigcup_{n} T_n$ is consistent by compactness. $\square$

This lemma is the key step in Henkin's proof of the Completeness Theorem: a maximal consistent extension of $T^*$ can be turned directly into a model whose domain is the set of constant terms.

### credit_scheme (25.4s)

## Credit Scheme

**Definition.** Let $N = \{1, 2, \ldots, n\}$ be a finite set of *players* and let $v : 2^N \to \mathbb{R}$ be a *characteristic function* satisfying $v(\emptyset) = 0$. The pair $(N, v)$ is called a *cooperative game*. A **credit scheme** (also called a *solution concept* or *value function*) is a map $\varphi : (N, v) \mapsto \mathbb{R}^n$ that assigns to each player $i$ a real number $\varphi_i(N, v)$ representing their allocated share of the total generated value $v(N)$. A credit scheme is said to be *efficient* if $\sum_{i \in N} \varphi_i = v(N)$, ensuring no value is created or destroyed by the allocation process.

The most celebrated credit scheme is the **Shapley value**, defined by

$$\varphi_i^{\mathrm{Sh}}(N,v) = \sum_{S \subseteq N \setminus \{i\}} \frac{|S|!\,(n - |S| - 1)!}{n!}\bigl[v(S \cup \{i\}) - v(S)\bigr].$$

The term $v(S \cup \{i\}) - v(S)$ is player $i$'s *marginal contribution* when joining coalition $S$. The coefficient weights each coalition by the probability that $i$ arrives at position $|S|+1$ in a uniformly random ordering of $N$.

**Worked Example.** Consider $N = \{A, B, C\}$ with $v(\{A\})=0$, $v(\{B\})=0$, $v(\{C\})=0$, $v(\{A,B\})=6$, $v(\{A,C\})=4$, $v(\{B,C\})=4$, $v(N)=10$. For player $A$, summing over all six orderings of $N$ and recording $A$'s marginal contribution in each yields $\varphi_A^{\mathrm{Sh}} = \frac{1}{6}(0+6+0+6+4+4) = \frac{10}{3}$. Analogous calculations give $\varphi_B^{\mathrm{Sh}} = \frac{10}{3}$ and $\varphi_C^{\mathrm{Sh}} = \frac{10}{3}$, confirming efficiency: $\frac{10}{3} \times 3 = 10 = v(N)$.

**Theorem (Shapley 1953).** There exists a *unique* credit scheme satisfying efficiency, symmetry, the dummy-player axiom, and additivity. That scheme is the Shapley value $\varphi^{\mathrm{Sh}}$.

*Proof sketch.* Linearity and the dummy-player axiom force $\varphi$ on any game to coincide with its value on a spanning basis of unanimity games $u_T$, defined by $u_T(S)=1$ iff $T \subseteq S$. Symmetry pins the coefficient for each $T$, yielding the Shapley formula uniquely.

```python
# Lab cell — Shapley value via SymPy
from itertools import permutations
from fractions import Fraction

N = ['A', 'B', 'C']
v = {frozenset(): 0, frozenset(['A']): 0, frozenset(['B']): 0,
     frozenset(['C']): 0, frozenset(['A','B']): 6,
     frozenset(['A','C']): 4, frozenset(['B','C']): 4,
     frozenset(['A','B','C']): 10}

def shapley(player, N, v):
    total, n = Fraction(0), len(N)
    for perm in permutations(N):
        idx = perm.index(player)
        S_before = frozenset(perm[:idx])
        total += v[S_before | {player}] - v[S_before]
    return total / len(list(permutations(N)))

for p in N:
    print(f"phi_{p} = {shapley(p, N, v)}")
```

## Scapegoat Add

**Definition.** A *scapegoat tree* is a binary search tree (BST) that maintains approximate balance by selectively rebuilding subtrees upon insertion. Unlike AVL or red–black trees, it requires no per-node balance metadata; instead, it uses a global weight parameter $\alpha \in \bigl(\tfrac{1}{2}, 1\bigr)$ to define the *$\alpha$-weight-balance* property. A node $v$ with subtree size $\mathrm{size}(v)$ is called **$\alpha$-balanced** if

$$\mathrm{size}(\mathrm{left}(v)) \leq \alpha \cdot \mathrm{size}(v) \quad \text{and} \quad \mathrm{size}(\mathrm{right}(v)) \leq \alpha \cdot \mathrm{size}(v).$$

The **scapegoat add** operation inserts a key $k$ into the tree via standard BST insertion, then walks back up the insertion path to find the highest ancestor that violates $\alpha$-weight-balance. That ancestor is the *scapegoat node*; its entire subtree is flattened into a sorted array and rebuilt as a perfectly balanced BST in $O(m)$ time, where $m$ is the size of the scapegoat's subtree.

**Worked Example.** Let $\alpha = 0.6$ and suppose the tree contains keys $\{10, 20, 30, 40, 50\}$ arranged so that the root (key $30$) has a left subtree of size $1$ and a right subtree of size $3$. Before inserting $k = 45$:

$$\mathrm{size}(\mathrm{right}(\text{root})) = 3, \quad \mathrm{size}(\text{root}) = 5.$$

After inserting $45$ into the right subtree, the right child grows to size $4$, giving $\mathrm{size}(\mathrm{right}(\text{root})) / \mathrm{size}(\text{root}) = 4/6 \approx 0.667 > 0.6$. The root is identified as the scapegoat. The subtree $\{10, 20, 30, 40, 45, 50\}$ is collected in order and rebuilt with $40$ as the new root, restoring $\alpha$-balance.

**Key Theorem (Amortized Cost).** For a scapegoat tree with parameter $\alpha$, a sequence of $n$ insertions has a total cost of $O(n \log n)$, giving an **amortized cost of $O(\log n)$ per insertion**. The proof uses a potential function $\Phi = c \sum_{v} |\mathrm{size}(\mathrm{left}(v)) - \mathrm{size}(\mathrm{right}(v))|$; each rebuild reduces $\Phi$ enough to pay for the $O(m)$ reconstruction work.

## Scapegoat Remove

**Definition.** A *scapegoat tree* is a binary search tree parameterised by a balance factor $\alpha \in \bigl(\tfrac{1}{2}, 1\bigr)$. A node $v$ is *$\alpha$-weight-balanced* if

$$\max\!\bigl(\lvert T_L\rvert,\, \lvert T_R\rvert\bigr) \;\leq\; \alpha \cdot \lvert T_v \rvert,$$

where $\lvert T_v \rvert$ denotes the size of the subtree rooted at $v$. The **scapegoat-remove** operation deletes a key from such a tree in two stages. First, the key is located and spliced out with the standard BST deletion rule (replacing an internal node with its in-order successor if it has two children). Second, if the resulting tree has become too sparse—formally, if the total node count $n$ falls below $\alpha \cdot q$, where $q$ is the maximum size ever reached since the last full rebuild—the entire tree is flattened into a sorted array and rebuilt into a perfectly balanced BST in $O(n)$ time.

**Worked Example.** Let $\alpha = 0.75$ and consider the following tree with $n = 7$ nodes and high-water mark $q = 10$. Because $n = 7 > \alpha q = 7.5$ is not satisfied ($7 < 7.5$), the sparsity condition is triggered. We first delete key $k = 15$ with a standard splice. After deletion $n$ becomes $6$. Since $6 < 0.75 \times 10 = 7.5$, the tree is rebuilt: an in-order traversal produces the sorted array $[5, 10, 20, 25, 30, 40]$, and the recursive median-selection procedure constructs a new root at $20$, left subtree root at $10$, right subtree root at $30$, and so on, yielding a perfectly balanced tree of height $\lceil \log_2 7 \rceil = 3$.

**Key Theorem (Amortised Cost).** Over any sequence of $m$ insertions and deletions on a scapegoat tree, the amortised cost per operation is $O(\log n)$.

*Proof sketch.* Assign each node a credit proportional to the imbalance it accumulates. Any rebuild of a subtree of size $s$ costs $O(s)$ but clears $\Omega(s)$ accumulated credits, so the amortised charge per operation remains $O(\log n)$. The sparsity threshold $\alpha q$ ensures that at least a constant fraction of nodes must have been deleted before a global rebuild is triggered, bounding the total rebuild work. $\square$

```python
def rebuild_cost(n: int, alpha: float = 0.75) -> dict:
    """Return height and rebuild threshold for a scapegoat tree of size n."""
    h = int(floor(log(Integer(n), Integer(1) / alpha)))
    threshold = alpha * n          # rebuild when current size drops below this
    return {"height_bound": h, "rebuild_threshold": float(threshold)}
```

## Scapegoat Tree Performance

A **scapegoat tree** is a self-balancing binary search tree that achieves balance lazily: rather than rebalancing after every operation, it tolerates a degree of imbalance and rebuilds an entire subtree only when a node violates a balance condition. The key parameter is $\alpha \in \left(\tfrac{1}{2}, 1\right)$, which controls how much imbalance is permitted before a rebuild is triggered.

**Definition.** A node $v$ in a binary search tree is called an *$\alpha$-weight-balanced* node if

$$\max\!\bigl(\text{size}(v.\text{left}),\, \text{size}(v.\text{right})\bigr) \leq \alpha \cdot \text{size}(v),$$

where $\text{size}(v)$ denotes the number of nodes in the subtree rooted at $v$. A tree is $\alpha$-weight-balanced if every node satisfies this condition. When an insertion causes some ancestor to violate the condition, that ancestor is the *scapegoat*; its entire subtree is flattened to a sorted array and rebuilt as a perfectly balanced BST in $O(\text{size})$ time.

**Worked Example.** Suppose $\alpha = 0.7$ and we insert into a subtree of size 10 whose left child has size 7 and right child has size 2. Check: $\max(7, 2) = 7 \leq 0.7 \times 10 = 7$. The node is exactly at the boundary — still valid. Now suppose left grows to 8 after the next insert: $8 > 0.7 \times 11 = 7.7$, so this node becomes the scapegoat and its 11-node subtree is rebuilt in $O(11)$ time into a perfectly balanced tree of height $\lfloor \log_2 11 \rfloor = 3$.

**Key Theorem.** For any fixed $\alpha \in \left(\tfrac{1}{2}, 1\right)$, the scapegoat tree guarantees:

- **Search and deletion:** $O(\log n)$ worst-case time, since the $\alpha$-balance condition bounds tree height by $\log_{1/\alpha} n$.
- **Insertion:** $O(\log n)$ *amortized* time. Although a single insertion may cost $O(n)$ due to a rebuild, a potential-function argument shows that every node can only be rebuilt after at least $\Omega(\text{size})$ insertions into its subtree, distributing the cost evenly.

Formally, defining the potential $\Phi = c \sum_{v} \bigl|\text{size}(v.\text{left}) - \text{size}(v.\text{right})\bigr|$ yields an amortized cost of $O(\log n)$ per insertion.
