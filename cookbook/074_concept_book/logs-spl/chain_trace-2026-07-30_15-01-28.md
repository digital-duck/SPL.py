### big_data (0.0s)

## Big Data

**Definition.** A dataset is said to exhibit *big data* characteristics when its volume, velocity, or variety (the "three Vs") exceed the processing capacity of conventional single-machine systems. More precisely, let $N$ denote the number of records, $d$ the number of features per record, and $\tau$ the arrival rate (records per second). A dataset is operationally classified as big data when any one of the following conditions holds:

$$N \cdot d > M_{\text{RAM}}, \qquad \tau > \lambda_{\text{disk}}, \qquad \text{or} \quad \dim(\mathcal{S}) \text{ is heterogeneous},$$

where $M_{\text{RAM}}$ is available memory, $\lambda_{\text{disk}}$ is sustainable write throughput, and $\mathcal{S}$ is the schema space. The hallmark challenge is that standard $O(N)$ or $O(N \log N)$ algorithms become infeasible when $N \sim 10^9$ or larger, forcing a shift to distributed or streaming paradigms.

**Worked Example.** Suppose a retailer logs $N = 10^9$ transactions, each described by $d = 50$ floating-point features stored as 64-bit doubles. The raw storage requirement is

$$S = N \cdot d \cdot 8 \text{ bytes} = 10^9 \times 50 \times 8 = 4 \times 10^{11} \text{ bytes} = 400 \text{ GB}.$$

A workstation with 32 GB of RAM cannot load this dataset into memory; a naive pandas `read_csv` call would raise a `MemoryError`. The solution is to partition the data into $k$ shards of size $\lceil N/k \rceil$ each, process each shard independently, and aggregate partial statistics. For the sample mean $\bar{x}$, the aggregation is exact:

$$\bar{x} = \frac{1}{N} \sum_{i=1}^{k} n_i \bar{x}_i, \qquad n_i = \left\lceil \frac{N}{k} \right\rceil.$$

**Key Theorem (Embarrassingly Parallel Reduction).** Let $f: \mathbb{R}^d \to \mathbb{R}$ be a *decomposable* statistic, meaning $f(\mathcal{D}) = g\!\left(f(\mathcal{D}_1), \ldots, f(\mathcal{D}_k)\right)$ for some aggregator $g$. Then the total computation time satisfies $T_k = T_1 / k + T_{\text{comm}}$, where $T_{\text{comm}}$ is network overhead. When $T_{\text{comm}} \ll T_1$, near-linear speedup is achieved. Sum, count, min, max, and histogram bin counts are all decomposable; median and exact quantiles are not.

**Lab Cell.**

```python
import sympy as sp

N, k, n_i = sp.symbols('N k n_i', positive=True)
x_bar_i   = sp.Symbol(r'\bar{x}_i')

# Symbolic mean aggregation formula
x_bar_global = sp.Rational(1, 1) * sp.Sum(n_i * x_bar_i, (sp.Symbol('i'), 1, k)) / N
sp.pprint(sp.Eq(sp.Symbol(r'\bar{x}'), x_bar_global))

# Concrete shard size example
shard_size = sp.ceiling(sp.Integer(10**9) / 32)
print(f"Records per shard (32 shards): {shard_size}")
```

### regular_expressions (0.0s)

## Regular Expressions

**Definition.** A *regular expression* (regex) over a finite alphabet $\Sigma$ is a symbolic pattern that denotes a *regular language* — a set of strings. Formally, regular expressions are defined inductively:

1. $\emptyset$ denotes the empty language; $\varepsilon$ denotes $\{\varepsilon\}$ (the language containing only the empty string).
2. For any symbol $a \in \Sigma$, the expression $a$ denotes $\{a\}$.
3. If $r$ and $s$ are regular expressions denoting languages $L(r)$ and $L(s)$, then:
   - *Alternation* $r \mid s$ denotes $L(r) \cup L(s)$,
   - *Concatenation* $rs$ denotes $\{xy \mid x \in L(r),\, y \in L(s)\}$,
   - *Kleene star* $r^*$ denotes $\bigcup_{n=0}^{\infty} L(r)^n$, i.e., zero or more repetitions of strings in $L(r)$.

No other expressions are regular. This recursive definition ensures that every regular expression corresponds to a language recognizable by a *finite automaton*.

**Worked Example.** Let $\Sigma = \{0, 1\}$. Consider the regular expression $r = (0 \mid 1)^* 1 (0 \mid 1)^*$. The language $L(r)$ is the set of all binary strings containing at least one $1$. To verify: any string $w \in L(r)$ can be decomposed as $w = u\,1\,v$ where $u, v \in \{0,1\}^*$; conversely, every binary string with at least one $1$ admits such a decomposition. The complement $\overline{L(r)}$ is $\{0^n \mid n \geq 0\}$, described by $0^*$.

**Key Theorem (Kleene's Theorem).** A language $L \subseteq \Sigma^*$ is regular if and only if it is recognized by a deterministic finite automaton (DFA). Consequently, the class of regular languages is closed under union, concatenation, complementation, and Kleene star. The proof proceeds in two directions: given a regex, construct an $\varepsilon$-NFA by structural induction (Thompson's construction), then convert to a DFA via the subset construction; given a DFA, derive a regex by state elimination.

**Lab Cell.**

```python
import re

pattern = re.compile(r'^(0|1)*1(0|1)*$')   # binary strings containing a 1

test_strings = ["0", "00", "1", "101", "010", "000"]
for s in test_strings:
    matched = bool(pattern.match(s))
    print(f"  {s!r:>6}  →  {'accepted' if matched else 'rejected'}")
```

Running this cell prints `rejected` for `"0"` and `"00"` and `accepted` for every string containing at least one `1`, confirming the semantic claim above.

### string_manipulation (0.0s)

## String Manipulation

**Definition.** A *string* over an alphabet $\Sigma$ is a finite sequence of symbols drawn from $\Sigma$. Formally, a string $s$ of length $n$ is a function $s : \{0, 1, \ldots, n-1\} \to \Sigma$, and we write $|s| = n$. The set of all finite strings over $\Sigma$, including the empty string $\varepsilon$, is denoted $\Sigma^*$. String manipulation encompasses any operation that transforms one or more elements of $\Sigma^*$ into another: concatenation, slicing, substitution, splitting, and pattern matching, among others.

The fundamental binary operation is *concatenation*. Given strings $s, t \in \Sigma^*$, their concatenation $s \cdot t$ (often written $st$) is the string of length $|s| + |t|$ obtained by appending $t$ to $s$. Concatenation is associative, $(r \cdot s) \cdot t = r \cdot (s \cdot t)$, and $\varepsilon$ serves as the identity element, making $(\Sigma^*, \cdot, \varepsilon)$ a *monoid*.

**Worked Example.** Let $\Sigma = \{a, b, \ldots, z\}$ and consider $s = \texttt{"linear"}$, $t = \texttt{"algebra"}$. Concatenation gives $st = \texttt{"linearalgebra"}$ with $|st| = 13 = 6 + 7$. The *reverse* of $s$, denoted $s^R$, is $\texttt{"raeniL"}$ (case-insensitive here). A string satisfying $s = s^R$ is called a *palindrome*; the string $\texttt{"racecar"}$ is a canonical example. Slicing extracts a *substring*: in zero-based indexing, $s[2:5] = \texttt{"nea"}$, corresponding to characters at positions $2, 3, 4$.

**Key Theorem (String Equality via Hashing).** The Rabin–Karp rolling-hash scheme assigns to each string $s = s_0 s_1 \cdots s_{n-1}$ the hash value
$$H(s) = \sum_{i=0}^{n-1} s_i \, p^{\,i} \pmod{q},$$
where $p$ is a prime base and $q$ a large prime modulus. With high probability, $H(s) = H(t)$ if and only if $s = t$, enabling substring search in expected $O(n + m)$ time for a text of length $n$ and a pattern of length $m$.

**Lab Cell.**

```python
from sympy import symbols, Function

text    = "the cat sat on the mat"
pattern = "at"

# find all starting indices of pattern in text
indices = [i for i in range(len(text)) if text[i:i+len(pattern)] == pattern]
print("Occurrences of", repr(pattern), "at indices:", indices)

# demonstrate rolling hash concept
p, q = 31, 10**9 + 9
def rhash(s):
    return sum(ord(c) * p**i for i, c in enumerate(s)) % q

print("Hash match:", rhash("at") == rhash("at"), "| Collision test:", rhash("at") == rhash("ta"))
```

### parsing_and_extraction (0.0s)

## Parsing And Extraction

**Definition.** *Parsing* is the process of analysing a sequence of symbols according to a formal grammar and constructing a structured representation — typically a tree — that encodes the syntactic relationships among those symbols. *Extraction* is the subsequent operation of selecting and returning specific sub-structures or values from that tree. Formally, let $\Sigma$ be an alphabet and $G = (V, \Sigma, R, S)$ a context-free grammar with variables $V$, production rules $R$, and start symbol $S$. A *parse tree* for a string $w \in \Sigma^*$ is a rooted ordered tree $T$ in which each internal node is labelled by a variable, each leaf is labelled by a terminal symbol, and the children of every internal node correspond to the right-hand side of some rule $r \in R$ applied at that node. Extraction then defines a function $\phi : T \to D$ mapping selected nodes or paths in $T$ to a target domain $D$.

**Worked Example.** Consider the arithmetic expression $e = \texttt{"3 + 4 * 2"}$ and the grammar

$$S \to S + T \mid T, \quad T \to T * F \mid F, \quad F \to \textbf{num}$$

A recursive-descent parser builds the tree $S(S(T(F(3))),\,+,\,T(T(F(4)),\,*,\,F(2)))$. Operator precedence is encoded structurally: the multiplication node sits deeper in the tree than the addition node, so any left-to-right evaluator naturally computes $4 \times 2$ before adding $3$. Extraction of the root operator yields $+$; extraction of the right sub-tree's operator yields $*$.

**Key Theorem (Unambiguity and Unique Extraction).** If grammar $G$ is *unambiguous* — meaning every $w \in L(G)$ has exactly one parse tree — then for any extraction function $\phi$ defined on tree structure, the value $\phi(T)$ is uniquely determined by $w$. Ambiguous grammars violate this guarantee: a string may admit two trees differing in operator precedence, so extraction becomes ill-defined without an explicit disambiguation rule.

**Lab Cell.**

```python
from sympy.parsing.sympy_parser import parse_expr
from sympy import symbols

x, y = symbols('x y')

expr_str = "3 + 4 * x**2 - y"
expr = parse_expr(expr_str)

print("Parsed expression :", expr)
print("Free symbols      :", expr.free_symbols)
print("Degree in x       :", expr.as_poly(x).degree())
```

Running this cell demonstrates that SymPy's parser applies standard precedence rules, constructing an unambiguous internal tree from which `.free_symbols` and `.degree()` perform targeted extraction without re-parsing the string.

### data_processing (0.0s)

## Data Processing

**Definition.** *Data processing* is the systematic transformation of raw observations into a structured, analytically tractable form. Formally, let $\mathcal{D} = \{x_i\}_{i=1}^{n}$ be a finite sample drawn from a population with distribution $P$. A processing pipeline is a composition of functions

$$
\phi = \phi_k \circ \phi_{k-1} \circ \cdots \circ \phi_1 : \mathcal{X}_{\text{raw}} \longrightarrow \mathcal{X}_{\text{clean}},
$$

where each $\phi_j$ addresses a specific data quality concern: missing-value imputation, outlier removal, type coercion, or feature scaling. The goal is to produce a representation $\tilde{\mathcal{D}} = \phi(\mathcal{D})$ on which subsequent statistical or machine-learning methods yield valid and reproducible results.

**Worked Example.** Consider the sample $\mathcal{D} = \{2,\, 7,\, \text{NaN},\, 105,\, 4\}$ representing daily energy consumption (kWh). Three transformations are applied in sequence.

1. **Imputation ($\phi_1$):** Replace the missing value with the sample median. The sorted non-missing values are $\{2, 4, 7, 105\}$, giving median $\tilde{m} = (4+7)/2 = 5.5$. The result is $\mathcal{D}^{(1)} = \{2, 7, 5.5, 105, 4\}$.

2. **Outlier removal ($\phi_2$):** Retain only observations within $\mu \pm 3\sigma$. Here $\mu = 24.7$ and $\sigma \approx 41.8$, so the interval is $(-100.7,\; 150.1)$. All values pass, but in practice the value $105$ warrants domain scrutiny.

3. **Min–max scaling ($\phi_3$):** Map each observation to $[0,1]$ via
$$
x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}.
$$
With $x_{\min} = 2$ and $x_{\max} = 105$ the observation $7$ maps to $x' = 5/103 \approx 0.049$.

**Key Theorem (Consistency of Sample Statistics Under Imputation).** Let $\hat{\mu}_n$ denote the sample mean computed after mean imputation of $m$ missing values among $n$ total slots. Then $\hat{\mu}_n$ is identical to the complete-case mean $\bar{x}_{n-m}$, but its variance is underestimated by a factor of $(n-m)/n$. Consequently, imputation inflates the apparent precision of the estimate; variance-corrected inference requires multiple imputation or likelihood-based methods.

**Lab Cell.**

```python
import sympy as sp
import statistics

data_raw = [2, 7, None, 105, 4]

# Impute with median of non-missing values
non_missing = [x for x in data_raw if x is not None]
med = statistics.median(non_missing)
data_imputed = [x if x is not None else med for x in data_raw]

# Min-max scaling
x_min, x_max = sp.Rational(min(data_imputed)), sp.Rational(max(data_imputed))
data_scaled = [sp.Rational(x) - x_min) / (x_max - x_min) for x in data_imputed]

print("Imputed:", data_imputed)
print("Scaled: ", [float(v) for v in data_scaled])
```

Running this cell confirms $\phi_3(\phi_1(\mathcal{D})) = [0,\; 0.049,\; 0.034,\; 1.0,\; 0.019]$, providing a clean, bounded representation ready for downstream analysis.

## Data Storage

**Definition.** *Data storage* refers to the systematic encoding of information as discrete, retrievable symbols in a physical or virtual medium. Formally, let $\Sigma$ be a finite alphabet (e.g., $\Sigma = \{0, 1\}$ for binary storage). A *storage system* is a triple $\mathcal{S} = (M, \text{enc}, \text{dec})$, where $M$ is a set of memory states, $\text{enc}: \mathcal{D} \to M$ maps data objects to memory states, and $\text{dec}: M \to \mathcal{D}$ is the retrieval map satisfying $\text{dec}(\text{enc}(d)) = d$ for all $d \in \mathcal{D}$. The *capacity* of the system is $C = \log_2 |M|$ bits. A storage unit capable of holding $n$ independent binary digits therefore has capacity $C = n$ bits.

**Worked Example.** Suppose we wish to store the integer $42$ in an 8-bit unsigned register. We apply the binary encoding: $42 = 32 + 8 + 2 = 2^5 + 2^3 + 2^1$, yielding the bit string $\mathbf{b} = 00101010$. Each bit $b_k \in \{0,1\}$ occupies one storage cell, and the original value is recovered via $\text{dec}(\mathbf{b}) = \sum_{k=0}^{7} b_k \cdot 2^k = 0 + 0 + 2 + 0 + 8 + 0 + 32 + 0 = 42$. The 8-bit register has capacity $C = 8$ bits and can represent any integer in $[0, 255]$.

**Key Theorem (Shannon's Source Coding Theorem).** Let $X$ be a discrete random variable over alphabet $\mathcal{D}$ with probability mass function $p$. The minimum expected number of bits required to encode a symbol from $X$ without loss of information satisfies
$$\bar{\ell} \geq H(X) = -\sum_{d \in \mathcal{D}} p(d)\log_2 p(d),$$
where $H(X)$ is the *Shannon entropy* of $X$. Moreover, there exists an encoding (e.g., Huffman coding) achieving $\bar{\ell} < H(X) + 1$. This theorem establishes entropy as the fundamental lower bound on storage efficiency: no lossless scheme can compress below $H(X)$ bits per symbol on average.

**Lab Cell.**
```python
from sympy import *
from sympy.utilities.iterables import multiset

data = [0, 1, 1, 0, 1, 0, 0, 1, 1, 1]          # sample bit stream
freq = {s: data.count(s)/len(data) for s in set(data)}
H = -sum(p * log(p, 2) for p in freq.values())
print(f"Entropy H(X) = {float(H):.4f} bits/symbol")
print(f"42 in binary: {bin(42)}")
print(f"Decoded:      {int('00101010', 2)}")
```

### cloud_computing (0.0s)

## Cloud Computing

**Definition.** Cloud computing is the on-demand delivery of computing resources—processors, memory, storage, and software—over a network, typically the public internet, with usage billed in proportion to consumption. Rather than owning physical hardware, a consumer rents capacity from a provider who operates large-scale data centers. The three canonical service models are *Infrastructure as a Service* (IaaS), which exposes raw virtual machines; *Platform as a Service* (PaaS), which abstracts the operating system and runtime; and *Software as a Service* (SaaS), which delivers fully managed applications. Resource allocation is governed by an *elasticity* principle: capacity scales up or down automatically in response to workload, subject to provider limits and a cost function.

Formally, let $D(t)$ denote the computational demand at time $t$ (measured in CPU-core-seconds per unit time) and let $C(n)$ denote the hourly cost of provisioning $n$ virtual cores. For a provider offering linear pricing, $C(n) = c \cdot n$ for some rate constant $c > 0$. The total cost over an interval $[0, T]$ is

$$
\text{Cost} = c \int_{0}^{T} n(t)\, dt,
$$

where $n(t) = \lceil D(t) \rceil$ is the number of cores allocated at each instant, assuming the scheduler rounds demand up to the nearest integer.

**Worked example.** Suppose demand follows a sinusoidal pattern: $D(t) = 50 + 30\sin\!\bigl(\tfrac{2\pi t}{24}\bigr)$ cores over a 24-hour period, with $c = \$0.05$ per core-hour. The average demand is $\bar{D} = 50$ cores, so the expected daily cost is approximately $c \cdot \bar{D} \cdot T = 0.05 \times 50 \times 24 = \$60$. A fixed on-premises deployment sized for peak demand ($80$ cores) would cost $0.05 \times 80 \times 24 = \$96$, a 37.5 % premium.

**Key theorem (Cost–Elasticity Trade-off).** For any non-constant demand signal $D(t) \geq 0$ and linear pricing $C(n) = cn$, elastic provisioning satisfies

$$
\int_{0}^{T} C\!\bigl(\lceil D(t) \rceil\bigr)\, dt \;\leq\; C\!\bigl(\max_{t} D(t)\bigr) \cdot T,
$$

with equality only when $D(t)$ is constant. Elastic clouds therefore weakly dominate static provisioning in cost.

**Lab cell.**

```python
import sympy as sp

t, T, c = sp.symbols('t T c', positive=True)
D = 50 + 30 * sp.sin(2 * sp.pi * t / 24)

# Average demand over one day
avg_demand = sp.integrate(D, (t, 0, 24)) / 24
elastic_cost = c * avg_demand * 24
static_cost  = c * 80 * 24          # peak-sized fixed deployment

print("Elastic cost :", sp.simplify(elastic_cost))
print("Static cost  :", static_cost)
print("Savings ratio:", sp.simplify(1 - elastic_cost / static_cost))
```

Running this cell confirms the 37.5 % savings derived analytically and demonstrates how symbolic integration makes cost-model reasoning tractable before any real workload data is collected.

### data_chunking (0.0s)

## Data Chunking

**Definition.** Given a sequence of $n$ data elements $S = (s_1, s_2, \ldots, s_n)$ and a chunk size $k \in \mathbb{Z}^+$, *data chunking* is the partition of $S$ into $\lceil n/k \rceil$ contiguous subsequences (chunks) $C_1, C_2, \ldots, C_{\lceil n/k \rceil}$, where

$$C_i = \bigl(s_{(i-1)k+1},\, s_{(i-1)k+2},\, \ldots,\, s_{\min(ik,\, n)}\bigr), \quad i = 1, 2, \ldots, \lceil n/k \rceil.$$

The chunks are pairwise disjoint and their union recovers $S$ exactly:

$$\bigsqcup_{i=1}^{\lceil n/k \rceil} C_i = S.$$

Chunking transforms an arbitrarily large, monolithic sequence into bounded units amenable to parallel processing, memory-constrained computation, or windowed analysis.

**Worked Example.** Let $S = (2, 5, 1, 8, 4, 7, 3, 6)$ with $n = 8$ and chunk size $k = 3$. Then $\lceil 8/3 \rceil = 3$ chunks are formed:

$$C_1 = (2, 5, 1), \quad C_2 = (8, 4, 7), \quad C_3 = (3, 6).$$

Note that $|C_3| = 2 < k$; the final chunk holds the remainder $n \bmod k = 2$ elements. The per-chunk sum vector is $(8, 19, 9)$, and the global sum $\sum_{s \in S} s = 36$ equals $8 + 19 + 9$, illustrating that additive aggregates distribute perfectly across chunks.

**Key Theorem (Additivity of Chunk Aggregates).** Let $f : 2^S \to \mathbb{R}$ be a function expressible as a commutative, associative binary operation $\oplus$ applied to element-wise values $\phi(s)$. Then

$$f(S) = \bigoplus_{i=1}^{\lceil n/k \rceil} f(C_i).$$

*Proof sketch.* By associativity and commutativity of $\oplus$, the order of application is immaterial. Partitioning $S$ into chunks and reducing each chunk independently before combining yields the same element-wise accumulation as processing $S$ in a single pass. $\square$

This theorem underpins map-reduce architectures: functions such as sum, product, maximum, and count all satisfy the additivity condition.

**Lab Cell.**

```python
from sympy import symbols, summation, floor, ceiling

# Symbolic chunk count
n, k = symbols('n k', positive=True, integer=True)

# Number of chunks
num_chunks = ceiling(n / k)

# Verify for n=8, k=3
print(num_chunks.subs({n: 8, k: 3}))   # → 3

# Concrete chunking utility
def chunk(seq, k):
    return [seq[i*k:(i+1)*k] for i in range(-(-len(seq) // k))]

S = [2, 5, 1, 8, 4, 7, 3, 6]
chunks = chunk(S, 3)
print(chunks)            # [[2,5,1],[8,4,7],[3,6]]
print(sum(sum(c) for c in chunks) == sum(S))  # True
```

### data_compression (0.0s)

## Data Compression

**Definition.** Given a source alphabet $\mathcal{X}$ with probability distribution $P$, *data compression* is the process of mapping sequences of source symbols to shorter binary codewords, thereby reducing the average number of bits required for storage or transmission. A *lossless* compression scheme is a bijective mapping $C : \mathcal{X}^* \to \{0,1\}^*$ such that the original sequence can be recovered exactly from its encoding. The fundamental quantity governing how far compression can proceed is the *Shannon entropy*:

$$H(X) = -\sum_{x \in \mathcal{X}} P(x) \log_2 P(x) \quad \text{(bits per symbol)}.$$

Entropy measures the irreducible average information content of the source; no lossless code can achieve an average codeword length below $H(X)$.

**Worked Example.** Suppose a source emits four symbols with probabilities $P(a)=\tfrac{1}{2}$, $P(b)=\tfrac{1}{4}$, $P(c)=\tfrac{1}{8}$, $P(d)=\tfrac{1}{8}$. The entropy is:

$$H(X) = -\tfrac{1}{2}\log_2\tfrac{1}{2} - \tfrac{1}{4}\log_2\tfrac{1}{4} - 2\cdot\tfrac{1}{8}\log_2\tfrac{1}{8} = \tfrac{1}{2}+\tfrac{2}{4}+\tfrac{3}{8}+\tfrac{3}{8} = 1.75 \text{ bits}.$$

A Huffman code assigns $a \mapsto 0$, $b \mapsto 10$, $c \mapsto 110$, $d \mapsto 111$, yielding average length $\bar{L} = \tfrac{1}{2}(1)+\tfrac{1}{4}(2)+\tfrac{1}{8}(3)+\tfrac{1}{8}(3) = 1.75$ bits — achieving the entropy bound exactly because all probabilities are negative powers of two.

**Key Theorem (Shannon's Source Coding Theorem).** For a discrete memoryless source with entropy $H(X)$, there exists a uniquely decodable code with average codeword length $\bar{L}$ satisfying:

$$H(X) \leq \bar{L} < H(X) + 1.$$

Moreover, no uniquely decodable code can achieve $\bar{L} < H(X)$. The upper bound is always achieved by Huffman coding, making it optimal among symbol-by-symbol schemes.

**Lab Cell.**

```python
from sympy import Rational, log, N

probs = [Rational(1,2), Rational(1,4), Rational(1,8), Rational(1,8)]
H = -sum(p * log(p, 2) for p in probs)

lengths = [1, 2, 3, 3]
L_bar = sum(p * l for p, l in zip(probs, lengths))

print("Entropy H(X) =", N(H, 4), "bits")
print("Average codeword length =", N(L_bar, 4), "bits")
print("Bound satisfied:", H <= L_bar < H + 1)
```

Running this cell confirms $H(X) = \bar{L} = 1.75$ bits and that the Huffman code achieves the lower bound of Shannon's theorem.

### data_indexing (0.0s)

## Data Indexing

**Definition.** Given a finite sequence $A = (a_0, a_1, \ldots, a_{n-1})$ of $n$ elements drawn from a set $S$, a *data index* is a mapping $\iota : \{0, 1, \ldots, n-1\} \to S$ defined by $\iota(k) = a_k$. More generally, for a multi-dimensional array $A \in S^{d_1 \times d_2 \times \cdots \times d_m}$, the index is a tuple $(i_1, i_2, \ldots, i_m)$ satisfying $0 \le i_j < d_j$ for each $j$, and the element retrieved is $A[i_1, i_2, \ldots, i_m]$. Zero-based indexing — where the first element occupies position $0$ — is the convention adopted in most modern computing systems and throughout this text.

**Worked Example.** Let $A = (7, 3, 11, 5, 9)$, so $n = 5$. The valid indices are $\{0, 1, 2, 3, 4\}$. We have $\iota(0) = 7$, $\iota(2) = 11$, and $\iota(4) = 9$. For a negative offset $k = -1$, many languages define a *wrap-around* index equivalent to $k \bmod n$, giving $\iota((-1) \bmod 5) = \iota(4) = 9$. For a two-dimensional matrix

$$M = \begin{pmatrix} 1 & 2 & 3 \\ 4 & 5 & 6 \end{pmatrix} \in \mathbb{Z}^{2 \times 3},$$

the element at row $1$, column $2$ is $M[1,2] = 6$, corresponding to the linear offset $1 \cdot 3 + 2 = 5$ in row-major (C-order) storage.

**Key Theorem (Random-Access Cost).** For an array stored in contiguous memory with element size $w$ bytes and base address $\alpha$, the address of $A[i_1, i_2, \ldots, i_m]$ under row-major layout is

$$\text{addr} = \alpha + w \sum_{j=1}^{m} i_j \prod_{k=j+1}^{m} d_k.$$

Each address computation requires $O(m)$ arithmetic operations and $O(1)$ memory accesses, so element retrieval runs in constant time $O(1)$ regardless of $n$, the central performance guarantee of array structures.

**Lab Cell.**

```python
import sympy as sp

# Symbolic index address formula
alpha, w = sp.symbols('alpha w', positive=True)
i1, i2, d2 = sp.symbols('i1 i2 d2', nonneg=True)

addr = alpha + w * (i1 * d2 + i2)
print("Address formula:", addr)

# Concrete evaluation: 3-column matrix, element M[1,2]
print("M[1,2] offset:", addr.subs({alpha: 0, w: 4, i1: 1, i2: 2, d2: 3}))
```

Running this cell confirms that $M[1,2]$ lies at byte offset $20$ when each integer occupies $4$ bytes, matching the theoretical formula.

## Dbms

A **Database Management System (DBMS)** is software that provides a structured interface for defining, storing, retrieving, and manipulating persistent collections of interrelated data. Formally, a DBMS manages a **database** $\mathcal{D} = \{r_1, r_2, \ldots, r_n\}$, where each $r_i$ is a **relation** (table) defined over a schema $R_i(A_1 : D_1,\, A_2 : D_2,\, \ldots,\, A_k : D_k)$, with attributes $A_j$ drawn from domains $D_j$. The system enforces **integrity constraints**, controls concurrent access, and guarantees durability through transaction management.

**Worked Example.** Consider a university database with two relations:

$$\texttt{Student}(\underline{\texttt{sid}},\, \texttt{name},\, \texttt{gpa}) \qquad \texttt{Enroll}(\underline{\texttt{sid}},\, \underline{\texttt{cid}},\, \texttt{grade})$$

A registrar query — *"retrieve the names of all students with GPA above 3.5 who are enrolled in course C101"* — is expressed in relational algebra as

$$\pi_{\texttt{name}}\!\left(\sigma_{\texttt{gpa} > 3.5}(\texttt{Student}) \bowtie_{\texttt{sid}} \sigma_{\texttt{cid}=\text{'C101'}}(\texttt{Enroll})\right)$$

The DBMS **query optimizer** rewrites this expression into a physical execution plan, choosing between nested-loop joins, hash joins, or index scans to minimise I/O cost $C = C_{\text{read}} + C_{\text{write}}$, measured in disk-page accesses.

**Key Theorem (ACID Guarantees).** Every well-formed DBMS transaction satisfies four properties: *Atomicity* (a transaction commits entirely or not at all), *Consistency* (every committed state satisfies all declared constraints), *Isolation* (concurrent transactions produce results equivalent to some serial execution — formally captured by **serializability**), and *Durability* (committed writes survive failures). These properties are enforced jointly by a **write-ahead log (WAL)** and a **concurrency-control protocol** such as two-phase locking (2PL).

**Lab Cell (SQLite via Python).**

```python
import sqlite3, sympy as sp

conn = sqlite3.connect(":memory:")
conn.executescript("""
    CREATE TABLE Student(sid INTEGER PRIMARY KEY, name TEXT, gpa REAL);
    CREATE TABLE Enroll(sid INTEGER, cid TEXT, grade TEXT);
    INSERT INTO Student VALUES (1,'Alice',3.8),(2,'Bob',3.2),(3,'Carol',3.9);
    INSERT INTO Enroll  VALUES (1,'C101','A'),(3,'C101','A+');
""")

rows = conn.execute("""
    SELECT S.name FROM Student S JOIN Enroll E ON S.sid=E.sid
    WHERE S.gpa > 3.5 AND E.cid='C101'
""").fetchall()

print(rows)          # [('Alice',), ('Carol',)]
gpa_vals = sp.Matrix([3.8, 3.9])
print("Mean GPA:", sp.Rational(gpa_vals.applyfunc(lambda x: x).dot(sp.ones(2,1)), 2))
```

Running this cell confirms the relational-algebra result and illustrates how a DBMS translates a declarative SQL query into verifiable output.

## Large Dataset Management

**Definition.** A *large dataset* is a collection $\mathcal{D} = \{(x_i, y_i)\}_{i=1}^{N}$ where $N$ is sufficiently large that loading all records into primary memory simultaneously is impractical or impossible. Formally, if $M$ denotes available RAM in bytes and $s$ the average record size, the dataset is *large* when $N \cdot s \gg M$. Effective large dataset management encompasses three interlocking concerns: *chunked access* (reading subsets $\mathcal{D}_k \subset \mathcal{D}$ of size $B \ll N$), *streaming aggregation* (computing statistics without full materialisation), and *lazy evaluation* (deferring computation until results are explicitly needed).

A foundational quantity is the *sample mean* computed in a single pass. Suppose we receive records in non-overlapping chunks of size $B$. After processing chunk $k$ containing values $\{x_i\}_{i \in I_k}$, we maintain a running sum $S_k = S_{k-1} + \sum_{i \in I_k} x_i$ and a running count $C_k = C_{k-1} + |I_k|$. The global mean is recovered as $\bar{x} = S_K / C_K$ after all $K = \lceil N/B \rceil$ chunks. Memory cost is $O(B)$ rather than $O(N)$.

**Worked Example.** Suppose $N = 10^6$ temperature readings stored in a CSV file too large for RAM, and $B = 10^4$. We read each chunk of $10^4$ rows, accumulate their column sums and counts, and compute the grand mean once all chunks are processed. If chunks 1 through 100 yield partial sums $S_1, \ldots, S_{100}$, the global mean is $\bar{x} = \left(\sum_{k=1}^{100} S_k\right) / 10^6$. Welford's online algorithm extends this idea to variance without numerical cancellation: it updates $M_{2,k} = M_{2,k-1} + (x_i - \bar{x}_{k-1})(x_i - \bar{x}_k)$, giving $\sigma^2 = M_{2,N}/(N-1)$ at termination.

**Key Theorem (Chunk-Independence of Linear Statistics).** Let $f : \mathbb{R}^N \to \mathbb{R}$ be a linear statistic of the form $f(\mathcal{D}) = \sum_{i=1}^{N} g(x_i)$ for some function $g$. Then $f(\mathcal{D}) = \sum_{k=1}^{K} f(\mathcal{D}_k)$, and the statistic can be computed exactly using $O(B + K)$ memory regardless of $N$.

**Lab Cell.**

```python
import sympy as sp
import pandas as pd

# Simulate chunked mean on a large sequence
chunk_size = 1000
total, count = 0, 0
for chunk in pd.read_csv("temperatures.csv", chunksize=chunk_size):
    total += chunk["temp"].sum()
    count += len(chunk)

grand_mean = sp.Rational(int(total * 1e6), count * 1000000)  # exact rational
print("Grand mean:", float(grand_mean))
```

This pattern generalises to any associative aggregation—sums, counts, extrema—making it the backbone of scalable data pipelines.
