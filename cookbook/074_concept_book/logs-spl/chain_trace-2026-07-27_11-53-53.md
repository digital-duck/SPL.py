## Binary Search Tree

**Definition.** A *binary search tree* (BST) is a rooted binary tree in which every node $v$ stores a key $k(v)$ drawn from a totally ordered set, subject to the *BST invariant*: for every node $v$, all keys in the left subtree of $v$ are strictly less than $k(v)$, and all keys in the right subtree of $v$ are strictly greater than $k(v)$. Formally, if $L(v)$ and $R(v)$ denote the left and right subtrees,

$$\forall u \in L(v):\ k(u) < k(v), \qquad \forall u \in R(v):\ k(u) > k(v).$$

This invariant holds recursively at every node, not merely at the root.

**Worked Example.** Insert the sequence $\langle 5, 3, 7, 1, 4 \rangle$ into an initially empty BST. The first key, $5$, becomes the root. Key $3 < 5$ goes left; $7 > 5$ goes right. Key $1 < 5$, then $1 < 3$, so it becomes the left child of $3$. Key $4 < 5$, then $4 > 3$, so it becomes the right child of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node. An in-order traversal (left $\to$ root $\to$ right) yields $\langle 1, 3, 4, 5, 7 \rangle$—the keys in sorted order, which is a direct consequence of the invariant.

**Key Theorem (Search Complexity).** A search, insertion, or deletion in a BST containing $n$ nodes requires $O(h)$ comparisons, where $h$ is the height of the tree. For a *balanced* BST, $h = \Theta(\log n)$, giving $O(\log n)$ worst-case operations. In the degenerate case—keys inserted in sorted order—the tree degenerates to a linked list with $h = n - 1$ and $O(n)$ operations. Self-balancing variants (AVL trees, red–black trees) maintain $h = O(\log n)$ unconditionally.

**Lab Cell (SymPy/Python).**

```python
# Minimal BST node; insert and in-order traversal
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root

def inorder(root):
    return [] if root is None else inorder(root.left) + [root.key] + inorder(root.right)

root = None
for k in [5, 3, 7, 1, 4]:
    root = insert(root, k)

print(inorder(root))   # → [1, 3, 4, 5, 7]
```

## Random Permutation

**Definition.** Let $S = \{1, 2, \ldots, n\}$ be a finite set of $n$ elements. A *permutation* of $S$ is a bijection $\sigma: S \to S$. A *random permutation* is a permutation drawn uniformly at random from the set of all such bijections, denoted $S_n$. Since $|S_n| = n!$, each permutation $\sigma$ satisfies

$$\Pr[\sigma] = \frac{1}{n!}.$$

This model is also called the *uniform random permutation* and forms the probability space underlying the analysis of sorting algorithms, card shuffles, and combinatorial optimization.

**Worked Example.** Consider $n = 3$, so $S = \{1, 2, 3\}$ and $|S_3| = 6$. The six permutations in one-line notation are

$$123,\; 132,\; 213,\; 231,\; 312,\; 321,$$

each occurring with probability $\frac{1}{6}$. Suppose we ask: what is the expected number of *fixed points* — elements $i$ for which $\sigma(i) = i$?

Define the indicator $X_i = \mathbf{1}[\sigma(i) = i]$. Then $\Pr[\sigma(i) = i] = \frac{(n-1)!}{n!} = \frac{1}{n}$, since fixing position $i$ leaves $(n-1)!$ completions. By linearity of expectation,

$$\mathbb{E}\!\left[\sum_{i=1}^{n} X_i\right] = \sum_{i=1}^{n} \frac{1}{n} = 1.$$

For $n = 3$ one verifies directly: the permutations $123$, $132$, $213$, $231$, $312$, $321$ have $3, 1, 1, 0, 0, 1$ fixed points respectively, summing to $6$, giving average $1$. ✓

**Theorem (Expected Fixed Points).** *For a uniform random permutation of $n$ elements, the expected number of fixed points equals $1$ for every $n \geq 1$.*

The proof follows from the indicator argument above; remarkably, the expectation is independent of $n$. A deeper result (via inclusion–exclusion) shows that the number of *derangements* — permutations with no fixed points — equals $D_n = n!\sum_{k=0}^{n}\frac{(-1)^k}{k!}$, which converges to $n!/e$ as $n \to \infty$.

**Lab Cell.**

```python
from sympy.combinatorics import Permutation, SymmetricGroup
from sympy import Rational

n = 4
G = SymmetricGroup(n)
perms = list(G.generate())

fixed_counts = [
    sum(1 for i in range(n) if p(i) == i)
    for p in perms
]

expected = Rational(sum(fixed_counts), len(perms))
print(f"E[fixed points] = {expected}")   # expect 1
```

Running this cell confirms $\mathbb{E}[\text{fixed points}] = 1$ for $n = 4$, illustrating how symbolic enumeration validates the analytic result.

### heap_property (0.0s)

## Heap Property

**Definition.** A *binary heap* is a complete binary tree stored in an array $A[1..n]$ satisfying the **heap property**: for every node at index $i$ with children at indices $2i$ and $2i+1$,

$$A[\lfloor i/2 \rfloor] \geq A[i] \qquad \text{(max-heap)}$$

or, dually,

$$A[\lfloor i/2 \rfloor] \leq A[i] \qquad \text{(min-heap).}$$

In a max-heap the root $A[1]$ is the global maximum; in a min-heap it is the global minimum. The completeness of the tree guarantees height $h = \lfloor \log_2 n \rfloor$, which is the key to the $O(\log n)$ complexity of insertion and deletion.

**Worked example.** Consider the array $A = [16, 14, 10, 8, 7, 9, 3, 2, 4, 1]$. Checking the max-heap property at $i = 2$: its parent is $A[1] = 16$ and its value is $A[2] = 14$, so $16 \geq 14$ holds. At $i = 4$: parent $A[2] = 14$, value $A[4] = 8$, and $14 \geq 8$ holds. Verifying all pairs confirms a valid max-heap. Now suppose we update $A[4] \leftarrow 20$. The property is violated at $i = 4$ since $14 < 20$. The *heapify-up* (sift-up) procedure repairs the heap by repeatedly swapping $A[i]$ with $A[\lfloor i/2 \rfloor]$ while the parent is smaller, restoring the invariant in $O(\log n)$ steps.

**Key theorem (Heapify correctness).** The `MAX-HEAPIFY` procedure, which sifts a node downward by swapping it with the larger child until the heap property is locally satisfied, runs in $O(\log n)$ time and restores the max-heap property for the subtree rooted at node $i$, given that both subtrees of $i$ already satisfy the property.

*Proof sketch.* At each recursive call the algorithm descends one level, reducing the remaining height by 1. Since $h = O(\log n)$, the total number of comparisons is bounded by $O(\log n)$. $\square$

Building a heap from an arbitrary array via bottom-up heapification costs only $O(n)$, a tighter bound than the naive $O(n \log n)$ obtained by $n$ successive insertions.

**Lab cell.**

from sympy import symbols, floor, log

## Random Binary Search Tree

**Definition.** A *random binary search tree* (RBST) is a binary search tree built by inserting the elements of a set $\{x_1, x_2, \ldots, x_n\}$ in a uniformly random order chosen from all $n!$ permutations. For a fixed key universe $\{1, 2, \ldots, n\}$, let $\Pi$ be a uniformly random permutation; the RBST is the BST that results from inserting $\Pi(1), \Pi(2), \ldots, \Pi(n)$ sequentially using the standard BST insertion rule. The first key inserted becomes the root, and each subsequent key is routed left or right by comparison until it occupies an empty child slot.

**Worked Example.** Take $n = 4$ with keys $\{1,2,3,4\}$ and suppose the insertion order is $3, 1, 4, 2$. The key $3$ becomes the root. Since $1 < 3$, it becomes the left child. Since $4 > 3$, it becomes the right child. Since $2 < 3$ and $2 > 1$, it becomes the right child of $1$. The resulting tree has height $2$, whereas the worst-case insertion order $1,2,3,4$ produces a degenerate chain of height $3$. Averaging over all $4! = 24$ permutations reveals that most orderings yield balanced-looking trees.

**Key Theorem (Expected Height).** For a uniformly random permutation of $\{1, \ldots, n\}$, the expected height of the resulting RBST satisfies

$$\mathbb{E}[h_n] \sim 2\ln n \approx 4.311 \log_2 n,$$

so every search, insertion, or deletion runs in $O(\log n)$ expected time. The proof rests on the harmonic number $H_n = \sum_{i=1}^{n} \frac{1}{i}$, the single new tool this section introduces. One shows that the expected depth of any node is bounded by $2H_n - 2$ by observing that node $j$ is an ancestor of node $k$ exactly when $j$ is the first of $\{\min(j,k), \ldots, \max(j,k)\}$ to be inserted, an event of probability $\tfrac{1}{|j-k|+1}$. Summing these probabilities over all potential ancestors and applying $H_n \approx \ln n + \gamma$ yields the stated bound.

**Lab Cell.**

```python
from sympy import harmonic, N

# Compare 2·H_n with 2·ln n for increasing n
import math
ns = [10, 100, 1000, 10000]
for m in ns:
    Hn = float(N(harmonic(m)))
    print(f"n={m:5d}  2·H_n = {2*Hn:.4f}  2·ln n = {2*math.log(m):.4f}")
```

Running this cell confirms that $2H_n$ tracks $2\ln n$ closely across several orders of magnitude, making RBSTs a practical structure whose average-case guarantee holds without any explicit rebalancing logic.

## Sset Interface

### Definition

An **sset** (symbolic set) is a first-class mathematical object that pairs a carrier set with a declared algebraic signature. Formally, an sset $S$ is a triple

$$S = (U,\, \Sigma,\, \llbracket\cdot\rrbracket)$$

where $U$ is the **universe** (a Python iterable or a lazily described domain), $\Sigma = \{\sigma_1, \sigma_2, \ldots\}$ is a finite **signature** of named operations, and $\llbracket \sigma_i \rrbracket : U^{a_i} \to U$ is the **interpretation** of each $\sigma_i$ with arity $a_i$. The *interface* of an sset is the contract that any concrete implementation must satisfy: it must expose membership testing (`__contains__`), iteration (`__iter__`) over a representative sample, and an `.ops` mapping that resolves each signature symbol to a callable.

In SPL, `sset_interface` is the abstract base from which every symbolic domain (integers modulo $n$, polynomial rings, graph vertex sets, and so on) inherits. It enforces a uniform protocol so that higher-order recipes—pattern matching, algebraic rewriting, automated theorem checking—can operate polymorphically across domains without knowing the concrete representation.

### Worked Example

Consider the sset $\mathbb{Z}_5 = (\{0,1,2,3,4\},\; \{+, \times\},\; \llbracket\cdot\rrbracket)$ where $\llbracket + \rrbracket(a,b) = (a+b)\bmod 5$. Constructing it under `sset_interface` requires registering both operations in `.ops`:

```python
ops = {'+': lambda a, b: (a + b) % 5,
       '*': lambda a, b: (a * b) % 5}
```

Membership of $3$ is resolved by `3 in Z5`, and the expression $3 + 4$ is evaluated by dispatching through `Z5.ops['+'](3, 4)` to yield $2$.

### Key Theorem

**Homomorphism Preservation.** Let $S = (U, \Sigma, \llbracket\cdot\rrbracket_S)$ and $T = (V, \Sigma, \llbracket\cdot\rrbracket_T)$ be two ssets sharing the same signature. A function $\varphi : U \to V$ is a *homomorphism* if and only if for every $\sigma \in \Sigma$ and every tuple $(u_1,\ldots,u_a) \in U^a$,

$$\varphi\!\left(\llbracket\sigma\rrbracket_S(u_1,\ldots,u_a)\right) = \llbracket\sigma\rrbracket_T\!\left(\varphi(u_1),\ldots,\varphi(u_a)\right).$$

Because `sset_interface` enforces a uniform `.ops` dictionary, SPL's `sset_homomorphism_check` routine can verify this property mechanically by sampling the domain and comparing both sides—no manual proof is required for finite carriers.

    }

## Treap

**Definition.** A *treap* is a binary search tree (BST) in which every node stores two keys: a *search key* $k$ drawn from a totally ordered set, and a *priority* $p$ drawn uniformly at random from $\mathbb{R}$ (or a large integer range). The structure simultaneously satisfies the BST property on search keys and the max-heap property on priorities:

- **BST property:** for every node $v$, all keys in its left subtree are $< k_v$ and all keys in its right subtree are $> k_v$.
- **Heap property:** for every non-root node $v$ with parent $u$, $p_v < p_u$.

The name is a portmanteau of *tree* and *heap*.

**Worked Example.** Insert keys $\{3, 1, 4, 1, 5\}$ (ignoring the duplicate for clarity: $\{1, 3, 4, 5\}$) with randomly assigned priorities $p_1=0.9,\; p_3=0.5,\; p_4=0.7,\; p_5=0.2$. The node with the largest priority becomes the root: node $1$ ($p=0.9$). Node $4$ ($p=0.7$) is its right child; node $3$ ($p=0.5$) is the left child of $4$; node $5$ ($p=0.2$) is the right child of $4$. One can verify that in-order traversal yields $1,3,4,5$, confirming the BST property, while every parent has a higher priority than its children, confirming the heap property.

**Key Theorem.** *The treap on $n$ distinct keys with independent, uniformly random priorities is identically distributed to a random BST built by inserting the same keys in a uniformly random order.* In particular, the expected height is $\Theta(\log n)$ and the expected cost of search, insertion, and deletion is $O(\log n)$. Insertion and deletion are implemented via standard BST pointer manipulation followed by rotations that restore the heap property; each operation requires $O(\text{depth})$ rotations in expectation.

The treap's elegance lies in reducing tree balance to a probabilistic argument: because priorities are independent of keys, no adversary can construct a worst-case input sequence that forces $O(n)$ height.

**Lab Cell.**

```python
import random

class Node:
    def __init__(self, key):
        self.key, self.pri = key, random.random()
        self.left = self.right = None

def rotate_right(y):
    x = y.left; y.left = x.right; x.right = y; return x

def rotate_left(x):
    y = x.right; x.right = y.left; y.left = x; return y

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
        if root.left.pri > root.pri:
            root = rotate_right(root)
    else:
        root.right = insert(root.right, key)
        if root.right.pri > root.pri:
            root = rotate_left(root)
    return root

keys = [5, 2, 8, 1, 4, 7, 9]
root = None
for k in keys:
    root = insert(root, k)

def inorder(node):
    if node is None: return []
    return inorder(node.left) + [node.key] + inorder(node.right)

print("In-order:", inorder(root))   # Expected: [1, 2, 4, 5, 7, 8, 9]
print("Root key:", root.key, "  Root priority:", round(root.pri, 4))
```

Running the lab cell confirms that in-order traversal recovers the sorted sequence regardless of insertion order, while the root holds the node with the highest sampled priority.

## Treap Hashing Priorities

**Definition.** A *treap* is a binary tree in which every node $v$ stores a *key* $k(v)$ from a totally ordered set and a *priority* $p(v) \in \mathbb{R}$, subject to two simultaneous structural invariants: the keys obey the *binary-search-tree (BST) property* — for every node $v$, all keys in its left subtree are less than $k(v)$ and all keys in its right subtree are greater — and the priorities obey the *max-heap property* — $p(v) \geq p(u)$ for every descendant $u$ of $v$. When priorities are drawn independently and uniformly at random from a continuous distribution, the resulting structure is called a *randomised treap*. A common implementation assigns $p(v) = h(k(v))$, where $h$ is a cryptographic or universal hash function; because good hash functions distribute outputs nearly uniformly, the hashed priority acts as an unbiased random tiebreaker.

**Worked Example.** Insert the keys $\{3, 1, 4, 2\}$ in that order, assigning priorities via $p(k) = (ak + b) \bmod m$ with $a = 7,\, b = 3,\, m = 97$: $p(3)=24,\; p(1)=10,\; p(4)=31,\; p(2)=17$. The key $4$ holds the maximum priority, so it becomes the root. A standard BST insertion of $3$ places it in the left child, and $2, 1$ fall beneath $3$. Because $p(3)=24 > p(2)=17$, node $3$ remains above $2$, satisfying the heap invariant. The final tree has height $3$, consistent with the expected logarithmic behaviour.

**Theorem (Expected Height).** If $n$ keys are inserted into a treap with priorities drawn independently from a continuous distribution, the expected height satisfies
$$\mathbb{E}[\text{height}] = O(\log n).$$
*Proof sketch.* The expected depth of a node with rank $r$ (i.e.\ the $r$-th smallest key) equals $H_r + H_{n-r+1} - 1$, where $H_k = \sum_{i=1}^{k} 1/i$ is the $k$-th harmonic number. Since $H_k = O(\log k)$, every node's expected depth is $O(\log n)$, and the height — the maximum depth — is $O(\log n)$ with high probability by a union bound over $n$ nodes.

**Lab Cell.**

```python
import sympy as sp

# Demonstrate hash-derived priorities symbolically
k, a, b, m = sp.symbols('k a b m', integer=True, positive=True)
priority = sp.Mod(a*k + b, m)

keys = [3, 1, 4, 2]
params = {a: 7, b: 3, m: 97}
for key in keys:
    p = int(priority.subs(params).subs(k, key))
    print(f"key={key}, priority={p}")

# Verify expected depth formula for rank r in n nodes
r, n = sp.symbols('r n', positive=True)
H = lambda t: sp.harmonic(t)
expected_depth = H(r) + H(n - r + 1) - 1
print(sp.simplify(expected_depth.subs({r: 2, n: 8})))
```
