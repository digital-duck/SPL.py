### shortest_path (14.8s)

## Shortest Path

A **shortest path** between two nodes in a weighted graph is the path whose total edge weight is minimized. In an unweighted graph, "weight" is simply the number of edges, so the shortest path is the one with fewest hops. Shortest-path algorithms appear everywhere: GPS routing, network packet delivery, social-network degree-of-separation queries, and dependency resolution in package managers.

The workhorse algorithm for non-negative edge weights is **Dijkstra's algorithm**. Starting from a source node, it maintains a priority queue of (distance, node) pairs and greedily expands the nearest unvisited node, updating neighbors' tentative distances whenever a shorter route is found. Because it never revisits a finalized node, it runs in $O((V + E) \log V)$ time with a binary heap, where $V$ is the number of vertices and $E$ the number of edges.

**Worked example.** Consider a small city map with five intersections:

```
A --4-- B
|       |
2       1
|       |
C --3-- D --5-- E
```

What is the shortest path from A to E?

```python
import heapq

graph = {
    'A': [('B', 4), ('C', 2)],
    'B': [('D', 1)],
    'C': [('D', 3)],
    'D': [('E', 5)],
    'E': []
}

def dijkstra(graph, start):
    dist = {node: float('inf') for node in graph}
    dist[start] = 0
    prev = {node: None for node in graph}
    pq = [(0, start)]

    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                prev[v] = u
                heapq.heappush(pq, (dist[v], v))
    return dist, prev

dist, prev = dijkstra(graph, 'A')
print(dist['E'])   # 10
```

Tracing back through `prev`: E ← D ← B ← A, total cost $4 + 1 + 5 = 10$. The route through C costs $2 + 3 + 5 = 10$ as well — a tie, both are optimal.

**Applying the concept.** When solving shortest-path problems, first check for negative edge weights: Dijkstra fails there, and you need the Bellman–Ford algorithm instead. Second, decide whether you need single-source shortest paths (one start, all destinations — use Dijkstra) or all-pairs shortest paths (every pair — use Floyd–Warshall in $O(V^3)$). Third, if the graph is unweighted, plain breadth-first search finds shortest paths in $O(V + E)$ without a priority queue, which is faster in practice. Matching the algorithm to the graph's properties is the key problem-solving skill.

### geodesic_distance (15.9s)

## Geodesic Distance

The straight-line distance between two points works perfectly in flat space, but the moment you move to a curved surface — a sphere, a road network, or a graph — the shortest path must follow the surface itself. **Geodesic distance** is the length of the shortest path between two points that stays on the surface or within the structure being measured. On a globe, geodesics are great-circle arcs; on a graph, they are shortest paths counted in edges or weighted costs.

Formally, if $G = (V, E, w)$ is a weighted graph with vertices $V$, edges $E$, and non-negative edge weights $w$, then the geodesic distance between vertices $u$ and $v$ is

$$d(u, v) = \min_{\text{paths } P: u \to v} \sum_{e \in P} w(e)$$

When all weights equal 1, this reduces to the hop count of the shortest path.

**Worked example.** Consider a graph representing five cities connected by roads with travel times (in hours) as edge weights. You want the fastest route from city A to city E.

```python
import heapq

def geodesic_distance(graph, source):
    dist = {node: float('inf') for node in graph}
    dist[source] = 0
    heap = [(0, source)]
    while heap:
        d, u = heapq.heappop(heap)
        if d > dist[u]:
            continue
        for v, w in graph[u]:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                heapq.heappush(heap, (dist[v], v))
    return dist

graph = {
    'A': [('B', 2), ('C', 5)],
    'B': [('C', 1), ('D', 4)],
    'C': [('E', 3)],
    'D': [('E', 1)],
    'E': []
}
print(geodesic_distance(graph, 'A'))
# {'A': 0, 'B': 2, 'C': 3, 'D': 6, 'E': 6}
```

Dijkstra's algorithm expands the frontier by current shortest known distance, guaranteeing that when a node is finalized, no cheaper path remains. Here $d(A, E) = 6$ via $A \to B \to C \to E$.

**Problem-solving application.** Geodesic distance drives real decisions: navigation apps minimize it over road networks, social-network analysts compute it to find how many handshakes separate any two people, and machine-learning researchers use pairwise geodesic distances to "unfold" curved data manifolds (the key idea behind ISOMAP). When you encounter a problem asking for the "most efficient connection" under structural constraints — geographic, social, or computational — reframe it as finding geodesic distances on an appropriately weighted graph, then apply Dijkstra's algorithm for sparse graphs or Floyd–Warshall when you need all pairs at once.

### vertex_degree (0.0s)

## Vertex Degree

The **degree** of a vertex in a graph is the number of edges directly connected to it. If vertex $v$ has degree $k$, written $\deg(v) = k$, then exactly $k$ edges touch $v$. A vertex with degree 0 is called **isolated** — it has no neighbors. A vertex with degree 1 is a **leaf**, common in tree structures. In directed graphs the concept splits into **in-degree** (edges arriving) and **out-degree** (edges leaving), but for undirected graphs a single degree value suffices.

One foundational fact connects vertex degrees to the total number of edges. If a graph $G$ has $n$ vertices and $m$ edges, then

$$\sum_{v \in G} \deg(v) = 2m$$

because every edge contributes exactly 1 to the degree of each of its two endpoints, so the sum double-counts every edge. An immediate corollary: the number of vertices with odd degree is always even.

**Worked example.** Consider a social network with five people — Alice, Bob, Carlos, Dana, and Eve — where friendships form the edges: Alice–Bob, Alice–Carlos, Bob–Dana, Carlos–Dana, Dana–Eve. Listing degrees: $\deg(\text{Alice}) = 2$, $\deg(\text{Bob}) = 2$, $\deg(\text{Carlos}) = 2$, $\deg(\text{Dana}) = 3$, $\deg(\text{Eve}) = 1$. The sum is $2+2+2+3+1 = 10 = 2 \times 5$, confirming the handshaking identity with $m = 5$ edges. Dana is the most connected person; Eve is a leaf.

**Problem-solving application.** Degree sequences are a quick sanity check when building or validating graph data. Suppose you're given a claimed degree sequence $[3, 3, 2, 2, 1, 1]$ and asked whether a valid simple graph exists. First, sum the degrees: $3+3+2+2+1+1 = 12$, which is even, so the handshaking identity is not violated — a necessary condition. The Erdős–Gallai theorem gives a complete test, but for small cases you can often construct the graph directly: pair the two degree-3 vertices together and with two degree-2 vertices, then attach the degree-1 vertices. If construction succeeds, the sequence is **graphical**. In code or algorithm design, computing degree for every vertex takes $O(m)$ time (one pass over the edge list), making it one of the cheapest structural features to extract — and often the first one queried when profiling network connectivity or detecting hub nodes in scale-free graphs.

### centrality (16.1s)

## Centrality

In a network, not all nodes are equal. Some sit at busy intersections, connecting many others; some bridge separate clusters; some sit close to everyone else. **Centrality** is a family of metrics that quantify how "important" or "influential" a node is within a graph, each metric capturing a different dimension of that importance.

The most common measures are:

- **Degree centrality** — the fraction of other nodes a node is directly connected to. High degree means many direct neighbors.
- **Betweenness centrality** — the fraction of all shortest paths in the network that pass *through* a node. High betweenness means the node is a broker or bottleneck.
- **Closeness centrality** — the inverse of the average shortest-path distance to all other nodes. High closeness means the node can reach everyone quickly.
- **Eigenvector centrality** — a node's score is proportional to the sum of its neighbors' scores. Being connected to influential nodes amplifies your own score. PageRank is a variant of this idea.

**Worked example.** Consider a five-node friendship network: Alice knows Bob and Carol; Bob knows Alice, Carol, and Dave; Carol knows Alice and Bob; Dave knows Bob and Eve; Eve knows Dave.

Draw the edges: A–B, A–C, B–C, B–D, D–E.

- Degree: Bob has degree 3 (highest) — the social hub.
- Betweenness: Bob lies on every path between {A, C} and {D, E}, so Bob has the highest betweenness — remove Bob and the network splits.
- Closeness: Bob reaches every other node in at most 2 hops, giving him the smallest average distance and highest closeness.
- Eigenvector: Bob is connected to three nodes; Dave is connected only to Bob and Eve, so Bob's neighbors are collectively more central — Bob scores highest here too.

**Applying centrality to a real problem.** Suppose a public-health team wants to slow rumor spread in a social network. Rather than randomly selecting people to receive accurate information, they identify the top-5 nodes by betweenness centrality — the brokers through whom almost all inter-community messages flow. Targeting those five nodes reaches the entire network far faster than targeting five random users.

In code, this is a one-liner with NetworkX:

```python
import networkx as nx
G = nx.karate_club_graph()
scores = nx.betweenness_centrality(G)
top5 = sorted(scores, key=scores.get, reverse=True)[:5]
```

Choosing *which* centrality measure to use is itself a design decision: betweenness for bottlenecks, closeness for broadcast speed, eigenvector for prestige, degree for raw connectivity.

### eccentricity (17.5s)

## Eccentricity

Every conic section — circle, ellipse, parabola, hyperbola — can be described by a single number that measures how "stretched" or "open" it is. That number is **eccentricity**, denoted $e$, and it is defined as the ratio of two distances built into the curve's geometry:

$$e = \frac{c}{a}$$

where $a$ is the length of the semi-major axis and $c$ is the distance from the center to a focus. For a circle, the two foci collapse to the center, so $c = 0$ and $e = 0$. As the shape stretches into an elongated ellipse, $c$ grows toward $a$, and $e$ approaches 1. A parabola sits exactly at $e = 1$, and a hyperbola has $e > 1$ because its foci lie *outside* the curve entirely.

| Conic | Eccentricity |
|---|---|
| Circle | $e = 0$ |
| Ellipse | $0 < e < 1$ |
| Parabola | $e = 1$ |
| Hyperbola | $e > 1$ |

**Worked example.** Earth's orbit is an ellipse with semi-major axis $a = 1.496 \times 10^8\ \text{km}$ and eccentricity $e \approx 0.0167$. Find the distance from Earth's center to the Sun (a focus).

From $e = c/a$:

$$c = e \cdot a = 0.0167 \times 1.496 \times 10^8 \approx 2.50 \times 10^6\ \text{km}$$

So the Sun sits about 2.5 million km off-center — close enough to nearly circular, which is why seasonal temperature differences are driven by axial tilt rather than orbital distance.

**Problem-solving application.** Suppose a satellite is placed in an elliptical orbit with perigee (closest point) $r_p = 7{,}000\ \text{km}$ and apogee (farthest point) $r_a = 42{,}000\ \text{km}$ from Earth's center. Find the eccentricity.

The semi-major axis and focal offset are:

$$a = \frac{r_a + r_p}{2} = \frac{42{,}000 + 7{,}000}{2} = 24{,}500\ \text{km}$$

$$c = \frac{r_a - r_p}{2} = \frac{42{,}000 - 7{,}000}{2} = 17{,}500\ \text{km}$$

$$e = \frac{c}{a} = \frac{17{,}500}{24{,}500} \approx 0.714$$

That high eccentricity means the satellite spends most of its time near apogee — a property deliberately exploited in Molniya orbits to provide long dwell time over high-latitude regions. Eccentricity, then, is not just a geometric label; it directly predicts physical behavior.

### closeness_centrality (14.0s)

## Closeness Centrality

In a network, not every node is equally well-positioned to spread information or coordinate activity. **Closeness centrality** measures how close a node is to all other nodes in the graph — specifically, how quickly it can reach every other node by the shortest available paths. A node with high closeness centrality sits near the center of the network; messages or influence from it travel few hops to reach anyone else.

Formally, the closeness centrality of a node $v$ in a connected graph $G$ with $n$ nodes is:

$$C(v) = \frac{n - 1}{\sum_{u \neq v} d(v, u)}$$

where $d(v, u)$ is the length of the shortest path between $v$ and $u$. The numerator $n - 1$ normalizes the score so that a node directly connected to every other node scores exactly 1.

**Worked example.** Consider a simple five-node path graph: $A - B - C - D - E$. The sum of shortest distances from $C$ to all others is $1 + 1 + 2 + 2 = 6$, giving $C(C) = 4/6 \approx 0.67$. From $A$, the sum is $1 + 2 + 3 + 4 = 10$, so $C(A) = 4/10 = 0.40$. Node $C$, sitting at the center, reaches every node in fewer steps and earns the highest closeness centrality — exactly the intuition we want.

**Problem-solving application.** Suppose you are choosing where to place an emergency response depot in a city modeled as a road network. You want a location that minimizes average travel time to all neighborhoods. Computing closeness centrality for every node and selecting the highest-scoring one gives a principled, data-driven answer. In Python with NetworkX:

```python
import networkx as nx

G = nx.read_edgelist("city_roads.txt")
scores = nx.closeness_centrality(G)
best_depot = max(scores, key=scores.get)
print(f"Optimal depot: {best_depot}, score: {scores[best_depot]:.3f}")
```

One practical caution: the standard formula assumes the graph is connected. For disconnected graphs, NetworkX uses a variant that normalizes by the fraction of nodes actually reachable, preventing artificially inflated scores for isolated clusters. Always inspect your graph's connectivity before interpreting closeness scores at face value.

### radius (13.3s)

## Radius

The **radius** of a circle is the distance from the center of the circle to any point on its boundary. Because all points on a circle are equidistant from the center by definition, the radius is both a unique measurement and the defining parameter of a circle. If a circle has center $(h, k)$ and radius $r$, every point $(x, y)$ on the circle satisfies:

$$
(x - h)^2 + (y - k)^2 = r^2
$$

This equation follows directly from the Pythagorean theorem applied to the horizontal and vertical distances between the center and a boundary point.

The radius controls the fundamental measurements of a circle. The circumference is $C = 2\pi r$, the area is $A = \pi r^2$, and the diameter is $d = 2r$. Knowing any one of these lets you recover the rest.

**Worked example.** A circular irrigation field has an area of $5024 \text{ m}^2$. What is its radius?

Start from $A = \pi r^2$ and solve for $r$:

$$
r = \sqrt{\frac{A}{\pi}} = \sqrt{\frac{5024}{\pi}} \approx \sqrt{1599} \approx 40 \text{ m}
$$

So the radius is approximately $40$ meters, meaning the sprinkler at the center reaches $40$ meters in every direction.

**Problem-solving application.** Suppose you need to place a cell tower so that it covers a circular region containing two hospitals located at coordinates $(0, 0)$ and $(6, 0)$ (in kilometers), and a school at $(3, 4)$. You want the smallest circle that passes through all three points — this is the **circumscribed circle**, and its radius is called the **circumradius**.

Using the circumradius formula for a triangle with side lengths $a$, $b$, $c$ and area $K$:

$$
R = \frac{abc}{4K}
$$

The triangle has sides $a = 6$, $b = \sqrt{(3-6)^2 + 4^2} = 5$, $c = \sqrt{9 + 16} = 5$, and area $K = \frac{1}{2} \cdot 6 \cdot 4 = 12$. Therefore:

$$
R = \frac{6 \cdot 5 \cdot 5}{4 \cdot 12} = \frac{150}{48} = 3.125 \text{ km}
$$

The tower must be placed at the circumcenter with a broadcast radius of $3.125$ km to reach all three sites efficiently.

## Facility Placement

Where you put something matters as much as what it does. Facility placement is the problem of choosing locations for one or more service points — hospitals, warehouses, cell towers, fire stations — to optimize some measure of coverage, cost, or response time across a set of demand points. It sits at the intersection of logistics, operations research, and graph theory, and it shows up any time resources are finite and geography is real.

The core idea is straightforward: given a set of candidate sites and a set of customers (or demand points), select $k$ sites to open such that the total or maximum distance customers must travel is minimized. Two classic formulations capture most real-world variants:

- **$p$-median**: minimize the *total* weighted distance from every demand point to its nearest open facility.
- **$p$-center**: minimize the *maximum* distance any single demand point must travel — useful when equity or worst-case response time matters more than average efficiency.

**Worked example.** Suppose a county has five towns with populations $[800, 600, 1200, 400, 900]$ and you must place two clinics. Represent the towns as nodes in a graph with road distances as edge weights. For each pair of candidate sites, compute the assignment cost: each town is served by whichever clinic is closer, and the total cost is $\sum_i w_i \cdot d(i, \text{nearest clinic})$, where $w_i$ is the population and $d$ is road distance. Enumerate all $\binom{5}{2} = 10$ pairs, compute costs, and pick the minimum.

```python
import itertools

towns = ['A','B','C','D','E']
pop   = {'A':800,'B':600,'C':1200,'D':400,'E':900}
dist  = {('A','B'):10,('A','C'):20,('A','D'):15,('A','E'):25,
         ('B','C'):12,('B','D'):18,('B','E'):30,
         ('C','D'):8, ('C','E'):10,('D','E'):22}

def road(u, v):
    return dist.get((u,v), dist.get((v,u), 0 if u==v else float('inf')))

best, best_pair = float('inf'), None
for s1, s2 in itertools.combinations(towns, 2):
    cost = sum(pop[t] * min(road(t,s1), road(t,s2)) for t in towns)
    if cost < best:
        best, best_pair = cost, (s1, s2)

print(best_pair, best)
```

**Applying the concept.** Real instances are too large for brute-force enumeration — a network with 500 candidate sites and $k=10$ yields over $10^{18}$ combinations. Practitioners use greedy interchange heuristics (open the single best site, then swap sites one at a time as long as cost drops) or integer linear programming solvers. When demand is uncertain — a storm may shift where ambulances are needed — stochastic extensions add scenario weights. The choice between $p$-median and $p$-center also carries an ethical dimension: optimizing average distance can leave remote communities with very long travel times, while $p$-center explicitly protects the worst-served location.
