### connected_graph (0.5s)

## 连通图

**定义。** 在无向图 $G=(V,E)$ 中，如果任意两个顶点 $u,v\in V$ 之间都存在一条路径（即由边首尾相接构成的顶点序列），则称 $G$ 是**连通图**。如果存在一对顶点无法互相到达，则 $G$ 是**非连通图**。非连通图会分裂成若干个互不相连的**连通分量**，每个连通分量本身是连通的。

连通性是"网络是否完整"的基本判据：城市道路能否让每个路口互通，计算机网络里每台机器能否互相通信，都是在问同一个问题。

在有向图中，要求更严格。若任意两点之间都存在双向的有向路径，则称为**强连通**。若只在忽略边的方向后连通，则称为**弱连通**。

**例题。** 设图 $G$ 的顶点集为 $\{A,B,C,D,E\}$，边集为
$$E=\{AB,\ BC,\ CA,\ DE\}.$$
判断 $G$ 是否连通。

从 $A$ 出发做广度优先搜索（BFS）：

1. 访问 $A$，其邻居为 $B$、$C$；
2. 访问 $B$、$C$，它们的邻居都已访问过；
3. 队列为空，搜索结束。

已访问的顶点为 $\{A,B,C\}$，而 $D$、$E$ 没有被访问到。因此 $G$ 不连通，它有两个连通分量：$\{A,B,C\}$ 和 $\{D,E\}$。

**问题求解应用。** 判断连通性的标准方法是：从任一顶点出发做一次 BFS 或 DFS，检查访问到的顶点数是否等于 $|V|$。时间复杂度为 $O(|V|+|E|)$。用 Python 实现如下：

```python
from collections import deque

def is_connected(graph):
    start = next(iter(graph))
    seen = {start}
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in seen:
                seen.add(v)
                queue.append(v)
    return len(seen) == len(graph)

g = {"A": ["B", "C"], "B": ["A", "C"], "C": ["A", "B"],
     "D": ["E"], "E": ["D"]}
print(is_connected(g))  # False
```

**一个常用的计数结论。** 一个有 $n$ 个顶点的连通图至少有 $n-1$ 条边，恰好有 $n-1$ 条边的连通图就是**树**。因此，如果一个图有 $n$ 个顶点却少于 $n-1$ 条边，可以立刻断定它不连通，不必再做搜索。

**应用练习。** 一个通信网络有 8 台服务器和 6 条链路。它能否连通？

因为 $6<8-1=7$，所以网络必定不连通。要使它连通，至少还需要增加 $1$ 条链路。

**小结。** 判断连通性有两步：先用边数做快速检查（$|E|<|V|-1$ 则必不连通），再用 BFS 或 DFS 做确切判断。连通分量的个数还能告诉你，要让整个网络连通，至少需要增加多少条边：若有 $k$ 个连通分量，则至少需要再加 $k-1$ 条边。

### tree (13.0s)

## 树

**定义。** 树(tree)是一种由节点和边构成的连通图,且其中没有环。通俗地说,树就像一棵倒过来画的家谱:最上面有一个特殊的节点,称为**根**;每个节点向下可以连接若干**子节点**;没有子节点的节点称为**叶**。一棵含有 $n$ 个节点的树恰好有 $n-1$ 条边。这个数量关系很有用:少一条边,图就不连通;多一条边,就会出现环。

树中还有几个常用术语:

- **深度**:从根到某节点所经过的边数。
- **高度**:整棵树中最大的深度。
- **二叉树**:每个节点至多有两个子节点的树。

**例题。** 某文件系统的结构如下:根目录 `/` 下有 `home` 和 `etc` 两个文件夹;`home` 下有 `alice` 和 `bob`;`alice` 下有 `notes.txt` 和 `pic.png`。

1. 节点数:`/`、`home`、`etc`、`alice`、`bob`、`notes.txt`、`pic.png`,共 $n=7$ 个。
2. 边数:$7-1=6$ 条,可逐条数出来验证。
3. 叶:`etc`、`bob`、`notes.txt`、`pic.png`。
4. `notes.txt` 的深度为 3(路径 `/` → `home` → `alice` → `notes.txt`),这也是整棵树的高度。

由于树中没有环,从根到任一节点的路径是**唯一**的,所以文件路径才能准确定位一个文件。

**问题求解应用。** 树最常见的用法是递归遍历。下面的代码用嵌套字典表示树,并计算它的高度:

```python
def height(node):
    children = node.get("children", [])
    if not children:          # 叶:高度为 0
        return 0
    return 1 + max(height(c) for c in children)

tree = {"name": "/", "children": [
    {"name": "home", "children": [
        {"name": "alice", "children": [
            {"name": "notes.txt"}, {"name": "pic.png"}]},
        {"name": "bob"}]},
    {"name": "etc"}]}

print(height(tree))   # 输出 3
```

思路是:一棵树的高度等于最高子树的高度加 1。这种"把大问题拆成同类的子问题"的思路,同样适用于求节点总数、查找文件、判断某个节点是否在树中等问题。

再看一个计数问题:一棵完全二叉树的高度为 $h$,且每一层都被填满。它的节点总数是多少?第 $k$ 层有 $2^k$ 个节点,所以

$$n=\sum_{k=0}^{h}2^k=2^{h+1}-1.$$

反过来,$n$ 个节点的满二叉树高度约为 $\log_2 n$。因此,在平衡的二叉搜索树中查找数据,只需要大约 $\log_2 n$ 步。例如 $n=1{,}000{,}000$ 时,大约只需 20 步,而逐个检查可能需要上百万次。这就是树在数据库索引、决策树和语法分析中被广泛使用的原因。

**练习。** 若一棵树有 15 个节点,它有多少条边?若它是高度最小的二叉树,高度是多少?(答案:14 条边;高度为 3。)

### spanning_tree (12.8s)

## 生成树

**定义。** 设 $G=(V,E)$ 是一个连通的无向图。$G$ 的**生成树**是这样一个子图 $T$:它包含 $G$ 的全部顶点,只使用 $G$ 的部分边,并且连通且不含回路。要点是"覆盖所有顶点"与"没有多余的边"。若 $|V|=n$,则任何生成树恰好有 $n-1$ 条边:再少一条就不连通,再多一条就会产生回路。

**直观理解。** 想象要用光纤连接 5 个校区。我们希望每两个校区之间都能通信(连通),但每多铺一条光纤就多一份成本。生成树给出的就是"刚好够用"的铺设方案。

**例题。** 设图 $G$ 有顶点 $A,B,C,D$,边为 $AB,\ BC,\ CD,\ DA,\ AC$,共 5 条边。

1. $n=4$,所以生成树需要 $n-1=3$ 条边。
2. 取 $\{AB, BC, CD\}$:四个顶点都被连通,没有回路,所以是生成树。
3. 取 $\{AB, BC, AC\}$:这三条边构成回路 $A\to B\to C\to A$,而且顶点 $D$ 没有被覆盖,所以不是生成树。
4. 判断方法:选出 $n-1$ 条边后,检查它们是否连通(等价于检查是否无回路)。

**问题求解:最小生成树。** 给每条边赋予权重(成本),求总权重最小的生成树。**Kruskal 算法**是一种贪心策略:

1. 将所有边按权重从小到大排序。
2. 依次考察每条边;若加入它不会形成回路,就保留,否则跳过。
3. 当选中 $n-1$ 条边时停止。

设上图的权重为 $AB=1,\ BC=2,\ AC=3,\ CD=4,\ DA=5$。
- 取 $AB\,(1)$,保留。
- 取 $BC\,(2)$,保留。
- 取 $AC\,(3)$:$A,B,C$ 已经连通,加入会形成回路,跳过。
- 取 $CD\,(4)$,保留。此时已有 3 条边,停止。

最小总成本为 $1+2+4=7$。

判断是否会形成回路,常用**并查集**数据结构实现:

```python
def find(p, x):
    while p[x] != x:
        p[x] = p[p[x]]
        x = p[x]
    return x

def kruskal(n, edges):          # edges: (w, u, v)
    p = list(range(n)); total = 0
    for w, u, v in sorted(edges):
        ru, rv = find(p, u), find(p, v)
        if ru != rv:            # 不同分量,不成环
            p[ru] = rv; total += w
    return total
```

**应用与拓展。** 生成树出现在网络设计(最小成本布线)、交换机的生成树协议(消除网络环路)和聚类算法中。若图有 $n$ 个顶点且完全连通,Cayley 公式指出共有 $n^{n-2}$ 棵不同的生成树;当 $n=4$ 时有 $16$ 棵。解题时先确认图是否连通,再用"$n-1$ 条边、无回路"来检验答案。

### weighted_graph (0.4s)

## 加权图

**定义。** 加权图(weighted graph)是在普通图 $G=(V,E)$ 的基础上,给每条边再附加一个数值(称为**权重**)的图,记作 $G=(V,E,w)$,其中 $w:E\to\mathbb{R}$。权重可以表示距离、时间、费用、容量或相似度。图可以是有向的,也可以是无向的。一条路径的**总权重**等于路径上所有边的权重之和。需要注意:在加权图中,"最短路径"指总权重最小的路径,而不是经过边数最少的路径。

**例题。** 设有四个城市 $A,B,C,D$,各条道路的行驶时间(分钟)如下:

| 道路 | 时间 |
|---|---|
| $A$–$B$ | 4 |
| $A$–$C$ | 1 |
| $C$–$B$ | 2 |
| $B$–$D$ | 5 |
| $C$–$D$ | 8 |

求从 $A$ 到 $D$ 的最快路线。

先列出所有简单路径并求和:

- $A\to B\to D$:$4+5=9$
- $A\to C\to D$:$1+8=9$
- $A\to C\to B\to D$:$1+2+5=8$

最小值为 $8$,因此最快路线是 $A\to C\to B\to D$。它经过 3 条边,比前两条路线多一条,却更省时。这说明:边数最少并不等于总权重最小。

**问题求解应用。** 当图较大时,枚举所有路径不现实。若所有权重非负,可以使用 Dijkstra 算法:每一步选取"当前已知距离最小且尚未确定"的顶点,再用它来更新邻居的距离。在上例中:

1. 初始化:$d(A)=0$,其余为 $\infty$。
2. 确定 $A$:更新 $d(B)=4$,$d(C)=1$。
3. 确定 $C$(最小):经 $C$ 到 $B$ 为 $1+2=3<4$,所以 $d(B)=3$;$d(D)=1+8=9$。
4. 确定 $B$:经 $B$ 到 $D$ 为 $3+5=8<9$,所以 $d(D)=8$。

结果与枚举法一致。用 Python 实现时,可以借助优先队列:

```python
import heapq

def dijkstra(graph, start):
    dist = {v: float("inf") for v in graph}
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in graph[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(pq, (dist[v], v))
    return dist
```

**常见陷阱。** Dijkstra 算法要求权重非负;若存在负权边(如带有补贴的路段),应改用 Bellman–Ford 算法。若要连接所有顶点且总权重最小,需要求的是**最小生成树**(Prim 或 Kruskal 算法),而不是最短路径,这两类问题不要混淆。

**练习。** 把上例中 $C$–$B$ 的权重改为 $5$,重新求 $A$ 到 $D$ 的最短路径,并说明最优路线是否发生变化。

### cycle (13.5s)

## 循环

**定义。** 循环(cycle)是指在某个系统中,从一个状态出发,经过若干步骤后又回到起始状态的过程。在图论中,循环是一条起点与终点相同、且中途不重复经过其他顶点的路径。在更广泛的场景中,如水循环、程序中的迭代、经济周期,循环都表示"过程首尾相接、可以重复进行"的结构。判断循环的关键有两点:**能够回到起点**,以及**可以再次重复**。

**例题。** 考虑一个有向图,顶点为 $A, B, C, D$,边为 $A\to B,\ B\to C,\ C\to A,\ C\to D$。

问:图中是否存在循环?

解:从 $A$ 出发,依次沿 $A\to B\to C\to A$ 走,三步后回到 $A$,且中间的顶点 $B, C$ 没有重复,所以这是一个长度为 $3$ 的循环。顶点 $D$ 只有入边而没有出边,一旦进入就无法返回,因此 $D$ 不在任何循环中。

再看一个周期性的例子:某种细菌的生活周期为 $6$ 小时,在时刻 $t=0$ 处于状态 $S$。则对任意整数 $k$,在 $t=6k$ 时它都回到状态 $S$。这里"周期"就是循环走完一圈所需的时间。

**问题求解应用。** 循环的判断在实际问题中非常常见,下面是三类典型用法。

1. **检测依赖死锁。** 假设任务 $T_1$ 等待 $T_2$,$T_2$ 等待 $T_3$,$T_3$ 又等待 $T_1$。把"等待"画成有向边,就得到一个循环 $T_1\to T_2\to T_3\to T_1$,说明这些任务将永远互相等待。因此,**有向图中存在循环,等价于不可能给顶点排出一个满足所有依赖的先后顺序**(即无法做拓扑排序)。

2. **程序中的循环检测。** 在 Python 中,可以用深度优先搜索检测循环:

```python
def has_cycle(graph):
    state = {}  # 0=访问中, 1=已完成
    def dfs(u):
        state[u] = 0
        for v in graph.get(u, []):
            if state.get(v) == 0:        # 回到了"访问中"的点
                return True
            if v not in state and dfs(v):
                return True
        state[u] = 1
        return False
    return any(dfs(u) for u in list(graph) if u not in state)

g = {"A": ["B"], "B": ["C"], "C": ["A", "D"], "D": []}
print(has_cycle(g))  # True
```

关键思想是:如果搜索时遇到一个仍处于"访问中"的顶点,就说明沿当前路径绕了一圈又回来了,即发现了循环。

3. **周期性计算。** 若一个序列每 $p$ 步重复一次,则 $x_{n+p}=x_n$。例如星期几每 $7$ 天循环一次,问"今天是周三,$100$ 天后是星期几?"只需计算 $100 \bmod 7 = 2$,所以是周五。

**小结。** 遇到"首尾相接"的结构时,先找出一圈包含哪些状态,再确定一圈的长度,这样就能把无限重复的过程化简为一个有限的问题。

### minimum_spanning_tree (13.6s)

## 最小生成树

**定义。** 设 $G=(V,E)$ 是一个连通的带权无向图,每条边 $e$ 有权重 $w(e)$。$G$ 的**生成树**是包含全部顶点、连通且无环的子图,它恰有 $|V|-1$ 条边。所有生成树中总权重 $\sum_{e\in T} w(e)$ 最小的那一棵,就是**最小生成树**(MST)。典型场景:用最短的总线缆长度把若干座城市连成网络。

**两条关键性质。**
- **割性质**:把顶点分成两个非空集合,横跨两侧的所有边中,权重最小的边必属于某棵 MST(边权互不相同时)。
- **圈性质**:任何环中权重最大的边不会出现在 MST 中(边权互不相同时)。

两条性质保证了"贪心"的正确性:每一步选当前最安全的边,不会后悔。

**Kruskal 算法。** 将边按权重升序排列,依次考察;若加入某条边不会形成环,就选用它,直到选出 $|V|-1$ 条边。判断是否成环,通常用并查集(检查两端点是否已在同一连通分量)。

**例题。** 顶点为 $A,B,C,D,E$,边权如下:

| 边 | $AB$ | $BC$ | $AC$ | $CD$ | $BD$ | $DE$ | $CE$ |
|---|---|---|---|---|---|---|---|
| 权重 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |

按升序处理:
1. $AB(1)$:加入。
2. $BC(2)$:加入。
3. $AC(3)$:$A,C$ 已连通,会成环,跳过。
4. $CD(4)$:加入。
5. $BD(5)$:$B,D$ 已连通,跳过。
6. $DE(6)$:加入,此时已有 $4=|V|-1$ 条边,停止。

总权重为 $1+2+4+6=13$。

**问题求解应用。** 某地要用光纤连接 5 个村庄,上表的权重表示铺设成本(单位:万元)。问最低总造价是多少?

建模:村庄是顶点,可铺设的线路是边,成本是权重。要求"所有村庄互通且总成本最低",这正是 MST 问题。由上面的计算,最低造价为 13 万元,铺设线路 $AB, BC, CD, DE$。

下面是 Python 实现的核心片段:

```python
def kruskal(n, edges):
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    total, chosen = 0, []
    for w, u, v in sorted(edges):
        ru, rv = find(u), find(v)
        if ru != rv:
            parent[ru] = rv
            total += w
            chosen.append((u, v))
    return total, chosen
```

时间复杂度主要由排序决定,为 $O(|E|\log|E|)$。

**检验思路。** 解题时可用两点自查:选出的边数是否恰为 $|V|-1$;每条被舍弃的边,是否确实是它所在环中最重的边(圈性质)。若边权有相同的,MST 可能不唯一,但最小总权重一定唯一。

### kruskals_algorithm (13.4s)

## Kruskal 算法

**定义。** 给定一个连通的带权无向图,*最小生成树*(MST)是包含所有顶点、边权之和最小且不含环的边子集。Kruskal 算法用"贪心"策略求它:先把所有边按权重从小到大排序,然后依次考察每条边——如果加入这条边**不会形成环**,就选中它;否则跳过。当选出 $n-1$ 条边($n$ 为顶点数)时停止。

判断"是否成环"的关键工具是**并查集**(Union-Find):每个顶点属于某个连通分量。若一条边的两个端点已在同一分量,则加入它必然成环;若不在同一分量,就选中该边并合并这两个分量。

**例题。** 图有顶点 $A,B,C,D,E$,边及权重如下:

| 边 | AB | BC | AC | CD | DE | BD | CE |
|---|---|---|---|---|---|---|---|
| 权重 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |

按权重排序后依次处理:

1. $AB$(1):$A,B$ 不同分量,选中,合并为 $\{A,B\}$。
2. $BC$(2):$C$ 不在其中,选中,得 $\{A,B,C\}$。
3. $AC$(3):$A,C$ 已同属一个分量,选中会成环,**跳过**。
4. $CD$(4):选中,得 $\{A,B,C,D\}$。
5. $DE$(5):选中,得到全部 5 个顶点,已有 $4=n-1$ 条边,停止。

MST 的边为 $AB, BC, CD, DE$,总权重 $1+2+4+5=12$。

**问题求解应用。** 某地要用光缆连接 5 个村庄,每段光缆造价正比于距离,目标是在所有村庄互通的前提下使总造价最低。这正是 MST 问题:把村庄看作顶点,可铺设的线路看作带权边。下面是 Python 实现:

```python
def kruskal(n, edges):          # edges: (w, u, v)
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]   # 路径压缩
            x = parent[x]
        return x
    mst, total = [], 0
    for w, u, v in sorted(edges):
        ru, rv = find(u), find(v)
        if ru != rv:            # 不同分量才选中
            parent[ru] = rv
            mst.append((u, v)); total += w
    return mst, total
```

**复杂度。** 排序耗时 $O(E\log E)$,并查集操作近似常数,因此总复杂度为 $O(E\log E)$,等价于 $O(E\log V)$。边数较少的稀疏图上它尤其高效。

**为何贪心是正确的?** 其依据是*割性质*:对于任意把顶点分成两部分的割,跨越该割的最轻边必属于某棵 MST。Kruskal 每次选中的边,正是连接两个不同分量的最轻边,因此每一步都安全。

**常见错误。** 忘记检测环,或只比较边权而不检查连通分量;另外,若图不连通,算法得到的是*最小生成森林*,边数少于 $n-1$。
