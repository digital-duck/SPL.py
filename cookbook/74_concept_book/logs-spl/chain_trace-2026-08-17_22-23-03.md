## 基本情形

**定义**

递归是一种"把大问题拆成同类小问题"的策略，而**基本情形**（base case）是递归得以终止的那个出口。没有基本情形，函数会无限调用自身，最终导致栈溢出。形式上，一个递归定义由两部分构成：基本情形给出最小输入的直接答案，递归情形则将较大的输入化归为规模更小的同类问题。数学归纳法与此结构完全对应：基本情形对应归纳基础，递归情形对应归纳步骤。

**例题：计算阶乘**

定义 $n! = n \times (n-1) \times \cdots \times 1$，并约定 $0! = 1$。用递归写法：

$$
n! = \begin{cases} 1 & n = 0 \\ n \times (n-1)! & n \geq 1 \end{cases}
$$

这里 $n = 0$ 就是基本情形——它不再调用自身，直接返回 $1$。用 Python 实现：

```python
def factorial(n: int) -> int:
    if n == 0:          # 基本情形
        return 1
    return n * factorial(n - 1)   # 递归情形
```

追踪 `factorial(3)` 的调用链：

```
factorial(3) → 3 × factorial(2)
                    → 2 × factorial(1)
                          → 1 × factorial(0)
                                → 1        # 基本情形触发
```

返回时逐层展开：$1 \to 1 \to 2 \to 6$。

**解题应用**

判断一段递归代码是否正确，首先问两个问题：①基本情形是否覆盖了所有"最小输入"？②每次递归调用是否真的让输入规模缩小、最终到达基本情形？

考虑斐波那契数列 $F(n) = F(n-1) + F(n-2)$。这里需要**两个**基本情形：

```python
def fib(n: int) -> int:
    if n == 0:   # 基本情形 1
        return 0
    if n == 1:   # 基本情形 2
        return 1
    return fib(n - 1) + fib(n - 2)
```

若只写 `if n == 0` 而漏掉 `if n == 1`，调用 `fib(1)` 时会触发 `fib(0) + fib(-1)`，进而无限递归。这说明：**基本情形的数量和位置由问题本身决定，不能随意省略**。设计递归时，先把基本情形写对，再补递归情形，是最稳妥的顺序。

### induction_proof (0.0s)

## Induction Proof

**数学归纳法**是证明"对所有正整数 $n$ 成立"的命题时最常用的工具。它的逻辑结构只有两步：先验证最小情形，再证明"如果第 $k$ 步成立，那么第 $k+1$ 步也成立"。两步合并，就像多米诺骨牌——第一块倒下，后面每一块都跟着倒。

**形式化表述。** 设 $P(n)$ 是关于正整数 $n$ 的命题。若满足：

1. **基础步骤**：$P(1)$ 成立；
2. **归纳步骤**：对任意 $k \geq 1$，若 $P(k)$ 成立（归纳假设），则 $P(k+1)$ 也成立，

则 $P(n)$ 对所有正整数 $n$ 成立。

---

### 例题：证明前 $n$ 个正整数之和

**命题**：$\displaystyle 1 + 2 + \cdots + n = \frac{n(n+1)}{2}$

**基础步骤**：当 $n = 1$ 时，左边 $= 1$，右边 $= \dfrac{1 \cdot 2}{2} = 1$，成立。

**归纳假设**：设 $n = k$ 时命题成立，即

$$1 + 2 + \cdots + k = \frac{k(k+1)}{2}$$

**归纳步骤**：需证 $n = k+1$ 时也成立。在等式两边同时加上 $k+1$：

$$1 + 2 + \cdots + k + (k+1) = \frac{k(k+1)}{2} + (k+1) = (k+1)\left(\frac{k}{2} + 1\right) = \frac{(k+1)(k+2)}{2}$$

这正是将 $n = k+1$ 代入公式的结果，归纳步骤成立。由数学归纳法，命题对所有正整数 $n$ 成立。$\blacksquare$

---

### 解题应用

遇到需要归纳证明的题目，按以下流程操作：

1. **识别命题**：将待证结论写成关于 $n$ 的统一形式 $P(n)$。
2. **验证基础**：代入最小值（通常是 $n = 1$）直接计算。
3. **写出归纳假设**：明确假设 $P(k)$ 成立，把它当作已知条件。
4. **推导 $P(k+1)$**：从 $P(k)$ 出发，通过代数变形到达目标形式——这是最考验技巧的一步，关键在于把"$k+1$ 的情形"拆出"$k$ 的情形"加上一个新项。
5. **收尾**：说明两步均成立，结论成立。

常见错误是在归纳步骤中直接"假设结论成立"，绕过推导过程——那是循环论证，不是归纳证明。正确做法是只假设 $P(k)$，然后**推导**出 $P(k+1)$。

### reduction (20.0s)

## 归约（Reduction）

**归约**是一种将陌生问题转化为已知问题来求解的方法论。其核心思想是：如果问题 $A$ 可以被"归约"到问题 $B$，那么任何能解决 $B$ 的算法或工具都可以间接解决 $A$。归约不是直接求解，而是构造一个映射——把 $A$ 的输入转换成 $B$ 的输入，再将 $B$ 的输出反向解释为 $A$ 的答案。这一思想在算法设计、计算复杂度理论和数学建模中无处不在。

**示例：最大独立集归约为最小顶点覆盖**

给定一个图 $G = (V, E)$，**最大独立集**（Max Independent Set）要求找到顶点子集 $S \subseteq V$，使得 $S$ 中任意两点之间没有边，且 $|S|$ 最大。**最小顶点覆盖**（Min Vertex Cover）要求找到最小子集 $C \subseteq V$，使得每条边至少有一个端点在 $C$ 中。

这两个问题看似无关，但存在一个精妙的归约：若 $S$ 是最大独立集，则 $V \setminus S$ 是最小顶点覆盖；反之亦然。因此：

$$|S^*| + |C^*| = |V|$$

其中 $S^*$ 和 $C^*$ 分别是最优解。这意味着，只要能解决其中一个问题，另一个问题的答案立刻可得——无需重新发明算法。

**问题求解应用：将排序问题归约为比较问题**

归约也可以是更朴素、实用的。考虑一个新问题：给定一组区间 $[l_i, r_i]$，按区间长度升序排列。你不需要"重新发明"排序——只需将每个区间映射为其长度 $d_i = r_i - l_i$，然后对 $(d_i, i)$ 对运行标准排序算法，再按结果索引还原原始区间。这就是归约：把"区间排序"归约为"数字排序"。

识别归约的关键问题是：**这个新问题和哪个已知问题在结构上最相似？** 归约成立的条件是：转换步骤的代价远低于直接求解的代价，且 $B$ 的解确实能被无损地"翻译回" $A$ 的解。掌握归约思维，意味着你的工具箱从单个算法扩展为一张可复用的问题网络。

### recursion (17.2s)

## 递归

**递归**是指一个函数在其定义中调用自身的编程技巧。它将一个复杂问题分解为更小的同类子问题，直到问题简单到可以直接求解为止。每个递归函数都必须包含两个要素：**基本情形**（base case，直接返回结果，不再递归）和**递归情形**（recursive case，将问题规模缩小后调用自身）。若缺少基本情形，函数将无限调用自身，最终导致栈溢出。

---

**从阶乘看递归的逻辑**

计算 $n!$ 是理解递归的经典入口。其数学定义本身就是递归的：

$$n! = \begin{cases} 1 & n = 0 \\ n \times (n-1)! & n \geq 1 \end{cases}$$

用 Python 直接翻译这个定义：

```python
def factorial(n):
    if n == 0:          # 基本情形
        return 1
    return n * factorial(n - 1)  # 递归情形

print(factorial(5))  # 输出 120
```

调用 `factorial(5)` 时，程序依次展开：$5 \times 4! \to 5 \times 4 \times 3! \to \cdots \to 5 \times 4 \times 3 \times 2 \times 1 \times 1$，再逐层返回结果。关键在于：每次调用都让 $n$ 减小 1，保证最终触及基本情形。

---

**实战：用递归遍历嵌套结构**

递归真正的威力体现在处理**层级不确定的结构**上，循环在这里往往力不从心。假设需要计算一个任意嵌套列表中所有整数的总和：

```python
def deep_sum(data):
    total = 0
    for item in data:
        if isinstance(item, list):   # 遇到子列表，递归处理
            total += deep_sum(item)
        else:
            total += item            # 基本情形：直接累加
    return total

nested = [1, [2, [3, 4], 5], [6, 7]]
print(deep_sum(nested))  # 输出 28
```

此处的"基本情形"是遇到整数时直接返回其值；"递归情形"是遇到列表时再次调用 `deep_sum`。无论嵌套多少层，结构相同，逻辑不变。

设计递归函数时，建议先问自己两个问题：**最小的、可直接回答的情形是什么？** 以及 **如何把当前问题缩减为更小的同类问题？** 能清晰回答这两个问题，递归结构便自然浮现。

## 分而治之

**定义**

分而治之（Divide and Conquer）是一种递归算法设计策略：将一个规模较大的问题拆分为若干结构相同的子问题，分别求解后再将子问题的结果合并，得到原问题的答案。这一策略的核心在于"拆分—递归—合并"三个步骤的循环应用。

**经典示例：归并排序**

归并排序（Merge Sort）是分而治之最典型的应用。对一个长度为 $n$ 的数组排序时，算法分三步进行：

1. **拆分**：将数组从中间一分为二，得到左右两个子数组。
2. **递归**：对左、右子数组分别递归地调用归并排序，直到子数组长度为 1（天然有序）。
3. **合并**：将两个已排序的子数组逐一比较，按序合并为一个有序数组。

```python
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left  = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    return result + left[i:] + right[j:]
```

每一层递归将问题规模减半，共有 $\log_2 n$ 层；每层合并的总操作数为 $O(n)$，因此整体时间复杂度为 $O(n \log n)$，显著优于简单选择排序的 $O(n^2)$。

**问题求解应用**

分而治之的适用性远不止排序。遇到以下信号时，可以考虑这一策略：

- 问题可以自然地分解为**结构相同、规模更小**的子问题；
- 子问题之间**相互独立**，结果可直接合并；
- 暴力枚举的复杂度难以接受，需要借助递归压缩搜索空间。

例如，在一个含 $n$ 个元素的**有序**数组中查找目标值，二分搜索每次排除一半候选元素，将 $O(n)$ 的线性搜索压缩为 $O(\log n)$。解题时，先问自己："能否将问题规模减半，并用相同方法处理每一半？"若答案是肯定的，分而治之往往是最自然的起点。
