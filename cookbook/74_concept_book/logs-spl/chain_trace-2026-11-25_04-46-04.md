### connected_graph (0.4s)

## 连通图

**定义。** 在无向图 $G=(V,E)$ 中，如果任意两个顶点 $u,v\in V$ 之间都存在一条路径（即由边首尾相接构成的顶点序列），则称 $G$ 是**连通图**。如果存在一对顶点无法互相到达，则 $G$ 是**非连通图**。非连通图会分裂成若干个互不相连的**连通分量**，每个连通分量本身是连通的。

连通性是"网络是否完整"的基本判据：城市道路能否让每个路口互通，计算机网络里每台机器能否互相通信，都是在问同一个问题。

在有向图中，要求更严格。若任意两点之间都存在双向的有向路径，则称为**强连通**。若只在忽略边的方向后连通，则称为**弱连通**。

**例题。** 设图 $G$ 的顶点集为 $\{A,B,C,D,E\}$，边集为
$$E=\{AB,\ BC,\ CA,\ DE\}.$$
判断 $G$ 是否连通。

从 $A$ 出发做广度优先搜索（BFS）：

1. 访问 $A$，其邻居为 $B$、$C$；
2. 访问 $B$、$C$，它们的邻居都已访问过；
3. 队列为空，搜索结束。

已访问的顶点为 $\{A,B,C\}$，而 $D$、$E$ 没有被访问到。因此 $G$ 不连通，它有两个连通分量：$\{A,B,C\}$ 和 $\{D,E\}$。

**问题求解应用。** 判断连通性的标准方法是：从任一顶点出发做一次 BFS 或 DFS，检查访问到的顶点数是否等于 $|V|$。时间复杂度为 $O(|V|+|E|)$。用 Python 实现如下：

```python
from collections import deque

def is_connected(graph):
    start = next(iter(graph))
    seen = {start}
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in seen:
                seen.add(v)
                queue.append(v)
    return len(seen) == len(graph)

g = {"A": ["B", "C"], "B": ["A", "C"], "C": ["A", "B"],
     "D": ["E"], "E": ["D"]}
print(is_connected(g))  # False
```

**一个常用的计数结论。** 一个有 $n$ 个顶点的连通图至少有 $n-1$ 条边，恰好有 $n-1$ 条边的连通图就是**树**。因此，如果一个图有 $n$ 个顶点却少于 $n-1$ 条边，可以立刻断定它不连通，不必再做搜索。

**应用练习。** 一个通信网络有 8 台服务器和 6 条链路。它能否连通？

因为 $6<8-1=7$，所以网络必定不连通。要使它连通，至少还需要增加 $1$ 条链路。

**小结。** 判断连通性有两步：先用边数做快速检查（$|E|<|V|-1$ 则必不连通），再用 BFS 或 DFS 做确切判断。连通分量的个数还能告诉你，要让整个网络连通，至少需要增加多少条边：若有 $k$ 个连通分量，则至少需要再加 $k-1$ 条边。

### tree (0.6s)

## 树

**定义。** 树(tree)是一种由节点和边构成的连通图,且其中没有环。通俗地说,树就像一棵倒过来画的家谱:最上面有一个特殊的节点,称为**根**;每个节点向下可以连接若干**子节点**;没有子节点的节点称为**叶**。一棵含有 $n$ 个节点的树恰好有 $n-1$ 条边。这个数量关系很有用:少一条边,图就不连通;多一条边,就会出现环。

树中还有几个常用术语:

- **深度**:从根到某节点所经过的边数。
- **高度**:整棵树中最大的深度。
- **二叉树**:每个节点至多有两个子节点的树。

**例题。** 某文件系统的结构如下:根目录 `/` 下有 `home` 和 `etc` 两个文件夹;`home` 下有 `alice` 和 `bob`;`alice` 下有 `notes.txt` 和 `pic.png`。

1. 节点数:`/`、`home`、`etc`、`alice`、`bob`、`notes.txt`、`pic.png`,共 $n=7$ 个。
2. 边数:$7-1=6$ 条,可逐条数出来验证。
3. 叶:`etc`、`bob`、`notes.txt`、`pic.png`。
4. `notes.txt` 的深度为 3(路径 `/` → `home` → `alice` → `notes.txt`),这也是整棵树的高度。

由于树中没有环,从根到任一节点的路径是**唯一**的,所以文件路径才能准确定位一个文件。

**问题求解应用。** 树最常见的用法是递归遍历。下面的代码用嵌套字典表示树,并计算它的高度:

```python
def height(node):
    children = node.get("children", [])
    if not children:          # 叶:高度为 0
        return 0
    return 1 + max(height(c) for c in children)

tree = {"name": "/", "children": [
    {"name": "home", "children": [
        {"name": "alice", "children": [
            {"name": "notes.txt"}, {"name": "pic.png"}]},
        {"name": "bob"}]},
    {"name": "etc"}]}

print(height(tree))   # 输出 3
```

思路是:一棵树的高度等于最高子树的高度加 1。这种"把大问题拆成同类的子问题"的思路,同样适用于求节点总数、查找文件、判断某个节点是否在树中等问题。

再看一个计数问题:一棵完全二叉树的高度为 $h$,且每一层都被填满。它的节点总数是多少?第 $k$ 层有 $2^k$ 个节点,所以

$$n=\sum_{k=0}^{h}2^k=2^{h+1}-1.$$

反过来,$n$ 个节点的满二叉树高度约为 $\log_2 n$。因此,在平衡的二叉搜索树中查找数据,只需要大约 $\log_2 n$ 步。例如 $n=1{,}000{,}000$ 时,大约只需 20 步,而逐个检查可能需要上百万次。这就是树在数据库索引、决策树和语法分析中被广泛使用的原因。

**练习。** 若一棵树有 15 个节点,它有多少条边?若它是高度最小的二叉树,高度是多少?(答案:14 条边;高度为 3。)

### routing_protocol (0.6s)

## 路由协议

**定义。** 路由协议(routing protocol)是网络中的路由器之间用来交换信息、并据此自动计算“数据包下一步该往哪走”的一套规则。它的核心任务是维护每台路由器的**路由表**:对每个目的网络,记录应当从哪个接口、交给哪个下一跳转发。静态路由由人工配置,网络变化时需要手动修改;路由协议则让路由器自动发现拓扑、在链路故障时重新计算路径。

常见协议按算法分为两类:

- **距离向量**(如 RIP):每台路由器只告诉邻居“我到各网络的距离”,以跳数等简单度量选路。
- **链路状态**(如 OSPF):每台路由器向全网广播自己的链路信息,各自构建完整拓扑图,再用最短路径算法计算路由。

按作用范围又可分为域内协议(RIP、OSPF)和域间协议(BGP,用于互联网中不同自治系统之间)。

**worked example:距离向量更新。** 设路由器 A、B、C 依次相连,链路代价均为 1。起初 A 只知道直连网络。B 向 A 通告:“我到网络 N(挂在 C 后面)的距离是 1。”A 据此更新:

$$d_A(N) = \min\big(d_A(N),\; c(A,B) + d_B(N)\big) = 1 + 1 = 2$$

于是 A 的路由表新增一条:目的 N,下一跳 B,距离 2。这就是 Bellman-Ford 更新:到目的地的新距离等于“到邻居的代价”加上“邻居报告的距离”,取最小值。

**问题求解应用。** 现在 A 与 C 之间新增一条直连链路,代价为 5,同时 B–C 链路代价为 1,A–B 为 1。A 到 C 有两条路径:

1. 直连:代价 5;
2. 经 B:$1 + 1 = 2$。

距离向量更新取最小值,A 选择经 B 的路径,下一跳为 B。若此后 B–C 链路故障,B 会通告 $d_B(C)=\infty$,A 重新比较:经 B 不可达,直连代价 5 成为最优,路由表自动切换,无需人工介入。

这里也暴露了距离向量的缺陷:收敛慢,可能出现“计数到无穷”的环路问题,实践中用水平分割、最大跳数(RIP 以 16 表示不可达)等手段缓解。链路状态协议因为每台路由器都掌握全图,用 Dijkstra 算法直接计算,收敛更快,但需要更多内存与计算。

**选择建议。** 小型、结构简单的网络可用 RIP;企业或校园的大中型内部网络通常选 OSPF;跨组织互联则必须使用 BGP,并依靠策略(而非单纯最短路径)决定路由。

**小结。** 路由协议 = 信息交换 + 路径计算 + 故障自适应。理解它的关键,是看清每台路由器“知道什么、向谁通告什么、如何据此更新路由表”。

### spanning_tree (0.5s)

## 生成树

**定义。** 设 $G=(V,E)$ 是一个连通的无向图。$G$ 的**生成树**是这样一个子图 $T$:它包含 $G$ 的全部顶点,只使用 $G$ 的部分边,并且连通且不含回路。要点是"覆盖所有顶点"与"没有多余的边"。若 $|V|=n$,则任何生成树恰好有 $n-1$ 条边:再少一条就不连通,再多一条就会产生回路。

**直观理解。** 想象要用光纤连接 5 个校区。我们希望每两个校区之间都能通信(连通),但每多铺一条光纤就多一份成本。生成树给出的就是"刚好够用"的铺设方案。

**例题。** 设图 $G$ 有顶点 $A,B,C,D$,边为 $AB,\ BC,\ CD,\ DA,\ AC$,共 5 条边。

1. $n=4$,所以生成树需要 $n-1=3$ 条边。
2. 取 $\{AB, BC, CD\}$:四个顶点都被连通,没有回路,所以是生成树。
3. 取 $\{AB, BC, AC\}$:这三条边构成回路 $A\to B\to C\to A$,而且顶点 $D$ 没有被覆盖,所以不是生成树。
4. 判断方法:选出 $n-1$ 条边后,检查它们是否连通(等价于检查是否无回路)。

**问题求解:最小生成树。** 给每条边赋予权重(成本),求总权重最小的生成树。**Kruskal 算法**是一种贪心策略:

1. 将所有边按权重从小到大排序。
2. 依次考察每条边;若加入它不会形成回路,就保留,否则跳过。
3. 当选中 $n-1$ 条边时停止。

设上图的权重为 $AB=1,\ BC=2,\ AC=3,\ CD=4,\ DA=5$。
- 取 $AB\,(1)$,保留。
- 取 $BC\,(2)$,保留。
- 取 $AC\,(3)$:$A,B,C$ 已经连通,加入会形成回路,跳过。
- 取 $CD\,(4)$,保留。此时已有 3 条边,停止。

最小总成本为 $1+2+4=7$。

判断是否会形成回路,常用**并查集**数据结构实现:

```python
def find(p, x):
    while p[x] != x:
        p[x] = p[p[x]]
        x = p[x]
    return x

def kruskal(n, edges):          # edges: (w, u, v)
    p = list(range(n)); total = 0
    for w, u, v in sorted(edges):
        ru, rv = find(p, u), find(p, v)
        if ru != rv:            # 不同分量,不成环
            p[ru] = rv; total += w
    return total
```

**应用与拓展。** 生成树出现在网络设计(最小成本布线)、交换机的生成树协议(消除网络环路)和聚类算法中。若图有 $n$ 个顶点且完全连通,Cayley 公式指出共有 $n^{n-2}$ 棵不同的生成树;当 $n=4$ 时有 $16$ 棵。解题时先确认图是否连通,再用"$n-1$ 条边、无回路"来检验答案。

### sink_tree (0.7s)

## 汇点树(Sink Tree)

**定义。** 在网络路由中,选定一个目的节点 $t$(称为汇点)。对每个源节点,把它到 $t$ 的所有最优路径(按跳数、延迟或代价衡量)合并起来,得到的结构是一棵以 $t$ 为根的树,称为汇点树。它依赖**最优性原理**:若路由器 $J$ 位于 $I$ 到 $K$ 的最优路径上,则 $J$ 到 $K$ 的最优路径必是该路径的后半段。因此所有最优路径在汇合后不会再分开,合起来没有环,形成一棵树。

汇点树有 $n$ 个节点、$n-1$ 条边,任何分组最多经过 $n-1$ 跳到达目的地。路由算法的任务,就是为每个目的地找出并维护这样一棵树。

**例题。** 设网络有节点 A、B、C、D、E,各链路代价如下:

- A–B:2,A–C:5
- B–C:2,B–D:4
- C–D:1,C–E:3
- D–E:1

以 E 为汇点,求各节点到 E 的最短路径。

1. E 的邻居是 C(3)和 D(1),所以 D 到 E 的代价为 1,C 到 E 的代价暂记为 3。
2. C 经 D 到 E 的代价为 $1+1=2<3$,所以 C 的下一跳是 D,代价为 2。
3. B 的候选路径有:经 C 为 $2+2=4$,经 D 为 $4+1=5$。取经 C 的路径,代价为 4。
4. A 的候选路径有:经 B 为 $2+4=6$,经 C 为 $5+2=7$。取经 B 的路径,代价为 6。

汇点树的边为 D→E、C→D、B→C、A→B,共 4 条,正好是 $n-1=4$。注意 C 的最优路径 C→D→E 是 B 的最优路径 B→C→D→E 的后半段,这正是最优性原理的体现。

**应用。** 汇点树能解决三类实际问题。

*(1)转发表构造。* 每个路由器只需记住自己在树上的"父节点",即到该目的地的下一跳。在上例中,A 的转发表里,目的地 E 对应的下一跳是 B。

*(2)故障分析。* 若链路 C–D 中断,树要重新计算:C 改走 C–E 直连(代价 3),B 的代价变为 $2+3=5$,与经 D 的路径 $4+1=5$ 相同,出现平局,需要用确定的规则选择,否则可能产生环路。

*(3)广播与组播。* 汇点树的反向结构可用于从一点向全网分发报文,每条链路只传一次。

**练习。** 在上例中,若 B–C 的代价改为 6,重新求以 E 为汇点的树。(提示:B 的两条候选路径代价分别是 $6+2=8$ 和 $4+1=5$,所以 B 改用 D 作下一跳,A 的代价也随之变化。)

**说明。** 实际网络中的拓扑和代价会不断变化,汇点树只是一个理想模型。距离向量协议和链路状态协议,都是在近似地计算并维护这样的树。

### weighted_graph (0.6s)

## 加权图

**定义。** 加权图(weighted graph)是在普通图 $G=(V,E)$ 的基础上,给每条边再附加一个数值(称为**权重**)的图,记作 $G=(V,E,w)$,其中 $w:E\to\mathbb{R}$。权重可以表示距离、时间、费用、容量或相似度。图可以是有向的,也可以是无向的。一条路径的**总权重**等于路径上所有边的权重之和。需要注意:在加权图中,"最短路径"指总权重最小的路径,而不是经过边数最少的路径。

**例题。** 设有四个城市 $A,B,C,D$,各条道路的行驶时间(分钟)如下:

| 道路 | 时间 |
|---|---|
| $A$–$B$ | 4 |
| $A$–$C$ | 1 |
| $C$–$B$ | 2 |
| $B$–$D$ | 5 |
| $C$–$D$ | 8 |

求从 $A$ 到 $D$ 的最快路线。

先列出所有简单路径并求和:

- $A\to B\to D$:$4+5=9$
- $A\to C\to D$:$1+8=9$
- $A\to C\to B\to D$:$1+2+5=8$

最小值为 $8$,因此最快路线是 $A\to C\to B\to D$。它经过 3 条边,比前两条路线多一条,却更省时。这说明:边数最少并不等于总权重最小。

**问题求解应用。** 当图较大时,枚举所有路径不现实。若所有权重非负,可以使用 Dijkstra 算法:每一步选取"当前已知距离最小且尚未确定"的顶点,再用它来更新邻居的距离。在上例中:

1. 初始化:$d(A)=0$,其余为 $\infty$。
2. 确定 $A$:更新 $d(B)=4$,$d(C)=1$。
3. 确定 $C$(最小):经 $C$ 到 $B$ 为 $1+2=3<4$,所以 $d(B)=3$;$d(D)=1+8=9$。
4. 确定 $B$:经 $B$ 到 $D$ 为 $3+5=8<9$,所以 $d(D)=8$。

结果与枚举法一致。用 Python 实现时,可以借助优先队列:

```python
import heapq

def dijkstra(graph, start):
    dist = {v: float("inf") for v in graph}
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in graph[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(pq, (dist[v], v))
    return dist
```

**常见陷阱。** Dijkstra 算法要求权重非负;若存在负权边(如带有补贴的路段),应改用 Bellman–Ford 算法。若要连接所有顶点且总权重最小,需要求的是**最小生成树**(Prim 或 Kruskal 算法),而不是最短路径,这两类问题不要混淆。

**练习。** 把上例中 $C$–$B$ 的权重改为 $5$,重新求 $A$ 到 $D$ 的最短路径,并说明最优路线是否发生变化。

### dijkstras_sink_tree_algorithm (0.7s)

## 迪杰斯特拉汇树算法

**定义。** 在一个带非负边权的有向图中,若要求出*所有*结点到某个固定目标结点 $t$(称为"汇")的最短路径,可以使用迪杰斯特拉汇树算法。它把经典的单源迪杰斯特拉算法作用于**反向图**(把每条边 $u\to v$ 反转为 $v\to u$,权重不变),从 $t$ 出发扩展。最终得到的最短路径树以 $t$ 为根,每个结点 $v$ 记录一个"下一跳" $\text{next}(v)$,沿着下一跳一路走下去就会到达 $t$。这棵树就是**汇树**(sink tree)。路由协议中,每台路由器只需存储通往目的地的下一跳,正是汇树的思想。

**算法步骤。**
1. 令 $d(t)=0$,其余结点 $d(v)=\infty$。
2. 每次从未确定的结点中取出 $d$ 最小的结点 $u$,将其标记为已确定。
3. 对原图中每条边 $v\to u$(权重 $w$),若 $d(u)+w<d(v)$,则更新 $d(v)=d(u)+w$,并令 $\text{next}(v)=u$。
4. 重复步骤 2–3,直到所有结点都已确定。

**例题。** 设有边:$A\to B$(4),$A\to C$(1),$C\to B$(2),$B\to T$(3),$C\to T$(6)。求所有结点到 $T$ 的最短路径。

- 初始:$d(T)=0$。确定 $T$。检查指向 $T$ 的边:$d(B)=3$,$\text{next}(B)=T$;$d(C)=6$,$\text{next}(C)=T$。
- 取最小的 $B$($d=3$)。指向 $B$ 的边:$A\to B$ 给出 $d(A)=7$;$C\to B$ 给出 $2+3=5<6$,于是更新 $d(C)=5$,$\text{next}(C)=B$。
- 取 $C$($d=5$)。边 $A\to C$ 给出 $1+5=6<7$,更新 $d(A)=6$,$\text{next}(A)=C$。
- 取 $A$,算法结束。

汇树为:$A\to C\to B\to T$,距离分别是 $d(A)=6,\ d(C)=5,\ d(B)=3$。注意 $C$ 的直连边($6$)并不是最优,经 $B$ 绕行反而更短。

**问题求解应用。** 某物流网络中,有数十个仓库,所有货物最终都要送往同一个港口 $T$。若对每个仓库分别运行一次单源算法,需要重复计算很多次;而用汇树算法只需**运行一次**,就能得到每个仓库的最优路线和总成本。当某条道路封闭(边权变为 $\infty$)时,只需重新计算受影响的子树即可。

**为什么正确。** 非负权重保证:一旦结点 $u$ 以最小的 $d(u)$ 被确定,之后不可能有更短的路径到达它,因为任何其他路径都必须先经过某个距离不小于 $d(u)$ 的未确定结点,再加上非负的边权。使用二叉堆实现时,时间复杂度为 $O\big((|V|+|E|)\log|V|\big)$。

**常见错误:** 忘记反转边的方向,或在含负权边的图中使用此算法,都会导致错误结果。
