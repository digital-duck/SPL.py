## Graph

A graph is a mathematical structure for representing pairwise relationships between objects. Formally, a graph is an ordered pair $G = (V, E)$, where $V$ is a finite set of *vertices* (also called nodes) and $E$ is a set of *edges*, each edge joining exactly two vertices. If the pair is unordered, $\{u, v\}$, the edge is *undirected* and the graph models a symmetric relationship (e.g., "is friends with"); if the pair is ordered, $(u, v)$, the edge is *directed*, and the graph models an asymmetric relationship (e.g., "points to" or "must precede"). The size of a graph is described by $|V| = n$ vertices and $|E| = m$ edges, and every vertex $v$ has a *degree* — the number of edges incident to it — written $\deg(v)$.

**Worked example.** Consider a small social network with $V = \{A, B, C, D\}$ and $E = \{\{A,B\}, \{B,C\}, \{C,D\}, \{A,D\}\}$. This graph can be drawn as a square: $A$—$B$—$C$—$D$—$A$. Every vertex has degree 2, and summing degrees gives $2+2+2+2 = 8 = 2|E|$, illustrating the handshake lemma:
$$\sum_{v \in V} \deg(v) = 2|E|$$
This identity holds for any undirected graph because each edge contributes exactly 1 to the degree count of each of its two endpoints.

**Problem-solving application.** Graphs are the natural representation whenever a problem involves connections rather than raw values — road networks (vertices = intersections, edges = roads), dependency chains (vertices = tasks, edges = "must finish before"), or communication networks (vertices = servers, edges = links). The first modeling decision is always: *should edges be directed, and should they carry weights?* An unweighted, undirected graph like the one above is well-suited to a reachability question — e.g., is there a path from $A$ to $C$? — while a weighted directed graph is needed to model something like flight routes with cost or duration. In code, a graph is typically stored as an adjacency list, a dictionary mapping each vertex to its neighbors:

```python
graph = {
    "A": ["B", "D"],
    "B": ["A", "C"],
    "C": ["B", "D"],
    "D": ["C", "A"],
}
```

This representation, using $O(n + m)$ space, underlies the traversal and shortest-path algorithms — breadth-first search, depth-first search, Dijkstra's algorithm — that turn the abstract structure $G = (V, E)$ into a tool for solving concrete routing, scheduling, and connectivity problems.
