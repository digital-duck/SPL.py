## Vertex Coloring

A **vertex coloring** of a graph assigns a color to every vertex so that no two adjacent vertices share the same color. The minimum number of colors needed to achieve this is called the **chromatic number**, written $\chi(G)$. Vertex coloring shows up wherever you need to partition things that conflict: scheduling exams so no student has two at once, allocating radio frequencies so nearby towers don't interfere, or assigning register slots in a compiler so live variables don't collide.

**Worked Example.** Consider a cycle graph $C_5$ — five vertices arranged in a pentagon, each connected to its two neighbors. Can you color it with two colors? Start at vertex 1 and alternate: red, blue, red, blue… but vertex 5 is adjacent to both vertex 4 (blue) and vertex 1 (red), so it needs a third color. Therefore $\chi(C_5) = 3$. Any odd cycle requires three colors; any even cycle needs only two. This simple observation already tells you something useful: if a graph contains an odd cycle, it cannot be 2-colored (bipartite).

**Problem-Solving Application.** Suppose a university must schedule seven final exams. Two exams conflict if at least one student is enrolled in both. Build a conflict graph: each exam is a vertex, and draw an edge between two exams whenever they conflict. Finding a valid exam schedule that uses the fewest time slots is exactly finding $\chi(G)$.

```python
import networkx as nx

G = nx.Graph()
G.add_edges_from([
    ("Math", "Physics"), ("Math", "CS"),
    ("Physics", "CS"), ("CS", "Bio"),
    ("Bio", "Chem"), ("Chem", "History")
])

coloring = nx.coloring.greedy_color(G, strategy="largest_first")
num_slots = max(coloring.values()) + 1

print(f"Time slots needed: {num_slots}")
for exam, slot in sorted(coloring.items(), key=lambda x: x[1]):
    print(f"  Slot {slot}: {exam}")
```

The greedy algorithm assigns colors in decreasing degree order — high-conflict exams get scheduled first. It doesn't always find the true minimum, but it produces a valid coloring quickly. Finding the exact chromatic number is NP-hard in general, so in practice greedy heuristics and approximation algorithms dominate. The key insight to carry forward: whenever you face a resource-assignment problem with pairwise conflicts, model it as a graph and reach for vertex coloring.

### chromatic_number (14.4s)

## Chromatic Number

The **chromatic number** of a graph $G$, written $\chi(G)$, is the minimum number of colors needed to color every vertex so that no two adjacent vertices share the same color. "Adjacent" means connected by an edge — the rule is purely local, but satisfying it across the whole graph can be surprisingly demanding.

This is not just a puzzle. Scheduling problems, register allocation in compilers, and frequency assignment in wireless networks all reduce to graph coloring: two things that conflict get different colors, and $\chi(G)$ tells you the fewest resources you need.

**Worked example.** Consider a cycle on five vertices — a pentagon $C_5$. Label the vertices $1, 2, 3, 4, 5$ around the ring. Try two colors: assign color A to vertex 1, then B to 2, A to 3, B to 4 — but vertex 5 is adjacent to both 4 (color B) and 1 (color A), so it needs a third color. Three colors work: A, B, A, B, C in order. Therefore $\chi(C_5) = 3$.

A key observation: any odd cycle requires 3 colors; any even cycle requires only 2 (it is **bipartite**). More generally, $\chi(G) = 2$ if and only if $G$ is bipartite and has at least one edge.

**Problem-solving application.** Suppose a university must schedule seven exams, and two exams conflict if any student is enrolled in both. Build a conflict graph: vertices are exams, edges connect conflicting pairs. Finding $\chi(G)$ gives the minimum number of time slots needed.

In practice, computing $\chi(G)$ exactly is NP-hard for general graphs, so you reach for bounds and heuristics. Two useful bounds:

- **Lower bound:** if the graph contains a clique of size $k$ (every pair connected), then $\chi(G) \geq k$.
- **Upper bound (greedy):** process vertices in some order; assign each vertex the smallest color not used by its already-colored neighbors. This greedy algorithm uses at most $\Delta(G) + 1$ colors, where $\Delta(G)$ is the maximum degree.

For the exam-scheduling graph, compute the maximum clique size to get a floor on slots, then run greedy coloring to get a concrete schedule — the gap between the two bounds tells you how much room for improvement remains.

## Class Scheduling Application

A **class scheduling problem** asks: given a set of courses, students enrolled in them, and a fixed number of time slots, assign every course to a slot so that no student is required to be in two places at once. This is one of the most natural applications of **graph coloring**. Model each course as a vertex; draw an edge between two courses whenever at least one student is enrolled in both. A valid schedule is then a proper coloring of this graph — assign a "color" (time slot) to each vertex so that no two adjacent vertices share a color. The minimum number of slots needed equals the chromatic number $\chi(G)$ of the conflict graph $G$.

**Worked example.** Suppose a school offers four courses — Math (M), Biology (B), History (H), and Art (A) — and three students have the following enrollments:

| Student | Courses |
|---------|---------|
| 1 | M, B |
| 2 | B, H |
| 3 | M, H, A |

Build the conflict graph: Student 1 forces edge $M\text{–}B$; Student 2 forces $B\text{–}H$; Student 3 forces $M\text{–}H$, $M\text{–}A$, and $H\text{–}A$. The resulting graph has a triangle $\{M, H, A\}$, which requires at least three colors. Assigning Slot 1 → M, Slot 2 → H, Slot 3 → A, then checking B: it conflicts with M (Slot 1) and H (Slot 2), so B goes in Slot 3. Final schedule: **Slot 1**: Math; **Slot 2**: History; **Slot 3**: Biology, Art. Every student's courses land in different slots — the schedule is conflict-free.

**Problem-solving application.** In practice, building this model by hand scales poorly. A greedy coloring algorithm — repeatedly assign the lowest-numbered available slot to each uncolored vertex — runs in $O(V + E)$ time and produces a workable schedule quickly, though it may use more slots than $\chi(G)$. For tighter solutions, degree-first ordering (color high-degree vertices first) reduces wasted slots. Real schedulers layer in additional constraints — room capacity, instructor availability, back-to-back penalties — turning the pure graph-coloring problem into an **integer linear program** or a **constraint satisfaction problem (CSP)** solved with branch-and-bound or local search. Recognizing the graph-coloring skeleton underneath, however, lets you reason about lower bounds ($\chi(G) \geq$ clique number) and spot when a conflict graph is bipartite (two slots always suffice).
