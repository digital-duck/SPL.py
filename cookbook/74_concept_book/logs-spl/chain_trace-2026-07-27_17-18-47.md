### recursion (0.0s)

## Recursion

**Definition.** A function $f$ is defined *recursively* if its value at an argument is expressed in terms of its value at one or more strictly simpler arguments, together with one or more *base cases* that terminate the descent. Formally, a recursive definition specifies:

1. **Base case(s):** explicit values $f(n_0), f(n_1), \ldots$ for the smallest inputs.
2. **Recursive case:** a rule $f(n) = g\bigl(n,\, f(n-1),\, f(n-2),\ldots\bigr)$ for $n$ beyond the base cases, where $g$ involves only arguments strictly less than $n$.

Well-foundedness—the guarantee that repeated application of the recursive case always reaches a base case—is what separates a valid recursive definition from a circular one.

**Worked example: the factorial function.** Define $n!$ for $n \in \mathbb{N}_0$ by

$$
0! = 1, \qquad n! = n \cdot (n-1)! \quad \text{for } n \geq 1.
$$

Computing $4!$ unwinds as follows:

$$
4! = 4 \cdot 3! = 4 \cdot 3 \cdot 2! = 4 \cdot 3 \cdot 2 \cdot 1! = 4 \cdot 3 \cdot 2 \cdot 1 \cdot 0! = 24.
$$

Each call reduces $n$ by $1$; since $n$ is a non-negative integer, the chain terminates at $0!$ in exactly $n$ steps. The *call stack* at depth $k$ holds the pending multiplication $k \cdot (\cdots)$, so the process requires $O(n)$ space as well as $O(n)$ time.

**Key theorem (Structural Induction Principle).** Let $P(n)$ be a property of natural numbers. If $P(0)$ holds, and $P(k)$ implies $P(k+1)$ for every $k \geq 0$, then $P(n)$ holds for all $n \in \mathbb{N}_0$. This principle is the mathematical counterpart of recursion: the base case mirrors the inductive base; the inductive step mirrors the recursive case. Any terminating recursion can therefore be reasoned about by induction, and correctness proofs for recursive algorithms follow this template directly.

### backtracking (0.0s)

## Backtracking

**Definition.** Backtracking is a systematic algorithm design paradigm for solving constraint-satisfaction and combinatorial search problems. Given a partial candidate solution, the algorithm extends it one component at a time; whenever an extension violates a problem constraint, the algorithm *backtracks*—it undoes the most recent choice and tries the next available alternative. Formally, let $\mathcal{S}$ be a finite set of candidates representable as sequences $(c_1, c_2, \dots, c_k)$ with $c_i \in D_i$. A *constraint predicate* $P(c_1,\dots,c_j)$ is evaluated incrementally; backtracking performs a depth-first traversal of the implicit search tree, pruning every subtree rooted at a node that violates $P$.

**Worked Example: Four-Queens Problem.** Place four non-attacking queens on a $4\times 4$ chessboard. Represent a solution as a tuple $(c_1, c_2, c_3, c_4)$ where $c_i \in \{1,2,3,4\}$ is the column of the queen in row $i$. The constraint is that no two queens share a column or diagonal: for all $i \neq j$,

$$c_i \neq c_j \quad \text{and} \quad |c_i - c_j| \neq |i - j|.$$

Starting with $c_1 = 1$: we try $c_2 = 1$ (column conflict, prune), $c_2 = 2$ (diagonal conflict, prune), $c_2 = 3$ (valid). Continuing, $c_3 = 1$ (diagonal conflict), $c_3 = 2$ (conflict), $c_3 = 3$ (column conflict), $c_3 = 4$ (conflict)—all pruned. Backtrack to $c_2 = 4$; proceed to find the solution $(1, 3, ?, ?)$. Exhausting $c_1 = 1$ ultimately yields $(2,4,1,3)$ and $(3,1,4,2)$ as the two distinct solutions.

**Key Theorem (Pruning Efficiency).** Let $T$ be the search tree explored by backtracking and $T_0$ the full $\prod_i |D_i|$-leaf tree of all candidate sequences. Then $|T| \leq |T_0|$, with equality only when no constraint eliminates any partial candidate early. In practice, effective pruning reduces $|T|$ exponentially relative to brute-force enumeration.

**Lab Cell.**

```python
from sympy.combinatorics import Permutation

def four_queens():
    solutions = []
    def bt(queens):
        r = len(queens)
        if r == 4:
            solutions.append(tuple(queens)); return
        for c in range(4):
            if all(c != q and abs(c - q) != r - i
                   for i, q in enumerate(queens)):
                bt(queens + [c])
    bt([])
    return solutions

print(four_queens())   # [(1, 3, 0, 2), (2, 0, 3, 1)]
```

### exponential_running_time (17.3s)

## Exponential Running Time

**Definition.** An algorithm runs in *exponential time* if its worst-case running time is bounded by $T(n) = O(2^n)$, or more generally $O(c^n)$ for some constant $c > 1$. Formally, we say $T(n) \in O(2^n)$ if there exist positive constants $C$ and $n_0$ such that

$$T(n) \leq C \cdot 2^n \quad \text{for all } n \geq n_0.$$

Unlike polynomial-time algorithms whose cost grows as $n^k$ for some fixed $k$, an exponential-time algorithm's cost doubles (or multiplies by $c$) with every unit increase in input size. This growth rate renders such algorithms computationally infeasible for all but the smallest inputs.

**Worked Example.** Consider the naïve recursive computation of the $n$-th Fibonacci number:

$$F(n) = F(n-1) + F(n-2), \quad F(0) = 0,\ F(1) = 1.$$

Each call spawns two sub-calls, producing a binary recursion tree of depth $n$. The number of function calls satisfies the recurrence $T(n) = T(n-1) + T(n-2) + O(1)$, whose solution grows as $T(n) = O(\phi^n)$ where $\phi = \frac{1+\sqrt{5}}{2} \approx 1.618$ is the golden ratio. For $n = 50$, this yields on the order of $10^{10}$ calls — already impractical on modern hardware — compared to just 50 steps for the linear iterative version.

**Theorem (Exponential Lower Bound for Brute-Force Search).** Any algorithm that enumerates all subsets of an $n$-element set must perform at least $2^n$ operations, since the power set $\mathcal{P}(S)$ has exactly $2^n$ elements. Consequently, subset-enumeration problems — including the exact 0/1 Knapsack decision problem — have no known polynomial-time solutions, and naïve approaches are inherently exponential.

The practical implication is stark: a problem solvable in $1$ second at $n = 20$ would require approximately $2^{10} \approx 1000$ seconds at $n = 30$, and over $10^9$ years at $n = 90$.

### include_exclude_recursion (17.2s)

## Include Exclude Recursion

**Definition.** Let $A_1, A_2, \ldots, A_n$ be finite sets. The *inclusion-exclusion principle* gives the cardinality of their union by alternately adding and subtracting the sizes of intersections:

$$\left|\bigcup_{i=1}^{n} A_i\right| = \sum_{k=1}^{n} (-1)^{k-1} \sum_{1 \le i_1 < \cdots < i_k \le n} \left|A_{i_1} \cap \cdots \cap A_{i_k}\right|.$$

This identity admits a clean recursive formulation. Define $f(S)$ as the number of elements belonging to *at least one* set indexed by $S \subseteq \{1,\ldots,n\}$. Splitting on a pivot index $j \in S$ yields:

$$f(S) = f(S \setminus \{j\}) + \left|A_j\right| - \left|A_j \cap \bigcup_{i \in S\setminus\{j\}} A_i\right|,$$

with base case $f(\emptyset) = 0$. Each recursive call reduces the problem to a strictly smaller index set, guaranteeing termination in $O(2^n)$ subproblems.

**Worked Example.** Suppose $A_1 = \{1,2,3\}$, $A_2 = \{2,3,4\}$, $A_3 = \{3,4,5\}$. We compute $|A_1 \cup A_2 \cup A_3|$ via the formula:

$$|A_1| + |A_2| + |A_3| - |A_1 \cap A_2| - |A_1 \cap A_3| - |A_2 \cap A_3| + |A_1 \cap A_2 \cap A_3|$$
$$= 3 + 3 + 3 - 2 - 1 - 2 + 1 = 5.$$

Direct inspection confirms $A_1 \cup A_2 \cup A_3 = \{1,2,3,4,5\}$, which has five elements.

**Key Theorem** *(Correctness of inclusion-exclusion).* For every element $x$ belonging to exactly $m \ge 1$ of the sets $A_1,\ldots,A_n$, its net contribution to the right-hand side is

$$\sum_{k=1}^{m} (-1)^{k-1}\binom{m}{k} = 1 - (1-1)^m = 1.$$

Hence each element in the union is counted exactly once, and elements outside the union contribute zero. $\square$

**Lab Cell (SymPy).**

```python
from sympy import symbols, FiniteSet

A1 = FiniteSet(1, 2, 3)
A2 = FiniteSet(2, 3, 4)
A3 = FiniteSet(3, 4, 5)
sets = [A1, A2, A3]

def inclusion_exclusion(sets):
    from itertools import combinations
    n, total = len(sets), 0
    for k in range(1, n + 1):
        for combo in combinations(sets, k):
            intersection = combo[0]
            for s in combo[1:]:
                intersection = intersection.intersect(s)
            total += ((-1) ** (k - 1)) * len(intersection)
    return total

print(inclusion_exclusion(sets))   # 5
```

## Subset Sum

**Definition.** Given a finite set $S = \{a_1, a_2, \ldots, a_n\}$ of integers and a target value $T \in \mathbb{Z}$, the *subset sum problem* asks whether there exists a subset $A \subseteq S$ such that

$$\sum_{a \in A} a = T.$$

The decision version — does such an $A$ exist? — is one of the canonical NP-complete problems. The optimization variant seeks the subset whose sum is as close to $T$ as possible without exceeding it, and appears in scheduling, cryptography, and resource allocation.

**Worked Example.** Let $S = \{3, 1, 4, 1, 5\}$ and $T = 9$. We ask: can we select elements that sum exactly to $9$? Observe $\{3, 1, 5\} \subset S$ and $3 + 1 + 5 = 9$. Hence the answer is yes, witnessed by this subset. Note that the element $1$ appears twice in $S$; elements are taken by position, not by value, so both copies are available independently.

**Key Theorem (DP Recurrence).** Define the Boolean table $\text{dp}[i][s]$, where $0 \le i \le n$ and $0 \le s \le T$, by

$$\text{dp}[i][s] = \begin{cases} \text{True} & \text{if } s = 0, \\ \text{False} & \text{if } i = 0 \text{ and } s > 0, \\ \text{dp}[i-1][s] \lor \text{dp}[i-1][s - a_i] & \text{if } s \ge a_i, \\ \text{dp}[i-1][s] & \text{otherwise.} \end{cases}$$

The answer is $\text{dp}[n][T]$. This recurrence embodies the *inclusion–exclusion* principle: either $a_i$ is excluded (first branch) or included, reducing the remaining target by $a_i$ (second branch). The time complexity is $O(nT)$ and space complexity $O(nT)$, or $O(T)$ with a rolling array. Because $T$ may be exponential in the input bit-length, this is a *pseudo-polynomial* algorithm, not a polynomial one.

**Lab Cell.**

```python
from sympy import symbols, Rational

def subset_sum_dp(S, T):
    dp = [False] * (T + 1)
    dp[0] = True
    for a in S:
        for s in range(T, a - 1, -1):   # traverse right-to-left to avoid reuse
            dp[s] = dp[s] or dp[s - a]
    return dp[T]

S = [3, 1, 4, 1, 5]
T = 9
print(subset_sum_dp(S, T))   # True
print(subset_sum_dp(S, 11))  # False
```
