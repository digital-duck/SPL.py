### parent_structure (0.0s)

## Parent Structure

You already know that in Sage, `5` behaves differently depending on context — sometimes it's a plain integer, sometimes a fraction, sometimes a symbolic variable's coefficient. What decides this? Every object in Sage lives inside a **parent**: a mathematical structure that defines what operations mean and what results are allowed.

Think of a parent as the "address" of a number's mathematics. The integer $5$ can live in $\mathbb{Z}$ (the integers), $\mathbb{Q}$ (the rationals), or even $\mathbb{F}_7$ (integers mod 7). The symbol `5` looks the same, but $5$ in $\mathbb{Z}$ has no inverse under multiplication, while $5$ in $\mathbb{Q}$ does — $\frac{1}{5}$ exists there but not in $\mathbb{Z}$. The parent decides which rules apply.

In Sage, you check an object's parent with `.parent()`:

```
sage: x = ZZ(5)
sage: x.parent()
Integer Ring
sage: y = QQ(5)
sage: y.parent()
Rational Field
```

This matters because operations between objects from *different* parents trigger **coercion** — Sage finds a common parent where both objects can meaningfully interact, following a discoverable, rule-based hierarchy (not guesswork). This is why $\frac{1}{2} + 3$ works and correctly returns a rational number: Sage promotes $3 \in \mathbb{Z}$ into $\mathbb{Q}$ first.

**Rule of thumb:** if you're ever confused about why an operation succeeded, failed, or gave a surprising type, ask `.parent()` first — the object's mathematics is defined by where it lives, not just its printed value.

**Practice:** In Sage, evaluate `a = GF(7)(10)` and then call `a.parent()`. What integer does `a` actually equal, and why?

### symbolic_variable (0.0s)

## Symbolic Variable

You already know that in arithmetic, $x$ often stands for one hidden number you're trying to uncover — like in $x + 3 = 7$, where $x$ can only be $4$. A symbolic variable takes this idea and stretches it much further: instead of representing one unknown number, it can represent *every* number at once.

When you write `var('x')` in a computer algebra system, you're not asking the computer to solve for a specific value. You're creating a symbol — a placeholder that behaves like a number, follows all the rules of arithmetic and algebra, but isn't tied down to any particular value. This is the floor of generality: the idea that you can build true statements about *all* numbers simultaneously, without ever plugging one in.

This is why algebra comes before arithmetic in a real sense. The identity
$$(x+1)^2 = x^2 + 2x + 1$$
is true for every number $x$ — not because you checked it for $x=1$, $x=2$, $x=3$, and so on, but because the symbol $x$ carries the pattern itself. Arithmetic tells you facts about specific numbers; algebra, powered by symbolic variables, tells you facts about *all numbers at once*.

The simple rule: a symbolic variable is a placeholder, not a value. You manipulate it using algebra's rules (distributing, combining like terms, factoring), and whatever relationship you prove holds for every number that could ever be substituted in.

**Practice:** Let $x$ be a symbolic variable. Expand $(x+3)(x-3)$ and simplify. What pattern do you notice, and does it still work if you substitute $x=10$?

### symbolic_expression (0.0s)

## Symbolic Expression

A symbolic variable like $x$ is a single named placeholder. A **symbolic expression** is what happens when you start combining variables with operations and functions, but Sage refuses to collapse the result into a number — it keeps the *structure* exactly as written, living in what's called the Symbolic Ring, written $SR$.

So $\sin(x)^2 + \cos(x)^2$ isn't silently rewritten to $1$. Sage holds onto every piece — the exponents, the function calls, the addition — because that structure is the information. You decide later whether to simplify it, substitute a value into $x$, or leave it alone entirely.

This is the key shift from ordinary variables: an expression is a *tree*, not just a symbol. $x^2 + 3x + 5$ has an addition at the top, with a power and a product as its branches, and those branches have their own branches down to the symbols and constants at the leaves. Sage can walk this tree — that's how `.expand()`, `.factor()`, and `.simplify_full()` work: they're tree transformations, not number-crunching.

**The rule**: expressions in $SR$ are built recursively — a symbol is an expression, a number is an expression, and combining expressions with $+, -, \times, \div, {}^\wedge$, or a function like $\sin$, $\log$, $\sqrt{\phantom{x}}$ produces a new expression. Nothing evaluates until you explicitly ask it to, with `.subs()` or `.n()`.

**Practice problem:** Let $f = (x+1)^2 - (x^2+2x)$. Without expanding by hand, predict what `f.expand()` should simplify to, then check: is the result still "symbolic," or is it now just a plain number wearing a symbolic expression's clothing?

### exact_integer (0.0s)

## Exact Integer

You already know the whole numbers: $\ldots, -2, -1, 0, 1, 2, \ldots$. On a calculator or in most programming languages, though, whole numbers secretly have a ceiling. Try computing something huge, and you'll hit an error, silent rounding, or a wraparound to a nonsense negative number. Sage Integers refuse that limitation — they are **arbitrary-precision**, meaning the digits keep going as long as your computer's memory allows.

Structurally, this comes from how the number is stored. A fixed-width integer (say, 64 bits) reserves a constant chunk of memory, so it can represent only about $2^{64}$ distinct values before it overflows. A Sage Integer instead stores a *list* of digit-chunks that grows automatically: multiplying two big numbers just makes the list longer. So $2^{100}$ isn't approximated — it's computed and stored as the single exact value
$$2^{100} = 1267650600228229401496703205376,$$
digit for digit, with no rounding at all. Compare this to a float, which stores a fixed number of significant digits plus an exponent — floats trade exactness for range, while arbitrary-precision integers keep both correctness and range, at the cost of speed for very large numbers.

The simple rule: **integer operations in Sage (`+`, `-`, `*`, `//`, `^`) always return another exact Integer**, never a rounded approximation. Division with `/` is the one exception — it can produce an exact *rational* instead, which is a separate topic.

**Practice problem:** Without a calculator, predict how many digits $2^{100}$ has. (Hint: use $\log_{10}(2^{100}) = 100 \log_{10} 2 \approx 30.1$, then think about what that tells you about the digit count.) Then check your answer against the exact value above.

### simplification (0.0s)

## Simplification

You already know that $x + x$ and $2x$ are "the same" — you just rewrite one as the other in your head. Simplification is that instinct turned into a rigorous procedure: a set of rewrite rules applied to an expression until no rule can fire anymore, producing a canonical form.

Here's the structural piece worth sitting with: **simplification and zero-testing are different problems.** When you write `expr == 0` in a computer algebra system, you're not asking a question — you're building an *equation object*, a symbolic statement waiting to be evaluated. The function `is_zero()` is what actually answers it, and answering it can be surprisingly hard. Consider:

$$\sin^2(x) + \cos^2(x) - 1$$

A human recognizes this as $0$ instantly via the Pythagorean identity. But `simplify_full()` has to *search*: it applies a library of trig identities — double-angle, sum-to-product, Pythagorean — trying rewrites until the expression collapses or no further rule applies. This is why simplification isn't guaranteed to terminate at the "simplest" form; different rule orderings can produce different-looking (but equal) results.

**The rule:** two expressions are mathematically identical exactly when their difference simplifies to $0$ — that's the formal meaning of "same," and it's what `is_zero()` checks: $f \equiv g \iff \text{is\_zero}(f - g)$.

**Practice problem:** Using the identity $\cos(2x) = 1 - 2\sin^2(x)$, show by hand that
$$\cos(2x) + 2\sin^2(x) - 1$$
simplifies to $0$. Write out each substitution step — this is exactly what `simplify_full()` automates.

### polynomial_rings (0.0s)

## Polynomial Rings

You already know that $x^2 - 5x + 6$ factors as $(x-2)(x-3)$, and that you can add, multiply, or find roots of polynomials with ordinary rules. But there's a structural question hiding underneath: factor over *what*? The polynomial $x^2 - 2$ has no rational roots, yet it factors as $(x-\sqrt{2})(x+\sqrt{2})$ over the reals. The "right" answer to factor(), gcd(), or roots() depends entirely on which number system your coefficients — and your answers — are allowed to live in.

This is why computer algebra systems make you declare the ring explicitly, like $\mathbb{Q}[x]$, read "polynomials in $x$ with rational coefficients." Writing `PolynomialRing(QQ, 'x')` isn't decoration — it fixes the universe of discourse before any computation happens. Once the ring is fixed, $\mathbb{Q}[x]$ becomes an algebraic structure in its own right: you can add and multiply polynomials inside it, and every element factors *uniquely* into irreducible polynomials (over $\mathbb{Q}$), the same way every integer factors uniquely into primes. That's why $\gcd(f,g)$ for $f,g \in \mathbb{Q}[x]$ has one correct, unambiguous answer — it's the largest common divisor *inside that same ring*.

**The rule:** an operation on polynomials is only well-defined once you know the ring — the same polynomial can factor completely in one ring and stay irreducible in another.

**Practice:** Is $x^2 - 3$ irreducible over $\mathbb{Q}[x]$? Does it factor over $\mathbb{R}[x]$? Write both answers, and explain in one sentence why they differ.

### substitution_evaluation (9.0s)

## Substitution Evaluation

You've seen a symbolic expression like $f(x) = x^2 + 3x - 5$ — a formula that holds true for *any* value of $x$. But eventually you need an actual number out of it. That's where substitution and evaluation come in, and it's worth noticing they're really two separate steps, not one.

**Substitution** replaces the symbol $x$ with a specific value, say $x = 4$, giving you a new expression:

$$f(4) = 4^2 + 3(4) - 5$$

Nothing has been computed yet — this is still symbolic. In tools like SymPy, this step is `subs()`. It swaps a variable for a value (or even another expression) while leaving everything as an unevaluated formula.

**Evaluation** is the second step: actually carrying out the arithmetic to get a number.

$$f(4) = 16 + 12 - 5 = 23$$

In SymPy, this is `n()` (or `.evalf()`), which forces the numeric computation, including approximating irrational results like $\sqrt{2} \approx 1.41421$.

Why keep these separate? Because substitution can happen in stages — you might substitute one variable now and another later, or substitute a whole sub-expression instead of a number — while evaluation is the final, one-way trip from symbol to decimal. Once you evaluate, you can't easily "unevaluate" back to the general formula. Keeping `subs()` and `n()` distinct means you control exactly when that irreversible step happens.

**Rule of thumb:** *substitute first, evaluate last* — and only evaluate when you actually need a number.

**Practice problem:** Let $g(x) = 2x^2 - x + 7$. Substitute $x = -3$ to get a symbolic expression, then evaluate it to a number. What do you get?

### exact_rational (0.0s)

## Exact Rational

You already know that division doesn't always come out even. $1 \div 3$ isn't a tidy whole number — but that doesn't mean the answer is fuzzy or approximate. In an **Exact Rational** system, $1 \div 3$ produces the value $\frac{1}{3}$, stored and carried forward exactly as that fraction, forever. No rounding, no drift, no "0.333..." unless you specifically ask to see it that way.

Here's the structural idea: a rational number is really a pair of integers, a numerator and a denominator, written $\frac{p}{q}$ with $q \neq 0$. The system keeps that pair intact. When you add, subtract, multiply, or divide rationals, it applies the exact rules you already know from fractions:

$$
\frac{a}{b} + \frac{c}{d} = \frac{ad+bc}{bd}, \qquad \frac{a}{b} \times \frac{c}{d} = \frac{ac}{bd}
$$

and then simplifies by dividing out the greatest common divisor of the result, so $\frac{2}{4}$ becomes $\frac{1}{2}$ automatically. Every step stays a fraction — the *decimal* $0.5$ or $0.333...$ only appears if you explicitly convert it, and that conversion is a one-way street: once you round to a decimal, you can lose information that the fraction never lost.

**The rule:** decimals are a *view*, not the *value*. The value is the pair $(p,q)$; the decimal is just one way to display it, and often an incomplete one.

**Practice problem:** Using exact fractions (no decimals), compute $\frac{1}{3} + \frac{1}{6}$, and simplify your answer to lowest terms.

### number_theory_sage (0.0s)

## Number Theory Sage

Back in the exact-integer section, you saw that integers keep exact values in SageMath. Number theory takes that exactness and asks deeper questions: What are the building blocks of a number? Can we find hidden patterns in how numbers relate? Sage answers these questions instantly using PARI, a specialized number-theory engine running silently underneath.

Every positive integer factors uniquely into primes — this is the Fundamental Theorem of Arithmetic:

$$n = p_1^{a_1} \cdot p_2^{a_2} \cdots p_k^{a_k}$$

Sage's `factor(n)` computes this decomposition even for numbers hundreds of digits long, and `is_prime(n)` tests primality without ever attempting full factorization — using fast probabilistic and deterministic tests instead.

A second key idea is Euler's totient function $\phi(n)$, which counts integers from $1$ to $n$ that share no common factor with $n$. It has a clean formula built from the prime factorization:

$$\phi(n) = n \prod_{p \mid n} \left(1 - \frac{1}{p}\right)$$

Sage computes this instantly via `euler_phi(n)`.

Finally, the **Chinese Remainder Theorem (CRT)** solves systems of congruences. If $\gcd(m,n)=1$, then any pair of remainders $(x \bmod m, x \bmod n)$ corresponds to exactly one solution $x \bmod mn$. Sage's `crt()` builds that solution directly, no guesswork required.

Together these tools turn number theory from "check by hand" into "ask and verify" — you form a conjecture, then let Sage confirm it on real numbers, fast.

**Practice:** Use `factor(84)` to find the prime factorization of 84, then compute $\phi(84)$ by hand using the formula above. Check your answer with `euler_phi(84)`.

### calculus_sage (0.0s)

## Calculus Sage

You've learned to differentiate and integrate by hand, following rules like $\frac{d}{dx}x^n = nx^{n-1}$ or $\int x^n\,dx = \frac{x^{n+1}}{n+1}+C$. A Calculus Sage does exactly this — but as a *symbolic* computation, manipulating the expression itself rather than a number.

Structurally, a Calculus Sage combines two building blocks you've already met: a **symbolic expression** (the formula, kept in its exact algebraic form — $\sin(x^2)$, not a decimal) and a **simplification** engine (rules that rewrite expressions into cleaner equivalent forms). Differentiation, integration, limits, and series expansion are each just a set of transformation rules applied to that expression tree. For example, given $f(x) = x^3 - 2x$, the derivative operator applies the power rule term-by-term to produce $f'(x) = 3x^2 - 2$ — still a formula, ready for further work.

The key safeguard is the **Fundamental Theorem of Calculus**, which states:

$$
\frac{d}{dx}\int_a^x f(t)\,dt = f(x)
$$

A well-built Calculus Sage exploits this as a built-in check: after finding an antiderivative $F(x)$ for $f(x)$, it differentiates $F(x)$ right back and confirms the result matches $f(x)$ through simplification. If they don't match exactly, something in the integration step was wrong.

**Simple rule:** integrate, then differentiate your answer — if you don't recover the original function, the antiderivative is incorrect.

**Practice problem:** Let $f(x) = 6x^2 + 4$. Find an antiderivative $F(x)$, then differentiate $F(x)$ to verify $F'(x) = f(x)$.

### exact_linear_algebra (0.0s)

## Exact Linear Algebra

You've solved systems of equations by hand — combining rows, eliminating variables, checking your work. That process is called Gaussian elimination, and it has a target: **reduced row echelon form (RREF)**, a unique "simplest version" of any matrix that reveals a system's solutions at a glance.

The catch with doing this on a computer is that most software stores numbers as decimals with rounding error. Divide by 3 enough times and tiny errors creep in, until a matrix that should be singular looks almost-but-not-quite singular. Working over $\mathbb{Q}$, the rationals, sidesteps this entirely: $\frac{1}{3}$ stays $\frac{1}{3}$ forever, with no decimal approximation at any step.

This matters for three core computations. First, RREF of a matrix $A$: elementary row operations (swap, scale, add a multiple of one row to another) reduce $A$ to a form where each pivot is $1$ and is the only nonzero entry in its column. Second, the **kernel** (null space), $\ker(A) = \{x \in \mathbb{Q}^n : Ax = 0\}$ — found directly from RREF's free variables, with no rounding blurring which vectors are "basically zero." Third, **eigenvalues**: solving $\det(A - \lambda I) = 0$ exactly, over $\mathbb{Q}$ or an algebraic extension like $\mathbb{Q}(\sqrt{2})$, so $\lambda = \sqrt{2}$ appears as itself, not $1.41421356...$

The rule: exact arithmetic means exact answers, at the cost of numbers that can grow large as computations chain together — a tradeoff of speed for certainty.

**Practice:** Using exact fractions (no decimals), row-reduce
$$A = \begin{pmatrix} 2 & 4 \\ 1 & 2 \end{pmatrix}$$
to RREF, then find a nonzero vector in $\ker(A)$.

### plotting_visualization (8.0s)

## Plotting Visualization

You've been building expressions symbolically — substituting values, simplifying, solving. But a symbol like $f(x) = x^3 - 3x$ is easier to understand once you *see* it. Plotting turns an algebraic object into a picture, generated straight from the exact expression itself, not from a rough sketch.

The idea has more structure than "draw the graph." A 2D plot samples a function over an interval, $x \in [a, b]$, computes $f(x)$ at each sample, and connects the points — so `plot(f(x), (x, a, b))` is really evaluating $f$ many times and stitching the results together. `plot3d` does the same for a surface $z = f(x, y)$ over a two-dimensional region, giving you a height map in three dimensions.

Some relationships aren't written as $y = f(x)$ at all — a circle is $x^2 + y^2 = r^2$, not a function you can solve cleanly for $y$. For these, `implicit_plot` searches the plane for every point $(x, y)$ satisfying the equation $F(x, y) = 0$ and draws the resulting curve, without ever isolating a variable.

The real power is using the picture as a check on your algebra. If you solve $x^3 - 3x = 0$ symbolically and get roots at $x = -\sqrt{3}, 0, \sqrt{3}$, plotting $f(x)$ should show the curve crossing zero at exactly those three points. If it doesn't, you've likely made an error — the picture doesn't lie about the symbols.

**Practice problem:** Plot $f(x) = x^2 - 4$ over $x \in [-4, 4]$. Where does the curve cross the x-axis? Solve $x^2 - 4 = 0$ symbolically and check that your answer matches.

### solving_equations (8.4s)

## Solving Equations

You already know that solving an equation means finding the value that makes both sides equal — like discovering $x = 3$ satisfies $x^2 - 9 = 0$. But a symbolic solver like `solve()` doesn't guess-and-check numbers. It works with the equation as an algebraic object over the *symbolic ring*, manipulating expressions exactly, so it returns roots as exact values — fractions, radicals, even $\pi$ or $i$ — never rounded decimals.

Consider $x^2 - 9 = 0$. Factoring gives $(x-3)(x+3) = 0$, so the solution set is $\{x = 3, x = -3\}$. Now try $x^2 - 6x + 9 = 0$. This factors as $(x-3)^2 = 0$ — the root $x = 3$ appears twice. We call this a root of **multiplicity 2**. A solver tracks multiplicity because it tells you *how* the graph touches zero: multiplicity 1 means the curve crosses the x-axis; multiplicity 2 means it just touches and bounces back.

Sometimes an equation has infinitely many solutions unless you restrict the search. This is where `assume()` comes in: telling the solver something like "$x$ is real" or "$x > 0$" narrows the answer set before solving begins, discarding solutions like $x = -3$ if you've assumed positivity, or complex roots if you've assumed realness. This is the solver combining two earlier ideas — simplifying an expression and substituting constraints — into one exact, rigorous search.

**Practice problem:** Solve $x^2 - 4x + 4 = 0$ by hand. Factor it, state the root(s), and give the multiplicity. Then explain in one sentence what the graph of $y = x^2 - 4x + 4$ looks like at that root.

### conjecture_loop (9.7s)

## Conjecture Loop

You already know the drill: guess a pattern, test it, trust it once it survives a few checks. The conjecture loop makes that instinct rigorous — and fast enough to run hundreds of times before lunch.

Here's the structure. Say you want to know something about a class of objects — maybe "is $n^2 + n + 41$ always prime?" Instead of checking by hand, you generate examples exhaustively with a tool like Sage:

$$
f(n) = n^2 + n + 41, \qquad n = 0, 1, 2, \dots, k
$$

You compute $f(0), f(1), \dots, f(k)$ and check primality on each — a computer does this in milliseconds for thousands of values. The pattern *looks* solid for small $n$: every value is prime up through $n = 39$. That's your conjecture. But a conjecture is not a theorem — it's a claim waiting to be broken.

The crucial move is the second half of the loop: **hunt the counterexample**, don't just admire the pattern. Push $n$ further. At $n = 40$, $f(40) = 41^2$ — not prime. One counterexample destroys the conjecture completely, no matter how many times it worked before.

This is the actual experimental method in number theory: generate exact data (not floating-point approximations — exact integers, exact fractions), plot it to spot structure visually, then actively search for where it fails rather than where it holds. A conjecture that survives aggressive counterexample-hunting becomes worth trying to *prove*.

**Practice:** Using exact arithmetic, compute $g(n) = n^2 - n + 41$ for $n = 1$ through $10$. Conjecture whether it's always prime, then find the smallest $n$ where it fails.

### group_theory_sage (9.5s)

## Group Theory Sage

You've met groups as sets with an operation satisfying closure, associativity, identity, and inverses. Now let's see how a computer actually *holds* a group in its hands — and why that changes what questions you can ask.

Take the symmetries of a square: rotations and flips that map the square onto itself. In Sage, you don't list these abstractly — you build a permutation group, where each symmetry is written as a permutation of the square's four corners. For example, a 90° rotation might be $(1\,2\,3\,4)$, meaning corner 1 goes to corner 2, 2 goes to 3, and so on. The whole symmetry set becomes:

$$
D_4 = \langle (1\,2\,3\,4),\ (1\,3) \rangle
$$

This says: generate the group from a rotation and a flip, then let closure fill in the rest. Sage's engine — built on a system called GAP — computes every element, the group's order $|D_4| = 8$, its center $Z(D_4)$ (elements that commute with everything), and its full lattice of subgroups, all on command.

Why does this matter? Groups defined by generators can be astronomically large — some have more elements than atoms in a small asteroid — yet a computer can still answer "is this group abelian?" or "what's the order of this element?" without ever writing out the full list. That's the power of computational group theory: reasoning about symmetry at scale.

**Practice:** The group of symmetries of an equilateral triangle has order 6. If it's generated by a 120° rotation $r$ and a flip $f$, write down what $r^3$ and $f^2$ should equal, using the identity element $e$.

### manifolds_geometry (0.0s)

## Manifolds Geometry

You've met curved spaces intuitively — the surface of a sphere, the warped fabric of spacetime near a mass. Now let's give that intuition a precise skeleton. A manifold is a space that looks flat up close (like Euclidean space) even if it's curved overall. We describe it with a chart: a coordinate map $\phi: U \to \mathbb{R}^n$ that assigns coordinates $(x^1, \dots, x^n)$ to points in an open patch $U$. Where two charts overlap, transition functions tell you how to convert between coordinate systems — this is what lets the manifold be curved globally while flat locally.

The key structure is the metric tensor $g_{ij}$, which measures distance: $ds^2 = g_{ij}\, dx^i dx^j$ (using the Einstein summation convention). From the metric, we build the Levi-Civita connection $\nabla$, which tells vectors how to change as you move across the manifold — this generalizes the derivative to curved space. Applying the connection twice and comparing paths gives the Riemann curvature tensor $R^i_{\ jkl}$, the object that actually detects curvature. Flat space has $R = 0$ everywhere; a sphere doesn't.

SageManifolds turns this from symbol-pushing into computation: you declare a chart, input a metric, and Sage computes the Christoffel symbols, curvature tensors, and geodesic equations symbolically — exactly, not numerically approximated.

**Rule to remember**: curvature is measured by how much a vector changes when parallel-transported around a closed loop — zero change means flat, nonzero means curved.

**Practice problem**: For the flat 2D metric $ds^2 = dx^2 + dy^2$, argue (without full computation) why every Christoffel symbol $\Gamma^k_{ij}$ must vanish.

### experimental_mathematics (9.3s)

## Experimental Mathematics

You've now seen three tools in action: forming conjectures from patterns, exploring the shapes manifolds trace out, and letting SageMath crunch group structure faster than any hand computation could. Put them together, and you get something bigger than any one piece — a whole *way of doing math*.

For most of history, mathematicians worked almost like philosophers: think hard, write a proof, done. Computers changed that. Now you can work more like a scientist. You guess a pattern (a conjecture), you run experiments (compute lots of cases), and you check whether the pattern breaks (falsify) or keeps holding (believe, provisionally). This loop — conjecture, compute, check — is called **experimental mathematics**, and it's exactly how researchers discover real results today, from number theory to the shapes of manifolds studied in geometry.

But here's the catch: a pattern that holds for a million examples still isn't a proof. Fermat's conjecture about primes of the form $2^{2^n}+1$ looked solid for small $n$ — until Euler found a counterexample at $n=5$. Experiments find *candidates*; they don't guarantee truth. So the loop has a final step: once you believe a conjecture, you hand it off to a **proof assistant** — software like Lean or Coq — which checks every logical step with total rigor, no hand-waving allowed.

$$\text{conjecture} \xrightarrow{\text{compute}} \text{evidence} \xrightarrow{\text{believe?}} \text{proof assistant} \to \text{theorem}$$

**Practice problem:** Using a computer (or by hand for small cases), check whether $n^2 - n + 41$ is prime for $n = 1, 2, \dots, 10$. Do you believe it's prime for *all* positive integers $n$? Try $n = 41$ — what happens, and what does that teach you about trusting patterns?

### math_research (9.4s)

## Math Research

You already know mathematicians look for patterns. But today, a huge amount of that pattern-hunting is done by computers running exact, symbolic computation — and that's changing what a "conjecture" even looks like.

Here's the structure of the loop. A mathematician picks an object — say, the number of ways to partition an integer $n$, written $p(n)$ — and computes it exactly (not approximated!) for thousands or millions of values using a computer algebra system. Exact computation matters: floating-point rounding would hide the very patterns you're searching for, especially with huge integers or fractions. Then the researcher searches that data for structure: does $p(n)$ satisfy a recurrence? Does it factor nicely modulo some prime? Ramanujan famously noticed, just from hand-computed tables, that

$$p(5n+4) \equiv 0 \pmod{5}$$

for every integer $n$. Today's computers can generate that kind of evidence across billions of cases in seconds — turning what once took a genius's intuition into a systematic search.

But evidence isn't proof. A pattern holding for a million cases is a *conjecture*, not a theorem — mathematics has real examples of patterns that broke on the millionth-and-first case. The proof still requires human (or increasingly, computer-assisted) reasoning to show the pattern holds for *all* $n$, not just the tested ones.

**The pattern:** Compute exactly → search for structure → conjecture → prove.

**Practice problem:** Using a spreadsheet or calculator, compute $p(n) \bmod 5$ for $n = 4, 9, 14, 19, 24$. Confirm Ramanujan's pattern above, then predict the next value.
