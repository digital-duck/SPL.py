## Comparison

比较（comparison）是一个二元谓词：给定集合中的两个元素 $a$ 和 $b$，它回答"谁排在前面"这一个问题，输出结果只有三种可能——$a<b$、$a=b$、$a>b$。这是基于比较的排序算法（comparison-based sorting）与数据交互的**唯一**方式：算法不能"看见"元素的内部结构或数值大小，只能不断地问"这两个谁更小"，然后根据答案决定下一步动作。归并排序、快速排序、堆排序——几乎所有经典排序算法——都建立在这一单一操作之上。

**信息论下界**。既然算法对数据的全部认知都来自一连串的是/否式比较结果，我们可以把整个排序过程看作一棵二叉决策树：每个内部节点代表一次比较，每条边代表比较的两种结果之一，每个叶子代表一种最终排列（permutation）。对于 $n$ 个互不相同的元素，共有 $n!$ 种可能的排列，而算法必须能够区分出所有这些排列——否则就会把两种不同的正确顺序混为一谈。一棵二叉树若要拥有至少 $n!$ 个叶子，其深度（即最坏情况下的比较次数）至少为

$$
\log_2(n!)
$$

由斯特林公式（Stirling's approximation），$\log_2(n!) = \Theta(n \log n)$。这就是排序问题的信息论下界：任何仅依赖两两比较的算法，最坏情况下都无法避免做 $\Omega(n \log n)$ 次比较。归并排序和堆排序达到了这一下界，因此在比较模型下是渐近最优的；而计数排序、基数排序之所以能做到 $O(n)$，恰恰是因为它们绕开了"比较"这一原语，直接利用了数据的数值结构。

**问题求解应用**。这一下界给出的是一把判断工具：当你想优化一个排序算法时，首先要问它是否属于比较模型。如果是，$O(n \log n)$ 已是理论极限，继续压缩只是常数因子上的优化；如果你能够利用数据的额外结构（如已知范围、整数键、多关键字），就可能跳出比较模型，获得线性时间。例如，对 $0$ 到 $999$ 的整数排序，若坚持用比较排序，最坏也要 $\Omega(n\log n)$ 次比较；但改用计数排序则可在 $O(n+k)$ 时间内完成——因为它不再依赖"比较"这一原语,而是直接利用了键值的数值信息。

### memory_access (0.0s)

## Memory Access

**定义**

RAM(随机存取内存,Random-Access Memory)模型假设：给定一个地址 $i$,读取或写入该地址处的值所需时间为常数 $O(1)$,与内存总大小 $n$ 或地址 $i$ 的数值无关。这与磁带、链表这类"顺序存取"结构形成鲜明对比——在那些结构中,访问第 $i$ 个元素需要 $O(i)$ 的时间来遍历前面的元素。随机存取赋予了数组一个关键能力:**下标即地址**。若数组首地址为 $\text{base}$,每个元素占用 $w$ 个字节,则第 $i$ 个元素的物理地址为

$$
\text{addr}(i) = \text{base} + i \times w
$$

这是一次乘法加一次加法,常数时间内完成——这正是数组支持 $O(1)$ 随机访问、而链表只能 $O(n)$ 顺序访问的根本原因。

**问题求解应用**

随机存取的意义远不止"数组比链表快"。它是**非比较类排序算法**(如计数排序、基数排序)之所以能够突破 $\Omega(n \log n)$ 下界的物理基础。比较排序(快速排序、归并排序)的下界来自决策树论证:任何只依赖"比较两个元素大小"的算法,至少需要 $\log_2(n!) \approx n\log_2 n$ 次比较才能区分所有可能的排列。但计数排序完全不比较元素——它把元素的**值本身当作数组下标**。

例如,对 $n$ 个取值范围在 $[0, k]$ 的整数排序:开辟一个大小为 $k+1$ 的计数数组 `count`,对每个输入元素 $x$,执行 `count[x] += 1`。这里的关键在于:`count[x]` 这次访问是 $O(1)$ 的——因为地址由 $x$ 直接计算得出,不需要搜索或比较。整个过程只需 $O(n+k)$ 时间,当 $k = O(n)$ 时即为线性时间,彻底绕开了比较排序的理论下界。

基数排序(radix sort)进一步利用这一点:把每个数字按位(十进制的十位、百位……)反复用计数排序稳定分桶,每一轮都是 $O(n+k)$,总时间 $O(d(n+k))$,其中 $d$ 是位数。哈希表同样依赖这一原理:通过哈希函数把键映射为数组下标,实现平均 $O(1)$ 的查找、插入。可以说,随机存取内存把"下标"从单纯的位置标记,升级为一种可供算法直接计算和利用的信息通道——这正是它作为第二基本原语的核心价值。

### recursion (0.0s)

## Recursion

**定义**：递归是一种解决问题的方式——函数通过调用自身来解决规模更小的同类子问题，再将子问题的结果组合成原问题的答案。任何递归函数都必须具备两个要素：一个或多个**基准情形**（base case），即不再需要递归、可以直接给出答案的最简单输入；以及一个**递归步骤**（recursive step），把原问题分解为更小的实例并调用自身。若缺少基准情形，或递归步骤没有让问题严格变小，函数会无限调用下去，最终耗尽调用栈而崩溃。

递归之所以是与"比较、交换"并列的第二个根本算法原语，是因为它捕捉了一种无法由排序中的逐元素比较或交换动作导出的结构：**问题与子问题在形式上自相似**。这一结构正是分治法（如归并排序、快速排序）、动态规划（将问题分解为重叠子问题）以及树/图上算法（如二叉树遍历、深度优先搜索）共享的底层骨架。

**递归的正确性**依赖数学归纳法：若基准情形正确，且递归步骤在"子问题已正确解决"的假设下能正确构造原问题的解，那么整个函数对所有合法输入都正确。这与归纳证明中"归纳基础 + 归纳步骤"的结构完全对应，因此递归不只是一种编程技巧，而是归纳推理在计算过程中的直接体现。

**worked example：阶乘函数**

$$
n! =
\begin{cases}
1 & n = 0 \\
n \cdot (n-1)! & n > 0
\end{cases}
$$

```python
def factorial(n):
    if n == 0:          # 基准情形
        return 1
    return n * factorial(n - 1)   # 递归步骤：更小的子问题
```

调用 `factorial(4)` 展开为 $4 \cdot 3! = 4 \cdot 3 \cdot 2! = \cdots$，直到触达 $0! = 1$，再逐层回溯相乘。

**问题求解应用**：递归树的高度决定了调用栈深度与时间复杂度。以斐波那契数列的朴素递归 $F(n) = F(n-1) + F(n-2)$ 为例，其递归树会产生大量重复子问题，时间复杂度为 $O(2^n)$；而动态规划正是通过缓存已求解的子问题结果（记忆化），把复杂度压缩到 $O(n)$。理解这一点，是从"会写递归"迈向"会用递归设计高效算法"的关键一步。

### dynamic_programming (0.0s)

## Dynamic Programming

**定义**

动态规划（Dynamic Programming，简称 DP）是一种通过把问题分解为**重叠子问题**（overlapping subproblems）并把每个子问题的结果**存储**起来（记忆化 memoization 或表格法 tabulation），从而保证每个子问题只计算一次的算法设计范式。它适用的问题必须具备两个标志性属性：

1. **最优子结构**（optimal substructure）：问题的最优解可以由其子问题的最优解构造出来；
2. **重叠子问题**（overlapping subproblems）：朴素递归会反复求解同一个子问题。

若把朴素递归记为 $T(n) = a \cdot T(n-1) + O(1)$ 这类指数增长的递推，DP 通过引入一个数组（或哈希表）$dp[\,]$ 缓存已求解的状态，把重复的 $O(a^n)$ 计算降为每个状态只算一次，从而将时间复杂度压到多项式级别，代价是 $O(\text{状态数})$ 的额外空间——这正是"用内存换时间"的本质，是**递归（recursion）+ 内存访问（memory access）**这两个基础机制的组合。

**范例求解**

以斐波那契数 $F(n) = F(n-1) + F(n-2)$，$F(0)=0, F(1)=1$ 为例。朴素递归会对同一个 $F(k)$ 反复求值，产生 $O(2^n)$ 次调用。加入记忆化后：

$$
dp[n] =
\begin{cases}
n, & n \le 1 \\
dp[n-1] + dp[n-2], & n > 1
\end{cases}
$$

从 $dp[0], dp[1]$ 出发自底向上填表（tabulation），每个 $dp[k]$ 只计算一次，总时间复杂度降为 $O(n)$，空间复杂度 $O(n)$（若只保留最近两项则可优化到 $O(1)$）。

**问题求解应用**

DP 的实践关键不是记住某个公式，而是学会识别问题中的"状态"与"转移方程"。以经典的**背包问题**（0/1 Knapsack）为例：给定容量 $W$ 和 $n$ 件物品（重量 $w_i$、价值 $v_i$），求

$$
dp[i][w] = \max\big(dp[i-1][w],\; dp[i-1][w-w_i] + v_i\big)
$$

其中 $dp[i][w]$ 表示"仅考虑前 $i$ 件物品、容量为 $w$ 时可获得的最大价值"。第一项对应"不选第 $i$ 件物品"，第二项对应"选它"，取较大者即体现最优子结构。该表可用二维数组自底向上填充，总复杂度为 $O(nW)$，远优于枚举所有子集的 $O(2^n)$。解题的通用步骤是：先定义状态含义，再写出状态转移方程，最后确定填表顺序与边界条件——这套流程适用于最长公共子序列、编辑距离、最短路径等一大类问题。

## 贪心算法

贪心算法（Greedy Algorithm）在每一步都做出当前看起来最优的选择，并且一旦做出决定，绝不回头修改。这种策略之所以吸引人，是因为它通常比穷举所有可能性快得多——但它并不总能得到全局最优解。贪心算法只有在问题具备"贪心选择性质"（greedy-choice property）时才保证正确，即局部最优选择经过一系列决策后必然导向全局最优解，且问题还需具备"最优子结构"：整体问题的最优解包含子问题的最优解。

**霍夫曼编码（Huffman Coding）** 是贪心思想的经典应用。给定一组字符及其出现频率，目标是构造一棵前缀码树，使得编码后的总比特数最小。算法每一步都合并当前频率最小的两个节点，生成一个新节点，其频率为二者之和，反复执行直到只剩一个节点（树根）。例如字符集 $\{A:5, B:9, C:12, D:13, E:16, F:45\}$，先合并 $A$ 与 $B$（频率 $14$），再依次合并较小的节点，最终得到的树保证了整体编码长度最短。这一贪心策略之所以正确，是因为可以证明：频率最小的两个符号在最优树中必然处于最深、且互为兄弟的位置——这正是贪心选择性质成立的证明基础。

**活动选择问题（Activity Selection）** 则是另一类例子：给定若干个有起止时间的活动，要选出互不冲突、数量最多的活动集合。贪心策略是每次选择"结束时间最早"的、且与已选活动不冲突的活动。直觉上这为后续留下最多的时间窗口，可以用交换论证（exchange argument）严格证明其最优性。

**Dijkstra 算法**（用于非负权图的单源最短路径）同样是贪心的：每一步从未确定最短路径的顶点中选取当前距离最小者并"固定"下来。之所以正确，是因为边权非负保证了已固定顶点的最短距离不会再被后续路径缩短。若图中存在负权边，这个假设被打破，贪心便会给出错误答案，必须改用 Bellman-Ford 等动态规划方法。

**问题解决要点**：拿到一个优化问题时，先检验贪心选择性质是否成立——通常需要用交换论证或反证法证明"某个局部最优选择必定出现在某个全局最优解中"。若无法证明，贪心可能只是一个启发式近似算法，而非精确算法，这时应转向动态规划等其他方法。

## Compression

**定义**

压缩（Compression）是指在不丢失信息（无损压缩）或可接受地丢失部分信息（有损压缩）的前提下，将数据编码为更小的表示形式。本节聚焦无损压缩，其理论基础是信息论中的熵：一个符号源的最小平均编码长度由其信息熵决定，

$$H(X) = -\sum_{i} p_i \log_2 p_i$$

其中 $p_i$ 是符号 $i$ 出现的概率。任何前缀码（prefix-free code，即没有一个码字是另一个码字的前缀）的平均码长都不能低于 $H(X)$，这是压缩算法可达到的理论下界。

**Huffman 编码：贪心且可证明最优**

Huffman 编码是一种贪心算法：反复取出当前频率最小的两个节点，合并为一个新节点（频率为两者之和），直到只剩一个根节点，由此构建一棵二叉树，叶子对应原始符号，从根到叶的路径即为该符号的编码。由于合并顺序总是优先处理频率最低的符号，高频符号获得更短的码字，低频符号获得更长的码字——这正是可变长度编码能逼近熵下界的关键。可以证明，Huffman 编码在所有前缀码中给出的期望码长是最优的（不超过 $H(X)+1$）。

*例：* 设符号 A, B, C, D 的出现频率分别为 0.5, 0.25, 0.125, 0.125。Huffman 树给出编码 A=0, B=10, C=110, D=111，期望码长为 $0.5(1)+0.25(2)+0.125(3)+0.125(3) = 1.75$ 比特，恰好等于该分布的熵 $H(X)=1.75$，达到理论最优。

**LZ77 / LZ78：以动态规划视角看匹配**

Huffman 编码假设符号独立出现，无法利用重复子串（如英文文本中反复出现的单词）。LZ77 通过滑动窗口在已处理的数据中寻找当前位置的最长匹配子串，并用 (回溯距离, 匹配长度, 下一字符) 三元组替代重复内容；LZ78 则维护一个动态增长的字典，将新出现的字符串前缀映射为索引。二者的核心都是在每个位置上做出"最长可复用匹配"的最优子结构选择，可视为一种在线动态规划过程：每一步的最优编码依赖于此前子问题（已扫描前缀）的最优匹配结果。

**综合应用**

现实压缩工具（gzip、zstd 等）将两者串联：先用 LZ77/LZ78 消除重复结构，再对输出的字面量和匹配长度用 Huffman（或算术编码）做熵编码，逼近信息熵下界。理解这一分层结构，是设计或调优任何数据压缩流水线的基础。
