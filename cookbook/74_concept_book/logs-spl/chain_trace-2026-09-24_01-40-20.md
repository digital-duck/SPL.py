## Parent Structure

**Definition.** In Sage, every mathematical object $x$ carries a distinguished attribute $x.parent()$, an object $P$ called its *parent*, which is itself an instance of a subclass of the `Parent` class in the category-theoretic hierarchy `sage.structure.parent`. The parent encodes the algebraic structure — the set together with its operations — to which $x$ is asserted to belong: $\mathbb{Z}$ (`ZZ`), $\mathbb{Q}$ (`QQ`), the finite field $\mathbb{F}_7$ (`GF(7)`), the symbolic ring `SR`, a polynomial ring $R[x]$, a matrix space $\mathrm{Mat}_{m\times n}(R)$, and so on. Formally, Sage's coercion model realizes a fragment of category theory: each parent $P$ is associated to a category $\mathcal{C}$ (rings, fields, groups, modules, …), and arithmetic between elements of parents $P$ and $Q$ is only well-defined once a *coercion morphism* $P \to R$ or $Q \to R$ into some common parent $R$ has been established, via `sage.structure.coerce`.

**Theorem (uniqueness and canonicity of parents).** Sage's parent structure satisfies a *unique parent axiom*: for any given mathematical structure with fixed defining data, the parent object is a singleton up to `==` and often `is` (via a global cache, `UniqueRepresentation`). That is, `GF(7) is GF(7)` returns `True`, and two elements $a, b$ with $a.parent() \equiv b.parent()$ (structurally identical constructor arguments) are guaranteed interoperable without ambiguity. *Proof sketch:* `UniqueRepresentation` overrides `__classcall__` to hash the constructor arguments and consult a weak-value cache; if a parent with identical arguments already exists, the cached instance is returned instead of instantiating anew. This guarantees that parent identity (`is`), and not merely equality (`==`), can be used as a fast structural test — an essential invariant for the coercion model's performance, since exact structural comparison would otherwise require re-deriving canonical forms at each operation. $\blacksquare$

**Literature context.** The design descends from Magma's type/parent system and from Axiom/Aldor's categorical hierarchy, and is documented formally in the Sage coercion model reference and in Bosma–Cannon's original design papers for computer algebra category hierarches. What remains open, and is an active area of Sage development, is the completeness and soundness of the coercion *graph*: with an increasing number of parents (p-adics, number fields, quotient rings, tensor products), the discovery of coercion paths becomes a nontrivial search problem, and cases of ambiguous or missing coercions (e.g., between two number fields with no canonical embedding) surface regularly as reported issues.

**Suggested investigation.** Construct three parents — $\mathbb{Z}[x]$, $\mathbb{Q}[x]$, and $\mathbb{F}_5[x]$ — and systematically test which pairs support automatic coercion of a nonzero-degree element via `x.parent().has_coerce_map_from(y.parent())`. Extend to $\mathbb{Q}(\sqrt{2})$ and $\mathbb{Q}(\sqrt{3})$ and observe the failure mode when no canonical map exists. Trace the actual coercion path found (if any) using `sage.structure.coerce.py`'s `_richcmp_` and `get_action` internals with verbose coercion tracing enabled (`Parent._coerce_map_from_` debugging hooks).

**Report-writing note.** A write-up should state precisely which coercion tests succeeded and failed, give the categorical justification (ring homomorphism existence) for each success, and for each failure explain why no canonical morphism exists (as opposed to one merely not being implemented) — distinguishing mathematical obstruction from implementation gap.

## Symbolic Variable

**Definition.** A symbolic variable is an element $x$ of a free commutative algebra (typically $\mathbb{Q}[x]$, $\mathbb{R}[x]$, or a polynomial ring in several indeterminates over a base ring $R$) that is *uninterpreted*: no evaluation map $\phi: R[x] \to R$ is fixed a priori. Formally, `var('x')` in a computer algebra system (CAS) such as SageMath or a symbolic-manipulation library instantiates a generator of a free $R$-algebra, distinguished from a *numeric* variable — a name bound to a single element of $R$ — precisely by the absence of this binding. The symbol $x$ is not "a number we don't know yet" in the probabilistic sense; it is a formal placeholder satisfying only the axioms of the ring it generates (commutativity, distributivity, etc.), nothing more.

**Theorem (Universal property of the polynomial ring).** Let $R$ be a commutative ring. The polynomial ring $R[x]$, together with the inclusion $\iota: R \hookrightarrow R[x]$ and the distinguished element $x \in R[x]$, satisfies: for every commutative $R$-algebra $A$ and every element $a \in A$, there exists a unique $R$-algebra homomorphism $\varepsilon_a: R[x] \to A$ with $\varepsilon_a(x) = a$.

*Proof.* Existence: define $\varepsilon_a\left(\sum_{i=0}^n c_i x^i\right) = \sum_{i=0}^n c_i a^i$; this is well-defined since every element of $R[x]$ has a unique representation as a finite sum of monomials with coefficients in $R$, and one checks directly that $\varepsilon_a$ respects addition and multiplication because $A$ is commutative. Uniqueness: any $R$-algebra homomorphism $\psi$ with $\psi(x) = a$ must satisfy $\psi(c_i x^i) = c_i \psi(x)^i = c_i a^i$ by $R$-linearity and multiplicativity, forcing $\psi = \varepsilon_a$ on every monomial, hence on all of $R[x]$ by additivity. $\blacksquare$

This is precisely why `var('x')` grants access to "every number at once": $x$ is the *generic point* of $\mathbb{A}^1_R$, and any specific number $a$ is recovered by the evaluation homomorphism $\varepsilon_a$ — substitution. Algebra with $x$ (simplification, factoring, differentiation as a formal $R$-derivation) is computation performed once, in $R[x]$, that commutes with every subsequent specialization $\varepsilon_a$; this is the sense in which "algebra precedes arithmetic."

**Literature context.** The universal property above is standard commutative algebra (Atiyah–Macdonald, Lang); its computational incarnation is the subject of computer algebra (von zur Gathen & Gerhard). What remains genuinely active research is efficient *representation* of symbolic expressions (DAG sharing, canonical forms modulo associativity/commutativity — the word problem for expression equivalence is undecidable in general once transcendental functions are admitted, per Richardson's theorem) and the interplay between symbolic and numeric computation (interval arithmetic, hybrid symbolic-numeric algorithms).

**Suggested investigation.** Implement $\varepsilon_a$ explicitly in a CAS (Sage or SymPy) for a nontrivial $A$ (e.g. $A = M_n(R)$, matrices) and verify the homomorphism property computationally on random polynomials and matrices; then explore where naive symbolic simplification fails to detect $A$-specific identities (e.g. Cayley–Hamilton) that a numeric substitution would trivially satisfy for tested values but that require the ring structure of $A$ to prove in general.

**Report-writing note.** A write-up should state the universal property precisely, give the proof, then present the computational experiment with explicit code and output, and discuss at least one case where symbolic and numeric approaches to the same identity diverge in what they can certify (numeric: verified at sampled points; symbolic: proved for all $a \in A$).

### symbolic_expression (0.0s)

## Symbolic Expression

**Definition.** In Sage, the Symbolic Ring $SR$ is a commutative ring whose elements are formal expression trees built from symbolic variables (see [[symbolic_variable]]), numeric literals, and function/operator nodes (arithmetic operators, elementary and special functions), closed under composition. Formally, $SR$ is the free structure generated by an alphabet of symbols $x_1, x_2, \ldots$ under the signature $\Sigma = \{+, \cdot, -, /, {}^{\wedge}, \sin, \exp, \log, \Gamma, \ldots\}$, modulo no relations beyond the syntactic ones imposed by the parser — i.e., $SR$ is (up to normalization by Maxima/Pynac's simplification routines) the term algebra $T_\Sigma(X)$ over variable set $X$. An element $e \in SR$ carries its construction history exactly: $e = f(g(x), h(y))$ is stored as a directed acyclic graph (a *parent structure*, see [[parent_structure]]) with $f, g, h \in \Sigma$ and leaves $x, y \in X$, not as a floating-point approximation of its value.

**Theorem (structural uniqueness up to evaluation order).** Two symbolic expressions $e_1, e_2 \in SR$ are syntactically distinct in general even when they are semantically equal as functions of their free variables (e.g., $\sin^2(x) + \cos^2(x)$ and $1$), because $SR$ performs no automatic theorem-proving simplification — only canonicalization at the level of associativity/commutativity normal forms maintained by the underlying CAS kernel (Pynac, itself a C++ reimplementation of GiNaC's expression-tree engine). Consequently equality testing in $SR$ splits into two distinct operations: `bool(e1 == e2)`, which invokes symbolic simplification and possibly numerical sampling as a heuristic, and `(e1 - e2).is_zero()` or `.simplify_full()`, which attempts exact reduction. Neither is a decision procedure in general, since the equivalence problem for expressions involving $\exp$, $\log$, and algebraic operations is undecidable (Richardson's theorem, 1968) even for finite closed forms.

**Literature context.** Richardson's undecidability result is the standard reference bounding what any symbolic engine — Sage, Mathematica, Maple — can guarantee about expression equivalence; it explains why $SR$ deliberately exposes the raw expression tree rather than pretending to a canonical form. The design of Pynac/GiNaC follows the term-rewriting and computer-algebra tradition surveyed in von zur Gathen–Gerhard's *Modern Computer Algebra*; open questions remain in simplification heuristics (which rewrite rules to apply, in what order, to approach — never guarantee — a "simplest" form) and in efficient common-subexpression sharing across large expression DAGs, an active concern in symbolic differentiation and automatic differentiation research.

**Suggested investigation.** Construct a family of expressions known to be equal (e.g., trigonometric identities, telescoping sums, or instances of Ramanujan-type series) and empirically test: (1) does `bool(e1==e2)` succeed, (2) does `.simplify_full()` succeed, (3) how does runtime scale with expression-tree depth? Compare Sage's success rate against a direct call to Maxima and to a CAS using a different simplification strategy (e.g., Mathematica's `FullSimplify`).

**Report-writing note.** The write-up should report the DAG size (node count) of each test expression, distinguish failures due to timeout from failures due to genuine simplification incompleteness, and state explicitly which equivalences were verified exactly versus only numerically (interval sampling), since this distinction is the crux of what "symbolic" guarantees mean in practice.

## Exact Integer

**Definition.** Let $\mathbb{Z}$ denote the ring of rational integers. A computational representation of $\mathbb{Z}$ is *exact* if it realizes every element of $\mathbb{Z}$ as a finite bit-string $b(n)$ such that the map $n \mapsto b(n)$ is injective and the ring operations $+, -, \times$ are computed via algorithms that return $b(n_1 \circ n_2)$ exactly, with no truncation, rounding, or modular wraparound, for any $n_1, n_2 \in \mathbb{Z}$ and any bit-length. Sage's `Integer` type (built on GMP/MPIR's `mpz_t`) is such a representation: an integer is stored as a sign bit plus a variable-length array of machine words (limbs) in base $2^{64}$ (or $2^{32}$), so $2^{100}$ is stored as roughly two limbs encoding one exact value, not as a floating-point approximation with a 53-bit mantissa. This stands in contrast to IEEE 754 doubles, or to fixed-width machine integers (`int32`, `int64`), whose representations are quotients of $\mathbb{Z}$ by $2^k\mathbb{Z}$ or by the floating-point rounding relation, and are therefore *not* injective on all of $\mathbb{Z}$.

**Theorem (correctness of arbitrary-precision arithmetic).** Let $a, b$ be integers represented in base-$B$ positional form with $\ell(a), \ell(b)$ limbs respectively. Schoolbook addition/subtraction runs in $O(\max(\ell(a),\ell(b)))$ word operations and produces the exact sum with no information loss, by the standard carry-propagation argument (each digit sum is bounded by $2B-1 < B^2$, representable in one extra limb of carry). Schoolbook multiplication runs in $O(\ell(a)\ell(b))$; GMP additionally implements Karatsuba ($O(n^{\log_2 3})$) and, for very large operands, Schönhage–Strassen/FFT-based multiplication ($O(n \log n \log\log n)$), each provably exact because they operate entirely over $\mathbb{Z}$ (or $\mathbb{Z}/(2^n+1)\mathbb{Z}$ with exact reconstruction) rather than over a rounded field.

*Proof sketch.* Addition/subtraction correctness follows by induction on limb position using the invariant that the running carry is bounded by the base. Karatsuba correctness follows from the algebraic identity $(a_1 B + a_0)(b_1 B + b_0) = a_1 b_1 B^2 + \big((a_1+a_0)(b_1+b_0) - a_1b_1 - a_0b_0\big)B + a_0 b_0$, which requires only three sub-multiplications instead of four, verified by direct expansion. FFT-based multiplication correctness rests on choosing a modulus large enough (via the Crandall–Fagin / Schönhage–Strassen construction) that no wraparound occurs before the final exact reconstruction, i.e. all convolution coefficients stay below the chosen modulus. $\blacksquare$

**Literature context.** The complexity landscape for exact integer multiplication has an active frontier: Schönhage–Strassen ($O(n\log n\log\log n)$, 1971) stood as the best known bound for decades until Harvey and van der Hoeven (2019, 2021) proved an $O(n\log n)$ algorithm, matching the conjectured lower bound from Fürer's work — but this algorithm is currently impractical for GMP's operand ranges (it wins only for astronomically large $n$), so GMP still switches among schoolbook, Karatsuba, Toom–Cook, and FFT methods by threshold. Open questions remain about practical crossover points, memory-bandwidth-optimal implementations, and whether Harvey–van der Hoeven-style methods can be made competitive at cryptographic or scientific-computing scales.

**Suggested investigation.** Using Sage, empirically measure the crossover points between GMP's multiplication algorithms: time `a*b` for random integers of increasing bit-length (e.g. $2^{10}$ to $2^{22}$ bits, log-spaced), and fit the timing curve to identify where the exponent of growth shifts from $\approx 2$ (schoolbook) to $\approx 1.585$ (Karatsuba) to $\approx 1$ (FFT regime). Compare against `int` overflow behavior in a fixed-width language to make the "floor of exactness" concrete.

**Report-writing note.** The write-up should state the measured crossover bit-lengths, the fitted growth exponents with error bars, and an explicit demonstration (via hash or digit-by-digit check) that Sage's product matches a symbolic/exact reference computation at every tested size — establishing exactness is preserved, not merely that timing scales as expected.

- [Harvey, van der Hoeven, *Integer multiplication in time $O(n\log n)$* (2021)](https://hal.science/hal-02070778/document)

## Substitution Evaluation

**Definition.** Let $E$ be a symbolic expression over a set of free variables $X = \{x_1, \dots, x_n\}$, formally an element of a term algebra $T(\Sigma, X)$ built from an operator signature $\Sigma$. *Substitution* is a map $\sigma: X \to T(\Sigma, X)$, extended homomorphically to $E\sigma$ by structural recursion on $E$'s syntax tree. *Numerical evaluation* $n(E)$ is the further map $T(\Sigma, \emptyset) \to \mathbb{R}$ (or $\mathbb{C}$, or a floating-point/interval type) obtained once every leaf of the tree is a numeral, defined by interpreting each operator symbol in $\Sigma$ as a concrete function on that codomain. The composition $\text{eval}_\sigma(E) = n(E\sigma)$ is what a user usually wants, but the API design in `subs()`/`n()` deliberately factors it into two independent stages.

**Theorem (well-definedness and commutativity of substitution).** If $\sigma_1, \sigma_2$ have disjoint domains, then $(E\sigma_1)\sigma_2 = (E\sigma_2)\sigma_1 = E(\sigma_1 \cup \sigma_2)$, and for any $E$ with $\text{FV}(E) \subseteq \text{dom}(\sigma)$, $E\sigma$ contains no free occurrence of any $x \in \text{dom}(\sigma)$.

*Proof.* By structural induction on $E$. Base case: $E = x_i$, a leaf; $E\sigma_1\sigma_2 = \sigma_1(x_i)\sigma_2$, which equals $\sigma_2(\sigma_1(x_i))$ trivially if $x_i \notin \text{dom}(\sigma_2)$; if instead $E = x_i \notin \text{dom}(\sigma_1)$, symmetric argument applies. Inductive step: for $E = f(E_1,\dots,E_k)$, substitution distributes over the operator, $E\sigma = f(E_1\sigma,\dots,E_k\sigma)$, so the claim reduces to the induction hypothesis on each $E_i$. The second claim follows since substitution replaces every occurrence of $x_i \in \text{dom}(\sigma)$ syntactically, leaving none behind (no variable capture occurs in a first-order term algebra without binders). $\blacksquare$

This is essentially the confluence property underlying $\beta$-reduction in the $\lambda$-calculus restricted to a binder-free term algebra, and it is what guarantees that the order of independent substitutions in a computer algebra system (Sage, SymPy, Mathematica) never affects the result.

**Literature context.** The separation of symbolic substitution from numeric evaluation mirrors the classical distinction in term rewriting systems (Baader & Nipkow) between *rewriting* (syntactic, confluent up to the rules) and *interpretation* (semantic, in a fixed algebra). What remains genuinely open is efficiency: naive substitution on a DAG-shared expression can cause exponential blow-up if sharing is not preserved (the "expression swell" problem well known in Gröbner basis and CAS implementations), and current systems differ substantially in how they cache or memoize $E\sigma$ for repeated $\sigma$.

**Suggested investigation.** Implement `subs()` on a DAG (not a tree) representation with hash-consing, and measure expression size growth versus a naive tree-copy implementation across a family of expressions with deep sharing (e.g., iterated squaring $E_{k+1} = E_k^2 + E_k$). Then benchmark $n(\cdot)$ under exact rational arithmetic versus floating point, tracking catastrophic cancellation.

**Report-writing note.** The write-up should state the sharing representation precisely, give asymptotic bounds (naive vs. hash-consed) with a proof sketch, and report empirical blow-up factors with the specific expression family and node counts used.

**References**
- [Baader, F. & Nipkow, T., *Term Rewriting and All That* (1998)](https://www.cambridge.org/core/books/term-rewriting-and-all-that/71768055278D0DEF4FFC58A2E4256088)
- [SymPy Development Team, *SymPy Documentation: Basic Operations*](https://docs.sympy.org/latest/tutorials/intro-tutorial/basic_operations.html)

### exact_rational (0.0s)

## Exact Rational

**Definition.** The type $\mathbb{Q}_{\text{exact}}$ represents a rational number as a pair $(n, d) \in \mathbb{Z} \times \mathbb{Z}_{>0}$ with $\gcd(n,d) = 1$, interpreted as the value $n/d \in \mathbb{Q}$. Arithmetic operations are defined by the field structure of $\mathbb{Q}$ and a normalization map $\rho: \mathbb{Z} \times (\mathbb{Z}\setminus\{0\}) \to \mathbb{Q}_{\text{exact}}$,
$$
\rho(a,b) = \left(\frac{a/g}{\,\text{sgn}(b)\,},\ \frac{|b|/g}{1}\right), \qquad g = \gcd(a,b).
$$
Decimal or floating-point representations are not part of the type; they arise only under an explicit coercion $\delta_k: \mathbb{Q}_{\text{exact}} \to \mathbb{R}$ truncated to $k$ digits, applied on output, never internally.

**Theorem (closure under the four operations).** Let $x = n_1/d_1$, $y = n_2/d_2$ be in lowest terms. Then
$$
x+y = \rho(n_1 d_2 + n_2 d_1,\ d_1 d_2), \quad x \cdot y = \rho(n_1 n_2,\ d_1 d_2), \quad x/y = \rho(n_1 d_2,\ n_2 d_1)\ (y\neq 0),
$$
and each result, after normalization by $\rho$, is again an element of $\mathbb{Q}_{\text{exact}}$ with a *unique* representative pair. Uniqueness follows immediately from $\gcd(n,d)=1$ combined with a fixed sign convention on $d>0$: any two coprime pairs representing the same rational differ by a unit $(-1,-1)$, which the sign convention eliminates.

*Proof sketch.* Closure is the standard verification that $\mathbb{Q}$ is a field under the usual fraction arithmetic; the substance here is that $\rho$ is total and computable via Euclid's algorithm, so no operation can silently leave lowest-terms form or introduce rounding. Uniqueness of the coprime representative is the fundamental theorem of arithmetic applied to $n/g, d/g$. $\blacksquare$

**Literature context.** This construction is the algebraic-datatype analogue of the classical field of fractions of $\mathbb{Z}$ (Hungerford, *Algebra*, Ch. III); its computational realization is the subject of exact/symbolic arithmetic systems (GMP's `mpq`, Python's `fractions.Fraction`, Lisp's rational tower). The open engineering question is not existence but *complexity*: repeated addition without intermediate GCD reduction causes numerator/denominator bit-length to grow, in the worst case, linearly per operation, giving quadratic-or-worse blowup over $k$ operations — a phenomenon studied under "coefficient growth" in computer algebra (von zur Gathen & Gerhard, *Modern Computer Algebra*). Whether a given implementation reduces eagerly (every operation) or lazily (only before comparison/output) is a genuine design tradeoff, not a settled matter.

**Suggested investigation.** Implement $\mathbb{Q}_{\text{exact}}$ two ways — eager reduction vs. lazy reduction — and empirically measure numerator bit-length growth over a random walk of $10^4$ additions/multiplications on rationals with small initial denominators (e.g. summing $1/1, 1/2, \dots$ as in the harmonic series). Compare wall-clock time against `Fraction` in an existing library.

**Report-writing note.** A write-up should state the normalization invariant precisely, prove it is preserved by each operation, and present the growth-rate measurement with a fitted asymptotic (linear vs. superlinear) alongside the theoretical worst-case bound, explicitly flagging any gap between the two.

### plotting_visualization (0.0s)

## Plotting Visualization

**Definition.** Let $f : D \subseteq \mathbb{R} \to \mathbb{R}$ be a computable expression in a computer algebra system (CAS), and let $S = \{(x, y) \in D \times \mathbb{R} : y = f(x)\}$ be its graph. The operation `plot(f, x, a, b)` computes a finite sample $P = \{(x_i, f(x_i))\}_{i=0}^n$, $x_i \in [a,b]$, and renders a piecewise-linear (or spline) interpolant $\hat{S}$ approximating $S$. The generalizations `plot3d` (surfaces $z = f(x,y)$, or parametric $\mathbf{r}(u,v)$) and `implicit_plot` (level sets $\{(x,y) : F(x,y) = 0\}$, computed via contouring algorithms such as marching squares/cubes) extend this to $\mathbb{R}^3$ and to relations not solvable in closed form for $y$. Crucially, these routines act directly on the symbolic object — not on a separately transcribed formula — so a plotting call is a structural query on the same expression tree used in `substitution_evaluation`.

**Theorem (plotting as a decision procedure, informally).** If $f$ and $g$ are symbolically distinct expressions with $f - g \not\equiv 0$ on $D$, then generically $\hat{S}_f \neq \hat{S}_g$ as rendered curves on any sufficiently fine sample grid with $n \geq N(\varepsilon)$ points, where $N(\varepsilon)$ depends on the modulus of continuity of $f-g$ and a visual tolerance $\varepsilon$. This is *not* a proof of $f \equiv g$ or $f \not\equiv g$ — visual coincidence at finite resolution is necessary but not sufficient evidence — but it is a fast, high-recall filter: a visible discrepancy refutes an algebraic claim ($f = g$) with near-certainty, since sampling error alone rarely conspires to hide a genuine functional difference over an interval. This asymmetry (plots reject, not confirm) is the logical content of "visualization as a check."

**Literature context.** The theoretical question of *how many samples suffice to guarantee no branch or singularity is missed* is genuinely open in general: adaptive plotting algorithms (as in Mathematica's `PlotPoints`/`MaxRecursionDepth`, or Sage's `plot` adaptive refinement, following Wolfram's and earlier Lane's heuristics) refine near high curvature or discontinuities, but no algorithm can certify completeness for arbitrary $f$ without additional structure (e.g. Lipschitz bounds, or symbolic detection of poles via `singularities`). Implicit plotting is harder still: marching-squares contouring (Lorensen & Cline 1987, originally for 3D marching cubes) can miss thin filaments or isolated points of a variety when the grid is coarser than the feature scale — a concrete instance of the aliasing problem in numerical algebraic geometry, connected to certified/interval-arithmetic plotting (e.g. Tupper's reliable implicit plotting algorithm, 2001).

**Suggested investigation.** Construct a family $f_\epsilon(x) = \sin(x) + \epsilon \sin(N x)$ for large $N$ and small $\epsilon$, and determine experimentally the sampling density $n(\epsilon, N)$ at which uniform-grid `plot` first visually distinguishes $f_\epsilon$ from $\sin(x)$; compare against adaptive plotting. Separately, implement (or study) Tupper's algorithm and construct an implicit curve with a component of measure zero (an isolated point or degenerate branch of $F(x,y)=0$) that a naive marching-squares implementation misses at a given resolution but interval-arithmetic contouring recovers.

**Report-writing note.** The write-up should state the exact sampling scheme used (grid vs. adaptive), quantify the resolution threshold at which the discrepancy or missed feature becomes visible/invisible, and explicitly distinguish "plot confirms an identity" (unjustified) from "plot refutes an identity" (the sound use), citing the specific $\varepsilon$–$n$ tradeoff observed.

- [Wolfram, Plot documentation and adaptive sampling](https://reference.wolfram.com/language/ref/Plot.html)
- [SageMath, plot and implicit_plot documentation](https://doc.sagemath.org/html/en/reference/plotting/index.html)

### preparser (19.5s)

## Preparser

**Definition.** Sage does not execute raw Python source directly at the interactive prompt or in `.sage` files; it first passes input through a *preparser*, a source-to-source transformation $\pi : \Sigma^* \to \Sigma^*$ mapping Sage syntax to valid Python syntax, which the standard Python interpreter then executes. The preparser is invoked automatically in the Sage REPL and on `.sage` files (via `sage.repl.preparse.preparse`), and can be disabled with `preparser(False)`, after which Sage behaves as an ordinary Python session augmented only by its library imports.

The three most consequential rewrites are:

1. **Exponentiation.** The token `^`, which Python reserves for bitwise XOR, is rewritten to `**`. Thus `2^10` becomes `2**10` before compilation. This is a purely lexical substitution and is context-sensitive only insofar as it respects string and comment boundaries (`preparse` tokenizes input rather than using regex substitution naively, to avoid corrupting string literals such as `"a^b"`).
2. **Integer and rational literals.** A bare integer literal $n$ is rewritten to `Integer(n)`, and a literal of the form $a/b$ with both operands integer literals is rewritten to `Integer(a)/Integer(b)`, which — since Sage's `Integer.__truediv__` returns an element of $\mathbb{Q}$ — evaluates to a `Rational`, not the truncated or floating-point quotient Python would produce. Formally, if $\iota:\mathbb{Z}\to\mathbb{Z}_{\mathrm{Sage}}$ denotes coercion into Sage's `Integer` ring, the preparser enforces $\pi(n) = \iota(n)$ for every integer literal $n$ in the source, so that arithmetic among literals is performed in the exact ring $\mathbb{Z}$ (or its fraction field $\mathbb{Q}$) rather than in Python's native `int`/`float` types.

**Theorem (idempotence up to fixed syntax).** For source $s$ already free of `^` and containing no bare numeric literals requiring promotion, $\pi(s) = s$; more generally $\pi$ is a well-defined total function on the grammar Sage accepts, since `preparse` is implemented as a single deterministic pass over the token stream with no recursive re-preparsing. *Proof sketch:* `preparse` tokenizes with Python's `tokenize` module, applies the substitution rules token-by-token (respecting `STRING`, `COMMENT`, and `NAME` token types to avoid rewriting identifiers or literal text), and reassembles the stream; determinism of tokenization and the absence of a fixed-point loop in the implementation give totality and single-pass termination. $\blacksquare$

**Literature and open questions.** The preparser is documented in the Sage Developer's Guide and reference manual but has received little independent formal treatment; its design inherits from the broader tradition of embedded DSLs realized via source transformation (cf. macro-expansion in Lisp, or Python's own `ast`-level rewriting used by libraries like `sympy`'s `parse_expr`). An open, tractable question for a graduate project: characterize $\pi$ precisely as a context-free (or context-sensitive, given the string/comment exclusions) transduction, and determine whether $\pi$ commutes with Python's own tokenizer in all edge cases (e.g., f-strings, walrus operator, numeric literals with underscores such as `1_000`).

**Suggested investigation.** Read `sage.repl.preparse` and reconstruct, from the source, the full grammar of literals it rewrites (integers, rationals, `Integer` vs `RealNumber` triggers via decimal points, `R.<x> = ...` bracket notation). Then construct adversarial inputs — strings containing `^`, nested f-strings, integers inside comments — and verify `preparse` behaves correctly; document any discrepancy as a potential bug report.

**Report-writing note.** A write-up should state the exact rewrite rules discovered (with before/after examples), give the token-level argument for why string/comment content is protected, and report the outcome of at least three adversarial test cases with `preparser(False)` used as a control to confirm Sage's Python-mode behavior matches vanilla Python semantics.

## Exact Vs Float

**Definition.** Let $\mathbb{Q}$ denote the field of rational numbers, represented in a computer algebra system by an exact pair $(p,q) \in \mathbb{Z} \times \mathbb{Z}_{>0}$ with $\gcd(p,q)=1$, and let $\mathbb{F} \subset \mathbb{Q}(2)$ (dyadic rationals, roughly — IEEE 754 double precision) denote the finite floating-point subset used for numerical display. Write $n : \mathbb{Q} \to \mathbb{F}$ for the evaluation map (e.g., Sage's `n()`, `N()`, or `.n()`). The central computational discipline is: perform all algebraic manipulation in $\mathbb{Q}$ (or an exact extension such as $\mathbb{Q}[\sqrt{2}]$, $\mathbb{Q}(\pi)$ as a formal symbol, or $\overline{\mathbb{Q}}$), and apply $n$ only as the last step, purely for human-readable output.

**Theorem (non-commutativity of $n$ with arithmetic).** For $a, b \in \mathbb{Q}$ and $\circ \in \{+, -, \times, \div\}$, in general
$$n(a \circ b) = n(a) \circ_{\mathbb{F}} n(b)$$
holds only up to rounding error $\varepsilon$ bounded by machine epsilon $u \approx 2^{-52}$, and for a *sequence* of $k$ operations the error compounds: $|n(a_1 \circ \cdots \circ a_k) - \text{fl}(a_1 \circ \cdots \circ a_k)| \le C k u$ for some condition-number-dependent constant $C$ (Higham 2002, Ch. 3). In particular, $n$ does not commute with $\circ_\mathbb{F}$ in the associative/distributive sense that exact $\circ$ satisfies over $\mathbb{Q}$: $(a+b)+c = a+(b+c)$ exactly, but $\text{fl}((a+b)+c) \ne \text{fl}(a+(b+c))$ in general. The proof is immediate from the fact that $\mathbb{F}$ is not closed under $\circ$: $n(a \circ b)$ requires an implicit rounding $\text{round}: \mathbb{Q} \to \mathbb{F}$, and $\text{round}$ is not a ring homomorphism.

**Literature context.** This is the foundational concern of numerical analysis (Higham's *Accuracy and Stability of Numerical Algorithms* is the standard reference) and of computer algebra system design (von zur Gathen & Gerhard, *Modern Computer Algebra*, discuss exact arithmetic complexity extensively). What is well understood: catastrophic cancellation, condition numbers, and backward-error analysis for standard algorithms (LU decomposition, root-finding). What remains active research: certified/interval arithmetic hybrids that combine exact symbolic bounds with floating-point speed (e.g., ball arithmetic in Arb/FLINT), and the design of CAS heuristics for *when* to switch representations (e.g., Sage's `QQbar` vs. numerical approximation trade-offs in real root isolation).

**Suggested investigation.** Take a moderately ill-conditioned linear system (e.g., a Hilbert matrix $H_n$ for $n=10$) and solve it two ways: (1) exactly over $\mathbb{Q}$ via `solve_right()` with rational entries, then apply $n()$ to the solution vector; (2) convert $H_n$ to floats first, then solve numerically. Measure the discrepancy against the exact solution as $n$ grows from $5$ to $15$, and relate the blow-up to $\kappa(H_n) \sim e^{3.5n}$ (known asymptotic condition number growth for Hilbert matrices, Wilf 1962).

**Report-writing note.** The write-up should present the exact and float solution vectors side by side for each $n$, plot $\log_{10}(\text{error})$ against $n$, and explicitly identify the point at which floating-point solving becomes numerically meaningless — connecting the empirical break-down to the theoretical $\kappa(H_n)$ growth rate rather than treating it as an unexplained artifact.

## Interactive Notebooks

**Definition.** An *interactive notebook* is a document $N = (C_1, C_2, \ldots, C_n)$, an ordered sequence of cells, where each $C_i$ is either a Markdown cell (static exposition) or a code cell evaluated by a kernel $K$ against a persistent state $\sigma_i$, so that $\sigma_i = K(C_i, \sigma_{i-1})$. In the SageMath context, $K$ is the Sage kernel: source in each code cell is first passed through the *preparser* $P$ (a syntactic transducer, $P: \texttt{Sage source} \to \texttt{Python source}$, rewriting `2/3` to `Integer(2)/Integer(3)`, `^` to `**`, and `R.<x> = QQ[]` to explicit generator assignment) before being handed to the Python/Cython evaluator. An `@interact`-decorated function $f(p_1,\ldots,p_k)$ over a parameter space $\prod_j D_j$ induces a map $\Phi: \prod_j D_j \to \text{Output}$ realized as a widget: each redraw is a fresh evaluation $f(p_1,\ldots,p_k)$ against the *current* $\sigma_i$, not a re-run of the whole notebook.

**Proposition (non-commutativity of cell execution).** The state $\sigma_n$ produced by a notebook is a function of the *execution order* actually performed, which need not equal the cell order $1,\ldots,n$ as displayed. Formally, if $\tau$ is any permutation of $\{1,\ldots,n\}$ realizable by out-of-order execution, $\sigma^{\tau} = K(C_{\tau(n)}, K(C_{\tau(n-1)}, \ldots))$ need not equal $\sigma^{\mathrm{id}}$, because $K$ is not associative-commutative in general (mutable global bindings, random seeds, and `@interact` closures over $\sigma_i$ all break commutativity). *Proof sketch:* exhibit $C_1: x=1$, $C_2: x=x+1$; executing $2,1$ then $1,2$ again yields $x=1$ vs. $x=3$ respectively at their final states — hence $K$ fails commutativity on this pair. $\blacksquare$ This is the formal reason a notebook is not, by itself, a reproducible artifact: reproducibility requires the additional claim "linear top-to-bottom re-execution reproduces $\sigma_n$," which must be checked (Kernel → Restart & Run All), not assumed.

**Literature context.** The Jupyter architecture (kernel/protocol separation, ZeroMQ messaging) is documented in [Kluyver et al., "Jupyter Notebooks — a publishing format for reproducible computational workflows" (2016)](https://ebooks.iospress.nl/publication/42900). SageMath's preparser and its grammar are specified in the [Sage Developer's Guide, Coercion and Preparsing](https://doc.sagemath.org/html/en/reference/misc/sage/misc/preparser.html), and `@interact` widgets are documented at [Sage Interactive Demos](https://doc.sagemath.org/html/en/thematic_tutorials/interact/index.html). An active empirical-software-engineering literature (Pimentel et al., Rule et al.) quantifies exactly the failure mode above — that a large fraction of public notebooks do not reproduce their displayed outputs under linear re-execution — motivating tools like `nbconvert --execute`, `papermill`, and CI-based notebook testing as remedies; the open question is less "does the failure occur" (well established) and more how to *statically* detect out-of-order-execution risk from notebook structure alone (e.g. via a dataflow analysis over the notebook's execution-count metadata) without dynamic re-execution.

**Suggested investigation.** Take a nontrivial Sage notebook you have already written for this course (e.g. one from the plotting or algebra recipes). (1) Record its current top-to-bottom output. (2) Deliberately execute cells out of order (simulate an editing session) and record the divergent output, identifying which mutable binding or `@interact` closure caused the divergence. (3) Write a short static check — a script over the `.ipynb` JSON's `execution_count` fields — that flags whether the *saved* execution order is monotonic, as a proxy for reproducibility risk.

**Report-writing note.** The write-up should state the divergence precisely (which variable, which two orderings, and the two resulting values), give the preparsed Python for the offending cell to show *why* it is order-dependent, and report whether the static execution-count check would have flagged the specific notebook before the divergence was found by hand.

## Stem Classroom

**Definition.** A *stem classroom* built on a free computer algebra system (CAS) is one in which every student's mathematical environment is bit-for-bit identical — same kernel version, same symbolic engine, same numerical backend — because the software carries no license fee and hence no institutional gatekeeping. SageMath, built atop GAP, PARI/GP, Singular, Maxima, and a Python interpreter, is the canonical instance: it unifies algebra, number theory, combinatorics, and numerical analysis under one syntax, and its `@interact` decorator converts a static Sage cell into a parametrized widget — sliders, checkboxes, dropdowns bound to a function `f(a, b, \dots)` that re-executes on every UI event.

**Theorem/Proof (interact as a discretized parameter sweep).** Let $f: \Theta \to X$ be a computation mapping a parameter tuple $\theta = (\theta_1, \dots, \theta_n) \in \Theta \subset \mathbb{R}^n$ to a rendered object $X$ (a plot, a matrix, a symbolic expression). An `@interact` block with widgets $w_i$ ranging over finite grids $G_i \subset \mathbb{R}$ realizes the discretized map

$$
\hat f: \prod_{i=1}^n G_i \longrightarrow X, \qquad \hat f(\theta_1,\dots,\theta_n) = f(\theta_1,\dots,\theta_n),
$$

evaluated eagerly on each callback. Correctness of $\hat f$ as a pedagogical proxy for the continuous phenomenon reduces to two claims: (1) $\hat f$ is *sound*, i.e., agrees with $f$ pointwise on $\prod G_i$ — trivial by construction, since Sage evaluates the same underlying routine; and (2) $\hat f$ is *sufficiently dense* to convey the qualitative behavior of $f$ on $\Theta$, which requires $|G_i|$ large enough relative to the modulus of continuity (or, for bifurcation phenomena, relative to the spacing of critical parameter values) of $f$ in the $i$-th coordinate. The proof of (2) is not automatic — a step size coarser than a bifurcation gap silently hides qualitative transitions — and is exactly the diagnostic a student must perform when designing an `@interact` demo.

**Literature context.** Sage's design philosophy is documented in [Stein, *Sage: Mathematics Software System*](https://www.sagemath.org) and the broader reproducibility argument for open CAS in education is made in Buchberger-style computer-algebra pedagogy literature and Jupyter-based interactive computing surveys. What remains open, and underexplored empirically, is a quantitative theory of grid density for `@interact` widgets: current practice sets slider steps by intuition, not by an error bound tied to $f$'s continuity modulus.

**Suggested investigation.** Pick a one-parameter family exhibiting a bifurcation — e.g., the logistic map $x_{n+1} = r x_n(1-x_n)$ — and build an `@interact` slider over $r \in [2.5, 4.0]$. Derive analytically the minimal slider resolution $\Delta r$ needed to not skip the first period-doubling cascade (accumulation point $r_\infty \approx 3.569946$), then empirically test whether Sage's default widget step satisfies this bound.

**Report-writing note.** The write-up should state the continuity/Lipschitz argument bounding $\Delta r$, report the empirical grid actually used, and explicitly flag any qualitative feature the default resolution would have missed.
