## Graph

A graph is a mathematical structure $G = (V, E)$ consisting of a set of vertices (or nodes) $V$ and a set of edges $E$, where each edge joins exactly two vertices. If the pair is unordered, $\{u, v\}$, the graph is *undirected*; if the pair is ordered, $(u, v)$, indicating a one-way relationship from $u$ to $v$, the graph is *directed* (a digraph). Graphs model relationships wherever entities connect pairwise: cities linked by roads, web pages linked by hyperlinks, people linked by friendships, tasks linked by dependencies.

**Worked example.** Let $V = \{A, B, C, D\}$ represent four servers in a network, and $E = \{\{A,B\}, \{B,C\}, \{C,D\}, \{A,D\}\}$ represent direct cables between them. This graph has $|V| = 4$ vertices and $|E| = 4$ edges, forming a cycle: $A$–$B$–$C$–$D$–$A$. Two vertices joined by an edge are *adjacent*; the number of edges touching a vertex is its *degree*. Here every vertex has degree 2, since each server connects to exactly two neighbors.

**Problem-solving application.** Suppose you must determine whether a message can travel from server $A$ to server $C$ using the existing cables, and if so, the minimum number of hops required. This is a *reachability* and *shortest path* problem, and it is why representing the network as a graph is useful rather than incidental: once the data is expressed as $(V, E)$, standard algorithms apply directly. Breadth-first search (BFS) explores vertices in order of increasing distance from the source, guaranteeing the first time it reaches $C$, it has found a shortest path. Starting from $A$, BFS visits $B$ and $D$ (distance 1), then $C$ (distance 2) — so the answer is 2 hops, via either $A$–$B$–$C$ or $A$–$D$–$C$.

The choice of representation matters for efficiency: an *adjacency list* stores, for each vertex, the list of its neighbors, using $O(|V| + |E|)$ space — efficient for sparse graphs. An *adjacency matrix* stores an $|V| \times |V|$ table of 0s and 1s indicating edges, using $O(|V|^2)$ space but allowing $O(1)$ edge lookups. Choosing between them is itself a problem-solving decision: sparse road networks favor adjacency lists, while dense graphs or algorithms requiring fast edge queries favor matrices.
