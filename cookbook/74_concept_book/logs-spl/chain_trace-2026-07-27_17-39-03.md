### depth_first_search (0.0s)

## Depth First Search

**Definition.** Let $G = (V, E)$ be a finite graph with vertex set $V$ and edge set $E$. *Depth-first search* (DFS) is a graph traversal algorithm that begins at a designated source vertex $s \in V$ and explores as far as possible along each branch before backtracking. Formally, DFS maintains a set $\text{visited} \subseteq V$ and, upon visiting vertex $u$, recursively visits every neighbour $v \in N(u)$ for which $v \notin \text{visited}$. Each vertex receives two timestamps: a *discovery time* $d[u]$ when it is first entered, and a *finish time* $f[u]$ when all descendants of $u$ have been fully explored.

**Worked Example.** Consider the directed graph $G$ with $V = \{1, 2, 3, 4, 5\}$ and edges $E = \{(1,2),(1,3),(2,4),(3,4),(4,5)\}$. Starting DFS from vertex $1$ with neighbours visited in numerical order:

1. Visit $1$: $d[1] = 1$. Recurse to $2$.
2. Visit $2$: $d[2] = 2$. Recurse to $4$.
3. Visit $4$: $d[4] = 3$. Recurse to $5$.
4. Visit $5$: $d[5] = 4$, $f[5] = 5$. Backtrack to $4$: $f[4] = 6$.
5. Backtrack to $2$: $f[2] = 7$. Recurse from $1$ to $3$.
6. Visit $3$: $d[3] = 8$; neighbour $4$ already visited, so $f[3] = 9$.
7. Finish $1$: $f[1] = 10$.

The DFS produces the finish-time ordering $f[5] < f[4] < f[2] < f[3] < f[1]$.

**Key Theorem (Parenthesis Theorem).** For any two vertices $u, v$ in a DFS of $G$, exactly one of the following holds: the intervals $[d[u], f[u]]$ and $[d[v], f[v]]$ are disjoint, or one is entirely contained within the other. Formally,

$$[d[v], f[v]] \subseteq [d[u], f[u]] \iff v \text{ is a descendant of } u \text{ in the DFS forest.}$$

This nesting structure is the foundation for cycle detection, topological sorting, and strongly connected component algorithms, all of which run in $\Theta(|V| + |E|)$ time.

**Lab Cell.**

```python
import sympy
from sympy.combinatorics.named_groups import SymmetricGroup

# Build adjacency list and run DFS with timestamps
graph = {1: [2, 3], 2: [4], 3: [4], 4: [5], 5: []}
visited, d, f, timer = set(), {}, {}, [0]

def dfs(u):
    visited.add(u)
    timer[0] += 1; d[u] = timer[0]
    for v in graph[u]:
        if v not in visited:
            dfs(v)
    timer[0] += 1; f[u] = timer[0]

dfs(1)
print("Discovery:", d)   # {1:1, 2:2, 4:3, 5:4, 3:8}
print("Finish:   ", f)   # {5:5, 4:6, 2:7, 3:9, 1:10}
```

Running this cell reproduces the timestamps computed by hand, confirming the parenthesis theorem: the interval $[2,7]$ for vertex $2$ properly contains $[3,6]$ for vertex $4$, which in turn contains $[4,5]$ for vertex $5$.

### preorder_postorder (17.1s)

## Preorder Postorder

**Definition.** Let $T$ be a rooted tree with root $r$, and let $\text{children}(v)$ denote the ordered list of children of a node $v$. A *preorder traversal* of $T$ visits $r$ first, then recursively traverses each subtree in left-to-right order. A *postorder traversal* visits each subtree recursively before visiting the root. Formally, if we write $\pi_{\text{pre}}(T)$ and $\pi_{\text{post}}(T)$ for the resulting node sequences:

$$\pi_{\text{pre}}(T) = r,\; \pi_{\text{pre}}(T_1),\; \pi_{\text{pre}}(T_2),\; \ldots,\; \pi_{\text{pre}}(T_k)$$

$$\pi_{\text{post}}(T) = \pi_{\text{post}}(T_1),\; \pi_{\text{post}}(T_2),\; \ldots,\; \pi_{\text{post}}(T_k),\; r$$

where $T_1, T_2, \ldots, T_k$ are the subtrees rooted at the children of $r$.

**Worked Example.** Consider the binary tree with root $A$, left child $B$ (with leaves $D$, $E$), and right child $C$ (with leaf $F$).

```
        A
       / \
      B   C
     / \   \
    D   E   F
```

Preorder visits the root before descending: $A, B, D, E, C, F$. Postorder processes all descendants before the root: $D, E, B, F, C, A$. Notice that in preorder, every node appears before all of its descendants, while in postorder every node appears after all of its descendants. This structural guarantee is the key property exploited in algorithms.

**Key Theorem.** *(Ancestor ordering)* Let $u$ and $v$ be nodes in a rooted tree $T$. Then $u$ is a proper ancestor of $v$ if and only if $u$ appears before $v$ in $\pi_{\text{pre}}(T)$ and after $v$ in $\pi_{\text{post}}(T)$. Equivalently, assigning each node $v$ the pair $(\text{pre}(v), \text{post}(v))$ of its positions in the two traversals, the ancestor relation satisfies:

$$u \text{ is an ancestor of } v \iff \text{pre}(u) < \text{pre}(v) \text{ and } \text{post}(u) > \text{post}(v).$$

This allows $O(1)$ ancestor queries after $O(n)$ preprocessing — a foundational technique in XML indexing, compiler symbol tables, and dependency resolution.

**Lab Cell.**

```python
from sympy import symbols
from sympy.combinatorics import Permutation

# Build tree as adjacency dict and run both traversals
tree = {'A': ['B','C'], 'B': ['D','E'], 'C': ['F'],
        'D': [], 'E': [], 'F': []}

def preorder(node):
    yield node
    for child in tree[node]:
        yield from preorder(child)

def postorder(node):
    for child in tree[node]:
        yield from postorder(child)
    yield node

pre  = list(preorder('A'))
post = list(postorder('A'))
print("Preorder: ", pre)
print("Postorder:", post)

# Verify ancestor theorem for pair (A, E)
pre_idx  = {n: i for i, n in enumerate(pre)}
post_idx = {n: i for i, n in enumerate(post)}
u, v = 'A', 'E'
print(f"{u} ancestor of {v}:",
      pre_idx[u] < pre_idx[v] and post_idx[u] > post_idx[v])
```

### active_interval (21.5s)

## Active Interval

### Definition

Let $f : \mathbb{R} \to \mathbb{R}$ be a real-valued function. The **active interval** of $f$, denoted $\mathcal{A}(f)$, is the smallest closed interval $[a, b] \subset \mathbb{R}$ such that $f(x) = 0$ for all $x \notin [a, b]$. Equivalently,

$$\mathcal{A}(f) = [\inf\{\,x \in \mathbb{R} : f(x) \neq 0\},\; \sup\{\,x \in \mathbb{R} : f(x) \neq 0\}].$$

When $f$ is identically zero, we adopt the convention $\mathcal{A}(f) = \emptyset$. The length of the active interval, $|\mathcal{A}(f)| = b - a$, measures the **temporal support** of $f$ and is central to the analysis of piecewise-defined signals, probability density functions with bounded support, and finite-duration control inputs.

### Worked Example

Consider the piecewise function

$$f(x) = \begin{cases} x - 1 & 1 \le x < 3, \\ 5 - x & 3 \le x \le 5, \\ 0 & \text{otherwise.} \end{cases}$$

To locate $\mathcal{A}(f)$, identify the leftmost point where $f$ is non-zero: $f(1) = 0$, but $f(1+\varepsilon) = \varepsilon > 0$ for any $\varepsilon > 0$, so $a = 1$. At the right end, $f(5) = 0$ and $f(5 - \varepsilon) = \varepsilon > 0$, giving $b = 5$. Hence $\mathcal{A}(f) = [1, 5]$ with $|\mathcal{A}(f)| = 4$. Note that $f(1) = f(5) = 0$; the boundary points belong to the active interval because they are limit points of the non-zero region.

### Key Theorem: Active Interval of a Convolution

**Theorem.** If $f$ and $g$ are compactly supported with $\mathcal{A}(f) = [a_1, b_1]$ and $\mathcal{A}(g) = [a_2, b_2]$, then

$$\mathcal{A}(f * g) \subseteq [a_1 + a_2,\; b_1 + b_2],$$

where $(f * g)(t) = \int_{-\infty}^{\infty} f(\tau)\,g(t - \tau)\,d\tau$.

*Proof sketch.* For $(f * g)(t)$ to be non-zero, there must exist $\tau \in [a_1, b_1]$ such that $t - \tau \in [a_2, b_2]$. This requires $t \in [a_1 + a_2, b_1 + b_2]$; outside this range the integrand vanishes identically. $\square$

This result is indispensable in filter design: convolving two finite-duration signals produces an output whose active interval is determined by the sum of the endpoint coordinates of the inputs.

### Lab Cell (SymPy)

```python
from sympy import symbols, Piecewise, integrate, plot

x = symbols('x', real=True)

f = Piecewise((x - 1, (x >= 1) & (x < 3)),
              (5 - x, (x >= 3) & (x <= 5)),
              (0, True))

# Confirm active interval by evaluating boundary behaviour
print(f.subs(x, 1), f.subs(x, 5))   # both 0
print(f.subs(x, 2), f.subs(x, 4))   # interior values

area = integrate(f, (x, 1, 5))
print("Area under f on active interval:", area)  # 4

plot(f, (x, 0, 6), ylabel='f(x)', title='Active Interval [1, 5]')
```

## Edge Classification

**Definition.** Let $G = (V, E)$ be a directed graph and let $T$ be the depth-first search (DFS) forest produced by running DFS on $G$. Every edge $(u, v) \in E$ falls into exactly one of four classes, determined by the discovery time $d[v]$ and finish time $f[v]$ assigned to each vertex during DFS:

- **Tree edge**: $(u, v)$ is traversed by DFS and $v$ is discovered for the first time through $u$. These edges constitute the DFS forest $T$.
- **Back edge**: $v$ is an ancestor of $u$ in $T$, i.e., $d[v] < d[u] < f[u] < f[v]$.
- **Forward edge**: $v$ is a proper descendant of $u$ in $T$ but $(u, v) \notin T$, i.e., $d[u] < d[v] < f[v] < f[u]$.
- **Cross edge**: $v$ and $u$ are in different branches of $T$, so $d[v] < f[v] < d[u]$.

In an **undirected** graph, DFS produces only tree edges and back edges; forward and cross edges cannot arise because the discovery of any edge $(u,v)$ with $v$ already visited implies $v$ is an ancestor of $u$.

**Worked Example.** Consider the directed graph with vertices $\{1,2,3,4\}$ and edges $\{(1,2),(1,3),(2,4),(4,3),(3,2)\}$. Running DFS from vertex $1$ yields timestamps:

| Vertex | $d$ | $f$ |
|--------|-----|-----|
| 1 | 1 | 8 |
| 2 | 2 | 7 |
| 4 | 3 | 6 |
| 3 | 4 | 5 |

Inspecting each edge: $(1,2)$ and $(2,4)$ and $(4,3)$ are **tree edges**; $(3,2)$ satisfies $d[2] < d[3] < f[3] < f[2]$, so it is a **back edge**; $(1,3)$ satisfies $d[1] < d[3] < f[3] < f[1]$ with $(1,3) \notin T$, making it a **forward edge**.

**Key Theorem.** A directed graph $G$ is a directed acyclic graph (DAG) if and only if DFS produces no back edges. Equivalently, $G$ contains a cycle if and only if some back edge $(u,v)$ exists, since such an edge closes a path from $v$ to $u$ through the DFS tree.

*Proof sketch.* If a back edge $(u,v)$ exists, the tree path $v \to \cdots \to u$ together with $(u,v)$ forms a cycle. Conversely, if a cycle $v_1 \to v_2 \to \cdots \to v_k \to v_1$ exists, the first vertex discovered in the cycle is an ancestor of all others in $T$, so the returning edge to it is a back edge. $\square$

### cycle_detection (18.1s)

## Cycle Detection

**Definition.** Let $G = (V, E)$ be a directed or undirected graph. A *cycle* is a closed walk $v_0, v_1, \ldots, v_k = v_0$ with $k \geq 1$ in which no edge is repeated (and, for simple cycles, no internal vertex is repeated). *Cycle detection* is the problem of determining whether $G$ contains at least one such cycle, and, when it does, identifying the vertices and edges that compose it.

For undirected graphs a cycle exists if and only if a depth-first search (DFS) encounters a *back edge*—an edge $(u, v)$ where $v$ is an ancestor of $u$ in the DFS tree. For directed graphs the same criterion applies, but back edges must be distinguished from *cross edges* and *forward edges* by tracking vertex colours: **white** (unvisited), **grey** (in the current DFS stack), and **black** (fully processed). An edge $(u, v)$ is a back edge precisely when $v$ is grey at the moment $u$ is visited.

**Worked Example.** Consider the directed graph $G$ with $V = \{1, 2, 3, 4\}$ and $E = \{(1,2),(2,3),(3,4),(4,2)\}$. Begin DFS from vertex 1. The colour sequence evolves as follows:

$$1 \xrightarrow{\text{grey}} 2 \xrightarrow{\text{grey}} 3 \xrightarrow{\text{grey}} 4 \xrightarrow{\text{grey}} 2$$

When the algorithm attempts to follow edge $(4, 2)$, vertex 2 is still grey. A back edge is detected, confirming the cycle $2 \to 3 \to 4 \to 2$.

**Theorem (DFS Cycle Criterion).** A directed graph $G$ is a *directed acyclic graph* (DAG) if and only if a DFS of $G$ produces no back edge.

*Proof sketch.* ($\Rightarrow$) If a back edge $(u,v)$ exists, the path from $v$ to $u$ in the DFS tree together with $(u,v)$ forms a directed cycle, contradicting the DAG assumption. ($\Leftarrow$) If $G$ contains a cycle $v_0 \to v_1 \to \cdots \to v_k \to v_0$, then whichever vertex in the cycle is discovered first by DFS will still be grey when the last edge of the cycle is traversed, producing a back edge. $\square$

Both directions establish that back-edge detection runs in $O(|V| + |E|)$ time.

```python
# Lab cell — detect a cycle in a directed graph using DFS
import sympy  # not needed for logic, but available for graph display

def has_cycle(adj):
    color = {v: 'white' for v in adj}

    def dfs(u):
        color[u] = 'grey'
        for v in adj.get(u, []):
            if color[v] == 'grey':
                return True          # back edge found
            if color[v] == 'white' and dfs(v):
                return True
        color[u] = 'black'
        return False

    return any(dfs(v) for v in adj if color[v] == 'white')

adj = {1: [2], 2: [3], 3: [4], 4: [2]}   # graph from worked example
print(has_cycle(adj))   # True
```
