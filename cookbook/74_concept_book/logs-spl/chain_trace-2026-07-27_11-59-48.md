## Binary Search Tree

**Definition.** A *binary search tree* (BST) is a rooted binary tree in which every node $v$ stores a key $k(v)$ drawn from a totally ordered set, subject to the *BST invariant*: for every node $v$, all keys in the left subtree of $v$ are strictly less than $k(v)$, and all keys in the right subtree of $v$ are strictly greater than $k(v)$. Formally, if $L(v)$ and $R(v)$ denote the left and right subtrees,

$$\forall u \in L(v):\ k(u) < k(v), \qquad \forall u \in R(v):\ k(u) > k(v).$$

This invariant holds recursively at every node, not merely at the root.

**Worked Example.** Insert the sequence $\langle 5, 3, 7, 1, 4 \rangle$ into an initially empty BST. The first key, $5$, becomes the root. Key $3 < 5$ goes left; $7 > 5$ goes right. Key $1 < 5$, then $1 < 3$, so it becomes the left child of $3$. Key $4 < 5$, then $4 > 3$, so it becomes the right child of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node. An in-order traversal (left $\to$ root $\to$ right) yields $\langle 1, 3, 4, 5, 7 \rangle$—the keys in sorted order, which is a direct consequence of the invariant.

**Key Theorem (Search Complexity).** A search, insertion, or deletion in a BST containing $n$ nodes requires $O(h)$ comparisons, where $h$ is the height of the tree. For a *balanced* BST, $h = \Theta(\log n)$, giving $O(\log n)$ worst-case operations. In the degenerate case—keys inserted in sorted order—the tree degenerates to a linked list with $h = n - 1$ and $O(n)$ operations. Self-balancing variants (AVL trees, red–black trees) maintain $h = O(\log n)$ unconditionally.

**Lab Cell (SymPy/Python).**

```python
# Minimal BST node; insert and in-order traversal
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root

def inorder(root):
    return [] if root is None else inorder(root.left) + [root.key] + inorder(root.right)

root = None
for k in [5, 3, 7, 1, 4]:
    root = insert(root, k)

print(inorder(root))   # → [1, 3, 4, 5, 7]
```

## Scapegoat Tree

**Definition.** A *scapegoat tree* is a self-balancing binary search tree that maintains balance lazily: it performs insertions and deletions without storing any balance metadata per node, instead rebuilding subtrees when a balance invariant is violated. Formally, a binary search tree $T$ with $n$ nodes is said to be *$\alpha$-weight-balanced* (for a fixed parameter $\alpha \in (1/2, 1)$) if, for every node $v$,

$$\text{size}(\text{left}(v)) \leq \alpha \cdot \text{size}(v) \quad \text{and} \quad \text{size}(\text{right}(v)) \leq \alpha \cdot \text{size}(v),$$

where $\text{size}(v)$ denotes the number of nodes in the subtree rooted at $v$. A node violating this condition is called a *scapegoat*. During an insertion, the algorithm walks back up the path from the newly inserted leaf and rebuilds the entire subtree rooted at the first scapegoat found into a perfectly balanced BST.

**Worked Example.** Suppose $\alpha = 2/3$ and consider inserting the sequence $1, 2, 3, 4$ into an initially empty tree. After inserting $1, 2, 3$, the root holds $1$ with size $3$; its right child has size $2$. Since $2/3 > 2/3$ is false, the right subtree is $2/3$-weight-balanced. Inserting $4$ yields a right child of size $3$ at the root of size $4$: $3/4 > 2/3$, so the root is the scapegoat. The algorithm flattens the entire tree into a sorted array $[1, 2, 3, 4]$ and rebuilds it as a perfectly balanced BST with $2$ as the root.

**Key Theorem.** For a scapegoat tree with parameter $\alpha$, the amortized cost of $m$ insertions beginning from an empty tree is $O(m \log m)$. Consequently, the amortized cost per insertion is $O(\log n)$. This follows from a potential argument: define $\Phi(T) = \sum_{v} \Delta(v)$, where $\Delta(v) = |\text{size}(\text{left}(v)) - \text{size}(\text{right}(v))|$. Each rebuild of a subtree of size $s$ costs $O(s)$ but reduces $\Phi$ by $\Omega(s)$, paying for itself amortized. Search and predecessor/successor queries run in $O(\log n)$ worst-case time because the tree height is bounded by $\log_{1/\alpha} n$.

    height_bound = floor(log(n, 1 / alpha))
    print(f"n={n:>5}: height ≤ {height_bound}")

## Subtree Size

**Definition.** Let $T = (V, E)$ be a rooted tree with root $r \in V$. For any node $v \in V$, the *subtree rooted at $v$*, denoted $T_v$, is the induced subgraph consisting of $v$ and all its descendants. The *subtree size* of $v$ is defined as

$$
\text{sz}(v) = |V(T_v)| = 1 + \sum_{c \in \text{children}(v)} \text{sz}(c).
$$

The base case is a leaf node $\ell$, for which $\text{children}(\ell) = \emptyset$ and therefore $\text{sz}(\ell) = 1$. The subtree size counts every node in $T_v$, including $v$ itself.

**Worked Example.** Consider the rooted tree below, with root $A$:

```
        A
       / \
      B   C
     / \
    D   E
```

Computing bottom-up: $\text{sz}(D) = 1$, $\text{sz}(E) = 1$, $\text{sz}(C) = 1$, $\text{sz}(B) = 1 + 1 + 1 = 3$, and $\text{sz}(A) = 1 + 3 + 1 = 5$. Observe that $\text{sz}(A) = |V| = 5$, which is always the case for the root.

**Key Theorem (Subtree-Size Recurrence and Complexity).** For a tree with $n$ nodes, the values $\{\text{sz}(v)\}_{v \in V}$ can be computed by a single post-order depth-first traversal in $O(n)$ time and $O(h)$ auxiliary stack space, where $h$ is the height of $T$. The post-order guarantee ensures that when $\text{sz}(v)$ is evaluated, $\text{sz}(c)$ is already known for every child $c$ of $v$.

*Proof sketch.* Each node is visited exactly once; at each visit, the algorithm performs work proportional to the degree of that node. Since $\sum_{v \in V} \deg(v) = 2(n-1)$ for a tree, the total work is $O(n)$. Stack depth equals the length of the root-to-node path, which is at most $h$. $\square$

Subtree sizes are fundamental in a wide range of algorithms: they enable $O(\log n)$ ancestor queries via Euler-tour flattening, underpin centroid decomposition, and allow balanced partition of trees for parallel processing.

**Lab Cell.**

```python
from sympy import symbols, Function
from collections import defaultdict

def subtree_sizes(adj, root):
    sz = {}
    def dfs(v, parent):
        sz[v] = 1
        for c in adj[v]:
            if c != parent:
                dfs(c, v)
                sz[v] += sz[c]
    dfs(root, None)
    return sz

adj = defaultdict(list)
for u, v in [('A','B'), ('A','C'), ('B','D'), ('B','E')]:
    adj[u].append(v); adj[v].append(u)

print(subtree_sizes(adj, 'A'))
# {'D': 1, 'E': 1, 'B': 3, 'C': 1, 'A': 5}
```

## Rebuild Operation

**Definition.** Let $T$ be a rooted expression tree whose nodes carry labels from an alphabet $\Sigma$ and whose leaves carry atomic terms from a domain $\mathcal{D}$. A *rebuild operation* is a function

$$\mathrm{rebuild} : T \times \Phi \;\longrightarrow\; T'$$

where $\Phi$ denotes a finite set of rewrite rules $\phi_i : \ell_i \mapsto r_i$, and $T'$ is a new tree obtained by replacing each subtree $s \subseteq T$ that matches the left-hand side $\ell_i$ of some rule with the corresponding right-hand side $r_i$, evaluated bottom-up. The operation is *complete* if every reducible subtree is replaced in a single pass, and *confluent* if the final tree $T'$ is independent of the order in which rules are applied.

**Worked Example.** Consider the arithmetic expression

$$E = (x^2 + 2x + 1) - (x + 1)^2.$$

Its initial tree contains a subtraction node whose children are the expanded polynomial $x^2 + 2x + 1$ and the squared binomial $(x+1)^2$. Applying the rule $\phi_1 : a^2 + 2ab + b^2 \mapsto (a+b)^2$ bottom-up, the left child is rewritten to $(x+1)^2$. The rebuild operation then propagates this change upward: the subtraction node now sees identical children, and rule $\phi_2 : u - u \mapsto 0$ reduces the root to the atomic term $0$. Thus $\mathrm{rebuild}(T,\{\phi_1,\phi_2\}) = T'$ with $T'$ the single-leaf tree labelled $0$.

**Key Theorem (Termination under Noetherian Ordering).** Let $>$ be a Noetherian (well-founded) ordering on expression trees such that $r_i < \ell_i$ for every rule $\phi_i \in \Phi$. Then the rebuild operation terminates for all inputs $T$. Moreover, if $\Phi$ is also Church–Rosser (locally confluent), then by Newman's Lemma the normal form $T'$ is unique.

*Proof sketch.* Each application of a rule strictly decreases the tree measure under $>$. Because $>$ is well-founded, no infinite descending chain exists, so the process must halt. Confluence then guarantees that any two terminating reduction sequences reach the same tree. $\square$

**Lab Cell (SymPy).**

```python
from sympy import symbols, expand, factor, simplify

x = symbols('x')

E = (x**2 + 2*x + 1) - (x + 1)**2

# Rebuild via symbolic simplification (applies rewrite rules internally)
E_rebuilt = simplify(E)
print("Before rebuild:", expand(E))   # x**2 + 2*x + 1 - (x+1)**2
print("After rebuild :", E_rebuilt)   # 0

```

Running this cell confirms that `simplify` implements a rebuild operation: the tree collapses from a multi-node structure to a single constant, and `count_ops` drops to zero, matching the theoretical result.

## Countdown Tree

**Definition.** A *countdown tree* is a finite rooted ordered tree $T = (V, E, r)$ in which every node $v \in V$ carries a non-negative integer *label* $\ell(v) \in \mathbb{N}_0$. A *reduction step* at a node $v$ with $\ell(v) > 0$ performs two actions simultaneously:

$$\ell(v) \;\longmapsto\; \ell(v) - 1,$$

and, if $\ell(v) - 1 = 0$, removes $v$ together with the entire subtree rooted at $v$. The *countdown process* applies reduction steps repeatedly until either all labels equal zero or the tree is empty; the resulting object is called the *terminal form* of $T$.

The depth of a node $v$, written $\operatorname{dep}(v)$, is the number of edges on the unique path from $r$ to $v$. This quantity plays a central role in measuring how quickly the process terminates.

**Worked Example.** Consider the path graph $r \to a \to b$ with labels $\ell(r) = 0$, $\ell(a) = 2$, $\ell(b) = 1$.

| Step | Action | Tree state |
|------|--------|------------|
| 0 | initial | $r(0) \to a(2) \to b(1)$ |
| 1 | reduce $b$: $1 \mapsto 0$, remove $b$ | $r(0) \to a(2)$ |
| 2 | reduce $a$: $2 \mapsto 1$ | $r(0) \to a(1)$ |
| 3 | reduce $a$: $1 \mapsto 0$, remove $a$ | $r(0)$ |

The terminal form is the single root node with label $0$. The total step count is $3$.

In general, for a path of $n$ nodes with labels $\ell_1, \ell_2, \ldots, \ell_n$ (root to leaf), the reduction count satisfies the recurrence

$$S(k) = \ell_k + \ell_{k-1} \cdot S(k), \quad S(1) = \ell_1,$$

producing a *tower-exponential* growth even for modest inputs—a fact that foreshadows the connection to ordinal arithmetic.

**Key Theorem (Termination).** *Every countdown tree terminates after finitely many reduction steps, regardless of the order in which nodes are selected.*

*Proof sketch.* Assign each tree $T$ an ordinal $\omega(T)$ by the map $\omega(\text{leaf with label } \ell) = \ell$ and $\omega(v) = \omega^{\omega(c_1)} + \cdots + \omega^{\omega(c_k)} + \ell(v)$, where $c_1, \ldots, c_k$ are the children of $v$ in order. Each reduction step strictly decreases $\omega(T)$ in the well-ordering of ordinals, so the process must terminate in finitely many steps. $\square$

This theorem is non-trivial: for trees with labels drawn from $\{0,\ldots,n\}$, the termination bound is not provable within $n$-th-order arithmetic, connecting countdown trees to Goodstein sequences and Kirby–Paris independence results.

**Lab Cell (SymPy).**

```python
from sympy import symbols, Symbol

def reduce_path_labels(labels):
    """Simulate countdown on a root-to-leaf path; return step count."""
    labels = list(labels)
    steps = 0
    while any(x > 0 for x in labels):
        for i in range(len(labels) - 1, -1, -1):
            if labels[i] > 0:
                labels[i] -= 1
                if labels[i] == 0:
                    labels = labels[:i]   # prune subtree
                steps += 1
                break
    return steps

# Example: labels [0, 2, 1] → expect 3 steps
print(reduce_path_labels([0, 2, 1]))   # 3

# Observe growth for deeper paths
for n in range(1, 6):
    print(f"depth {n}, all labels=2: {reduce_path_labels([2]*n)} steps")
```

Running the last loop reveals super-exponential growth, giving students direct computational evidence of the theorem's depth.
