## Hash Table

**Definition.** A *hash table* is a data structure that implements an associative array, mapping a set of keys $K$ to a set of values $V$ through a *hash function* $h : U \to \{0, 1, \ldots, m-1\}$, where $U$ is the universe of possible keys and $m$ is the number of available *slots* (buckets). The hash function compresses an arbitrarily large key space into a fixed index range, enabling average-case $O(1)$ lookup, insertion, and deletion. When two distinct keys $k_1 \neq k_2$ satisfy $h(k_1) = h(k_2)$, a *collision* occurs; standard resolution strategies include *chaining* (each slot holds a linked list of entries) and *open addressing* (probing alternative slots according to a fixed sequence).

A widely used hash function for integer keys is the *division method*:

$$h(k) = k \bmod m$$

where $m$ is chosen to be a prime not close to a power of 2, reducing systematic clustering.

**Worked Example.** Let $m = 7$ and consider inserting the keys $\{10, 22, 31, 4, 15\}$ using the division method. Computing $h(k) = k \bmod 7$:

| Key $k$ | $h(k)$ |
|---------|--------|
| 10 | 3 |
| 22 | 1 |
| 31 | 3 |
| 4  | 4 |
| 15 | 1 |

Slots 3 and 1 each receive two keys, so chaining appends $31$ behind $10$ and $15$ behind $22$. A lookup for key $31$ computes $h(31)=3$, accesses slot 3, and traverses the chain of length 2.

**Key Theorem (Simple Uniform Hashing).** Under the assumption that every key is equally likely to hash to any of the $m$ slots independently of all others, the expected length of a chain at any slot is $\alpha = n/m$, called the *load factor*, where $n$ is the number of stored keys. Consequently, the expected time for a successful search is $\Theta(1 + \alpha)$. Keeping $\alpha = O(1)$—achieved by resizing the table so that $m = \Theta(n)$—guarantees $O(1)$ amortised performance.

**Lab Cell (SymPy).**

```python
from sympy import isprime

m = 7
assert isprime(m), "Choose a prime table size"

keys = [10, 22, 31, 4, 15]
table = [[] for _ in range(m)]

for k in keys:
    table[k % m].append(k)

for slot, chain in enumerate(table):
    print(f"slot {slot}: {chain}")

load_factor = len(keys) / m
print(f"\nLoad factor α = {load_factor:.3f}")
```

Running this cell prints the populated chains and confirms $\alpha \approx 0.714$, well below 1, so expected chain length remains short.

### hash_function (15.8s)

## Hash Function

**Definition.** A *hash function* is a map $h : U \to \{0, 1, \ldots, m-1\}$ from a (typically large) universe $U$ of keys to a finite set of *buckets* of size $m$. For the function to be useful in practice it must be (i) *deterministic*—equal inputs always produce equal outputs—(ii) *efficient* to evaluate in $O(1)$ time, and (iii) *uniform* in the sense that, for a randomly chosen key $k \in U$, each bucket index $j$ satisfies $\Pr[h(k) = j] \approx 1/m$. A hash function used for data structures need not be cryptographically secure; a hash function used for message authentication must additionally be *collision-resistant* and *one-way*.

**Worked Example.** Let $U = \mathbb{Z}$ and $m = 7$. The *division method* defines

$$h(k) = k \bmod m.$$

For the key sequence $k \in \{14, 3, 22, 9\}$:

| $k$ | $k \bmod 7$ |
|-----|------------|
| 14  | 0          |
| 3   | 3          |
| 22  | 1          |
| 9   | 2          |

All four keys map to distinct buckets, so no collision occurs in this instance. Note that $k = 7$ and $k = 14$ would both map to bucket $0$, illustrating that collisions are unavoidable whenever $|U| > m$.

**Key Theorem (Birthday Bound).** If $n$ keys are inserted into a table of size $m$ using a perfectly uniform hash function, the probability that *at least one* collision occurs satisfies

$$\Pr[\text{collision}] \approx 1 - e^{-n(n-1)/(2m)}.$$

In particular, once $n \approx \sqrt{2m \ln 2}$ keys have been inserted, a collision occurs with probability exceeding $\tfrac{1}{2}$. This result, analogous to the classical birthday paradox, explains why even moderate load factors require an efficient collision-resolution strategy such as chaining or open addressing.

**Lab Cell.**

```python
from sympy import Mod, symbols, latex

k, m = symbols('k m', integer=True)
keys = [14, 3, 22, 9]
modulus = 7

print(f"Table size m = {modulus}")
for key in keys:
    bucket = key % modulus
    print(f"  h({key}) = {key} mod {modulus} = {bucket}")

# Symbolic form
h = Mod(k, m)
print("\nSymbolic hash function: h(k) =", latex(h))
```

Running this cell prints each bucket assignment and displays the symbolic expression $k \bmod m$ in $\LaTeX$, confirming the hand-computed values above.

### load_factor_invariant (19.1s)

## Load Factor Invariant

**Definition.** Let $T$ be a hash table with capacity $m$ (the number of available slots) and $n$ currently stored entries. The *load factor* of $T$ is the ratio

$$\alpha = \frac{n}{m}.$$

The *load factor invariant* is the guarantee maintained by a dynamic hash table implementation that $\alpha$ remains bounded within a fixed interval $[\alpha_{\min}, \alpha_{\max}]$ at the conclusion of every insertion or deletion operation. Typical implementations enforce $\alpha \leq 0.75$ for open-addressing schemes, with a lower bound such as $\alpha \geq 0.25$ enforced after deletions to prevent excessive memory waste.

**Worked Example.** Suppose a hash table is initialized with capacity $m = 8$ and $\alpha_{\max} = 0.75$. The threshold for rehashing is $\lfloor 0.75 \times 8 \rfloor = 6$ entries. As elements are inserted:

| Operation | $n$ | $m$ | $\alpha$ | Action |
|-----------|-----|-----|----------|--------|
| Insert 5 items | 5 | 8 | 0.625 | none |
| Insert 6th item | 6 | 8 | 0.750 | none |
| Insert 7th item | 7 | 8 | 0.875 | **rehash** to $m = 16$ |

After rehashing, $\alpha = 7/16 = 0.4375$, restoring the invariant.

**Key Theorem (Amortized Cost of Rehashing).** If a hash table doubles its capacity whenever $\alpha$ exceeds $\alpha_{\max}$, then the amortized cost per insertion is $O(1)$. 

*Proof sketch.* Let $n_0$ be the number of entries immediately after the last rehash. To trigger the next rehash, at least $n_0$ additional insertions must occur (since capacity doubled to $2m$, so the threshold is $2\alpha_{\max} m = 2n_0$). The rehash copies at most $2n_0$ entries, distributing a cost of $O(n_0)$ across $n_0$ insertions, yielding $O(1)$ amortized cost per operation. $\square$

This argument is an instance of the *potential method*: defining the potential $\Phi = 2n - m$ ensures each insertion contributes a constant amount toward the eventual rehash cost.

**Lab Cell (SymPy).**

```python
from sympy import symbols, solve, Rational

n, m = symbols('n m', positive=True)
alpha_max = Rational(3, 4)

# Find the minimum capacity m such that inserting one more item
# after n items does not exceed alpha_max
threshold = solve(n / m - alpha_max, m)
print("Rehash threshold m =", threshold)  # [4*n/3]

# Verify amortized invariant: entries needed before next rehash
n0 = 7  # entries after rehash to capacity 16
print(f"Entries at rehash trigger: {int(alpha_max * 16)}")  # 12
print(f"Insertions before next rehash: {int(alpha_max * 16) - n0}")  # 5
```

Running this cell confirms that after rehashing to $m = 16$ with $n = 7$, five more insertions are needed before the invariant is next threatened, consistent with the $O(1)$ amortized bound.

### chained_hash_table (18.2s)

## Chained Hash Table

**Definition.** A *chained hash table* is a data structure that maintains an array $T$ of $m$ *slots*, where each slot $T[i]$ is the head of a singly-linked list (called a *chain*) containing all keys $k$ satisfying $h(k) = i$. Given a universe of keys $U$ and a *hash function* $h : U \to \{0, 1, \ldots, m-1\}$, the table stores $n$ key–value pairs with an expected load factor $\alpha = n/m$. Formally, the structure is the triple $(T, h, m)$ together with the invariant

$$T[i] = \{k \in S \mid h(k) = i\}, \quad 0 \le i < m,$$

where $S \subseteq U$ is the current key set.

**Worked Example.** Let $m = 7$ and $h(k) = k \bmod 7$. Insert the keys $\{50, 700, 76, 85, 92, 73, 101\}$.

| Slot | Chain |
|------|-------|
| 0 | $700 \to 85$ |
| 1 | $50 \to 92 \to 85$... |

More precisely: $h(50)=1$, $h(700)=0$, $h(76)=6$, $h(85)=1$, $h(92)=1$, $h(73)=3$, $h(101)=3$. Slots 1 and 3 each carry chains of length 2; searching for key $85$ requires traversing two nodes in slot 1.

**Key Theorem (Expected Search Time).** Under the *Simple Uniform Hashing Assumption* (SUHA)—each key is equally likely to hash to any of the $m$ slots independently—an unsuccessful search visits an expected $\alpha$ nodes, and a successful search visits an expected $1 + \alpha/2$ nodes. Consequently, if $n = O(m)$ so that $\alpha = O(1)$, all dictionary operations (INSERT, DELETE, SEARCH) run in $O(1)$ expected time.

*Proof sketch.* For an unsuccessful search, the expected chain length is $\mathbb{E}[|T[h(k)]|] = n/m = \alpha$ by linearity of expectation and SUHA. For a successful search on key $k_i$ (the $i$-th key inserted), the expected number of keys inserted *after* $k_i$ that collide with it is $(n-i)/m$; summing and averaging over all $n$ keys yields $1 + \alpha/2$.

**Lab Cell.**

```python
from sympy import symbols, Integer, Rational, simplify

m, n = symbols('m n', positive=True)
alpha = n / m

expected_unsuccessful = alpha
expected_successful   = 1 + alpha / 2

print("Unsuccessful search:", simplify(expected_unsuccessful))
print("Successful search:  ", simplify(expected_successful))

# Concrete check: n=7, m=7 → alpha=1
print("alpha=1, successful:", expected_successful.subs({n: 7, m: 7}))
```

Running this cell confirms the analytic expressions and instantiates them for $\alpha = 1$, predicting an average of $1.5$ comparisons per successful lookup—consistent with the worked example above.

## Hash Collision Dos

**Definition.** A *hash collision* occurs when two distinct keys $k_1 \neq k_2$ satisfy $h(k_1) = h(k_2)$ for a hash function $h : U \to \{0, 1, \ldots, m-1\}$. Under *chaining*, a hash table resolves collisions by storing all colliding keys in a linked list at the same bucket. A *Hash Collision Denial-of-Service (DoS)* attack exploits this by supplying an adversarially chosen input set $S$ in which every element hashes to the same bucket, forcing every insertion and lookup to traverse a list of length $|S|$ rather than $O(1)$. The result is that $n$ operations degrade from expected $\Theta(n)$ total time to worst-case $\Theta(n^2)$, saturating server resources.

**Worked Example.** Suppose $h(k) = k \bmod 8$ and an attacker submits the keys $S = \{0, 8, 16, 24, 32, 40, 48, 56\}$. Every element satisfies $h(k) \equiv 0 \pmod{8}$, so all eight keys collide into bucket 0. A lookup for key $56$ must traverse all eight list nodes. With $n = 8$ such operations, the server performs $1 + 2 + \cdots + 8 = 36 = \Theta(n^2)$ comparisons rather than the $\Theta(n)$ expected under a uniform distribution.

**Key Theorem (Load Factor and Worst-Case Cost).** Let $T$ be a chained hash table with $m$ buckets storing $n$ keys, and define the *load factor* $\alpha = n/m$. Under a *uniform independent hashing* assumption, the expected search time is $\Theta(1 + \alpha)$. However, if the hash function $h$ is *deterministic and publicly known*, an adversary can always construct a set $S \subseteq U$ with $|S| = n$ such that all keys map to one bucket, yielding worst-case search time $\Theta(n)$ per operation. The standard defence is *universal hashing*: choose $h$ uniformly at random from a family $\mathcal{H}$ satisfying $\Pr_{h \in \mathcal{H}}[h(k_1) = h(k_2)] \leq 1/m$ for all $k_1 \neq k_2$. This guarantee holds regardless of adversarial input, bounding expected chain length at $1 + \alpha$.

**Lab Cell (SymPy / Python).**

```python
from collections import defaultdict
import random, time

def deterministic_hash(k, m=8):
    return k % m

def universal_hash(k, m, a, b, p=1_000_003):
    return ((a * k + b) % p) % m

m = 8
attack_keys = list(range(0, 8 * m, m))   # all collide under deterministic_hash

# Deterministic: measure bucket distribution
det_table = defaultdict(list)
for k in attack_keys:
    det_table[deterministic_hash(k, m)].append(k)
print("Deterministic max chain:", max(len(v) for v in det_table.values()))

# Universal: choose random a, b
a, b = random.randint(1, 999), random.randint(0, 999)
univ_table = defaultdict(list)
for k in attack_keys:
    univ_table[universal_hash(k, m, a, b)].append(k)
print("Universal max chain:", max(len(v) for v in univ_table.values()))
```

Running this cell will show the deterministic table concentrating all eight keys in one bucket (chain length 8), while the universal hash distributes them more evenly, illustrating the practical defence against Hash Collision DoS.
