### computer_network (0.6s)

## 计算机网络

**定义。** 计算机网络是由若干台计算机或设备通过通信链路连接起来、并遵循共同规则（协议）来交换数据的系统。网络中的设备称为**节点**，包括主机、路由器和交换机等。常见的分类有：局域网（LAN，覆盖一个房间或校园）、广域网（WAN，覆盖城市乃至全球）。互联网就是由无数个网络互联而成的"网络的网络"。

网络通信依赖**分层模型**。以常用的 TCP/IP 四层模型为例：应用层（HTTP、DNS）、传输层（TCP、UDP）、网络层（IP）、链路层（以太网、Wi-Fi）。每一层只处理自己的任务，并把结果交给相邻的层。

**两个核心指标。** 带宽 $B$ 表示链路每秒能传输的比特数；时延则由传输时延和传播时延组成：

$$
T = \frac{L}{B} + \frac{d}{v}
$$

其中 $L$ 为数据量（比特），$d$ 为链路长度，$v$ 为信号传播速度（光纤中约为 $2\times10^{8}$ m/s）。

**例题。** 通过一条长 $2000$ km、带宽 $100$ Mbit/s 的光纤链路发送一个 $10$ MB 的文件，忽略排队与处理时延，总时延是多少？

- 数据量：$L = 10\times 8\times10^{6} = 8\times10^{7}$ bit
- 传输时延：$\dfrac{8\times10^{7}}{10^{8}} = 0.8$ s
- 传播时延：$\dfrac{2\times10^{6}}{2\times10^{8}} = 0.01$ s
- 总时延：$T = 0.8 + 0.01 = 0.81$ s

可见，对于大文件，传输时延占主导，提高带宽会明显见效。

**问题求解应用。** 再看另一种情形：只发送一个 $100$ 字节的请求包（$800$ bit），链路相同。传输时延为 $\dfrac{800}{10^{8}} = 8\ \mu\text{s}$，而传播时延仍是 $10$ ms。此时传播时延占绝对主导，把带宽提高十倍几乎没有任何改善。这解释了为什么网页加载这类"小而多"的请求更依赖低延迟（例如就近部署服务器、使用 CDN），而下载大文件才更依赖高带宽。

在实际排查网络问题时，可以用下面的命令来观察延迟：

```bash
ping example.com        # 测量往返时延 RTT
traceroute example.com  # 查看数据包经过的每一跳路由器
```

若 RTT 很高，先看 `traceroute` 中是哪一跳开始变慢，再判断是链路距离、拥塞还是服务器本身的问题。

**小结。** 理解计算机网络的关键是：协议分层让复杂系统可以拆分处理；带宽与时延是两个不同的指标；解决问题时，先判断瓶颈究竟是传输时延还是传播时延，再决定优化方向。

### internet_service_provider (0.7s)

## 互联网服务提供商

**定义。** 互联网服务提供商(Internet Service Provider,简称 ISP)是向用户出售"接入互联网的资格"的机构。你的设备本身只能和局域网内的设备通信,ISP 则把这个局域网连接到全球的网络之中。它主要做三件事:

1. **提供物理链路**:光纤、同轴电缆、DSL 或蜂窝基站。
2. **分配网络地址**:通常通过 DHCP 为你的路由器分配一个公网 IP 地址。
3. **转发流量并互联**:通过与其他 ISP 的对等互联(peering)或购买上游"过境"(transit)服务,把你的数据包送到世界各地。

ISP 通常分层:一级 ISP 之间互相免费对等,覆盖全球骨干;二级、三级 ISP 向上游购买过境服务,再面向家庭和企业售卖接入。

**例题。** 你在家访问 `example.com`,数据包大致经过下面的路径:

1. 笔记本 → 家用路由器(NAT 将内网地址转换为公网地址)。
2. 路由器 → ISP 的接入网络(光纤到局端设备)。
3. ISP 区域网络 → 上游或对等网络。
4. 目标网站所在机构的 ISP → 服务器。

可以用命令亲自观察:

```bash
traceroute example.com
```

输出的前几跳通常是你的路由器,接着是 ISP 的网关,其主机名常带有该 ISP 的域名。当主机名换成另一家机构的域名时,说明数据包已经越过了两家 ISP 的互联点。

**问题求解应用。** 一家工作室要选择套餐:套餐 A 下行 500 Mbps、上行 20 Mbps;套餐 B 对称 200 Mbps。工作室每天要上传 $60\ \text{GB}$ 的视频素材。

先统一单位:$60\ \text{GB} = 60 \times 8 = 480\ \text{Gb} = 480{,}000\ \text{Mb}$。

- 套餐 A:上传时间 $t = \dfrac{480{,}000}{20} = 24{,}000\ \text{s} \approx 6.7\ \text{小时}$。
- 套餐 B:$t = \dfrac{480{,}000}{200} = 2{,}400\ \text{s} = 40\ \text{分钟}$。

虽然套餐 A 的"下行速度"更高,但这个工作室的瓶颈在**上行带宽**,所以套餐 B 更合适。(这里按理论带宽计算;实际速度会受协议开销、网络拥塞和对端服务器限制的影响,通常低于标称值。)

**排查思路。** 当"上不了网"时,可由近及远逐段判断:

- `ping 192.168.1.1`(换成你的路由器地址)失败 → 问题在局域网内部。
- 能 ping 通路由器,但 `ping 8.8.8.8` 失败 → 问题多半在 ISP 链路或路由器与 ISP 之间。
- `ping 8.8.8.8` 成功,但 `ping example.com` 失败 → 是域名解析(DNS)问题,可改用其他 DNS 服务器。

这种逐段隔离的方法,正是理解 ISP 在整个网络结构中所处位置的实际价值。

### router (0.5s)

## 路由器

**定义。** 路由器(router)是一个负责"分流"的决策组件:它接收一个输入,判断这个输入属于哪一类,再把它转交给最合适的处理者。路由器本身通常不解决问题,它的价值在于**选对解决者**。网络中的路由器根据目的地址选择下一跳;在 LLM 系统中,路由器根据任务类型,把问题派给小模型、专家模型或确定性工具。

一个路由器包含三个要素:

1. **输入**:待处理的请求;
2. **分类规则**:可以是确定性规则(关键词、正则),也可以是概率性判断(由 LLM 打分);
3. **分支目标**:一组可选的处理者,外加一个"兜底"分支。

**工作示例。** 设想一个学习助手,收到三类问题:算术计算、概念解释、代码调试。我们用 SPL 风格的伪代码写出路由逻辑:

```
GENERATE classify(@question) INTO @category

EVALUATE @category
  WHEN 'math'    THEN CALL calculator(@question) INTO @answer
  WHEN 'concept' THEN CALL explainer(@question) INTO @answer
  WHEN 'code'    THEN CALL debugger(@question) INTO @answer
  ELSE                CALL general_llm(@question) INTO @answer
END
```

输入"37 × 24 等于多少?"时,分类器输出 `math`,请求被交给计算器,得到确定的结果 888,不需要调用大模型。输入"解释什么是梯度下降",则被分到 `concept` 分支。注意 `ELSE` 兜底分支:分类器偶尔会出错或遇到未知类型,没有兜底,系统就会无响应。

**问题求解应用:路由是否划算?** 设两个处理者:便宜的小模型每次成本 $c_s$、正确率 $p_s$;昂贵的大模型成本 $c_l$、正确率 $p_l$;路由器自身每次成本 $c_r$。假设路由器把一部分比例为 $f$ 的"简单"请求发给小模型,其余发给大模型,则平均成本为

$$
C = c_r + f\,c_s + (1-f)\,c_l .
$$

取 $c_r=0.1,\ c_s=1,\ c_l=10$(单位任意),$f=0.7$:

$$
C = 0.1 + 0.7\times 1 + 0.3\times 10 = 3.8,
$$

而全部交给大模型的成本是 $10$,节省约 $62\%$。

但还要考虑**误路由**的代价:若路由器把难题错发给小模型,正确率就会下降。因此设计路由器时要权衡两件事:

- 分类准确率越高,节省越可靠;
- 对高风险任务,宁可保守地发给强模型,也不要冒险降级。

**练习。** 若 $f=0.5$、其余参数不变,平均成本是多少?当 $f$ 降到多少时,路由开始比"全部用大模型"更贵?(提示:令 $C=10$,解出 $f$。)

### autonomous_system (0.6s)

## 自治系统

**定义。** 在微分方程中,若方程的右端不显含自变量 $t$,即

$$\frac{dx}{dt}=f(x),$$

则称其为**自治系统**。它的含义很直观:系统的"演化规则"不随时间改变。无论在今天还是明天,只要处于同一状态 $x$,变化率就完全相同。因此,解的形状只取决于初始状态,把初始时刻平移,只会让整条解曲线沿 $t$ 轴平移。

自治系统最有用的概念是**平衡点**(也称临界点):满足 $f(x^*)=0$ 的点。系统一旦处于 $x^*$,就会永远停留在那里。平衡点的稳定性由 $f'(x^*)$ 的符号判断:若 $f'(x^*)<0$,附近的解会趋近 $x^*$(稳定);若 $f'(x^*)>0$,附近的解会远离 $x^*$(不稳定)。

**例题。** 考虑逻辑斯蒂增长模型

$$\frac{dP}{dt}=P\left(1-\frac{P}{K}\right),\quad K>0.$$

右端只含 $P$,不含 $t$,所以这是自治系统。令 $f(P)=P\left(1-\frac{P}{K}\right)=0$,得平衡点 $P^*=0$ 和 $P^*=K$。求导得

$$f'(P)=1-\frac{2P}{K}.$$

在 $P^*=0$ 处,$f'(0)=1>0$,不稳定;在 $P^*=K$ 处,$f'(K)=-1<0$,稳定。这与直觉一致:种群很小时会增长,并最终稳定在环境容纳量 $K$。

**问题求解应用。** 判断下面两个方程哪个是自治的,并分析其平衡点:

(a) $\dfrac{dx}{dt}=x^2-4$  (b) $\dfrac{dx}{dt}=x-t$

(b) 的右端含有 $t$,因此不是自治系统,无法定义与时间无关的平衡点。(a) 是自治系统。令 $x^2-4=0$,得 $x^*=\pm 2$。此时 $f'(x)=2x$:在 $x^*=-2$ 处,$f'=-4<0$,稳定;在 $x^*=2$ 处,$f'=4>0$,不稳定。

我们还可以不解方程就预测解的长期行为。若初值 $x(0)=1$,它位于 $-2$ 与 $2$ 之间,此区间内 $f(x)<0$,所以 $x$ 单调减小并趋向 $-2$。若 $x(0)=3>2$,则 $f>0$,解会不断增大并远离 $2$。

**小结。** 判断自治性只需检查右端是否显含 $t$。一旦确认,就可以通过"求平衡点 → 判断 $f$ 的符号 → 检验 $f'$"这三步,直接画出相线并预测所有解的走向。这种不求显式解的定性分析,正是自治系统的核心价值。

### peering_relationship (0.6s)

## 对等关系

**定义。** 对等关系(peering relationship)是指两个独立运营的网络或节点,在彼此地位平等、无需经过上级中心的前提下,直接互相交换流量、资源或服务的协议安排。它与"客户—供应商"关系不同:双方既不是上下级,也不必按流量向对方付费,而是因为互联能让双方都受益。典型例子包括互联网服务商之间的流量互换,以及分布式推理网格中两个中心(Hub)之间互相查询对方已注册的工作流。

对等关系通常具备三个特征:

1. **平等性**:任何一方都不是另一方的"父节点"。
2. **互惠性**:双方交换的价值大致相当。
3. **自治性**:各自保留对内部策略的完全控制权。

**例题。** 网络 A 有 $a = 8000$ 个用户,网络 B 有 $b = 2000$ 个用户。每个用户平均每天向对方网络的用户发出 $c = 0.5$ 个请求(目的地在对方网络的概率均匀分布)。判断两者是否适合建立免费对等关系。

*解。* 先估算双向流量。A 发往 B 的请求量与 B 的用户数成比例;若全网共 $N = a + b = 10000$ 个用户,则

$$T_{A\to B} = a \cdot c \cdot \frac{b}{N} = 8000 \times 0.5 \times 0.2 = 800,$$

$$T_{B\to A} = b \cdot c \cdot \frac{a}{N} = 2000 \times 0.5 \times 0.8 = 800.$$

两个方向的流量相等,因此交换是对称的,适合免费对等。(这并非巧合:在均匀假设下,$T_{A\to B} = T_{B\to A} = c\,ab/N$。)

**问题求解应用。** 现在假设 B 是一个内容提供商,它的用户几乎只"下载"而不"上传",使得 $T_{A\to B} = 800$,但 $T_{B\to A} = 4000$。此时流量比为

$$r = \frac{T_{B\to A}}{T_{A\to B}} = 5.$$

实践中,许多对等协议规定比例 $r$ 不得超过某个阈值(例如 $2$)。这里 $r = 5$ 超过阈值,A 承担了大量不对称的传输成本,于是有三种常见处理方式:

- **付费对等**:B 按超出部分向 A 付费;
- **协商限额**:双方约定只对等交换部分类别的流量;
- **改为转接关系**:A 把 B 当作客户,按量计费。

在分布式系统里,同样的判断逻辑也适用。假设你要让两个 Hub 对等,可以按下面的步骤检查:

1. 列出双方各自愿意公开的资源(例如已注册的工作流)。
2. 估算双向查询量,计算比例 $r$。
3. 若 $r$ 接近 $1$,采用开放的对等;若明显失衡,引入配额或计费。
4. 确认每一方都保留自己的访问控制,即自治性不受损害。

**小结。** 对等关系的核心不是技术协议本身,而是"平等、互惠、自治"这三条原则。遇到具体问题时,先量化双向价值是否对称,再据此选择免费对等、付费对等或层级式的转接关系。

### scale_free_network (0.6s)

## 无标度网络

**定义。** 无标度网络(scale-free network)是指节点度分布服从幂律的网络:随机选取一个节点,其度(即连接数)恰为 $k$ 的概率满足

$$P(k) \sim k^{-\gamma}, \qquad 2 < \gamma < 3 \ (\text{许多真实网络})$$

“无标度”的含义是:这种分布没有特征尺度。与随机网络(度分布集中在平均值附近,呈泊松分布)不同,无标度网络中大多数节点只有很少的连接,但少数“枢纽”(hub)节点拥有极多连接。万维网、航空网络、社交平台的关注关系和蛋白质相互作用网络都具有这种特征。

**形成机制:偏好连接。** Barabási–Albert 模型说明了这种结构如何产生:网络逐步增长,每个新节点连向已有节点时,选择节点 $i$ 的概率与其当前度成正比:

$$\Pi(i) = \frac{k_i}{\sum_j k_j}$$

这就是“富者愈富”。该模型给出 $\gamma = 3$。

**例题。** 某网络的度分布为 $P(k) = C k^{-2.5}$,$k \ge 1$。问:度至少为 10 的节点占多大比例,度至少为 100 的节点占多大比例?

用积分近似求和,累积分布为

$$P(K \ge k) \approx \int_k^\infty C x^{-2.5}\,dx \propto k^{-1.5}$$

因此从 $k=10$ 到 $k=100$,比例缩小为原来的

$$\left(\frac{100}{10}\right)^{-1.5} = 10^{-1.5} \approx 0.032$$

若度至少为 10 的节点占 $1\%$,则度至少为 100 的节点约占 $0.032\%$。注意:如果是泊松分布,度达到平均值 10 倍的节点几乎不可能存在;而这里每增大 10 倍,比例只下降约 30 倍,所以枢纽确实会出现。

**问题求解应用:网络的鲁棒性与脆弱性。** 假设网络有 $10^6$ 个节点,你要设计防护策略。

- **随机故障**:随机删除节点时,被删中的几乎都是低度节点,网络整体连通性基本不受影响,所以无标度网络对随机故障很稳健。
- **针对性攻击**:若专门删除度最高的少数枢纽,网络会很快碎裂成互不相连的小块。所以它对蓄意攻击很脆弱。
- **传播控制**:在疾病或谣言传播中,枢纽是超级传播者。优先对枢纽接种疫苗,比随机接种有效得多。

**判断方法。** 实际检验时,先画出度分布的双对数图;若数据近似落在一条斜率为 $-\gamma$ 的直线上,才可能是幂律。注意“看起来像直线”并不充分,还需要用最大似然估计拟合 $\gamma$,并与对数正态等其他分布做统计比较。

**小结。** 无标度网络的核心是幂律度分布与枢纽节点;偏好连接是其典型成因;其特点是“抗随机故障、怕定向攻击”。

### small_world_network (0.7s)

## 小世界网络

**定义。** 小世界网络(small-world network)是这样一类网络:节点数 $N$ 很大,每个节点只与少数邻居直接相连,但任意两个节点之间的平均最短路径长度 $L$ 却非常小,随 $N$ 呈对数增长,即 $L \propto \ln N$;同时,网络保持较高的聚类系数 $C$,也就是"朋友的朋友也常常是朋友"。规则格子网络聚类高但路径长,随机网络路径短但聚类低,小世界网络则兼得两者。

Watts 与 Strogatz 提出的构造方法很简单:先建立一个环形规则网络,每个节点连接最近的 $k$ 个邻居;然后以概率 $p$ 把每条边的一端"重连"到随机节点。只需很小的 $p$,少量的随机"捷径"就能大幅缩短路径长度,而聚类系数几乎不变。

**工作示例。** 设环上有 $N=1000$ 个节点,每个节点连接左右各 5 个邻居(共 $k=10$)。

- 规则网络($p=0$):平均路径长度约为 $L \approx \dfrac{N}{2k} = \dfrac{1000}{20} = 50$ 步。
- 随机网络:平均路径长度约为 $L \approx \dfrac{\ln N}{\ln k} = \dfrac{\ln 1000}{\ln 10} = 3$ 步,但聚类系数仅约 $C \approx k/N = 0.01$。
- 小世界网络($p\approx 0.01$):只有约 $1000\times 5\times 0.01 = 50$ 条边被重连,路径长度就降到约 $L\approx 7$ 步,而聚类系数仍保持在 $C\approx 0.6$ 左右(规则网络约为 $0.67$)。

可见,仅改动 1% 的连接,路径就缩短了约 85%,聚类却几乎没有损失。

**问题求解应用。** 如何判断真实网络是否为小世界网络?步骤如下:

1. 测量网络的 $L_{\text{real}}$ 和 $C_{\text{real}}$。
2. 生成节点数和边数相同的随机网络,得到 $L_{\text{rand}}$ 和 $C_{\text{rand}}$。
3. 计算小世界系数 $\sigma = \dfrac{C_{\text{real}}/C_{\text{rand}}}{L_{\text{real}}/L_{\text{rand}}}$。若 $\sigma \gg 1$,则该网络具有小世界特征。

例如,某社交网络有 $N=10^6$ 个用户,平均好友数 $k=50$。实测 $L_{\text{real}}=4.5$,$C_{\text{real}}=0.25$。同规模随机网络满足 $L_{\text{rand}}\approx \ln(10^6)/\ln 50\approx 3.5$,$C_{\text{rand}}\approx 50/10^6=5\times10^{-5}$。于是

$$\sigma=\frac{0.25/(5\times10^{-5})}{4.5/3.5}=\frac{5000}{1.29}\approx 3900 \gg 1,$$

说明该网络是典型的小世界网络。

**意义。** 小世界结构解释了"六度分隔"现象,也影响着许多实际问题:疾病和谣言沿捷径迅速扩散,因此防疫时切断少数"长程连接"往往比隔离大量本地接触更有效;设计通信网络或电网时,增加少量远程链路即可显著提升整体效率。

## 拓扑视角(As Topology)

**定义。** 用拓扑的眼光看一个对象,关注的不是它的具体大小、距离或形状,而是它的**连通结构**:哪些部分相连,哪些部分被隔开,有没有“洞”或“环”。如果一个对象可以通过拉伸、弯曲而不撕裂、不粘合变成另一个对象,拓扑上就认为二者等价。经典例子是咖啡杯与甜甜圈:都恰有一个洞。

在概念图(concept graph)中,“拓扑视角”意味着:把知识看成由节点(概念)和边(先修关系)构成的网络,只问三类问题:
1. 网络是否连通?
2. 从概念 A 到概念 B 有哪些路径?
3. 是否存在循环依赖?

这里不需要新的数学公式,只需要读懂图的结构。

**例题。** 设某线性代数学习图有如下先修边(箭头表示“先学左边,才能学右边”):

- 向量 → 内积
- 内积 → 正交
- 正交 → 格拉姆–施密特过程
- 向量 → 线性无关
- 线性无关 → 基
- 基 → 格拉姆–施密特过程

问:要学“格拉姆–施密特过程”,需要先学哪些概念?有几条学习路径?

**解。** 从目标节点沿箭头反向追溯:
- 经“正交”一支:正交 ← 内积 ← 向量;
- 经“基”一支:基 ← 线性无关 ← 向量。

两支在“向量”处汇合,所以先修集合为 $\{\text{向量},\ \text{内积},\ \text{正交},\ \text{线性无关},\ \text{基}\}$,共 5 个概念。从“向量”出发共有 2 条互不相交的路径,最终在目标节点汇合。拓扑上,这两条路径与起点、终点围成一个**环**(忽略箭头方向时),说明这里存在两种独立的理解角度。

**问题求解应用。** 拓扑视角能帮我们解决三类实际问题:

1. **排定学习顺序。** 只要图中没有有向环,就可以做拓扑排序,例如:向量 → 内积 → 正交 → 线性无关 → 基 → 格拉姆–施密特过程。顺序不唯一,但任何合法顺序都必须遵守先修边。
2. **检查设计错误。** 若出现“A 需要 B,B 需要 A”的有向环,说明课程设计有循环依赖,必须拆分或补充中间概念。
3. **找关键节点。** 若删去某个节点会使图断开(如“向量”),它就是枢纽概念,应优先教学、重点复习。

**练习。** 若再添加一条边“基 → 内积”,图中是否出现有向环?(提示:检查是否存在从内积回到基的路径。内积 → 正交 → 格拉姆–施密特过程,并不回到基,因此没有环;但“线性无关”会成为内积的间接先修,学习顺序需相应调整。)
