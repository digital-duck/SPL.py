## Heap Order Property

**Definition.** A *max-heap* is a complete binary tree stored in an array in which every node satisfies the *heap order property*: the key of each node is greater than or equal to the keys of its children. Indexing nodes $1, 2, \ldots, n$ from the root, with node $i$ having parent at index $\lfloor i/2 \rfloor$ and children at $2i$ and $2i+1$, the property requires

$$A[\lfloor i/2 \rfloor] \geq A[i] \quad \text{for all } 2 \leq i \leq n.$$

Because every ancestor of a node dominates it, the root $A[1]$ holds the global maximum. A min-heap is the symmetric variant in which $\leq$ replaces $\geq$ throughout; the root then holds the global minimum.

**Worked Example.** Consider the array $A = [16, 14, 10, 8, 7, 9, 3, 2, 4, 1]$. We verify the heap order property at three indices. At $i = 4$ (value $8$): parent index $\lfloor 4/2 \rfloor = 2$, parent value $14$, and $14 \geq 8$ holds. At $i = 5$ (value $7$): parent index $2$, parent value $14 \geq 7$. At $i = 6$ (value $9$): parent index $3$, parent value $10 \geq 9$. Checking all remaining pairs similarly confirms that every parent dominates its children, so $A$ is a valid max-heap. The root $A[1] = 16$ is the array's maximum, as the property guarantees.

**Key Theorem (Heap Height Bound).** A max-heap storing $n$ elements has height exactly $\lfloor \log_2 n \rfloor$. Because the underlying complete binary tree fills all levels before the last, the number of nodes satisfies $2^h \leq n < 2^{h+1}$, giving $h = \lfloor \log_2 n \rfloor$. This bound is the foundation of all $O(\log n)$ heap algorithms: any procedure that traverses a root-to-leaf path visits at most $h + 1$ nodes, each in $O(1)$ work.

## Binary Tree

**Definition.** A *binary tree* is a rooted tree in which every node has at most two children, designated the *left child* and the *right child*. Formally, a binary tree $T$ is either empty (the null tree $\emptyset$) or a triple $(r, T_L, T_R)$ where $r$ is the root node and $T_L$, $T_R$ are themselves binary trees. The *depth* of a node $v$, denoted $d(v)$, is the number of edges on the unique path from the root to $v$; the *height* of $T$ is $h(T) = \max_{v \in T} d(v)$. A binary tree is *full* if every internal node has exactly two children, and *complete* if every level except possibly the last is fully populated and all leaves on the last level are as far left as possible.

**Worked Example.** Consider the integer sequence $\langle 5, 3, 7, 1, 4 \rangle$ inserted in order into a *binary search tree* (BST), where the invariant requires every key in the left subtree of a node $x$ to be strictly less than $x$, and every key in the right subtree to be strictly greater. Inserting $5$ creates the root. Then $3 < 5$ goes left; $7 > 5$ goes right; $1 < 5, 1 < 3$ goes left-left; $4 < 5, 4 > 3$ goes right of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node, so an in-order traversal yields the sorted sequence $\langle 1, 3, 4, 5, 7 \rangle$.

**Key Theorem (Height–Node Bound).** Let $T$ be a binary tree with $n$ nodes and height $h$. Then

$$h \;\geq\; \lfloor \log_2 n \rfloor, \qquad h \;\leq\; n - 1.$$

The lower bound follows because a complete binary tree of height $h$ contains at most $2^{h+1} - 1$ nodes, so $n \leq 2^{h+1} - 1$ implies $h \geq \log_2(n+1) - 1 \geq \lfloor \log_2 n \rfloor$. The upper bound is achieved by a degenerate (path-like) tree. For a *balanced* BST this gives $O(\log n)$ search time, the essential motivation for balanced-tree data structures such as AVL trees and red-black trees.

```python
from sympy import symbols, Function, Lambda
# Build and query a BST using a plain Python dict as a node store.

def insert(tree, key):
    if tree is None:
        return {"key": key, "left": None, "right": None}
    if key < tree["key"]:

    elif key > tree["key"]:
        tree["right"] = insert(tree["right"], key)
    return tree

    if tree is None:
        return []
    return inorder(tree["left"]) + [tree["key"]] + inorder(tree["right"])

print("In-order traversal:", inorder(root))  # [1, 3, 4, 5, 7]
```

## Complete Binary Tree

**Definition.** A *complete binary tree* of height $h$ is a rooted binary tree in which every level $0, 1, \ldots, h-1$ is fully populated, and all nodes at level $h$ are as far left as possible. Formally, if we label nodes by their breadth-first search (BFS) index starting at $1$ for the root, a binary tree with $n$ nodes is complete if and only if every index in $\{1, 2, \ldots, n\}$ is occupied. For a node at index $i$, its left child resides at index $2i$, its right child at $2i+1$, and its parent at $\lfloor i/2 \rfloor$.

A complete binary tree with $n$ nodes has height $h = \lfloor \log_2 n \rfloor$, so the depth of any node is $O(\log n)$. The total number of nodes satisfies $2^h \leq n \leq 2^{h+1} - 1$.

**Worked Example.** Consider $n = 6$ nodes. Label them $1$ through $6$ in BFS order:

$$
\text{Level 0: } 1 \qquad \text{Level 1: } 2,\, 3 \qquad \text{Level 2: } 4,\, 5,\, 6
$$

Node $1$ has children $2$ and $3$. Node $2$ has children $4$ and $5$. Node $3$ has only a left child, $6$; no right child exists because $n = 6 < 7 = 2 \cdot 3 + 1$. Every level below level $2$ is empty. The height is $\lfloor \log_2 6 \rfloor = 2$.

**Key Theorem (Array Representation).** A complete binary tree on $n$ nodes can be stored in a one-indexed array $A[1 \ldots n]$ without any explicit pointer storage. The parent–child index formulas above yield $O(1)$ navigation. Consequently, the *binary heap* data structure uses exactly this layout, achieving $O(\log n)$ insertion and deletion by traversing at most $h = \lfloor \log_2 n \rfloor$ levels. The array representation is cache-friendly and eliminates pointer overhead, making heaps space-optimal in practice.

```python
def left_child(i):   return 2 * i
def right_child(i):  return 2 * i + 1

    print(f"Node {i}: parent={p}, left={lc}, right={rc}")

print(f"\nHeight h = floor(log2({n})) = {height}")
```

## Priority Queue

**Definition.** A *priority queue* is an abstract data type that maintains a dynamic multiset $S$ of elements, each associated with a numeric *key* (or priority), and supports two principal operations in addition to insertion:

- $\textsc{Insert}(S, x, k)$: add element $x$ with key $k$ to $S$.
- $\textsc{Extract-Min}(S)$: remove and return the element of $S$ with the smallest key.

(A *max-priority queue* symmetrically supports $\textsc{Extract-Max}$.) The canonical implementation is a *binary min-heap*: a complete binary tree stored in an array $A[1..n]$ satisfying the **heap property**

$$A[\lfloor i/2 \rfloor] \leq A[i] \quad \text{for all } i > 1.$$

The root $A[1]$ always holds the minimum. Insertion places the new element at position $n+1$, then repeatedly swaps it with its parent until the heap property is restored, requiring at most $\lfloor \log_2 n \rfloor$ comparisons and therefore $O(\log n)$ time. Extract-Min swaps the root with $A[n]$, decrements $n$, then pushes the new root downward by repeatedly swapping it with its smaller child until the heap property holds again, also in $O(\log n)$ time.

**Worked example.** Insert the keys $7, 3, 5, 1$ one at a time into an initially empty min-heap.

| Step | Action | Array state |
|------|--------|------------|
| 1 | Insert 7 | $[7]$ |
| 2 | Insert 3 | $[7,3]\xrightarrow{\text{swap with parent}}[3,7]$ |
| 3 | Insert 5 | $[3,7,5]$ (no swap needed) |
| 4 | Insert 1 | $[3,7,5,1]\xrightarrow{\text{swap}}[3,1,5,7]\xrightarrow{\text{swap}}[1,3,5,7]$ |

Calling $\textsc{Extract-Min}$ returns $1$, yielding the heap $[3,7,5]$ after the root is pushed downward.

**Theorem (Priority queue operation complexity).** In a binary min-heap of $n$ elements, both $\textsc{Insert}$ and $\textsc{Extract-Min}$ run in $O(\log n)$ worst-case time. Consequently, sorting $n$ elements by performing $n$ insertions followed by $n$ Extract-Min operations requires $\Theta(n \log n)$ total time.

*Proof sketch.* The binary min-heap has height $\lfloor \log_2 n \rfloor$. Insertion traverses at most one root-to-leaf path upward; Extract-Min traverses at most one root-to-leaf path downward. Each path has length $O(\log n)$, and each step costs $O(1)$. Applying both operations $n$ times gives $O(n \log n)$; the lower bound follows from the comparison-based sorting lower bound. $\square$

```python
    print(f"After inserting {k}: {heap}")

    print(f"Extract-Min → {heapq.heappop(heap)}, remaining: {heap}")
```

## Randomization Coin Toss

**Definition.** A *fair coin toss* is a Bernoulli trial: a random experiment with exactly two outcomes, conventionally labeled heads ($H$) and tails ($T$), each occurring with probability $\tfrac{1}{2}$. Formally, define a probability space $(\Omega, \mathcal{F}, P)$ where $\Omega = \{H, T\}$, $\mathcal{F} = 2^{\Omega}$, and $P(\{H\}) = P(\{T\}) = \tfrac{1}{2}$. The associated Bernoulli random variable $X$ maps outcomes to $\{0, 1\}$ by $X(T) = 0$, $X(H) = 1$, with expectation $\mathbb{E}[X] = \tfrac{1}{2}$ and variance $\operatorname{Var}(X) = \tfrac{1}{4}$.

Extending to $n$ independent tosses produces a sequence $(X_1, X_2, \ldots, X_n)$ of i.i.d. Bernoulli$(\tfrac{1}{2})$ variables. Their sum $S_n = \sum_{i=1}^n X_i$ counts the number of heads and follows the Binomial distribution: $S_n \sim \mathrm{Bin}(n, \tfrac{1}{2})$.

**Worked Example.** Suppose a student tosses a fair coin $n = 10$ times and records the number of heads. What is the probability of obtaining exactly 6 heads?

$$P(S_{10} = 6) = \binom{10}{6}\!\left(\tfrac{1}{2}\right)^{10} = \frac{210}{1024} \approx 0.205.$$

More than one-fifth of all such experiments will yield exactly 6 heads, illustrating that moderate deviations from the expected value $\mathbb{E}[S_{10}] = 5$ are common.

**Key Theorem (Law of Large Numbers).** Let $\bar{X}_n = S_n / n$ denote the sample proportion of heads. For any $\varepsilon > 0$,

$$P\!\left(\left|\bar{X}_n - \tfrac{1}{2}\right| > \varepsilon\right) \leq \frac{1}{4n\varepsilon^2} \to 0 \quad \text{as } n \to \infty.$$

The bound follows immediately from Chebyshev's inequality applied to $\bar{X}_n$ with $\operatorname{Var}(\bar{X}_n) = \tfrac{1}{4n}$. In practice, this guarantees that long-run frequencies converge to the true probability $\tfrac{1}{2}$, underpinning every Monte Carlo estimation method.

**Lab Cell.**

```python

prob = binomial(n, k) * p**k * (1 - p)**(n - k)

```

Running this cell confirms $P(S_{10} = 6) = 105/512 \approx 0.2051$ and verifies that the distribution sums to unity, providing a concrete computational check of the combinatorial formula.

### array_resizing_amortization (0.0s)

## Array Resizing Amortization

**Definition.** A dynamic array is a contiguous block of memory that doubles its capacity whenever insertion would exceed the current allocation. Because individual insertions occasionally trigger an expensive copy of all existing elements, naïve analysis overstates the true cost. *Amortized analysis* distributes the cost of rare expensive operations across the many cheap ones that precede them, yielding a more accurate average cost per operation over a sequence.

Formally, let $T(n)$ denote the total time to perform $n$ insertions into an initially empty array. The *amortized cost per insertion* is defined as

$$\hat{c} = \frac{T(n)}{n}.$$

We say an operation has amortized cost $O(f(n))$ if $T(n) = O(n \cdot f(n))$.

---

**Worked Example.** Suppose the array starts with capacity $1$ and doubles on overflow. Track the copy cost for each insertion:

| Insertion $i$ | Capacity before | Copy cost |
|---|---|---|
| 1 | 1 | 1 |
| 2 | 2 | 2 |
| 3 | 4 | 0 |
| 4 | 4 | 4 |
| 5–8 | 8 | 0 (×3), 8 |

After $n = 2^k$ insertions the total copy cost is $1 + 2 + 4 + \cdots + 2^k = 2^{k+1} - 1 < 2n$. Adding the $n$ unit-cost insertions gives $T(n) < 3n$, so $\hat{c} < 3 = O(1)$.

---

**Key Theorem (Aggregate Method).** *Each of $n$ successive append operations on a doubling dynamic array runs in $O(1)$ amortized time.*

*Proof sketch.* The copy cost at the $j$-th doubling event is $2^j$. Doublings occur at indices $1, 2, 4, \ldots, 2^{\lfloor \log_2 n \rfloor}$, so the total copy cost satisfies

$$\sum_{j=0}^{\lfloor \log_2 n \rfloor} 2^j = 2^{\lfloor \log_2 n \rfloor + 1} - 1 \leq 2n - 1 = O(n).$$

Dividing by $n$ yields $O(1)$ amortized cost per operation. $\blacksquare$

The result fails for a fixed increment strategy: incrementing by a constant $c$ causes copies at steps $c, 2c, 3c, \ldots$, giving total cost $\Theta(n^2)$ and amortized cost $\Theta(n)$.

---

**Lab Cell.**

```python

k = floor(log(n, 2))
copy_cost = summation(2**j, (j, 0, k))
print(simplify(copy_cost))   # prints 2**(floor(log(n)/log(2)) + 1) - 1
```

Running this cell confirms the closed form $2^{\lfloor \log_2 n \rfloor + 1} - 1$ derived in the proof, providing a symbolic check of the aggregate bound.

### eytzinger_method (0.0s)

## Eytzinger Method

**Definition.** The *Eytzinger method* (also called the *BFS-order layout* or *Eytzinger array layout*) is a technique for storing a complete binary search tree implicitly in a one-dimensional array such that the element at index $i$ has its left child at index $2i$ and its right child at index $2i + 1$, with the root stored at index $1$. Formally, given a sorted sequence $a_1 \le a_2 \le \cdots \le a_n$, the Eytzinger layout $E$ is the unique permutation satisfying: for every node at position $i$, all elements in the left subtree rooted at $2i$ are strictly less than $E[i]$, and all elements in the right subtree rooted at $2i+1$ are strictly greater than $E[i]$.

**Worked Example.** Consider the sorted array $[1, 2, 3, 4, 5, 6, 7]$. Its Eytzinger layout places the median $4$ at index $1$, the left-subtree median $2$ at index $2$, the right-subtree median $6$ at index $3$, and so on, yielding:

$$E = [\_, 4, 2, 6, 1, 3, 5, 7]$$

(index 0 is unused.) A binary search for the value $5$ traces the path $E[1]=4 \to E[3]=6 \to E[6]=5$, reading exactly three memory locations.

**Key Theorem (Cache-Optimal Binary Search).** For an Eytzinger-layout array of $n$ elements and a cache of line size $B$, a binary search accesses at most

$$\left\lceil \log_2(n+1) \right\rceil$$

comparisons, identical to classical binary search, yet the number of *cache misses* is at most

$$\left\lceil \log_B(n+1) \right\rceil$$

compared to $\Theta(\log n)$ misses in the sorted-array layout. The improvement arises because nodes visited in the first $\log_2 B$ levels of the traversal fit within a single cache line, so each cache fetch prefetches the next several comparison targets simultaneously. In practice, this layout yields binary search throughput improvements of 3–5× over the naïve sorted-array approach on modern hardware.

**Lab Cell.**

```python
from sympy import symbols, Integer

def eytzinger_fill(src, dst, si, di, n):
    """Recursively fill dst in Eytzinger order from sorted list src."""
    if di > n:
        return si
    si = eytzinger_fill(src, dst, si, 2 * di, n)
    dst[di] = src[si]; si += 1
    si = eytzinger_fill(src, dst, si, 2 * di + 1, n)
    return si

sorted_arr = [1, 2, 3, 4, 5, 6, 7]
n = len(sorted_arr)
layout = [None] * (n + 1)          # 1-indexed; index 0 unused
eytzinger_fill(sorted_arr, layout, 0, 1, n)
print(layout)                       # [None, 4, 2, 6, 1, 3, 5, 7]
```

Run this cell and verify that searching for any value $k$ by repeatedly halving the index ($i \leftarrow 2i$ if $k < E[i]$, else $i \leftarrow 2i+1$) terminates in $\lceil \log_2(n+1) \rceil$ steps.

## Merge Operation

**Definition.** Let $A = (a_1, a_2, \ldots, a_m)$ and $B = (b_1, b_2, \ldots, b_n)$ be two finite sequences whose elements belong to a totally ordered set $(S, \leq)$. The *merge operation* $\mathrm{merge}(A, B)$ produces a single sequence $C = (c_1, c_2, \ldots, c_{m+n})$ satisfying:

1. **Completeness:** every element of $A$ and every element of $B$ appears in $C$ (with multiplicity preserved).
2. **Order preservation:** $c_1 \leq c_2 \leq \cdots \leq c_{m+n}$.
3. **Stability:** among elements with equal key values, elements from $A$ precede elements from $B$ in $C$.

The operation is realized by the following procedure: maintain two index pointers $i = 1$, $j = 1$; repeatedly append $\min(a_i, b_j)$ to $C$ and advance the corresponding pointer; exhaust the remaining elements of whichever sequence still has entries.

**Worked Example.** Let $A = (2, 5, 8)$ and $B = (1, 4, 6, 9)$. Tracing the pointer procedure:

| Step | $i$ | $j$ | Compare | Append |
|------|-----|-----|---------|--------|
| 1 | 1 | 1 | $a_1=2,\;b_1=1$ | $1$ |
| 2 | 1 | 2 | $a_1=2,\;b_2=4$ | $2$ |
| 3 | 2 | 2 | $a_2=5,\;b_2=4$ | $4$ |
| 4 | 2 | 3 | $a_2=5,\;b_3=6$ | $5$ |
| 5 | 3 | 3 | $a_3=8,\;b_3=6$ | $6$ |
| 6 | 3 | 4 | $a_3=8,\;b_4=9$ | $8$ |
| 7 | — | 4 | exhaust $A$ | $9$ |

Result: $C = (1, 2, 4, 5, 6, 8, 9)$.

**Theorem (Linear Time Complexity).** If $|A| = m$ and $|B| = n$, then $\mathrm{merge}(A, B)$ performs at most $m + n - 1$ comparisons and runs in $\Theta(m + n)$ time and space.

*Proof sketch.* Each comparison advances at least one pointer, and the total number of pointer advances is exactly $m + n$. Hence comparisons are bounded by $m + n - 1$ (the last element requires no comparison). Space is $\Theta(m + n)$ for the output buffer. $\square$

The merge operation is foundational to merge sort, whose divide-and-conquer recurrence $T(n) = 2T(n/2) + \Theta(n)$ resolves by the Master Theorem to $T(n) = \Theta(n \log n)$.

**Lab Cell (SymPy).**

```python
from sympy import symbols, Rational

def merge(A, B):
    result, i, j = [], 0, 0
    while i < len(A) and j < len(B):
        if A[i] <= B[j]:
            result.append(A[i]); i += 1
        else:
            result.append(B[j]); j += 1
    return result + A[i:] + B[j:]

A = [Rational(2), Rational(5), Rational(8)]
B = [Rational(1), Rational(4), Rational(6), Rational(9)]
print(merge(A, B))   # [1, 2, 4, 5, 6, 8, 9]
```

Replacing `int` literals with `sympy.Rational` demonstrates that the merge operation is agnostic to the concrete representation of elements, requiring only that $\leq$ be defined on the underlying type.

### binary_heap (0.0s)

## Binary Heap

**Definition.** A *binary heap* is a complete binary tree stored implicitly in an array such that every node satisfies the *heap property*. In a *min-heap*, each node's key is less than or equal to the keys of its children; in a *max-heap*, each node's key is greater than or equal to its children's keys. For a zero-indexed array $A$ of length $n$, the parent of node $i$ is $\lfloor(i-1)/2\rfloor$, its left child is $2i+1$, and its right child is $2i+2$. The root $A[0]$ always holds the global minimum (or maximum).

**Worked Example.** Consider inserting the sequence $\{4, 8, 2, 5, 1\}$ into an initially empty min-heap.

| Step | Inserted | Array state |
|------|----------|-------------|
| 1 | 4 | $[4]$ |
| 2 | 8 | $[4, 8]$ |
| 3 | 2 | $[4, 8, 2] \xrightarrow{\text{sift-up}} [2, 8, 4]$ |
| 4 | 5 | $[2, 8, 4, 5]$ |
| 5 | 1 | $[2, 8, 4, 5, 1] \xrightarrow{\text{sift-up}} [1, 2, 4, 5, 8]$ |

At step 5, the new element $1$ is placed at index 4 and compared with its parent at index 1 (value $8$); since $1 < 8$ the pair is swapped, then compared with the root (value $2$); since $1 < 2$ another swap occurs, placing $1$ at the root.

**Key Theorem.** *Both* `insert` *and* `extract-min` *run in* $O(\log n)$ *time; building a heap from an arbitrary array of* $n$ *elements runs in* $O(n)$ *time.*

*Proof sketch.* `insert` appends the new key and calls `sift-up`, which traverses at most $\lfloor\log_2 n\rfloor$ levels. `extract-min` removes the root, places the last element there, and calls `sift-down`, again bounded by the tree height $\lfloor\log_2 n\rfloor$. For `heapify`, one applies `sift-down` to every internal node starting from index $\lfloor n/2\rfloor - 1$ down to $0$; the geometric sum of work across levels yields $\sum_{k=0}^{\lfloor\log n\rfloor} \lceil n/2^{k+1} \rceil \cdot k = O(n)$. $\square$

**Lab Cell (SymPy/Python).**

```python

data = [4, 8, 2, 5, 1]
heapq.heapify(data)          # O(n) in-place min-heap
print("Root (min):", data[0])

heapq.heappush(data, 0)
print("After push(0):", data[0])

smallest = heapq.heappop(data)
print("Extracted:", smallest, "| New root:", data[0])
```

Running this cell confirms that the root always equals the current minimum and that each push/pop preserves the heap property, matching the $O(\log n)$ theoretical guarantee.

### meldable_heap (0.0s)

## Meldable Heap

**Definition.** A *meldable heap* (also called a *mergeable heap*) is a priority queue that supports, in addition to the standard `insert`, `find-min`, and `delete-min` operations, a `meld` (or `merge`) operation that combines two heaps into a single heap in sub-linear time. Formally, let $H_1$ and $H_2$ be two min-heaps defined over totally ordered key sets $S_1$ and $S_2$ with $S_1 \cap S_2 = \emptyset$. The operation $\text{meld}(H_1, H_2)$ produces a valid min-heap over $S_1 \cup S_2$ without copying individual elements. The defining constraint is that all operations, including meld, run in $O(\log n)$ worst-case or amortized time, where $n = |S_1| + |S_2|$.

**Worked Example.** Consider two leftist heaps (one classical realization of a meldable heap). Let $H_1$ contain keys $\{2, 5, 8\}$ and $H_2$ contain keys $\{3, 6\}$, both organized as min-leftist trees. To meld, compare roots: $2 < 3$, so $2$ becomes the new root and we recursively meld $H_1$'s right spine with all of $H_2$. At the next level, roots are $5$ and $3$; since $3 < 5$, node $3$ absorbs the sub-problem. Continuing, $5$ and $6$ merge with $5$ winning. After the recursion unwinds, we restore the *leftist property*—that the rank (length of rightmost spine) of the left child is always $\geq$ the rank of the right child—by swapping children wherever violated. The final heap has root $2$, left subtree rooted at $5$, and right subtree rooted at $3$.

**Key Theorem (Leftist Heap Complexity).** In a leftist heap with $n$ nodes, the rightmost spine has length at most $\lfloor \log_2(n+1) \rfloor$. Because `meld` traverses only the two rightmost spines, its time complexity is $O(\log n)$. Since `insert` reduces to $\text{meld}(H, \{k\})$ and `delete-min` reduces to $\text{meld}(\text{left}(H), \text{right}(H))$, all three operations inherit the same bound.

*Proof sketch.* A rightmost spine of length $k$ implies the heap contains at least $2^k - 1$ nodes (the subtree rooted at each spine node has height $\geq$ its rank by the leftist invariant). Solving $2^k - 1 \leq n$ gives $k \leq \log_2(n+1)$. $\square$

### decrease_key (19.1s)

## Decrease Key

**Definition.** Let $H$ be a min-heap storing elements drawn from a totally ordered set, and let $x$ be a node currently in $H$ with key $k(x)$. The *decrease-key* operation replaces $k(x)$ with a new value $k' < k(x)$ and restores the heap-order invariant: for every non-root node $v$, $k(\text{parent}(v)) \leq k(v)$. Formally,

$$\text{decrease\_key}(H,\, x,\, k') \;\text{ where }\; k' < k(x).$$

Because the new key is strictly smaller, the node may now violate the invariant with respect to its parent; no child violation is possible, since reducing a key can only make a node a better candidate for the minimum.

**Worked Example.** Consider the min-heap with root $3$, whose left child is $7$ (with children $9$ and $11$) and right child is $5$. Apply $\text{decrease\_key}(x = 9,\; k' = 2)$. After the update the subtree rooted at $7$ has the ordering $7 \to 2$, violating heap order. The repair procedure (*sift-up* or *bubble-up*) compares $2$ with its parent $7$: since $2 < 7$, the two nodes swap. Now $2$ sits where $7$ was, with parent $3$: since $2 < 3$, another swap occurs. The node rises to the root, giving the corrected heap with root $2$.

**Key Theorem.** In a binary min-heap of $n$ nodes, decrease-key runs in $O(\log n)$ worst-case time. The sift-up path has length at most $\lfloor \log_2 n \rfloor$ (the height of the heap), and each step performs $O(1)$ comparisons and pointer updates. In a Fibonacci heap the amortised cost drops to $O(1)$, enabling Dijkstra's algorithm to achieve the optimal $O(|E| + |V|\log|V|)$ time complexity.

**Lab Cell (SymPy / Python).**

```python
import heapq

# heapq does not expose node references directly;
# the standard workaround uses lazy deletion.
heap = []
entry_finder = {}

def add_or_decrease(heap, entry_finder, item, priority):
    if item in entry_finder:
        entry_finder[item][-1] = float('inf')   # mark old entry invalid
    entry = [priority, item]
    entry_finder[item] = entry
    heapq.heappush(heap, entry)

def pop_min(heap, entry_finder):
    while heap:
        priority, item = heapq.heappop(heap)
        if priority != float('inf'):
            del entry_finder[item]
            return item, priority

add_or_decrease(heap, entry_finder, 'A', 9)
add_or_decrease(heap, entry_finder, 'B', 7)
add_or_decrease(heap, entry_finder, 'A', 2)   # decrease key of A from 9 to 2
print(pop_min(heap, entry_finder))             # expects ('A', 2)
```
