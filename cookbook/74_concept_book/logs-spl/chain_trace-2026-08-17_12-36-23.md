## Graph

A **graph** is a mathematical structure used to model relationships between objects. It consists of a set of **vertices** (also called nodes) and a set of **edges** that connect pairs of vertices. Formally, a graph $G = (V, E)$ where $V$ is the vertex set and $E \subseteq V \times V$ is the edge set. Edges can be **undirected** (a two-way connection, like a road between two cities) or **directed** (a one-way connection, like a hyperlink from one webpage to another). A graph can also carry **weights** on its edges — numerical values representing cost, distance, or capacity.

Graphs are the natural language for problems involving networks: social connections, routing, scheduling, and dependency resolution all reduce to graph problems.

**Worked example.** Consider a small network of five cities connected by roads:

```python
import networkx as nx

G = nx.Graph()
G.add_edges_from([
    ("A", "B", {"weight": 4}),
    ("A", "C", {"weight": 2}),
    ("B", "D", {"weight": 5}),
    ("C", "D", {"weight": 1}),
    ("D", "E", {"weight": 3}),
])
```

Here $|V| = 5$ and $|E| = 5$. The **degree** of a vertex is the number of edges incident to it; vertex D has degree 3 because it connects to B, C, and E. The **path** A → C → D has total weight $2 + 1 = 3$, which is shorter than A → B → D at weight $4 + 5 = 9$.

**Problem-solving application.** Graphs become powerful when you apply traversal and search algorithms to extract information. Suppose you want the shortest path from A to E in the weighted graph above. Dijkstra's algorithm explores vertices in order of cumulative distance and guarantees the optimal path:

```python
path = nx.dijkstra_path(G, "A", "E", weight="weight")
cost = nx.dijkstra_path_length(G, "A", "E", weight="weight")
print(path, cost)   # ['A', 'C', 'D', 'E']  6
```

The algorithm finds A → C → D → E with total weight 6, beating every alternative. This same pattern — model relationships as a graph, then query with a standard algorithm — solves problems ranging from GPS routing to compiler dependency checks to recommendation engines. Recognizing that a problem has graph structure is often the key insight; once you see it, a well-tested algorithm almost always exists.

## Graph Representation

A **graph** is a mathematical structure that models relationships between objects. Formally, a graph $G = (V, E)$ consists of a set of **vertices** $V$ (also called nodes) and a set of **edges** $E$, where each edge connects a pair of vertices. If the edges have a direction (A points to B, but not necessarily B to A), the graph is **directed**; otherwise it is **undirected**. Edges can also carry a **weight** — a numeric value representing cost, distance, or strength of connection.

The two standard ways to store a graph in memory are the **adjacency matrix** and the **adjacency list**.

An adjacency matrix is a $|V| \times |V|$ matrix $A$ where $A[i][j] = 1$ (or the edge weight) if an edge exists from vertex $i$ to vertex $j$, and $0$ otherwise. It allows $O(1)$ edge lookup but uses $O(|V|^2)$ space — wasteful when edges are sparse.

An adjacency list stores, for each vertex, only the list of its neighbors. Space drops to $O(|V| + |E|)$, which is far more efficient for real-world graphs where most pairs of nodes are not connected.

**Worked example.** Consider four cities: Atlanta (0), Boston (1), Chicago (2), Dallas (3), with direct flights Atlanta–Boston, Atlanta–Chicago, and Boston–Dallas. As an undirected adjacency list in Python:

```python
graph = {
    0: [1, 2],   # Atlanta connects to Boston, Chicago
    1: [0, 3],   # Boston connects to Atlanta, Dallas
    2: [0],      # Chicago connects to Atlanta
    3: [1],      # Dallas connects to Boston
}
```

To add a flight weight (in minutes), replace each neighbor with a tuple:

```python
graph = {
    0: [(1, 130), (2, 90)],
    1: [(0, 130), (3, 180)],
    2: [(0, 90)],
    3: [(1, 180)],
}
```

**Problem-solving application.** Suppose you need to find all cities reachable from Atlanta. Starting at node 0, a breadth-first search (BFS) follows the adjacency list layer by layer:

```python
from collections import deque

def bfs(graph, start):
    visited, queue = {start}, deque([start])
    while queue:
        node = queue.popleft()
        for neighbor, *_ in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return visited

print(bfs(graph, 0))  # {0, 1, 2, 3}
```

Choosing the right representation matters: use an adjacency matrix when the graph is dense and edge lookups dominate; use an adjacency list for sparse graphs or when you need to iterate over neighbors efficiently — which covers most practical cases.
