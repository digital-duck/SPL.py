## 图(Graph)

**定义。** 图是描述"对象及其相互关系"的数学结构。一个图 $G=(V,E)$ 由顶点集 $V$(对象)和边集 $E$(关系)组成。若边没有方向(如"互为好友"),称为无向图;若边有方向(如"课程A是课程B的先修课"),称为有向图。顶点 $v$ 的**度**是与它相连的边数,记作 $\deg(v)$。在无向图中,所有顶点度数之和等于边数的两倍:

$$\sum_{v\in V}\deg(v)=2|E|.$$

图的常见存储方式有两种:**邻接表**(每个顶点存一份邻居列表,适合稀疏图)和**邻接矩阵**($A_{ij}=1$ 表示 $i$ 到 $j$ 有边,适合稠密图)。

**例题。** 某校有四门课:微积分(C)、线性代数(L)、概率论(P)、机器学习(M)。先修关系为:C→L,C→P,L→M,P→M。

邻接表为:

- C: [L, P]
- L: [M]
- P: [M]
- M: []

问:要修机器学习,最少需要先修哪些课?它们的合法修读顺序是什么?

解:从 M 沿边反向追溯,得到 L 和 P;再追溯得到 C。因此必须先修 C、L、P 三门课。合法顺序需满足每条边的起点先于终点,例如 C, L, P, M 或 C, P, L, M。这种满足所有边方向的排列称为**拓扑排序**,它只在**无环**的有向图(DAG)中存在。

**问题求解应用。** 许多实际问题都可以先"建图",再用成熟算法求解:

1. **最短路径**:地图导航中,路口是顶点,道路是边,边权为距离或时间。无权图用广度优先搜索(BFS)即可求出最少边数的路径。
2. **连通性**:判断社交网络中两人是否能通过朋友链相识,即判断两顶点是否在同一连通分量中。可用深度优先搜索(DFS)实现:

```python
def reachable(graph, start, goal):
    seen, stack = set(), [start]
    while stack:
        v = stack.pop()
        if v == goal:
            return True
        if v not in seen:
            seen.add(v)
            stack.extend(graph[v])
    return False
```

3. **依赖检测**:若先修关系中出现环(如 A→B→C→A),则任何人都无法修完这些课。用 DFS 检测环,是软件构建系统、任务调度器的基本功能。

**小结。** 解图问题的关键在于三步:确定什么是顶点、什么是边;选择合适的存储方式;再套用 BFS、DFS 或拓扑排序等算法。把陌生问题转化为图,往往就解决了一大半。

## 图的表示

**定义。** 图 $G=(V,E)$ 由顶点集 $V$ 和边集 $E$ 组成。要在程序中处理图,首先要决定如何存储它。最常用的两种方式是:

- **邻接矩阵**:用 $n\times n$ 的矩阵 $A$ 存储,其中 $n=|V|$。若顶点 $i$ 到 $j$ 有边,则 $A_{ij}=1$,否则为 $0$(带权图则存放权值)。无向图的 $A$ 是对称矩阵。
- **邻接表**:为每个顶点保存一个列表,列出与它相邻的所有顶点。

两种表示描述的是同一个图,区别在于空间和操作的代价。

**例题。** 考虑无向图,顶点为 $\{0,1,2,3\}$,边为 $\{0\text{-}1,\ 0\text{-}2,\ 1\text{-}2,\ 2\text{-}3\}$。

邻接矩阵为

$$A=\begin{pmatrix}0&1&1&0\\1&0&1&0\\1&1&0&1\\0&0&1&0\end{pmatrix}$$

邻接表为:

```python
adj = {
    0: [1, 2],
    1: [0, 2],
    2: [0, 1, 3],
    3: [2],
}
```

由矩阵可以直接读出:第 $i$ 行元素之和就是顶点 $i$ 的度数,例如第 2 行之和为 $3$。在邻接表中,度数就是列表的长度。

**空间与时间的比较。** 设 $m=|E|$。

| 操作 | 邻接矩阵 | 邻接表 |
|---|---|---|
| 存储空间 | $O(n^2)$ | $O(n+m)$ |
| 判断边 $(i,j)$ 是否存在 | $O(1)$ | $O(\deg i)$ |
| 遍历 $i$ 的所有邻居 | $O(n)$ | $O(\deg i)$ |

**问题求解应用。** 假设要分析一个有 $n=10^5$ 个用户的社交网络,每人平均有 $50$ 个好友,于是 $m\approx 2.5\times10^6$。

1. 若用邻接矩阵,需要 $n^2=10^{10}$ 个单元。即使每个单元只占 1 字节,也要约 10 GB,通常无法接受。
2. 若用邻接表,只需约 $n+2m\approx 5\times10^6$ 个条目,普通内存即可容纳。

选择规则可以归纳为:

- **稀疏图**($m\ll n^2$,如社交网络、道路网):用邻接表,同时让广度优先搜索、深度优先搜索等遍历算法的时间降为 $O(n+m)$。
- **稠密图**($m$ 接近 $n^2$),或需要频繁查询"两点之间是否有边":用邻接矩阵。
- **需要矩阵运算时**:邻接矩阵有独特优势。例如 $(A^k)_{ij}$ 恰好等于从 $i$ 到 $j$ 长度为 $k$ 的路径条数。对上面的例子计算 $A^2$,可得 $(A^2)_{03}=1$,对应唯一的路径 $0\to2\to3$。

**小结。** 先估计 $n$ 与 $m$ 的关系,再确定最常做的操作(查边、遍历邻居,还是矩阵运算),据此选择表示方式。同一个算法换一种表示,运行时间和内存可能相差几个数量级。
