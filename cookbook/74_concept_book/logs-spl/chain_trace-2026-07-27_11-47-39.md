## Binary Tree

**Definition.** A *binary tree* is a rooted tree in which every node has at most two children, designated the *left child* and the *right child*. Formally, a binary tree $T$ is either empty (the null tree $\emptyset$) or a triple $(r, T_L, T_R)$ where $r$ is the root node and $T_L$, $T_R$ are themselves binary trees. The *depth* of a node $v$, denoted $d(v)$, is the number of edges on the unique path from the root to $v$; the *height* of $T$ is $h(T) = \max_{v \in T} d(v)$. A binary tree is *full* if every internal node has exactly two children, and *complete* if every level except possibly the last is fully populated and all leaves on the last level are as far left as possible.

**Worked Example.** Consider the integer sequence $\langle 5, 3, 7, 1, 4 \rangle$ inserted in order into a *binary search tree* (BST), where the invariant requires every key in the left subtree of a node $x$ to be strictly less than $x$, and every key in the right subtree to be strictly greater. Inserting $5$ creates the root. Then $3 < 5$ goes left; $7 > 5$ goes right; $1 < 5, 1 < 3$ goes left-left; $4 < 5, 4 > 3$ goes right of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node, so an in-order traversal yields the sorted sequence $\langle 1, 3, 4, 5, 7 \rangle$.

**Key Theorem (Height–Node Bound).** Let $T$ be a binary tree with $n$ nodes and height $h$. Then

$$h \;\geq\; \lfloor \log_2 n \rfloor, \qquad h \;\leq\; n - 1.$$

The lower bound follows because a complete binary tree of height $h$ contains at most $2^{h+1} - 1$ nodes, so $n \leq 2^{h+1} - 1$ implies $h \geq \log_2(n+1) - 1 \geq \lfloor \log_2 n \rfloor$. The upper bound is achieved by a degenerate (path-like) tree. For a *balanced* BST this gives $O(\log n)$ search time, the essential motivation for balanced-tree data structures such as AVL trees and red-black trees.

```python
    if tree is None:

```

## Total Order

**Definition.** Let $S$ be a non-empty set and let $\leq$ be a binary relation on $S$. The relation $\leq$ is called a *total order* (or *linear order*) on $S$ if it satisfies the following four axioms for all $a, b, c \in S$:

1. **Reflexivity:** $a \leq a$.
2. **Antisymmetry:** If $a \leq b$ and $b \leq a$, then $a = b$.
3. **Transitivity:** If $a \leq b$ and $b \leq c$, then $a \leq c$.
4. **Totality (Comparability):** Either $a \leq b$ or $b \leq a$ (or both).

The pair $(S, \leq)$ is called a *totally ordered set*, or *chain*. Axioms 1–3 alone define a *partial order*; it is the totality axiom that distinguishes a total order by demanding every pair of elements be comparable. Consequently, in a totally ordered set one can always arrange elements in a single linear sequence from least to greatest.

**Worked Example.** Consider $S = \{2, 5, 3\}$ with the usual $\leq$ on $\mathbb{Z}$. Checking totality: $2 \leq 3$, $2 \leq 5$, $3 \leq 5$. Every pair is comparable, so $(\{2,3,5\}, \leq)$ is a chain with the unique arrangement $2 \leq 3 \leq 5$. Contrast this with the power set $\mathcal{P}(\{1,2\}) = \{\emptyset, \{1\}, \{2\}, \{1,2\}\}$ under inclusion $\subseteq$: neither $\{1\} \subseteq \{2\}$ nor $\{2\} \subseteq \{1\}$, so $\subseteq$ is only a partial order here.

**Key Theorem (Well-Ordering Principle).** Every non-empty subset of $\mathbb{N}$ has a least element under the usual $\leq$. More generally, a total order on $S$ is called a *well-order* if every non-empty subset of $S$ has a least element. Well-ordering underpins mathematical induction and guarantees that recursive algorithms on $\mathbb{N}$ terminate.

*Proof sketch.* Suppose $T \subseteq \mathbb{N}$ is non-empty. Let $m = \min T$ be the element obtained by iterating $0, 1, 2, \ldots$ until the first element of $T$ is found; totality ensures this search is unambiguous, and finiteness of the descent guarantees termination. $\square$

## Binary Search Tree

**Definition.** A *binary search tree* (BST) is a rooted binary tree in which every node $v$ stores a key $k(v)$ drawn from a totally ordered set, subject to the *BST invariant*: for every node $v$, all keys in the left subtree of $v$ are strictly less than $k(v)$, and all keys in the right subtree of $v$ are strictly greater than $k(v)$. Formally, if $L(v)$ and $R(v)$ denote the left and right subtrees,

$$\forall u \in L(v):\ k(u) < k(v), \qquad \forall u \in R(v):\ k(u) > k(v).$$

This invariant holds recursively at every node, not merely at the root.

**Worked Example.** Insert the sequence $\langle 5, 3, 7, 1, 4 \rangle$ into an initially empty BST. The first key, $5$, becomes the root. Key $3 < 5$ goes left; $7 > 5$ goes right. Key $1 < 5$, then $1 < 3$, so it becomes the left child of $3$. Key $4 < 5$, then $4 > 3$, so it becomes the right child of $3$. The resulting tree has height $h = 2$ and satisfies the BST invariant at every node. An in-order traversal (left $\to$ root $\to$ right) yields $\langle 1, 3, 4, 5, 7 \rangle$—the keys in sorted order, which is a direct consequence of the invariant.

**Key Theorem (Search Complexity).** A search, insertion, or deletion in a BST containing $n$ nodes requires $O(h)$ comparisons, where $h$ is the height of the tree. For a *balanced* BST, $h = \Theta(\log n)$, giving $O(\log n)$ worst-case operations. In the degenerate case—keys inserted in sorted order—the tree degenerates to a linked list with $h = n - 1$ and $O(n)$ operations. Self-balancing variants (AVL trees, red–black trees) maintain $h = O(\log n)$ unconditionally.

**Lab Cell (SymPy/Python).**

```python
# Minimal BST node; insert and in-order traversal
class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def insert(root, key):
    if root is None:
        return Node(key)
    if key < root.key:
        root.left = insert(root.left, key)
    else:
        root.right = insert(root.right, key)
    return root

def inorder(root):
    return [] if root is None else inorder(root.left) + [root.key] + inorder(root.right)

root = None
for k in [5, 3, 7, 1, 4]:
    root = insert(root, k)

print(inorder(root))   # → [1, 3, 4, 5, 7]
```

## Bst Search

A **binary search tree (BST)** is a rooted binary tree in which every node $v$ stores a key $k(v)$ satisfying the **BST invariant**: for every node $v$, all keys in the left subtree of $v$ are strictly less than $k(v)$, and all keys in the right subtree are strictly greater. Formally, if $L(v)$ and $R(v)$ denote the left and right subtrees, then

$$\forall u \in L(v): k(u) < k(v) \qquad \text{and} \qquad \forall u \in R(v): k(u) > k(v).$$

The **BST search** procedure locates a target key $t$ by exploiting this invariant. Starting at the root, the algorithm compares $t$ with the current node's key: if $t$ equals the key, the search succeeds; if $t < k(v)$, it recurses into the left subtree; if $t > k(v)$, it recurses into the right subtree. If a null child is reached, $t$ is absent from the tree.

**Worked Example.** Consider the BST with keys inserted in the order $\{8, 3, 10, 1, 6, 14, 4, 7\}$. The root is $8$. To search for $t = 6$: compare $6 < 8$, move left to $3$; compare $6 > 3$, move right to $6$; keys match — search succeeds after three comparisons. To search for $t = 5$: the path $8 \to 3 \to 6 \to 4$ terminates at the right child of $4$, which is null, so $5$ is not in the tree.

**Theorem (Search Complexity).** Let $h$ denote the height of a BST on $n$ nodes. BST search runs in $O(h)$ time. For a balanced BST, $h = \Theta(\log n)$, giving $O(\log n)$ worst-case search time. For an unbalanced tree built from a random permutation, the expected height is $O(\log n)$; however, adversarial insertion order can produce $h = \Theta(n)$, degrading search to linear time.

**Lab Cell (SymPy).**

```python
from sympy.combinatorics.permutations import Permutation

class BSTNode:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def bst_insert(root, key):
    if root is None:
        return BSTNode(key)
    if key < root.key:
        root.left = bst_insert(root.left, key)
    elif key > root.key:
        root.right = bst_insert(root.right, key)
    return root

def bst_search(root, target, depth=0):
    if root is None:
        return None, depth
    if target == root.key:
        return root, depth
    if target < root.key:
        return bst_search(root.left, target, depth + 1)
    return bst_search(root.right, target, depth + 1)

keys = [8, 3, 10, 1, 6, 14, 4, 7]
root = None
for k in keys:
    root = bst_insert(root, k)

node, depth = bst_search(root, 6)
print(f"Found: {node.key}, comparisons: {depth + 1}")  # Found: 6, comparisons: 3
```

## Bst Addition

**Definition.** Let $T$ be a *binary search tree* (BST), a rooted binary tree in which every node $v$ stores a key $k(v)$ satisfying the *BST invariant*: for every node $v$, all keys in $v$'s left subtree are strictly less than $k(v)$, and all keys in $v$'s right subtree are strictly greater than $k(v)$. The *BST addition* (insertion) operation takes a key $x \notin T$ and produces a new tree $T' = T \cup \{x\}$ that preserves the BST invariant. Insertion locates the unique position where $x$ must reside—following left or right child pointers according to comparisons with each encountered key—and attaches a new leaf node there.

**Worked Example.** Consider the BST with keys inserted in order $\{5, 3, 7\}$, yielding a root $5$ with left child $3$ and right child $7$. Insert $x = 4$:

1. Compare $4 < 5$: descend to left child $3$.
2. Compare $4 > 3$: descend to right child of $3$, which is $\mathrm{nil}$.
3. Attach a new node with key $4$ as the right child of $3$.

The resulting tree satisfies the BST invariant: $3 < 4 < 5 < 7$.

**Key Theorem (Correctness of BST Insertion).** *If $T$ satisfies the BST invariant before insertion of key $x$, then $T' = \mathrm{insert}(T, x)$ satisfies the BST invariant.*

*Proof sketch.* The algorithm traverses a root-to-leaf path $v_1, v_2, \ldots, v_d$ determined entirely by comparisons with $x$. At each step, moving left records $x < k(v_i)$ and moving right records $x > k(v_i)$. These comparisons partition the existing keys into sets that are provably less than or greater than $x$, so placing a new leaf at position $v_{d+1}$ violates no existing ordering constraint. Formally, an inductive argument on tree height establishes the invariant for every subtree. $\square$

The time complexity of a single insertion is $O(h)$, where $h$ is the tree height. For a balanced BST, $h = O(\log n)$, giving efficient $O(\log n)$ insertion.

**Lab Cell (SymPy).**

```python
from sympy import symbols, Function

    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def bst_insert(root, x):
    if root is None:
        return BSTNode(x)
    if x < root.key:
        root.left = bst_insert(root.left, x)
    elif x > root.key:
        root.right = bst_insert(root.right, x)
    return root

def inorder(node, result=None):
    if result is None:
        result = []
    if node:
        inorder(node.left, result)
        result.append(node.key)
        inorder(node.right, result)
    return result

root = None
for k in [5, 3, 7, 4]:
    root = bst_insert(root, k)

print(inorder(root))  # [3, 4, 5, 7] — sorted, confirming BST invariant
```

The `inorder` traversal yields keys in sorted order, providing an empirical check that the BST invariant holds after every insertion.

## Bst Removal

**Definition.** Given a binary search tree $T$ and a key $k$, *BST removal* produces a new tree $T'$ that contains every node of $T$ except the node with key $k$, while preserving the BST invariant: for every node $n$ with left subtree $L$ and right subtree $R$,
$$\forall x \in L,\; x.\mathit{key} < n.\mathit{key} \quad \text{and} \quad \forall y \in R,\; y.\mathit{key} > n.\mathit{key}.$$

Removal is handled by three cases determined by the number of children of the target node $v$:

1. **Leaf node** ($v$ has no children): delete $v$ directly.
2. **One child**: replace $v$ with its sole child; the subtree rooted there already satisfies the BST invariant.
3. **Two children**: find $v$'s *in-order successor* $s$ — the minimum-key node in $v$'s right subtree — copy $s.\mathit{key}$ into $v$, then recursively remove $s$ from the right subtree. Because $s$ is a minimum, it has no left child, so this recursive call falls into case 1 or 2.

**Worked example.** Consider the BST with keys $\{10, 5, 15, 3, 7, 12, 20\}$ and root $10$. Remove $k = 15$ (a two-child node). Its right subtree contains $\{20\}$ and its left subtree contains $\{12\}$, so the in-order successor is $s = 12$. Copy $12$ into the node formerly holding $15$, then delete the original node holding $12$ (a leaf). The resulting tree has root $10$, left child $5$, and right child $12$ (with right child $20$). Verify: $10 < 12 < 20$ along the right spine — the invariant holds.

**Key theorem (correctness).** Let $T$ be a BST satisfying the BST invariant and let $v$ be the node with key $k$. The tree $T'$ produced by the three-case procedure above satisfies the BST invariant and contains exactly the keys $\mathit{keys}(T) \setminus \{k\}$.

*Proof sketch.* Cases 1 and 2 preserve the invariant locally by direct substitution. For case 3, the in-order successor $s$ satisfies $v.\mathit{key} < s.\mathit{key} \leq y$ for every $y$ in $v$'s right subtree, so replacing $v.\mathit{key}$ with $s.\mathit{key}$ maintains the ordering between the left subtree, the new root key, and the right subtree. $\blacksquare$

The worst-case time complexity is $O(h)$ where $h$ is the tree height; for a balanced BST this gives $O(\log n)$.

```python
from sympy import symbols, Function, Piecewise

# Lab: trace BST removal symbolically
class BSTNode:
    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right

def bst_remove(node, k):
    if node is None:
        return None
    if k < node.key:
        node.left = bst_remove(node.left, k)
    elif k > node.key:
        node.right = bst_remove(node.right, k)
    else:                                  # found target
        if node.left is None:
            return node.right
        if node.right is None:
            return node.left
        # two children: find in-order successor
        s = node.right
        while s.left:
            s = s.left
        node.key = s.key
        node.right = bst_remove(node.right, s.key)
    return node

def inorder(node):
    return inorder(node.left) + [node.key] + inorder(node.right) if node else []

root = BSTNode(10, BSTNode(5, BSTNode(3), BSTNode(7)),
                   BSTNode(15, BSTNode(12), BSTNode(20)))
print("Before:", inorder(root))          # [3, 5, 7, 10, 12, 15, 20]
bst_remove(root, 15)
print("After removing 15:", inorder(root))  # [3, 5, 7, 10, 12, 20]
```

## Unbalanced Bst Performance

**Definition.** A *binary search tree* (BST) is a rooted binary tree in which every node $x$ satisfies the BST property: all keys in the left subtree of $x$ are strictly less than $\text{key}(x)$, and all keys in the right subtree are strictly greater. The *height* $h$ of a BST is the length of the longest root-to-leaf path. For a tree storing $n$ distinct keys, the worst-case time complexity of search, insertion, and deletion is $\Theta(h)$. An *unbalanced* BST is one in which $h$ grows super-logarithmically with $n$, degrading these operations well beyond the $O(\log n)$ bound that balanced variants guarantee.

**Worked Example.** Consider inserting the keys $1, 2, 3, 4, 5$ into an initially empty BST in sorted order. Because each successive key is larger than all existing keys, every new node becomes the right child of the current rightmost leaf. The resulting tree is a right-leaning chain (a *degenerate* or *pathological* BST) of height $h = n - 1 = 4$. Searching for the key $5$ requires traversing all five nodes, giving $\Theta(n)$ time rather than the $\Theta(\log n)$ achievable in a balanced tree of the same size.

**Key Theorem.** *(Expected height under random insertion.)* If $n$ distinct keys are inserted into an empty BST in a uniformly random order, the expected height satisfies

$$\mathbb{E}[h] \leq 4.311 \ln n + O(1).$$

Thus, random insertion yields $O(\log n)$ expected performance. However, the *worst-case* height over all insertion orders is $h = n - 1$, achieved by any sorted or reverse-sorted sequence. Since real-world data is rarely uniformly random, relying on an unbalanced BST in production is unsafe; self-balancing trees (AVL, red–black) maintain $h = O(\log n)$ deterministically.

## Tree Balancing Strategies

A binary search tree (BST) supports search, insertion, and deletion in $O(h)$ time, where $h$ is the tree's height. For $n$ nodes, the ideal height is $\lfloor \log_2 n \rfloor$, achieved by a perfectly balanced tree. However, inserting keys in sorted order degenerates a BST into a linked list with $h = n - 1$, collapsing all operations to $O(n)$. Tree balancing strategies are structural maintenance rules that bound $h$ to $O(\log n)$ regardless of insertion order.

**Definition (Balance Factor).** For a node $v$ in a binary tree, let $h_L(v)$ and $h_R(v)$ denote the heights of its left and right subtrees, respectively. The *balance factor* of $v$ is

$$\beta(v) = h_L(v) - h_R(v).$$

A tree is *AVL-balanced* if $|\beta(v)| \leq 1$ for every node $v$.

**Worked Example.** Consider inserting the sequence $1, 2, 3$ into an AVL tree. After inserting $1$ and $2$, the root has $\beta = -1$, which is acceptable. Inserting $3$ makes the root's balance factor $\beta = -2$, violating the AVL condition. A *left rotation* at the root resolves this: node $2$ becomes the new root, with $1$ as its left child and $3$ as its right child. The resulting tree has height $1$ and $\beta = 0$ at every node.

Rotations are the fundamental repair operation. A *left rotation* at node $x$ promotes $x$'s right child $y$ to $x$'s position, making $x$ the left child of $y$ and attaching $y$'s former left subtree as $x$'s right subtree. The symmetric operation is a *right rotation*. For doubly-imbalanced cases (left-right or right-left), a *double rotation* — two single rotations in sequence — restores balance.

**Theorem (AVL Height Bound).** An AVL tree with $n$ nodes satisfies $h \leq 1.44 \log_2(n + 2)$.

*Proof sketch.* Let $N(h)$ be the minimum number of nodes in an AVL tree of height $h$. The recurrence $N(h) = N(h-1) + N(h-2) + 1$ with $N(0)=1$, $N(1)=2$ grows like Fibonacci numbers, giving $N(h) \approx \phi^h / \sqrt{5}$, where $\phi = (1+\sqrt{5})/2$. Inverting yields $h \leq \log_\phi(n\sqrt{5}) \approx 1.44\log_2 n$. $\square$
