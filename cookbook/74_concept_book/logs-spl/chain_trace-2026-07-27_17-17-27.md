## Recursion Tree

**Definition.** A *recursion tree* is a rooted tree that models the execution of a recursive algorithm by representing each recursive call as a node. The root corresponds to the initial call on an input of size $n$; each internal node spawns children corresponding to the sub-calls it makes; and each leaf represents a base case. The *cost* associated with a node is the work done at that call level, exclusive of its children. The total running time of the algorithm equals the sum of costs over all nodes in the tree.

More precisely, if an algorithm satisfies the recurrence

$$T(n) = a\,T\!\left(\frac{n}{b}\right) + f(n), \quad T(1) = \Theta(1),$$

then the recursion tree has depth $\log_b n$, exactly $a^k$ nodes at depth $k$, each performing cost $f(n/b^k)$, and $a^{\log_b n} = n^{\log_b a}$ leaves.

**Worked Example.** Consider merge sort, governed by $T(n) = 2\,T(n/2) + \Theta(n)$.

- **Level 0** (root): one call of size $n$, cost $cn$.
- **Level 1**: two calls of size $n/2$, total cost $2 \cdot c(n/2) = cn$.
- **Level $k$**: $2^k$ calls of size $n/2^k$, total cost $cn$.
- **Leaves** (level $\log_2 n$): $n$ calls of size $1$, total cost $\Theta(n)$.

Summing across all $\log_2 n + 1$ levels gives $T(n) = \Theta(n \log n)$.

**Key Theorem (Master Theorem, simplified).** For $T(n) = a\,T(n/b) + \Theta(n^d)$ with $a \geq 1$, $b > 1$, $d \geq 0$:

$$T(n) = \begin{cases} \Theta(n^d \log n) & \text{if } a = b^d, \\ \Theta(n^{\log_b a}) & \text{if } a > b^d, \\ \Theta(n^d) & \text{if } a < b^d. \end{cases}$$

The recursion-tree method provides the intuition behind each case: when $a = b^d$ the cost per level is constant at $\Theta(n^d)$ and there are $\log_b n$ levels; otherwise one of the two ends of the tree dominates.

## Game Tree

**Definition.** A *game tree* is a rooted directed tree $T = (V, E, r)$ in which each node $v \in V$ represents a *game state*, each directed edge $(u, v) \in E$ represents a *legal move* that transitions state $u$ to state $v$, and the root $r$ represents the initial state. Leaf nodes are *terminal states* carrying a numeric *payoff* $u(v) \in \mathbb{R}$. Internal nodes are labeled by the player whose turn it is to move. In a two-player zero-sum game, the players are conventionally called *MAX* and *MIN*: MAX seeks to maximize the payoff, MIN seeks to minimize it. The *depth* of the tree equals the maximum number of plies (half-moves) until termination.

**Worked Example.** Consider a two-ply game in which MAX moves first. The root $r$ has two children $m_1, m_2$ (MAX's choices). Each child has two children of its own (MIN's responses), yielding four leaves with payoffs $3, 5, 2, 9$:

$$
r \xrightarrow{m_1} \begin{cases} v_1 \to 3 \\ v_2 \to 5 \end{cases}, \qquad r \xrightarrow{m_2} \begin{cases} v_3 \to 2 \\ v_4 \to 9 \end{cases}
$$

MIN, playing at $m_1$, picks $\min(3,5)=3$; at $m_2$, picks $\min(2,9)=2$. MAX then picks $\max(3,2)=3$, so the *minimax value* of the root is $3$ and the optimal strategy is $m_1$ followed by MIN choosing $v_1$.

**Key Theorem (Minimax).** In a finite, deterministic, two-player zero-sum game with perfect information, the minimax value $V(v)$ satisfies the recursion

$$
V(v) = \begin{cases} u(v) & \text{if } v \text{ is terminal,} \\ \max_{c \in \mathrm{ch}(v)} V(c) & \text{if } v \text{ is a MAX node,} \\ \min_{c \in \mathrm{ch}(v)} V(c) & \text{if } v \text{ is a MIN node,} \end{cases}
$$

where $\mathrm{ch}(v)$ denotes the children of $v$. Both players playing optimally guarantees payoff $V(r)$ to MAX. The time complexity of exhaustive minimax evaluation is $O(b^d)$, where $b$ is the branching factor and $d$ is the tree depth.

**Lab Cell (SymPy).**

```python
from sympy import symbols, Max, Min

# Leaf payoffs
leaves = {
    'v1': 3, 'v2': 5,   # children of m1
    'v3': 2, 'v4': 9,   # children of m2
}

# MIN nodes
m1_val = Min(leaves['v1'], leaves['v2'])
m2_val = Min(leaves['v3'], leaves['v4'])

# MAX node (root)
root_val = Max(m1_val, m2_val)
print(f"Minimax value at root: {root_val}")   # 3
```

Running this cell confirms the hand calculation: the minimax value is $3$, achieved via move $m_1$.

## Good Bad State

**Definition.** Let $\mathcal{S}$ be a finite or countable *state space* and let $f : \mathcal{S} \to \mathcal{S}$ be a *transition function* that maps each state to its successor under a deterministic process. A *predicate* $P : \mathcal{S} \to \{\mathtt{true}, \mathtt{false}\}$ partitions $\mathcal{S}$ into two disjoint, exhaustive sets:

$$\mathcal{G} = \{s \in \mathcal{S} \mid P(s) = \mathtt{true}\}, \qquad \mathcal{B} = \mathcal{S} \setminus \mathcal{G}.$$

Elements of $\mathcal{G}$ are called **good states** (the system satisfies its invariant); elements of $\mathcal{B}$ are **bad states** (the invariant is violated). A finite trajectory $s_0, s_1, \ldots, s_n$ with $s_{k+1} = f(s_k)$ is *safe* if $s_k \in \mathcal{G}$ for every $k \in \{0, \ldots, n\}$ and *unsafe* otherwise. The step at which the trajectory first enters $\mathcal{B}$ is called the **failure index**:

$$\tau = \min\{k \ge 0 \mid s_k \in \mathcal{B}\}.$$

**Worked example.** Consider a discrete temperature controller whose state is an integer temperature $T \in \mathbb{Z}$. The transition rule is $f(T) = T + \delta$ where $\delta \in \{-1, 0, +1\}$ is a control signal. The safety invariant is $P(T) \equiv (20 \le T \le 80)$, so $\mathcal{G} = \{20, 21, \ldots, 80\}$ and $\mathcal{B} = \mathbb{Z} \setminus \mathcal{G}$. Starting at $T_0 = 78$ with $\delta = +1$ each step, the trajectory is $78, 79, 80, 81, \ldots$; the failure index is $\tau = 3$ because $T_3 = 81 \notin \mathcal{G}$.

**Key theorem (Invariant persistence).** Let $\mathcal{G}$ be *forward-closed* under $f$, meaning $s \in \mathcal{G} \Rightarrow f(s) \in \mathcal{G}$. Then any trajectory beginning in $\mathcal{G}$ remains in $\mathcal{G}$ for all future steps; equivalently, $\tau = \infty$. Forward-closure can be verified by checking that $f(\mathcal{G}) \subseteq \mathcal{G}$, which for finite state spaces reduces to a finite enumeration.

*Proof sketch.* By induction: $s_0 \in \mathcal{G}$ is given. If $s_k \in \mathcal{G}$, forward-closure gives $s_{k+1} = f(s_k) \in \mathcal{G}$. The claim follows by induction on $k$. $\blacksquare$

**Lab cell.**

```python
from sympy import symbols, And, Integer

T = symbols('T', integer=True)

def good_state(T_val, lo=20, hi=80):
    return lo <= T_val <= hi

trajectory = [78 + k for k in range(6)]  # delta = +1

for k, state in enumerate(trajectory):
    label = "GOOD" if good_state(state) else "BAD"
    print(f"k={k}  T={state}  [{label}]")

# Verify forward-closure for a shrinking control: delta in {-1, 0}
G = set(range(20, 81))
delta_set = {-1, 0}
forward_closed = all((s + d) in G for s in G for d in delta_set)
print("Forward-closed under {-1, 0}:", forward_closed)
```

## Game Tree Search

**Definition.** A *game tree* is a rooted directed acyclic graph $T = (V, E)$ in which each node $v \in V$ represents a game state, each edge $(v, u) \in E$ represents a legal move, and the root $r$ encodes the initial position. Nodes are partitioned into *MAX nodes* (whose active player seeks to maximise a utility) and *MIN nodes* (whose active player seeks to minimise it). Terminal nodes carry a real-valued *utility* $U(v) \in \mathbb{R}$. The *minimax value* of a node $v$ is defined recursively:

$$\text{minimax}(v) = \begin{cases} U(v) & \text{if } v \text{ is terminal,} \\ \max_{(v,u)\in E}\,\text{minimax}(u) & \text{if } v \text{ is a MAX node,} \\ \min_{(v,u)\in E}\,\text{minimax}(u) & \text{if } v \text{ is a MIN node.} \end{cases}$$

**Worked Example.** Consider a depth-2 game tree whose root is a MAX node with two children (MIN nodes). The left MIN node has leaf utilities $\{3, 5\}$; the right MIN node has leaf utilities $\{2, 9\}$. Applying the recurrence bottom-up: the left MIN node evaluates to $\min(3,5) = 3$; the right evaluates to $\min(2,9) = 2$. The root MAX node therefore evaluates to $\max(3,2) = 3$. The optimal strategy for MAX is to move left.

**Key Theorem (Alpha–Beta Pruning).** The minimax value of the root can be computed while safely ignoring subtrees that cannot influence the outcome. Maintain a window $[\alpha, \beta]$ where $\alpha$ is the best value MAX can already guarantee and $\beta$ is the best value MIN can already guarantee. Any node $v$ with value $v \leq \alpha$ under a MIN node, or $v \geq \beta$ under a MAX node, is *pruned*. In the best case (perfect move ordering), alpha–beta reduces the effective branching factor from $b$ to $\sqrt{b}$, halving the search depth achievable in a fixed time budget.

**Lab Cell.**

```python
from sympy import oo

def minimax(tree, node, is_max):
    children = tree.get(node, [])
    if not children:
        return tree[node]          # leaf utility stored directly
    vals = [minimax(tree, c, not is_max) for c in children]
    return max(vals) if is_max else min(vals)

# Encode the worked example: leaves store utilities, internal nodes store child lists
tree = {
    "root": ["L", "R"],
    "L": ["l1", "l2"],
    "R": ["r1", "r2"],
    "l1": 3, "l2": 5,
    "r1": 2, "r2": 9,
}

```
