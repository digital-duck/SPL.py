## Graph

A **graph** is a mathematical structure used to model relationships between objects. It consists of a set of **vertices** (also called nodes) and a set of **edges** that connect pairs of vertices. Formally, a graph $G = (V, E)$ where $V$ is the vertex set and $E \subseteq V \times V$ is the edge set. Edges can be **undirected** (a two-way connection, like a road between two cities) or **directed** (a one-way connection, like a hyperlink from one webpage to another). A graph can also carry **weights** on its edges — numerical values representing cost, distance, or capacity.

Graphs are the natural language for problems involving networks: social connections, routing, scheduling, and dependency resolution all reduce to graph problems.

**Worked example.** Consider a small network of five cities connected by roads:

```python
import networkx as nx

G = nx.Graph()
G.add_edges_from([
    ("A", "B", {"weight": 4}),
    ("A", "C", {"weight": 2}),
    ("B", "D", {"weight": 5}),
    ("C", "D", {"weight": 1}),
    ("D", "E", {"weight": 3}),
])
```

Here $|V| = 5$ and $|E| = 5$. The **degree** of a vertex is the number of edges incident to it; vertex D has degree 3 because it connects to B, C, and E. The **path** A → C → D has total weight $2 + 1 = 3$, which is shorter than A → B → D at weight $4 + 5 = 9$.

**Problem-solving application.** Graphs become powerful when you apply traversal and search algorithms to extract information. Suppose you want the shortest path from A to E in the weighted graph above. Dijkstra's algorithm explores vertices in order of cumulative distance and guarantees the optimal path:

```python
path = nx.dijkstra_path(G, "A", "E", weight="weight")
cost = nx.dijkstra_path_length(G, "A", "E", weight="weight")
print(path, cost)   # ['A', 'C', 'D', 'E']  6
```

The algorithm finds A → C → D → E with total weight 6, beating every alternative. This same pattern — model relationships as a graph, then query with a standard algorithm — solves problems ranging from GPS routing to compiler dependency checks to recommendation engines. Recognizing that a problem has graph structure is often the key insight; once you see it, a well-tested algorithm almost always exists.

### walk_trail_path_cycle (16.4s)

## Walk Trail Path Cycle

A **graph traversal** is any sequence of vertices connected by edges. Graph theory gives precise names to four increasingly restrictive kinds of traversals, and knowing the distinctions unlocks a wide range of routing and network problems.

A **walk** is the most general: a sequence of vertices $v_0, v_1, \ldots, v_k$ where each consecutive pair $(v_i, v_{i+1})$ is an edge. Vertices and edges may repeat freely. A **trail** tightens this by forbidding repeated *edges* — every edge appears at most once, but you may revisit a vertex. A **path** is stricter still: no repeated vertices (which automatically forbids repeated edges). A **cycle** is a closed path — a path that starts and ends at the same vertex, with no other repeated vertices.

Think of navigating a city. Walking the same street twice is allowed on a walk. An Euler trail (a famous special case) crosses every bridge exactly once — that is a trail. A path through a city visits each intersection at most once. A cycle brings you home without retracing your steps.

**Worked example.** Consider the graph with vertices $\{A, B, C, D\}$ and edges $\{AB, BC, CD, DA, AC\}$.

- Walk: $A \to B \to C \to A \to D$ — valid; edge $AC$ is unused but $A$ repeats, which is fine.
- Trail: $A \to B \to C \to D \to A \to C$ — each edge used at most once, but vertex $A$ repeats; still a trail.
- Path: $A \to B \to C \to D$ — no repeated vertices or edges.
- Cycle: $A \to B \to C \to D \to A$ — starts and ends at $A$, no interior vertex repeats.

**Problem-solving application.** Delivery routing problems often reduce to finding a trail or path. Suppose a postal worker must traverse every street (edge) in a neighborhood without retracing. That requires an **Eulerian trail** — a trail covering every edge exactly once. An Eulerian trail exists if and only if the graph has exactly zero or two vertices of odd degree (a result known as Euler's theorem). If two such vertices exist, start at one and end at the other. If zero exist, the trail is actually a closed **Eulerian circuit** (a special cycle).

To check in code:

```python
import networkx as nx
G = nx.Graph([(0,1),(1,2),(2,3),(3,0),(0,2)])
odd_degree = [v for v, d in G.degree() if d % 2 == 1]
print(len(odd_degree))  # 0 → Eulerian circuit; 2 → Eulerian trail
```

Distinguishing walk, trail, path, and cycle is the first step in any graph routing problem — the correct abstraction determines which algorithms apply.

### connectedness (14.8s)

## Connectedness

A graph is **connected** if there is a path between every pair of vertices — you can travel from any node to any other node by following edges. If even one pair of vertices has no path between them, the graph is **disconnected**, and it breaks into two or more **connected components**: maximal subgraphs that are themselves connected internally but share no edges with each other.

Connectedness is one of the first structural questions you ask about any network: can every city be reached from every other city? Can every computer in a network communicate with every other? If the answer is no, the graph's components reveal natural fault lines in the system.

**Worked example.** Consider a graph with six vertices $\{A, B, C, D, E, F\}$ and edges $\{AB, BC, AC, DE\}$. Starting from $A$, you can reach $B$ via edge $AB$, and $C$ via edge $AC$ or the path $A \to B \to C$. But there is no path from $A$ to $D$, $E$, or $F$. Running a depth-first search (DFS) from $A$ visits $\{A, B, C\}$ and then stops — it never reaches the rest. Restarting DFS from $D$ visits $\{D, E\}$, and a final restart from $F$ visits $\{F\}$ alone. The graph has three connected components: $\{A, B, C\}$, $\{D, E\}$, and $\{F\}$.

**Problem-solving application.** To find all connected components in code, run a DFS or BFS from each unvisited vertex and label every vertex you reach with the same component ID. The number of times you restart the search equals the number of components.

```python
def connected_components(graph):
    visited = {}
    component_id = 0
    for node in graph:
        if node not in visited:
            stack = [node]
            while stack:
                v = stack.pop()
                if v not in visited:
                    visited[v] = component_id
                    stack.extend(graph[v])
            component_id += 1
    return visited
```

This runs in $O(V + E)$ time, where $V$ is the number of vertices and $E$ the number of edges — you visit each vertex and edge at most once. A practical check: if the returned dictionary maps every vertex to the same component ID, the graph is connected. Connectedness also determines whether algorithms like Dijkstra's shortest path will reach all nodes from a given source — if the graph is disconnected, you must run the algorithm once per component.

### vertex_degree (15.2s)

## Vertex Degree

The **degree** of a vertex in a graph is the number of edges directly connected to it. If vertex $v$ has degree $k$, written $\deg(v) = k$, then exactly $k$ edges touch $v$. A vertex with degree 0 is called **isolated** — it has no neighbors. A vertex with degree 1 is a **leaf**, common in tree structures. In directed graphs the concept splits into **in-degree** (edges arriving) and **out-degree** (edges leaving), but for undirected graphs a single degree value suffices.

One foundational fact connects vertex degrees to the total number of edges. If a graph $G$ has $n$ vertices and $m$ edges, then

$$\sum_{v \in G} \deg(v) = 2m$$

because every edge contributes exactly 1 to the degree of each of its two endpoints, so the sum double-counts every edge. An immediate corollary: the number of vertices with odd degree is always even.

**Worked example.** Consider a social network with five people — Alice, Bob, Carlos, Dana, and Eve — where friendships form the edges: Alice–Bob, Alice–Carlos, Bob–Dana, Carlos–Dana, Dana–Eve. Listing degrees: $\deg(\text{Alice}) = 2$, $\deg(\text{Bob}) = 2$, $\deg(\text{Carlos}) = 2$, $\deg(\text{Dana}) = 3$, $\deg(\text{Eve}) = 1$. The sum is $2+2+2+3+1 = 10 = 2 \times 5$, confirming the handshaking identity with $m = 5$ edges. Dana is the most connected person; Eve is a leaf.

**Problem-solving application.** Degree sequences are a quick sanity check when building or validating graph data. Suppose you're given a claimed degree sequence $[3, 3, 2, 2, 1, 1]$ and asked whether a valid simple graph exists. First, sum the degrees: $3+3+2+2+1+1 = 12$, which is even, so the handshaking identity is not violated — a necessary condition. The Erdős–Gallai theorem gives a complete test, but for small cases you can often construct the graph directly: pair the two degree-3 vertices together and with two degree-2 vertices, then attach the degree-1 vertices. If construction succeeds, the sequence is **graphical**. In code or algorithm design, computing degree for every vertex takes $O(m)$ time (one pass over the edge list), making it one of the cheapest structural features to extract — and often the first one queried when profiling network connectivity or detecting hub nodes in scale-free graphs.

### vertex_edge_cut (18.2s)

## Vertex Edge Cut

**Definition.** A *vertex cut* of a connected graph $G$ is a set of vertices $S \subseteq V(G)$ whose removal leaves the remaining graph disconnected (or trivially a single node). The minimum such set has size $\kappa(G)$, called the *vertex connectivity* of $G$. Analogously, an *edge cut* is a set of edges $F \subseteq E(G)$ whose removal disconnects $G$; the smallest edge cut has size $\lambda(G)$, the *edge connectivity*. These two numbers measure how robust a network is against targeted failures: vertex cuts model node failures (a router going offline), while edge cuts model link failures (a cable being severed).

A classical inequality ties everything together: for any connected graph,

$$\kappa(G) \leq \lambda(G) \leq \delta(G)$$

where $\delta(G)$ is the minimum degree. Intuitively, you can always disconnect a graph by cutting all edges incident to the lowest-degree vertex, and you can often do at least as well by removing vertices instead.

**Worked example.** Consider a ring network of six nodes — a cycle $C_6$. Every vertex has degree 2, so $\delta = 2$. To disconnect the ring by removing edges, you need to cut at least 2 edges (snip two links and you isolate a segment), so $\lambda(C_6) = 2$. To disconnect it by removing vertices, removing any single vertex leaves a path, which is still connected; you must remove 2 vertices to break it into two components. Thus $\kappa(C_6) = 2$, and the inequality $2 \leq 2 \leq 2$ holds with equality.

**Problem-solving application.** Suppose you are designing a data-center network and need to guarantee that the network stays connected even if any two switches fail simultaneously. Your target is $\kappa(G) \geq 3$. One practical test: for each vertex $v$, use a max-flow algorithm on an auxiliary graph where each original vertex $u \neq v$ is split into $u_{\text{in}} \to u_{\text{out}}$ with capacity 1, and each edge $(u,w)$ becomes $u_{\text{out}} \to w_{\text{in}}$ with infinite capacity. The max flow from $v_{\text{out}}$ to any other sink equals the number of vertex-disjoint paths, and the minimum over all source–sink pairs gives $\kappa(G)$. If the result is below 3, you identify the bottleneck cut directly from the min-cut side of the flow partition, and add redundant links or switches there — a concrete, algorithmic path from definition to engineering decision.

### connectivity_numbers (17.9s)

## Connectivity Numbers

A graph can be disconnected by removing vertices, edges, or both — but some graphs require far more removals than others before they fall apart. **Connectivity numbers** quantify exactly how robust a graph is to this kind of disruption.

There are two flavors. The **vertex connectivity** $\kappa(G)$ is the minimum number of vertices whose removal either disconnects $G$ or reduces it to a single vertex. The **edge connectivity** $\lambda(G)$ is the minimum number of edges whose removal disconnects $G$. A graph with $\kappa(G) = k$ is called **$k$-connected**: you must delete at least $k$ vertices to break it apart. These two numbers obey a clean inequality involving the minimum degree $\delta(G)$ (the smallest number of edges incident to any vertex):

$$\kappa(G) \;\leq\; \lambda(G) \;\leq\; \delta(G).$$

Vertex connectivity is hardest to achieve (you have to knock out nodes and all their edges), so it is always the smallest of the three values.

**Worked example.** Consider a cycle graph $C_5$ (five vertices arranged in a pentagon). Every vertex has degree 2, so $\delta(C_5) = 2$. Removing any single vertex leaves a path, which is still connected — but removing any two adjacent vertices disconnects the remaining three nodes into two components. So $\kappa(C_5) = 2$. Similarly, you need to cut two edges to disconnect a cycle, giving $\lambda(C_5) = 2$. The inequality holds: $2 \leq 2 \leq 2$.

**Problem-solving application.** Connectivity numbers appear directly in network reliability problems. Suppose a city's fiber network is modeled as a graph where vertices are switching stations and edges are cable runs. If the graph has $\kappa(G) = 1$, there exists a single station (called a **cut vertex**) whose failure isolates part of the city — a critical vulnerability. An engineer tasked with hardening the network can compute $\kappa(G)$ using max-flow algorithms (via Menger's theorem, which equates $\kappa$ to the maximum number of internally vertex-disjoint paths) and then add redundant links only where the connectivity is lowest, rather than upgrading the entire network.

To find $\lambda(G)$ in code, model each undirected edge as two directed edges with unit capacity and run a max-flow from any source to any sink; the minimum cut value equals $\lambda(G)$. Tools like NetworkX expose this directly:

```python
import networkx as nx
G = nx.cycle_graph(5)
print(nx.edge_connectivity(G))   # 2
print(nx.node_connectivity(G))   # 2
```

Interpreting these numbers — not just computing them — is the practical skill: low connectivity flags single points of failure; high connectivity signals a resilient design worth the extra infrastructure cost.

## Harary Graph

A network is **$k$-connected** if it stays connected even after removing any $k - 1$ vertices (and all edges touching them). Higher connectivity means greater fault tolerance — a $k$-connected network can survive $k - 1$ simultaneous node failures. The natural engineering question is: *what is the fewest edges needed to guarantee $k$-connectivity on $n$ vertices?* The **Harary graph** $H(k, n)$ answers that question exactly. It is the unique (up to isomorphism) graph on $n$ vertices that is $k$-connected while using the minimum number of edges, $\lceil kn/2 \rceil$.

**Construction.** Label vertices $0, 1, \ldots, n-1$ arranged in a circle. Connect each vertex $i$ to the $\lfloor k/2 \rfloor$ nearest vertices on each side. This alone gives $(k - 1)$-connectivity or $k$-connectivity depending on parity. Two adjustment rules close the gap:

- If $k$ is odd and $n$ is even, additionally connect each vertex $i$ to the vertex directly opposite, $i + n/2 \pmod{n}$.
- If $k$ is odd and $n$ is odd, connect vertex $i$ to $i + (n-1)/2$ and $i + (n+1)/2$ (mod $n$) for $i = 0, \ldots, (n-1)/2$.

**Worked example.** Build $H(3, 6)$: six vertices, target 3-connectivity, minimum edges. Since $k = 3$ (odd) and $n = 6$ (even), connect each vertex to the 1 nearest on each side (covering $k - 1 = 2$ directions) plus add the antipodal edges. Vertex 0 connects to 1, 5 (neighbors), and 3 (opposite). Repeating for all vertices gives 9 edges total, matching $\lceil 3 \cdot 6/2 \rceil = 9$. Removing any two vertices leaves the remaining four still connected — verify by trying the worst case: remove two adjacent vertices and confirm the remaining path closes through the antipodal edges.

**Problem-solving application.** Harary graphs appear whenever you need to design a network with a specified fault tolerance at minimum cost — fiber routes, chip interconnects, or distributed system topologies. Given a budget of $m$ edges and $n$ nodes, compute $k = \lfloor 2m/n \rfloor$ and use $H(k, n)$ as the target topology; any design achieving fewer edges for the same $k$ would contradict the minimality theorem. In NetworkX, `nx.harary_graph(k, n)` generates the graph directly, letting you verify connectivity with `nx.node_connectivity(G)` and compare edge counts against alternative topologies before committing to a physical layout.
