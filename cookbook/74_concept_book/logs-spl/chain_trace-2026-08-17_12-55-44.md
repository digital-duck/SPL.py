## Vertex Degree

The **degree** of a vertex in a graph is the number of edges directly connected to it. If vertex $v$ has degree $k$, written $\deg(v) = k$, then exactly $k$ edges touch $v$. A vertex with degree 0 is called **isolated** — it has no neighbors. A vertex with degree 1 is a **leaf**, common in tree structures. In directed graphs the concept splits into **in-degree** (edges arriving) and **out-degree** (edges leaving), but for undirected graphs a single degree value suffices.

One foundational fact connects vertex degrees to the total number of edges. If a graph $G$ has $n$ vertices and $m$ edges, then

$$\sum_{v \in G} \deg(v) = 2m$$

because every edge contributes exactly 1 to the degree of each of its two endpoints, so the sum double-counts every edge. An immediate corollary: the number of vertices with odd degree is always even.

**Worked example.** Consider a social network with five people — Alice, Bob, Carlos, Dana, and Eve — where friendships form the edges: Alice–Bob, Alice–Carlos, Bob–Dana, Carlos–Dana, Dana–Eve. Listing degrees: $\deg(\text{Alice}) = 2$, $\deg(\text{Bob}) = 2$, $\deg(\text{Carlos}) = 2$, $\deg(\text{Dana}) = 3$, $\deg(\text{Eve}) = 1$. The sum is $2+2+2+3+1 = 10 = 2 \times 5$, confirming the handshaking identity with $m = 5$ edges. Dana is the most connected person; Eve is a leaf.

**Problem-solving application.** Degree sequences are a quick sanity check when building or validating graph data. Suppose you're given a claimed degree sequence $[3, 3, 2, 2, 1, 1]$ and asked whether a valid simple graph exists. First, sum the degrees: $3+3+2+2+1+1 = 12$, which is even, so the handshaking identity is not violated — a necessary condition. The Erdős–Gallai theorem gives a complete test, but for small cases you can often construct the graph directly: pair the two degree-3 vertices together and with two degree-2 vertices, then attach the degree-1 vertices. If construction succeeds, the sequence is **graphical**. In code or algorithm design, computing degree for every vertex takes $O(m)$ time (one pass over the edge list), making it one of the cheapest structural features to extract — and often the first one queried when profiling network connectivity or detecting hub nodes in scale-free graphs.

### degree_distribution (15.1s)

## Degree Distribution

In any network, every node has a **degree** — the number of edges connected to it. A social media user with 500 followers has degree 500; a router connected to three other routers has degree 3. The **degree distribution** of a network is the probability distribution $P(k)$, which gives the fraction of nodes that have exactly $k$ edges. It is one of the most informative single statistics you can extract from a graph, because it reveals the underlying architecture of how connections form.

To compute it, count how many nodes have each degree, then divide by the total number of nodes $N$:

$$P(k) = \frac{\text{number of nodes with degree } k}{N}$$

**Worked example.** Suppose a small network has 10 nodes with degrees: 1, 2, 2, 3, 3, 3, 4, 4, 5, 7. Count the occurrences:

| $k$ | Count | $P(k)$ |
|-----|-------|--------|
| 1   | 1     | 0.10   |
| 2   | 2     | 0.20   |
| 3   | 3     | 0.30   |
| 4   | 2     | 0.20   |
| 5   | 1     | 0.10   |
| 7   | 1     | 0.10   |

The distribution sums to 1. The mean degree is $\langle k \rangle = \frac{1}{N}\sum_i k_i = \frac{1+2+2+3+3+3+4+4+5+7}{10} = 3.4$.

**Why it matters for problem-solving.** The shape of $P(k)$ distinguishes fundamentally different network types. A random (Erdős–Rényi) graph produces a bell-shaped, Poisson-like distribution centered near $\langle k \rangle$ — most nodes have roughly the same number of connections. Real-world networks like the internet, citation graphs, and follower graphs instead follow a **power law**: $P(k) \propto k^{-\gamma}$, which appears as a straight line on a log-log plot. These are called **scale-free networks**. A handful of nodes (hubs) accumulate enormous degree while the vast majority have very few connections.

This distinction has practical consequences. In a scale-free network, removing nodes at random rarely disrupts the network because most nodes are low-degree. But targeted removal of the top hubs (highest-degree nodes) can fragment the entire network rapidly — a fact exploited in both cybersecurity (attacking infrastructure) and epidemiology (vaccinating superspreaders). Computing and plotting the degree distribution is therefore the first diagnostic step when analyzing any real network.

## Hub Identification

In any network — social, biological, transportation, or computational — a **hub** is a node with disproportionately many connections compared to the average. Hub identification is the process of algorithmically locating these high-influence nodes so that you can reason about them: who spreads information fastest, which protein disrupts a cell if removed, which airport grounds the most flights if it closes.

The core measure is **degree centrality**: for a node $v$ in an undirected graph $G = (V, E)$, its degree $\deg(v)$ is the count of edges incident to it. Normalized degree centrality is

$$C_D(v) = \frac{\deg(v)}{|V| - 1}$$

which scales the raw degree to $[0, 1]$ relative to the maximum possible connections. High $C_D$ flags a hub. For directed graphs (like Twitter follows), you track in-degree and out-degree separately, since a node that many people follow (high in-degree) plays a different role than one that follows many others.

**Worked example.** Consider a small network of seven research labs where edges represent active collaborations. Lab A collaborates with five others; Labs B through F each collaborate with two or three peers; Lab G collaborates only with A. Computing $C_D$ for each node immediately singles out Lab A ($C_D = 5/6 \approx 0.83$) as the hub. If Lab A's funding were cut, the network fragments — a finding that raw counts alone confirm, but that the normalized score makes comparable across networks of different sizes.

**Problem-solving application.** Suppose you are analyzing a supply-chain graph to identify single points of failure. You would load the graph, compute degree centrality for every supplier node, then sort and threshold:

```python
import networkx as nx

G = nx.read_edgelist("supply_chain.csv", delimiter=",")
centrality = nx.degree_centrality(G)
hubs = {node: score for node, score in centrality.items() if score > 0.3}
print(sorted(hubs.items(), key=lambda x: x[1], reverse=True))
```

Nodes above your threshold are hub candidates. From there you can run targeted what-if simulations: remove each hub and recompute the number of connected components. A hub whose removal splits the graph into two or more components is not just influential — it is a **cut vertex**, the highest-priority resilience risk.

Degree centrality is fast ($O(|V|)$) and intuitive, but it only counts direct neighbors. For networks where influence travels through intermediaries, you would complement it with betweenness or eigenvector centrality — but degree centrality remains the right first pass for identifying structural hubs quickly.
