## Http

超文本传输协议（HTTP）是万维网客户端与服务器之间请求和获取网页资源所使用的标准通信协议。HTTP 属于应用层协议，运行在传输控制协议（TCP）之上，采用请求—响应模型：客户端（通常是浏览器）向服务器发送一条请求消息，服务器处理后返回一条响应消息。每条 HTTP 消息都由三部分组成——起始行、若干头部字段、以及可选的消息体。请求的起始行包含方法（如 GET、POST、PUT、DELETE）、目标资源的路径以及协议版本；响应的起始行则包含协议版本、三位数的状态码和简短的状态说明（例如 200 表示成功，404 表示资源未找到，500 表示服务器内部错误）。

举一个具体场景：当用户在浏览器地址栏输入一个网址并按下回车，浏览器首先通过域名系统（DNS）将域名解析为服务器的 IP 地址，然后与该服务器建立 TCP 连接。连接建立后，浏览器发出一条类似如下的请求：

```
GET /index.html HTTP/1.1
Host: www.example.com
```

服务器收到请求后，在自己的文件系统或应用逻辑中定位对应资源，并返回响应：

```
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1256

<html>...</html>
```

浏览器解析响应体中的 HTML 内容，并渲染成用户看到的页面；如果页面中还引用了图片、样式表或脚本文件，浏览器会针对每个引用发出新的请求，重复上述过程。

理解 HTTP 的关键在于认识到它是无状态协议：服务器不会在两次独立请求之间保留关于客户端的记忆。这意味着，如果网站需要记住用户的登录状态或购物车内容，就必须借助额外机制，例如在响应头中设置 Cookie，客户端在后续每次请求时自动携带该 Cookie 头部，从而让服务器识别出这是同一用户的连续会话。这一无状态设计是刻意的工程选择：它简化了服务器的实现，使得单台服务器可以并行处理海量互不相关的请求，也是万维网能够大规模扩展的原因之一。在实际开发中，理解请求方法的语义差异（GET 用于获取数据且不应产生副作用，POST 用于提交并可能修改服务器状态）以及正确解读状态码，是调试网络应用、设计 REST 接口时必须掌握的基本功。

### url (17.3s)

## Url

**定义**

统一资源定位符(URL, Uniform Resource Locator)是用于在超链接中标识并定位网络服务器上某一文档或资源的引用字符串。一个URL本质上回答了三个问题:使用什么协议访问资源、资源存放在哪一台服务器上、资源在该服务器上的具体路径是什么。一个完整的URL通常遵循固定的结构:

$$
\text{协议}://\text{主机名}[:\text{端口}]/\text{路径}[?\text{查询参数}][\#\text{片段标识符}]
$$

其中协议(如 `http`、`https`、`ftp`)规定了客户端与服务器之间的通信规则;主机名(如 `www.example.com`)通过域名系统(DNS)被解析为服务器的IP地址;路径指向服务器文件系统或应用程序中的具体资源;查询参数以键值对形式向服务器传递额外信息;片段标识符则指向文档内部的某个锚点,仅由浏览器本地处理,不会被发送到服务器。

**实例解析**

以URL `https://www.library.edu/search?query=数据结构&page=2#results` 为例:`https` 表示使用加密的超文本传输协议;`www.library.edu` 是服务器的域名;`/search` 是服务器上处理搜索请求的程序路径;`?query=数据结构&page=2` 是查询字符串,告诉服务器搜索关键词为"数据结构"且请求第2页结果;`#results` 则指示浏览器在页面加载后自动滚动到标识为"results"的区域。可以看到,同一个URL中不同部分承担着完全不同的职责,缺一不可。

**问题解决应用**

理解URL结构使我们能够诊断网络请求中的常见问题。例如,当一个链接指向 `http://example.com//images/photo.jpg` 时出现404错误,排查思路应是检查路径中多余的斜杠是否被服务器错误解析。又如,在设计一个网页表单时,若需要将用户输入的空格、中文字符或特殊符号(如 `&`、`=`)传递给服务器,必须先对这些字符进行百分号编码(percent-encoding),否则它们会被误判为URL结构中的分隔符,导致查询参数解析错误——这正是为什么"数据结构"在实际网络请求中会显示为 `%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84`。掌握URL的分层结构,是排查网络请求错误、设计安全的Web接口、以及理解浏览器地址栏行为的基础技能。

### world_wide_web (17.4s)

## 万维网

万维网（World Wide Web，简称 Web）是建立在互联网之上的一个分布式信息系统：网页之间通过超链接相互连接,用户可以从一个文档跳转到另一个文档,而不必关心这些文档实际存放在世界上的哪台服务器上。需要区分两个常被混用的概念:互联网是全球计算机通过网络协议互联形成的物理与逻辑基础设施,而万维网是运行在这套基础设施之上的一种应用——除了万维网,互联网上还承载着电子邮件、文件传输等其他应用。万维网由三项核心技术支撑:统一资源定位符,用来唯一标识每一份网络资源;超文本传输协议,规定浏览器与服务器之间如何请求和传送数据;超文本标记语言,规定网页内容与超链接如何被描述和呈现。

举一个具体的例子来说明信息是如何被组织和获取的。假设一名学生在浏览器地址栏输入一个网址,例如 `https://www.example.com/articles/physics.html`。浏览器首先通过域名系统查询,把域名解析为对应服务器的网络地址；随后浏览器使用超文本传输协议向该服务器发出请求,请求方法通常是 GET,表示"取回这份资源"；服务器接收到请求后,返回一份用超文本标记语言编写的网页文档,其中包含文字、图片链接以及若干指向其他网页的超链接。浏览器解析这份文档并渲染成学生看到的页面。如果学生点击页面中的某个超链接,浏览器便会重复上述过程,向新的地址发出请求——这正是"网"这一名字的来源:成千上万个页面通过超链接彼此指向,构成一张巨大的、无中心的连接网络。

从信息系统设计的角度看,万维网的关键创新在于它是无状态、分布式且开放的:任何人都可以在自己的服务器上发布页面,不需要经过中央机构审批或注册,只要该页面能够被域名系统和超链接体系找到,就自动成为这张网络的一部分。这种开放性也带来了实际问题,例如如何在数以百亿计的页面中找到相关信息——这正是搜索引擎需要解决的问题,它们通过预先抓取并索引网页内容,让用户能够根据关键词而不是确切网址来定位资源。理解客户端发出请求、服务器返回响应这一基本交互模式,是进一步学习网页开发、网络安全或数据爬取等实践技能的基础。

## Web Graph

**定义**

网页图（Web Graph）是对万维网结构的一种有向图表示：每个顶点代表一个网页，每条有向弧 $(u, v)$ 代表页面 $u$ 中存在一个指向页面 $v$ 的超链接。设 $G = (V, E)$，其中 $V$ 是网页集合，$E \subseteq V \times V$ 是超链接的集合。由于超链接是单向的——$u$ 指向 $v$ 并不意味着 $v$ 也指向 $u$——网页图必须是有向图，而不能用无向图建模。这一结构是搜索引擎排名算法（如网页排名算法）的基础：一个页面的重要性不仅取决于有多少页面链接到它（入度），还取决于链接来源页面本身的重要性。

**实例分析**

考虑一个只有四个页面的小型网络：A、B、C、D。假设链接关系为：A→B，A→C，B→C，C→A，D→C。用图表示，顶点集为 $V = \{A, B, C, D\}$，弧集为 $E = \{(A,B), (A,C), (B,C), (C,A), (D,C)\}$。若要用矩阵刻画这个结构，可以构造邻接矩阵 $M$，其中 $M_{ij} = 1$ 表示第 $i$ 个页面指向第 $j$ 个页面，否则为 $0$：

$$
M = \begin{pmatrix}
0 & 1 & 1 & 0 \\
0 & 0 & 1 & 0 \\
1 & 0 & 0 & 0 \\
0 & 0 & 1 & 0
\end{pmatrix}
$$

观察这个矩阵可以发现：页面 C 的入度最高（被 A、B、D 三个页面指向），直觉上应比 D 更重要，因为 D 只被零个页面链接。而这正是入度中心性（in-degree centrality）这一简单排名思路的直观体现——但它忽略了链接来源本身的权威性，这也是后续更精细算法（如网页排名算法）要解决的问题。

**解题应用**

利用网页图分析网络结构时，一类常见的问题是判断信息或影响力能否从一个页面传播到另一个页面，这本质上是有向图中的可达性问题：从顶点 $u$ 沿有向弧序列能否到达顶点 $v$。在上例中，从 D 出发只能到达 C，再从 C 到达 A，再到 B——因此 D 可以到达网络中所有其他页面，但没有任何页面能到达 D（D 的入度为零，是一个"孤岛"入口）。这类可达性分析可以用深度优先搜索或广度优先搜索在 $O(|V| + |E|)$ 时间内完成，是判断网络连通性、寻找孤立页面或检测链接闭环（如 A→C→A）的标准手段。识别这类结构对于优化网站内部链接策略、避免死链陷阱, 都具有实际意义。

## Bowtie Structure

**定义**：蝴蝶结结构是对万维网有向图进行宏观分类的模型，其分类依据完全建立在有向可达性之上，而非页面内容或链接权重。给定有向图 $G=(V,E)$，定义两点 $u,v$ 之间的强连通关系：$u \sim v$ 当且仅当存在从 $u$ 到 $v$ 的有向路径，且同时存在从 $v$ 到 $u$ 的有向路径。可以证明 $\sim$ 是一个等价关系（自反、对称、传递），因此它把 $V$ 划分成若干等价类，每一类称为一个强连通分量（SCC）。万维网中最大的那个强连通分量记为核心 SCC，其余节点按照它们与该核心的可达关系分为四类：能到达 SCC 但不能被 SCC 到达的节点集合称为 IN；能被 SCC 到达但不能到达 SCC 的节点集合称为 OUT；既不能到达也不能被 SCC 到达、但通过 IN 或 OUT 间接相连的节点称为触须（tendrils）或管道（tubes，即连接 IN 与 OUT 但绕开 SCC 的路径）；完全没有路径连到上述任何部分的节点则构成孤立分量。

**实例分析**：2000 年 Broder 等人对约 2 亿个网页组成的爬取图进行了这一分类，发现四个主要部分（SCC、IN、OUT、触须与孤立部分）的规模大致相当，各占总节点数的四分之一左右；而且 SCC 内部任意两点间的平均最短路径长度约为 16，若允许无向穿行（忽略链接方向）则图的直径可达 28。这一结果表明，"网页之间高度互联"的直觉只对核心 SCC 成立，IN 和 OUT 部分的存在说明网络导航存在明显的方向性瓶颈。

**问题求解应用**：判断一个给定节点属于蝴蝶结的哪一部分，标准算法分两步。第一步用 Tarjan 算法或 Kosaraju 算法在线性时间 $O(|V|+|E|)$ 内求出所有强连通分量，取规模最大者为核心 SCC。第二步从 SCC 任选一点分别做正向广度优先搜索（沿边方向）与反向广度优先搜索（逆边方向）：正向可达且不在 SCC 中的节点归入 OUT，反向可达且不在 SCC 中的节点归入 IN；既非正向也非反向可达、但与 IN 或 OUT 存在路径连接的节点归入触须或管道，其余归为孤立分量。这一分类过程本质上是对可达性关系的两次遍历，是分析大规模有向图连通结构的通用方法，也应用于社交网络、引用网络等其他有向图的宏观结构分析。
