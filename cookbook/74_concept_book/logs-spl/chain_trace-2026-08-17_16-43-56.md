## 图（Graph）

**定义**

图是一种描述对象之间关系的数学结构，由两个要素组成：**顶点集合** $V$（也称节点）和**边集合** $E$。每条边连接一对顶点，表示它们之间存在某种关联。形式上，一个图记作 $G = (V, E)$。若边有方向（从 $u$ 指向 $v$），称为**有向图**；若无方向，称为**无向图**。边还可以带有权重，例如道路的距离或网络的带宽，称为**加权图**。

图的威力在于它的普适性——地图、社交网络、任务依赖关系、分子结构，都可以抽象成图来分析。

**具体示例**

考虑一个城市地铁网络：4个站点 $A, B, C, D$，以及以下连接：$A$–$B$，$A$–$C$，$B$–$D$，$C$–$D$。

用邻接表表示如下：

```python
graph = {
    'A': ['B', 'C'],
    'B': ['A', 'D'],
    'C': ['A', 'D'],
    'D': ['B', 'C']
}
```

**问题**：从 $A$ 出发，能否到达 $D$？若能，最短路径经过几条边？

使用**广度优先搜索（BFS）**：

```python
from collections import deque

def bfs_shortest_path(graph, start, goal):
    queue = deque([[start]])
    visited = set([start])
    while queue:
        path = queue.popleft()
        node = path[-1]
        if node == goal:
            return path
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(path + [neighbor])
    return None

print(bfs_shortest_path(graph, 'A', 'D'))
# 输出：['A', 'B', 'D'] 或 ['A', 'C', 'D']，长度为 2 条边
```

**解题应用**

面对图类问题，关键是先明确三个要素：**顶点是什么、边代表什么关系、是否有向或加权**。确定后再选择算法：无权最短路径用 BFS；加权最短路径用 Dijkstra 算法；检测环路或拓扑排序用深度优先搜索（DFS）。

例如，分析项目任务的依赖关系时，每个任务是顶点，"任务 $A$ 必须在 $B$ 之前完成"是有向边。若图中存在环，则说明依赖关系形成了死锁，项目无法完成。此时 DFS 可在 $O(V + E)$ 时间内检测出环。

图将复杂的现实问题化为结构清晰的计算问题，是算法与数据结构中最具表达力的工具之一。

## Graph Representation

**定义**

图（graph）是一种用于描述"对象之间关系"的数学结构。一个图 $G = (V, E)$ 由两部分组成：顶点集合 $V$（代表对象）和边集合 $E$（代表关系）。每条边连接 $V$ 中的两个顶点。若边有方向（如"A 关注 B"不等于"B 关注 A"），称为**有向图**；若边无方向（如"A 与 B 是朋友"），称为**无向图**。

在实际编程中，图有两种主流表示方式：**邻接矩阵**（adjacency matrix）和**邻接表**（adjacency list）。

- **邻接矩阵**：用一个 $|V| \times |V|$ 的矩阵 $A$ 表示，若顶点 $i$ 与顶点 $j$ 之间有边，则 $A[i][j] = 1$，否则为 $0$。查询任意一对顶点是否相连只需 $O(1)$ 时间，但空间占用为 $O(|V|^2)$，对稀疏图浪费严重。
- **邻接表**：用字典或列表存储每个顶点的邻居集合。空间占用为 $O(|V| + |E|)$，更适合边数远少于 $|V|^2$ 的真实网络。

**例题**

考虑一个有 4 个城市的航线网络：北京 → 上海、北京 → 成都、上海 → 广州。用邻接表表示如下：

```python
graph = {
    "北京": ["上海", "成都"],
    "上海": ["广州"],
    "成都": [],
    "广州": []
}
```

若改用邻接矩阵，则需要一个 $4 \times 4$ 的矩阵，其中大部分元素为 $0$——对只有 3 条边的网络而言，这显然是一种浪费。

**问题求解应用**

选择哪种表示方式，取决于你要解决的问题。若需要频繁判断"顶点 $i$ 和顶点 $j$ 是否直接相连"，邻接矩阵更高效；若需要遍历某个顶点的所有邻居（如广度优先搜索、深度优先搜索），邻接表更自然。

以"找出所有能从北京出发到达的城市"为例，使用邻接表进行 BFS：

```python
from collections import deque

def reachable(graph, start):
    visited, queue = set(), deque([start])
    while queue:
        node = queue.popleft()
        if node not in visited:
            visited.add(node)
            queue.extend(graph.get(node, []))
    return visited
```

调用 `reachable(graph, "北京")` 返回 `{'北京', '上海', '成都', '广州'}`。理解图的底层表示结构，是正确实现图算法的第一步。
