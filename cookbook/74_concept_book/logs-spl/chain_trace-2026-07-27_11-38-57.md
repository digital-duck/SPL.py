### coin_toss_randomization (16.8s)

## Coin Toss Randomization

**Definition.** A *coin toss* is a Bernoulli trial: a random experiment with exactly two mutually exclusive outcomes, conventionally labeled *heads* (H) and *tails* (T). For a fair coin, each outcome occurs with probability $\frac{1}{2}$. More generally, a *biased* coin assigns probability $p \in (0,1)$ to heads and $q = 1 - p$ to tails. The corresponding random variable $X$ satisfies

$$X = \begin{cases} 1 & \text{with probability } p, \\ 0 & \text{with probability } 1 - p, \end{cases}$$

with expectation $\mathbb{E}[X] = p$ and variance $\operatorname{Var}(X) = p(1-p)$.

Coin toss randomization serves as the primitive building block for a wide class of randomized algorithms, Monte Carlo simulations, and cryptographic protocols. The key utility is *independence*: successive tosses of a fair coin yield an independent and identically distributed (i.i.d.) sequence, making probabilistic analysis tractable.

**Worked Example.** Suppose an algorithm must randomly assign $n = 100$ tasks to one of two processors with equal probability. Model each assignment as an independent fair coin toss. Let $S_n = \sum_{i=1}^{n} X_i$ count the tasks assigned to Processor A. Then $S_n \sim \operatorname{Binomial}(100, 0.5)$, with

$$\mathbb{E}[S_n] = np = 50, \qquad \operatorname{Var}(S_n) = np(1-p) = 25, \qquad \sigma_{S_n} = 5.$$

By the Central Limit Theorem, $S_n$ is approximately $\mathcal{N}(50, 25)$ for large $n$. The probability that Processor A receives more than 60 tasks is

$$P(S_n > 60) \approx P\!\left(Z > \frac{60 - 50}{5}\right) = P(Z > 2) \approx 0.0228.$$

**Theorem (Law of Large Numbers).** Let $X_1, X_2, \ldots$ be i.i.d. Bernoulli$(p)$ random variables and $\bar{X}_n = \frac{1}{n}\sum_{i=1}^n X_i$. Then

$$\bar{X}_n \xrightarrow{P} p \quad \text{as } n \to \infty.$$

This guarantees that empirical frequencies converge to true probabilities, validating Monte Carlo estimates derived from repeated coin tosses.

### node_height (15.8s)

## Node Height

**Definition.** Let $T$ be a rooted tree with root $r$. The *height* of a node $v \in T$, denoted $h(v)$, is the length of the longest downward path from $v$ to any leaf in the subtree rooted at $v$. Formally,

$$
h(v) =
\begin{cases}
0 & \text{if } v \text{ is a leaf,} \\
1 + \max_{c \in \text{children}(v)} h(c) & \text{otherwise.}
\end{cases}
$$

The height of the tree itself is defined as $h(r)$. Note the distinction from *depth*: the depth of a node measures its distance from the root, whereas the height measures its distance to the farthest descendant.

**Worked Example.** Consider the following rooted binary tree:

```
        A
       / \
      B   C
     / \
    D   E
```

Node $D$ and $E$ are leaves, so $h(D) = h(E) = 0$. Node $C$ is also a leaf, giving $h(C) = 0$. Node $B$ has children $D$ and $E$, so

$$h(B) = 1 + \max(h(D),\, h(E)) = 1 + \max(0, 0) = 1.$$

Finally, node $A$ has children $B$ and $C$:

$$h(A) = 1 + \max(h(B),\, h(C)) = 1 + \max(1, 0) = 2.$$

The height of the tree is therefore $2$.

**Key Theorem.** *For a complete binary tree with $n$ nodes, the height of the root satisfies*

$$h(r) = \lfloor \log_2 n \rfloor.$$

*Proof sketch.* A complete binary tree of height $k$ contains between $2^k$ and $2^{k+1} - 1$ nodes, since level $i$ holds exactly $2^i$ nodes for $0 \le i < k$ and the last level is partially filled. Inverting the bound $2^k \le n < 2^{k+1}$ yields $k = \lfloor \log_2 n \rfloor$. $\square$

This logarithmic bound is precisely why balanced binary search trees guarantee $O(\log n)$ search time: the height controls the worst-case number of comparisons.

**Lab Cell (SymPy).**

```python
from sympy.combinatorics import tree_generators

def node_height(adj, root):
    """Return height of every node via post-order DFS."""
    height = {}
    def dfs(v, parent):
        children = [u for u in adj[v] if u != parent]
        if not children:
            height[v] = 0
        else:
            height[v] = 1 + max(dfs(c, v) for c in children)
        return height[v]
    dfs(root, None)
    return height

adj = {0:[1,2], 1:[0,3,4], 2:[0], 3:[1], 4:[1]}
print(node_height(adj, root=0))  # {0:2, 1:1, 2:0, 3:0, 4:0}
```

Running this cell reproduces the worked example and confirms that height is computed bottom-up in $O(n)$ time.

### sentinel_node (19.6s)

## Sentinel Node

**Definition.** A *sentinel node* is a dummy node inserted into a linked data structure — typically at the boundary positions (head, tail, or both) — that carries no meaningful data but participates in every structural operation on an equal footing with real nodes. Formally, given a linked list $L = (v_1, v_2, \ldots, v_n)$, we augment it to $L^* = (s_0, v_1, v_2, \ldots, v_n, s_{n+1})$, where $s_0$ and $s_{n+1}$ are sentinel nodes satisfying $s_0.\text{next} = v_1$ and $v_n.\text{next} = s_{n+1}$, with $s_{n+1}.\text{next} = \texttt{None}$.

The key invariant is that $L^*$ is **never empty**: even when $n = 0$, we have $s_0.\text{next} = s_{n+1}$. This eliminates the need to treat the empty-list and single-element cases separately.

**Worked Example.** Consider deleting node $v_k$ from $L^*$. Without sentinels, the algorithm must check whether $v_k$ is the head (requiring a pointer update to $L.\text{head}$) or an interior node. With sentinels, every node has a unique predecessor, so deletion reduces to a single uniform operation: locate $p$ such that $p.\text{next} = v_k$, then set $p.\text{next} \leftarrow v_k.\text{next}$. No branch on position is needed, reducing cyclomatic complexity from $O(\text{cases})$ to $1$.

**Key Theorem (Correctness of Sentinel-Based Traversal).** Let $L^*$ be a doubly-linked list with head sentinel $s_0$ and tail sentinel $s_{n+1}$. A traversal algorithm that initialises its cursor to $\text{cursor} \leftarrow s_0.\text{next}$ and halts when $\text{cursor} = s_{n+1}$ visits each data node $v_i$ exactly once, regardless of $n \geq 0$.

*Proof sketch.* By the loop invariant, at step $i$ the cursor points to $v_i$ (or $s_{n+1}$ if $i > n$). Since $s_{n+1}$ is distinct from every $v_i$ by construction, the halting condition triggers precisely after $v_n$ is processed. $\blacksquare$

The sentinel pattern has complexity consequences: insertion and deletion at any position run in $O(1)$ pointer operations with no conditional branches on boundary membership, compared with $O(1)$ but with $O(\text{cases})$ branch overhead in the unguarded implementation.

**Lab Cell.**

```python
from sympy import symbols

class Node:
    def __init__(self, val=None):
        self.val = val
        self.next = None

head = Node()          # sentinel head
tail = Node()          # sentinel tail
head.next = tail

def insert_after(p, val):
    node = Node(val)
    node.next = p.next
    p.next = node

def delete_after(p):
    assert p.next is not tail, "nothing to delete"
    p.next = p.next.next

insert_after(head, 10)
insert_after(head, 20)   # list: 20 → 10
delete_after(head)       # removes 20

cur, result = head.next, []
while cur is not tail:
    result.append(cur.val)
    cur = cur.next

print(result)  # [10]
```

Running this cell confirms that traversal, insertion, and deletion each require no special-case logic, validating the theorem above experimentally.

### singly_linked_list_hierarchy (18.6s)

## Singly Linked List Hierarchy

**Definition.** A *singly linked list* is a linear data structure consisting of a sequence of *nodes*, where each node contains a data field and a single reference (pointer) to the next node in the sequence. Formally, let $\mathcal{N}$ denote the set of nodes. Each node $n \in \mathcal{N}$ is a pair $n = (d, p)$, where $d$ is the stored datum and $p \in \mathcal{N} \cup \{\texttt{None}\}$ is the successor pointer. The list is anchored by a distinguished *head* node $h$, and terminates at the unique node $t$ satisfying $t.p = \texttt{None}$, called the *tail*. A list of $k$ nodes forms a chain $h = n_0 \to n_1 \to \cdots \to n_{k-1} = t$.

**Worked Example.** Consider the integer list $[3, 7, 2]$. Construct three nodes:

$$n_0 = (3,\, n_1),\quad n_1 = (7,\, n_2),\quad n_2 = (2,\, \texttt{None}).$$

Traversal begins at $h = n_0$. Following pointers yields $3 \to 7 \to 2 \to \texttt{None}$, visiting each datum exactly once. Inserting a new node $n' = (5, n_1)$ after $n_0$ requires only the reassignment $n_0.p \leftarrow n'$, an $O(1)$ operation at a known location, contrasting with the $O(k)$ shift required in an array.

**Key Theorem (Traversal Complexity).** *Let $L$ be a singly linked list of length $k$. Any algorithm that must inspect every element of $L$ requires $\Theta(k)$ time and $O(1)$ auxiliary space.*

*Proof sketch.* Each node is reachable only by following the unique chain of pointers from $h$; there is no random-access indexing. Thus at least $k$ pointer dereferences are necessary, giving the $\Omega(k)$ lower bound. A single-pass traversal achieves $O(k)$ with a single cursor variable, establishing $O(1)$ space. $\square$

This traversal asymmetry — efficient sequential access, costly arbitrary access — defines the fundamental trade-off that motivates more elaborate structures such as doubly linked lists and skip lists.

**Lab Cell (SymPy / Python).**

```python
class Node:
    def __init__(self, data, nxt=None):
        self.data, self.next = data, nxt

def build(items):
    head = None
    for x in reversed(items):
        head = Node(x, head)
    return head

def traverse(head):
    cur, result = head, []
    while cur:
        result.append(cur.data)
        cur = cur.next
    return result

head = build([3, 7, 2])
print(traverse(head))   # [3, 7, 2]

# Insert 5 after the first node
head.next = Node(5, head.next)
print(traverse(head))   # [3, 5, 7, 2]
```

Run this cell to observe $O(1)$ insertion and verify that traversal cost grows linearly with list length.

### pseudo_random_generator (18.0s)

## Pseudo Random Generator

**Definition.** A *pseudo-random number generator* (PRNG) is a deterministic algorithm that, given an initial value called the *seed* $s_0 \in \mathbb{Z}$, produces a sequence $s_1, s_2, s_3, \ldots$ that is statistically indistinguishable from a sequence of independent, uniformly distributed random variables. Because the sequence is fully determined by $s_0$, it is not truly random; however, for a well-designed PRNG, no polynomial-time algorithm can predict $s_{n+1}$ from $s_1, \ldots, s_n$ with probability meaningfully greater than chance.

The most classical family is the *linear congruential generator* (LCG), defined by the recurrence

$$s_{n+1} = (a \, s_n + c) \bmod m,$$

where $a$ is the multiplier, $c$ the increment, and $m$ the modulus. The sequence is periodic with period at most $m$; the Hull–Dobell theorem characterises exactly when the period equals $m$ (full period).

**Worked Example.** Let $a = 1664525$, $c = 1013904223$, $m = 2^{32}$ (the parameters used in Numerical Recipes). Starting from $s_0 = 42$:

$$s_1 = (1664525 \times 42 + 1013904223) \bmod 2^{32} = 1083814897.$$

Repeating the recurrence yields a sequence that wraps around $2^{32}$ and, after $2^{32}$ steps, returns to $s_0$. Normalising by $m$ maps every output to the interval $[0, 1)$.

**Key Theorem (Hull–Dobell, 1962).** An LCG with modulus $m$, multiplier $a$, and increment $c$ achieves full period $m$ if and only if:
1. $\gcd(c, m) = 1$,
2. $a - 1$ is divisible by every prime factor of $m$,
3. if $4 \mid m$, then $4 \mid (a - 1)$.

These conditions guarantee the sequence visits every residue class modulo $m$ exactly once before cycling, which is essential for unbiased sampling.

**Lab Cell.**

```python
from sympy import gcd, factorint

a, c, m = 1664525, 1013904223, 2**32

def lcg(seed, n):
    s = seed
    for _ in range(n):
        s = (a * s + c) % m
        yield s / m          # normalise to [0, 1)

# Verify Hull–Dobell conditions
prime_factors = factorint(m).keys()          # {2}
cond1 = gcd(c, m) == 1
cond2 = all((a - 1) % p == 0 for p in prime_factors)
cond3 = (m % 4 != 0) or ((a - 1) % 4 == 0)

print(cond1, cond2, cond3)                   # True True True
samples = list(lcg(seed=42, n=10000))
print(f"Mean ≈ {sum(samples)/len(samples):.4f}")   # ≈ 0.5000
```

Running this cell confirms full-period conditions and demonstrates that the sample mean converges to $0.5$, as expected for a uniform distribution on $[0,1)$.

### skiplist (18.7s)

## Skiplist

A **skiplist** is a probabilistic data structure that maintains a sorted sequence of elements across multiple linked lists of decreasing density, enabling expected $O(\log n)$ time for search, insertion, and deletion without the rotational bookkeeping required by balanced binary search trees.

**Definition.** Let $S$ be a sorted set of $n$ keys drawn from a totally ordered universe. A skiplist consists of $L$ levels, $S_0 \supseteq S_1 \supseteq \cdots \supseteq S_{L-1}$, where $S_0$ contains every element and each element present at level $i$ is independently promoted to level $i+1$ with probability $p \in (0,1)$, typically $p = \tfrac{1}{2}$. Each level is represented as a singly-linked list augmented with forward pointers; every node stores pointers to the next node at each level it inhabits.

**Worked Example.** Suppose $S = \{3, 7, 12, 19, 26\}$ and the coin flips produce the following tower heights (number of levels each key reaches): $3\!\to\!1,\ 7\!\to\!3,\ 12\!\to\!2,\ 19\!\to\!1,\ 26\!\to\!2$. The structure is:

$$
\text{Level 2:} \quad -\infty \;\longrightarrow\; 7 \;\longrightarrow\; +\infty
$$
$$
\text{Level 1:} \quad -\infty \;\longrightarrow\; 7 \;\longrightarrow\; 12 \;\longrightarrow\; 26 \;\longrightarrow\; +\infty
$$
$$
\text{Level 0:} \quad -\infty \;\longrightarrow\; 3 \;\longrightarrow\; 7 \;\longrightarrow\; 12 \;\longrightarrow\; 19 \;\longrightarrow\; 26 \;\longrightarrow\; +\infty
$$

To search for $19$: start at the highest level, advance while the next key does not exceed the target, then drop one level and repeat. The path visits $7$ (level 2), $12$ (level 1), $19$ (level 0) — three comparisons instead of five.

**Key Theorem** (Pugh 1990). With promotion probability $p$ and $n$ elements, the expected number of comparisons in a search is $\frac{\log_{1/p} n}{p} + \frac{1}{1-p}$, giving $O(\log n)$ expected time. The expected space is $O(n)$ because the geometric series $\sum_{i=0}^{\infty} n p^i = \frac{n}{1-p}$ converges.

**Lab Cell.**

```python
from sympy import symbols, log, Rational, simplify

p, n = symbols('p n', positive=True)
expected_comparisons = log(n, 1/p) / p + 1/(1 - p)
print("Expected comparisons:", simplify(expected_comparisons))

# Evaluate at p=1/2, n=1024
result = expected_comparisons.subs([(p, Rational(1,2)), (n, 1024)])
print("At p=1/2, n=1024:", float(result))
```

Running this cell yields approximately $22$ expected comparisons for $n = 1024$, consistent with $2\log_2 1024 = 20$, with the small additive constant arising from the level-drop overhead.

### pick_height_procedure (25.4s)

## Pick Height Procedure

### Definition

Let $T$ be a rooted tree whose nodes carry real-valued labels, and let $k \in \mathbb{Z}_{\geq 0}$ be a target level. The **pick-height procedure** is a deterministic algorithm that, given $T$ and $k$, returns the multiset of all node labels at depth exactly $k$ from the root.

Formally, define the **depth** of a node $v$ recursively: the root has depth $0$, and any child of a node at depth $d$ has depth $d+1$. Then

$$\text{PickHeight}(T,\, k) = \{\, \ell(v) \mid v \in V(T),\; \operatorname{depth}(v) = k \,\},$$

where $\ell : V(T) \to \mathbb{R}$ is the labelling function and $V(T)$ denotes the vertex set of $T$.

### Worked Example

Consider the binary tree with root $A = 5$, whose left child is $B = 3$ and right child is $C = 8$, and whose grandchildren are $D = 1$ (left of $B$), $E = 4$ (right of $B$), and $F = 7$ (left of $C$).

$$\text{PickHeight}(T, 0) = \{5\}, \quad \text{PickHeight}(T, 1) = \{3, 8\}, \quad \text{PickHeight}(T, 2) = \{1, 4, 7\}.$$

Choosing $k = 2$ yields all grandchildren of the root, giving the multiset $\{1, 4, 7\}$ whose sum is $12$ and whose maximum is $7$.

### Key Theorem

**Theorem (Breadth Bound).** *Let $T$ be a binary tree of height $h$. For any $0 \leq k \leq h$, the procedure $\text{PickHeight}(T, k)$ returns at most $2^{k}$ elements and runs in $\Theta(n)$ time, where $n = |V(T)|$.*

*Proof sketch.* Each node at depth $k-1$ contributes at most $2$ children, giving the bound $|\text{PickHeight}(T,k)| \leq 2^k$ by induction. Since every node is visited exactly once in a breadth-first traversal, the time complexity is $\Theta(n)$. $\blacksquare$

The bound $2^k$ is tight for complete binary trees and reveals the exponential growth of each level, a fact central to the analysis of divide-and-conquer recurrences.

### Lab Cell (SymPy)

```python
from sympy import symbols, Function, Rational
from collections import defaultdict

def pick_height(tree_edges, labels, k):
    """tree_edges: list of (parent, child) tuples; labels: dict node->value."""
    depth = defaultdict(lambda: float('inf'))
    root = {p for p, _ in tree_edges} - {c for _, c in tree_edges}
    root = next(iter(root)) if root else list(labels)[0]
    depth[root] = 0
    for parent, child in tree_edges:
        depth[child] = depth[parent] + 1
    return [labels[v] for v, d in depth.items() if d == k]

edges  = [('A','B'), ('A','C'), ('B','D'), ('B','E'), ('C','F')]
labels = {'A':5, 'B':3, 'C':8, 'D':1, 'E':4, 'F':7}

for level in range(3):
    print(f"k={level}: {pick_height(edges, labels, level)}")
```

Running this cell prints `k=0: [5]`, `k=1: [3, 8]`, `k=2: [1, 4, 7]`, confirming the worked example above.

### search_path (24.2s)

## Search Path

**Definition.** Let $G = (V, E)$ be a directed graph where $V$ is a finite set of *vertices* (states) and $E \subseteq V \times V$ is a set of *edges* (transitions). A **search path** from a source vertex $s \in V$ to a target vertex $t \in V$ is a finite sequence

$$\pi = \langle v_0, v_1, \ldots, v_k \rangle, \quad v_i \in V,$$

such that $v_0 = s$, $v_k = t$, and $(v_{i}, v_{i+1}) \in E$ for every $0 \le i < k$. The *length* of $\pi$ is $|\pi| = k$ (the number of edges traversed). A search path is called **simple** if all vertices $v_0, \ldots, v_k$ are distinct. The set of all simple search paths from $s$ to $t$ is denoted $\Pi(s, t)$.

In the context of heuristic search, each edge $(u, v)$ may carry a non-negative cost $c(u, v) \ge 0$. The **path cost** is then $\operatorname{cost}(\pi) = \sum_{i=0}^{k-1} c(v_i, v_{i+1})$, and finding an optimal search path reduces to minimising $\operatorname{cost}(\pi)$ over $\Pi(s, t)$.

**Worked example.** Consider the graph $G$ with $V = \{A, B, C, D\}$ and weighted edges

$$A \xrightarrow{1} B, \quad A \xrightarrow{4} C, \quad B \xrightarrow{2} C, \quad B \xrightarrow{5} D, \quad C \xrightarrow{1} D.$$

Two search paths from $A$ to $D$ exist: $\pi_1 = \langle A, B, D \rangle$ with $\operatorname{cost}(\pi_1) = 1 + 5 = 6$, and $\pi_2 = \langle A, B, C, D \rangle$ with $\operatorname{cost}(\pi_2) = 1 + 2 + 1 = 4$. Thus $\pi_2$ is the optimal search path.

**Key theorem (Bellman's optimality principle).** Let $\pi^* = \langle v_0, \ldots, v_k \rangle$ be an optimal search path from $s = v_0$ to $t = v_k$. Then for every $0 \le i \le j \le k$, the sub-sequence $\langle v_i, \ldots, v_j \rangle$ is an optimal search path from $v_i$ to $v_j$.

*Proof sketch.* Suppose some sub-path $\langle v_i, \ldots, v_j \rangle$ were not optimal; let $\pi'$ be a cheaper path from $v_i$ to $v_j$. Substituting $\pi'$ into $\pi^*$ yields a path from $s$ to $t$ with strictly lower cost, contradicting the optimality of $\pi^*$. $\square$

This principle underlies dynamic-programming algorithms such as Dijkstra's algorithm and the Bellman–Ford algorithm.

**Lab cell (SymPy).**

```python
import sympy as sp
from sympy.combinatorics.named_groups import SymmetricGroup

# Represent the example graph as an adjacency dictionary with costs
graph = {'A': [('B', 1), ('C', 4)],
         'B': [('C', 2), ('D', 5)],
         'C': [('D', 1)],
         'D': []}

def all_paths(graph, src, tgt, path=None):
    path = (path or []) + [src]
    if src == tgt:
        return [path]
    return [p for nbr, _ in graph.get(src, [])
              if nbr not in path
              for p in all_paths(graph, nbr, tgt, path)]

def path_cost(graph, path):
    costs = {(u, v): w for u, es in graph.items() for v, w in es}
    return sum(costs[(path[i], path[i+1])] for i in range(len(path)-1))

paths = all_paths(graph, 'A', 'D')
for p in paths:
    print(p, '->', path_cost(graph, p))
```

### skiplist_sset (19.0s)

## Skiplist Sset

**Definition.** A *skiplist sorted set* (SkiplistSSet) is a randomized data structure that maintains a totally ordered collection of elements and supports the operations $\texttt{find}(x)$, $\texttt{add}(x)$, and $\texttt{remove}(x)$, each in $O(\log n)$ expected time. Structurally, a skiplist consists of a hierarchy of $h$ singly-linked lists $L_0, L_1, \ldots, L_{h-1}$, where $L_0$ contains all $n$ elements in sorted order and each element present in $L_i$ is independently promoted to $L_{i+1}$ with probability $p = \tfrac{1}{2}$. Sentinel nodes $-\infty$ and $+\infty$ anchor every level. The expected height satisfies $h = O(\log n)$.

A node at level $i$ stores a key and an array of forward pointers $\texttt{next}[0], \ldots, \texttt{next}[i]$, where $\texttt{next}[j]$ points to the successor at level $j$. This layered structure lets a search descend from coarse to fine resolution, analogous to binary search on a sorted array but without requiring contiguous memory.

**Worked Example.** Suppose the skiplist contains the keys $\{3, 7, 12, 19, 26\}$ and the current height is $3$. To find $19$, begin at the head sentinel at level $2$. Moving right at level $2$ reaches $12$; the next node at level $2$ exceeds $19$, so drop to level $1$. Advancing at level $1$ reaches $19$ directly. Total comparisons: $3$, far fewer than a linear scan of $L_0$.

**Key Theorem.** *(Expected search cost.)* In a skiplist with $n$ elements and promotion probability $p = \tfrac{1}{2}$, the expected number of nodes examined during a search is

$$\mathbb{E}[\text{comparisons}] \leq 2\log_2 n + O(1).$$

*Proof sketch.* Model the search path in reverse: starting from the found node and moving upward or leftward. At each step, a move upward occurs with probability $\tfrac{1}{2}$ and a move left with probability $\tfrac{1}{2}$. Let $C(k)$ denote the expected cost to climb $k$ levels; then $C(k) = 2k$ by a straightforward recurrence. Since the expected height is $\log_2 n$, the bound follows. $\square$
