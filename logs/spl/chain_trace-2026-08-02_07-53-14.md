## Big Data

You already know data means information — names, temperatures, prices, likes. But at some point, the *amount* of data itself becomes the problem. That shift is what "Big Data" is really about.

**What makes data "big"?** Engineers use the **3 Vs** as a framework:

- **Volume** — the sheer size. A single social media platform processes over $10^{18}$ bytes (one exabyte) per day. A regular laptop holds about $10^{12}$ bytes (one terabyte) — so we are talking roughly a million laptops' worth.
- **Velocity** — how fast new data arrives. Stock prices update thousands of times per second; a self-driving car's sensors stream gigabytes every minute.
- **Variety** — data comes in messy forms: structured tables, free-text reviews, images, audio clips, GPS coordinates.

The core challenge is that traditional tools (a single spreadsheet, one database on one machine) break under these conditions. Solutions involve **distributing** the work across many computers at once.

A useful rule of thumb: if processing time scales as $O(n)$ on one machine, splitting across $k$ machines can bring it toward $O(n/k)$ — not perfectly, because coordinating the machines adds its own overhead, but roughly.

**Why it matters to you:** Nearly every recommendation system, weather forecast, and medical diagnosis tool you encounter is powered by large-scale data pipelines.

## Machine Learning Model

You already have the intuition: a machine learning model is a program that *learns from examples* rather than following hand-written rules. Now let's look at what's actually happening under the hood.

A model is essentially a mathematical function. It takes some input $x$ — say, pixel values in an image — and produces an output $\hat{y}$, a prediction. The model has internal numbers called **parameters** (often written $\theta$) that control its behavior:

$$\hat{y} = f(x;\, \theta)$$

Training is the process of adjusting $\theta$ so that $f(x;\,\theta)$ gets as close as possible to the true answer $y$ across many examples. We measure "how wrong" the model is with a **loss function** $\mathcal{L}(\hat{y}, y)$ — a small loss means good predictions, a large loss means poor ones.

The simplest model you'll meet is **linear regression**, where:

$$\hat{y} = w \cdot x + b$$

Here the parameters are just a slope $w$ and an intercept $b$. Training finds the $w$ and $b$ that minimize the total loss over all training examples. Neural networks follow exactly the same idea — they just stack many layers of these functions, giving them millions of parameters and far more expressive power.

**The core pattern:** every supervised model shares the same three-part story — a function family $f$, a loss $\mathcal{L}$, and an optimization step that nudges $\theta$ to reduce $\mathcal{L}$.

## Data Mining

You've probably heard that companies "collect data" about users — but raw data is just a pile of numbers and text sitting in a database. Data mining is the process of digging through that pile to find patterns that aren't obvious at first glance. Think of it like archaeology: the artifacts (insights) are already buried in the dirt (data); the job is to uncover them systematically.

Data mining pulls together ideas from statistics, databases, and machine learning into a practical workflow. The core steps are often called **KDD** — Knowledge Discovery in Databases:

1. **Selection** — choose which data to look at
2. **Preprocessing** — clean up errors, fill in missing values
3. **Transformation** — reshape data so algorithms can read it
4. **Mining** — run the actual pattern-finding algorithm
5. **Interpretation** — decide what the pattern means

The algorithms themselves fall into a few families. **Classification** assigns items to categories (spam vs. not spam). **Clustering** groups similar items together without predefined labels — the algorithm finds the groups on its own. **Association rule mining** finds co-occurrence patterns, famously summarized as rules of the form:

$$\text{support}(A \Rightarrow B) = \frac{\text{transactions containing both } A \text{ and } B}{\text{total transactions}}$$

A classic result: customers who buy diapers often also buy beer on Friday evenings — a pattern no manager would have guessed by intuition alone.

The key insight is that mining is *exploratory*: you don't always know what you're looking for until you find it.
